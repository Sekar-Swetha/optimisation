\begin{abstract}
This report presents a comprehensive comparative study of optimisation algorithms
applied to three benchmark problems: a linear regression quadratic loss (Benchmark~A),
a toy neural network loss with sinusoidal perturbation (Benchmark~B), and the
Rosenbrock function (Benchmark~C). Six categories of methods are investigated:
\emph{adaptive step-size methods} (Polyak, Adagrad, RMSprop, Heavy Ball);
\emph{momentum-based methods} (Nesterov acceleration, Adam);
\emph{Newton's method} with local quadratic approximations;
\emph{derivative-free approaches} (finite differences, Nesterov random search,
Nelder--Mead, grid search);
\emph{constrained optimisation} via projected gradient descent and penalty methods;
and the \emph{Frank--Wolfe} algorithm for linear-constrained problems.
Key quantitative findings include: Newton's method solves the quadratic Benchmark~A
in a single iteration ($J = 0.4826$), Nesterov acceleration achieves the lowest
Rosenbrock final value ($f = 0.479$) among first-order methods in 150 iterations,
and projected gradient descent enforces constraint feasibility immediately from
iteration~1 while penalty methods with $\lambda = 4.5$ require approximately
10 iterations to become feasible. Each method is evaluated in terms of convergence
speed, trajectory behaviour, stability, computational cost, and theoretical
convergence guarantees.
\end{abstract}

\section{Introduction}

Optimisation is the cornerstone of modern machine learning and data analysis.
The choice of optimisation algorithm has a profound impact on the convergence
speed, stability, and solution quality of a trained model. This report
systematically evaluates a spectrum of optimisation algorithms across six
methodological categories, spanning from adaptive gradient methods used in
deep learning to classical Newton-type methods and modern Frank--Wolfe
algorithms for constrained problems.

The experiments use three benchmark functions of varying difficulty.
Benchmark~A (linear regression) is a convex quadratic with a known closed-form
solution, providing a baseline for comparing convergence speeds.
Benchmark~B (toy neural network) introduces a nonlinear sinusoidal perturbation
that makes the function non-quadratic but still convex, with moderate anisotropy.
Benchmark~C (Rosenbrock function) is the canonical challenging benchmark with a
narrow curved valley and a condition number $\kappa \approx 2000$ at the optimum,
designed to stress-test any optimisation algorithm.

All experiments are fully reproducible via \texttt{np.random.seed(42)} and the
accompanying Python code file \texttt{CS7DS2\_Final\_Code\_25336453.py}.
Section~\ref{sec:benchmarks} describes the benchmarks; Sections~\ref{sec:q1}

\subsection{Benchmark A: Linear Regression Quadratic Loss}
\label{subsec:bench_a}
A synthetic dataset with $m = 1000$ samples and two parameters is generated:
\begin{equation}
\theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \quad
x^{(i)} \in \mathbb{R}^2, \quad
y^{(i)} = \theta^{\star T} x^{(i)} + \varepsilon^{(i)}, \quad
\varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The loss function is the mean squared error:
\begin{equation}
J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left(\theta^T x^{(i)} - y^{(i)}\right)^2
         = \frac{1}{2}\theta^T H\theta - b^T\theta + c,
\end{equation}
where $H = \frac{1}{m}X^TX \succ 0$ is the positive definite Hessian (constant),
$b = \frac{1}{m}X^Ty$, and $c = \frac{1}{2m}\|y\|^2$.
The gradient is $\nabla J(\theta) = \frac{1}{m}X^T(X\theta - y) = H\theta - b$.
Due to observation noise, the minimum loss is $J^{\star} \approx 0.4826$
(the OLS irreducible noise floor), not zero.
The condition number is $\kappa(H) \approx 3$, making this a well-conditioned problem.
Starting point: $\theta_0 = [0, 0]^T$.

\subsection{Benchmark B: Toy Neural Network Loss}
\label{subsec:bench_b}
\begin{equation}
f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
\end{equation}
The gradient is $\nabla f = [2(x_1 - 1) + \cos(x_1),\ 10(x_2 - 2)]^T$ and the Hessian is
$H(x) = \mathrm{diag}(2 - \sin(x_1),\ 10)$.
The sinusoidal term makes $f$ non-quadratic but maintains convexity
wherever $2 - \sin(x_1) > 0$ (satisfied globally since $\sin(x_1) \leq 1$).
The eigenvalue ratio varies between $\approx 1.8\!:\!10$ and $\approx 3\!:\!10$,
creating moderate anisotropy with condition number $\kappa \approx 5.6$.
The minimum satisfies $2(x_1^{\star} - 1) + \cos(x_1^{\star}) = 0$, giving
$x_1^{\star} \approx 0.582$ and $x_2^{\star} = 2.000$, with
$f^{\star} \approx 0.7244$.
Starting point: $x_0 = [-1, 4]^T$.

\subsection{Benchmark C: Rosenbrock Function}
\label{subsec:bench_c}
\begin{equation}
f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
\end{equation}
The global minimum is at $(1, 1)$ with $f^{\star} = 0$~\cite{rosenbrock}.
The Hessian at the optimum evaluates to
$H(1,1) = \begin{bmatrix} 802 & -400 \\ -400 & 200 \end{bmatrix}$,
with eigenvalues $\approx 0.5$ and $\approx 1001.5$, giving condition number
$\kappa \approx 2003$. This extreme ill-conditioning, combined with a narrow
curved valley along $x_2 = x_1^2$, makes Rosenbrock one of the most
challenging standard test functions for first-order methods.
Starting point: $x_0 = [-1, 1]^T$.

\subsection{Benchmark D: Constrained Feasible Set}
\label{subsec:bench_d}
For constrained problems:
$\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\ -5 \leq x_2 \leq 10\}$.
This is a compact, convex polytope (axis-aligned box), which admits
efficient projection and linear minimisation oracles.

\subsection{Algorithm Formulations and Theoretical Background}
\label{subsec:q1_theory}

Four adaptive methods are compared against a constant step-size gradient descent
baseline across all three benchmarks for 120 iterations.

\paragraph{Polyak Step Size.}
The Polyak step~\cite{polyak1964} is defined as:
\begin{align}
\alpha_k &= \frac{f(x_k) - f^{\star}}{\|\nabla f(x_k)\|^2 + \varepsilon}.
\label{eq:polyak}
\end{align}
For a strongly convex function with modulus $\mu > 0$ and known $f^{\star}$,
the Polyak step guarantees
$\|x_{k+1} - x^{\star}\|^2 \leq \left(1 - \tfrac{\mu}{\|\nabla f(x_k)\|^2/(f(x_k)-f^{\star})}\right)
\|x_k - x^{\star}\|^2$,
achieving at least linear convergence. Crucially, the step size adapts
automatically to the local curvature without requiring knowledge of the Lipschitz
constant $L$. However, knowledge of the exact optimal value $f^{\star}$ is required:
if $f^{\star}$ is \emph{under-estimated} (set lower than the true minimum),
the numerator $f(x_k) - f^{\star}$ remains large near convergence
even as $\|\nabla f(x_k)\| \to 0$, causing $\alpha_k \to \infty$ and divergence.

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, optimal value $f^{\star}$, tolerance $\varepsilon$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets \dfrac{f(x_k) - f^{\star}}{\|g_k\|^2 + \varepsilon}$
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\paragraph{Adagrad.}
Adagrad~\cite{adagrad} accumulates the sum of squared gradients per coordinate:
\begin{equation}
G_{k} = \sum_{j=0}^{k} g_j \odot g_j, \qquad
x_{k+1} = x_k - \frac{\alpha_0}{\sqrt{G_k} + \varepsilon} \odot g_k.
\end{equation}
Adagrad's per-coordinate learning rate shrinks monotonically, providing
implicit preconditioning: coordinates with large historical gradients receive
smaller updates. For convex objectives, the cumulative regret is bounded by
$O(\sqrt{T})$ over $T$ steps, matching the information-theoretic lower bound
for online learning~\cite{adagrad}. The key limitation is that $G_k$ grows without bound,
eventually making steps negligible; this hurts performance on non-stationary
or long-horizon problems.

\begin{algorithm}[H]
\caption{Adagrad}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Per-coordinate accumulation}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\paragraph{RMSprop.}
RMSprop replaces the full sum with an exponential moving average:
\begin{equation}
v_{k+1} = \beta\, v_k + (1-\beta)\, g_k \odot g_k, \qquad
x_{k+1} = x_k - \frac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k.
\end{equation}
The forgetting factor $\beta \in (0,1)$ discounts old gradients, so $v_k$
approximates the \emph{recent} second-moment scale rather than the full history.
This allows RMSprop to maintain informative step sizes for non-stationary problems
and avoids the excessive learning rate decay of Adagrad. The effective memory
length is approximately $1/(1-\beta)$ iterations; for $\beta = 0.9$, this is
10 iterations.

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponential moving average}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\paragraph{Heavy Ball (Polyak Momentum).}
The Heavy Ball method adds a momentum term to the gradient step:
\begin{equation}
z_{k+1} = \beta\, z_k + \alpha\, \nabla f(x_k), \qquad x_{k+1} = x_k - z_{k+1}.
\label{eq:hb}
\end{equation}
For quadratic objectives with condition number $\kappa$, the optimal momentum
parameter is $\beta^{\star} = \left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^2$,
yielding a convergence rate of $\left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^k$
compared to gradient descent's $\left(\frac{\kappa-1}{\kappa+1}\right)^k$.
This represents a quadratic improvement in the exponent for large $\kappa$.
However, Heavy Ball does not achieve the optimal $O(1/k^2)$ rate for general
smooth convex functions; Nesterov acceleration (Section~\ref{sec:q2}) is required
for that.

\begin{algorithm}[H]
\caption{Polyak Momentum / Heavy Ball}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$
    \State $x_{k+1} \gets x_k - z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

\textbf{Key finding on Polyak instability:}
The Polyak step is highly sensitive to the accuracy of $f^{\star}$.
When $f^{\star} = 0$ but the true minimum is $J_A^{\star} \approx 0.4826$ (Benchmark~A)
or $f_B^{\star} \approx 0.7244$ (Benchmark~B), the step size satisfies
$\alpha_k = (f(x_k) - 0)/(\|\nabla f(x_k)\|^2 + \varepsilon) \approx f_{\text{true}}^{\star} / \varepsilon$
as the iterate converges and $\|\nabla f\| \to 0$, growing proportional to
$1/\varepsilon$. This pathological growth causes the iterates to overshoot and
diverge. On Benchmark~C where $f^{\star} = 0$ is exact, Polyak achieves the
best convergence among all methods, validating the theoretical guarantee.

\subsection{Comparative Analysis}

\begin{itemize}[nosep]
\item \textbf{Convergence speed:} When $f^{\star}$ is known exactly, Polyak
converges fastest (Rosenbrock: $f = 0.009$). Otherwise, Adagrad and Heavy Ball
match or exceed GD baseline performance. Heavy Ball's advantage over GD grows
with the problem's condition number, consistent with its theoretical rate improvement
from $O((\kappa-1)/(\kappa+1))^k$ to $O((\sqrt{\kappa}-1)/(\sqrt{\kappa}+1))^k$.
For Benchmark~A with $\kappa \approx 3$, this difference is negligible
($0.5^k$ vs $0.27^k$), explaining why Heavy Ball offers little improvement on A.
For Benchmark~C with $\kappa \approx 2000$, the theoretical speedup is dramatic
($0.9990^k$ for GD vs $0.9776^k$ for optimal Heavy Ball), consistent with
the observed $3.5142 \to 1.4003$ improvement.
\item \textbf{Smoothness:} RMSprop produces the smoothest convergence curves
due to exponential averaging of recent gradient magnitudes. Heavy Ball exhibits
characteristic overshoot followed by damped oscillation, a consequence of the
momentum term building up velocity that must be dissipated near the minimum.
Adagrad converges monotonically --- its step size can only decrease, guaranteeing
no oscillation, though at the cost of slower asymptotic convergence.
\item \textbf{Stability:} The GD baseline is the most stable but slowest.
Polyak is \emph{unstable} when $f^{\star}$ is misspecified.
Adagrad is uniformly stable due to its monotonically decreasing step size,
though this may cause premature stagnation on problems requiring many iterations.
\item \textbf{Why condition number matters:} Benchmark~A has $\kappa \approx 3$
(well-conditioned), so all methods perform similarly. Benchmark~C has
$\kappa \approx 2000$ (highly ill-conditioned), exposing large performance gaps.
The condition number determines how much curvature information methods exploit:
GD ignores it entirely, Heavy Ball uses it implicitly through the momentum
schedule, while Newton (Section~\ref{sec:q3}) uses it exactly.
\item \textbf{Practical implication:} In practice, exact $f^{\star}$ is
rarely known, limiting Polyak's applicability. RMSprop and Adam
(Section~\ref{sec:q2}) are more robust choices for general deep learning problems.
For problems with known condition numbers (e.g., linear systems), Heavy Ball
with the theoretically optimal $\beta^{\star} = ((\sqrt{\kappa}-1)/(\sqrt{\kappa}+1))^2$
achieves near-optimal first-order convergence.
\end{itemize}

\subsection{Algorithm Formulations and Theoretical Background}

\paragraph{Nesterov Acceleration.}
Nesterov momentum modifies Heavy Ball by evaluating the gradient at a
\emph{lookahead} point:
\begin{equation}
\tilde{x}_k = x_k + \beta_k\, z_k, \qquad
z_{k+1} = \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k), \qquad
x_{k+1} = x_k + z_{k+1},
\label{eq:nesterov}
\end{equation}
with $\beta_k = \min\!\left(\frac{k-1}{k+2},\ \beta_{\max}\right)$.
This lookahead is the key distinction from Heavy Ball: by computing the gradient
at the anticipated next position, Nesterov can correct its trajectory \emph{before}
overshooting. For smooth convex functions, this achieves the optimal first-order
convergence rate of $O(1/k^2)$:
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2L\|x_0 - x^{\star}\|^2}{(k+1)^2},
\label{eq:nesterov_rate}
\end{equation}
where $L$ is the Lipschitz constant of the gradient. This compares favourably to
gradient descent's $O(1/k)$ rate and to Heavy Ball's rate which, despite being
faster than GD on quadratics, does not achieve $O(1/k^2)$ on general convex
functions. By Nesterov's 1983 lower bound~\cite{nesterov83}, $O(1/k^2)$ is \emph{optimal} for
first-order methods on smooth convex functions. The practical implementation uses $\beta_k = \min((k-1)/(k+2),\, \beta_{\max})$
with a capped maximum to avoid instability early in the run:
for small $k$, the schedule $(k-1)/(k+2)$ starts near zero (no momentum)
and grows towards $\beta_{\max}$ as convergence to the region of the optimum
is established. The cap $\beta_{\max} < 1$ ensures that the momentum does
not become so large that overshooting dominates.

\begin{algorithm}[H]
\caption{Nesterov Momentum / Acceleration}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\frac{k-1}{k+2},\ \beta_{\max}\right)$
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead point}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

\paragraph{Adam Optimiser.}
Adam~\cite{adam} combines momentum with per-coordinate adaptive scaling:
\begin{align}
m_t &= \beta_1\, m_{t-1} + (1-\beta_1)\, \nabla f(x_t), \label{eq:adam_m}\\
v_t &= \beta_2\, v_{t-1} + (1-\beta_2)\, (\nabla f(x_t))^{\odot 2}, \label{eq:adam_v}\\
\hat{m}_t &= m_t / (1-\beta_1^t), \quad \hat{v}_t = v_t/(1-\beta_2^t), \label{eq:adam_bc}\\
x_{t+1} &= x_t - \alpha\, \hat{m}_t / (\sqrt{\hat{v}_t} + \varepsilon). \label{eq:adam_update}
\end{align}
The bias correction terms in~\eqref{eq:adam_bc} prevent the early iterates from
being biased towards zero (since $m_0 = v_0 = \mathbf{0}$). Without bias
correction, $m_1 = (1-\beta_1)g_1 \approx 0.2g_1$ (for $\beta_1 = 0.8$),
which would artificially halve the effective step size in the first iteration.
Adam can be viewed as RMSprop with momentum: the denominator $\sqrt{\hat{v}_t} + \varepsilon$
provides curvature-aware scaling (like RMSprop), while the numerator $\hat{m}_t$
provides directional momentum (like Heavy Ball or Nesterov). Adam's effective
per-parameter learning rate is approximately $\alpha\sqrt{1-\beta_2^t}/(1-\beta_1^t)$
per iteration, converging to $\alpha$ for large $t$. This design makes Adam
relatively insensitive to the scale of gradients, a key advantage when different
parameters have very different typical gradient magnitudes.

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha$, moments $\beta_1, \beta_2$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\ v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{First moment estimate}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{Second moment estimate}
    \State $\hat{m}_t \gets m_t\, /\, (1 - \beta_1^t)$ \Comment{Bias correction}
    \State $\hat{v}_t \gets v_t\, /\, (1 - \beta_2^t)$
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t\, /\, (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

\textbf{Why Nesterov outperforms Adam on Rosenbrock:}
The Rosenbrock function exhibits a \emph{globally consistent descent direction}
along the valley floor: the long axis of the valley curves from
$(-1, 1)$ towards $(1,1)$, and gradients within this region all point approximately
in the same direction. Nesterov momentum accumulates velocity along this
consistent direction, effectively lengthening its steps along the valley.
Adam, by contrast, scales each coordinate by the root mean square of \emph{all
past gradients}, including those from the steep transverse direction
(perpendicular to the valley). As the Rosenbrock valley becomes progressively
more curved, Adam's accumulated second-moment estimate increasingly over-penalises
the $x_1$ coordinate (due to large transverse gradients early in the run),
under-scaling the valley-traversal steps. This is an instance where
adaptive preconditioning \emph{harms} performance relative to pure momentum,
because the historical gradient statistics misrepresent the current landscape.

\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]

\end{algorithmic}
\end{algorithm}

\paragraph{Convergence of Mini-Batch SGD.}
For strongly convex $f$ with strong-convexity constant $\mu > 0$ and Lipschitz
gradient constant $L$, mini-batch SGD with step size $\alpha_k = \alpha_0/(k+1)$
achieves the following bound on the expected suboptimality of the iterate average
$\bar{x}_T = \frac{1}{T}\sum_{k=0}^{T-1} x_k$:
\begin{equation}
\mathbb{E}[f(\bar{x}_T)] - f^{\star} \leq \frac{\sigma^2 \alpha_0}{b\, (2\mu\alpha_0 - 1)\, T},
\label{eq:sgd_rate}
\end{equation}
where $b$ is the batch size and $\sigma^2 = \mathbb{E}[\|g_k - \nabla f(x_k)\|^2]$
is the per-sample gradient variance. This $O(1/T)$ rate is optimal for stochastic
first-order methods on strongly convex problems. The key insight from~\eqref{eq:sgd_rate}
is that doubling the batch size halves the variance $\sigma^2/b$, which is equivalent
to running for twice as many iterations --- the \emph{linear scaling rule}. For a
constant step size $\alpha$, SGD converges not to $f^{\star}$ but to a neighbourhood
of radius $O(\alpha \sigma^2 / (b\mu))$, explaining the oscillation floor observed
in Figures~\ref{fig:q2_sgd_batch} and~\ref{fig:q2_sgd_noisy}: larger $\sigma$ (high noise)
raises this floor proportionally to $\sigma^2$.

\subsection[Local Approximations of g(x)]{Local Approximations of $g(x) = x^4$}
\label{subsec:q3_approx}

\textbf{First-order (Taylor) approximation} around $x_0 = 0.25$:
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0)
    = 0.25^4 + 4 \cdot 0.25^3\,(x - 0.25)
    = 0.003906 + 0.0625(x - 0.25).
\end{equation}
This linear model is exact in the sense that $g(x_0) = 0.003906$ and the slope
$g'(x_0) = 4(0.25)^3 = 0.0625$ are correct, but it captures no curvature.
Minimising this linear model is ill-posed (the minimum is $-\infty$), so a
gradient step on this approximation amounts to a fixed step in the negative
gradient direction.

\textbf{Second-order approximation:}
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0) + \tfrac{1}{2}g''(x_0)(x - x_0)^2
    = 0.003906 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{equation}
Here $g''(x_0) = 12(0.25)^2 = 0.75$. Minimising this quadratic with respect to $x$
gives the Newton update:
\begin{equation}
x^{\star} = x_0 - \frac{g'(x_0)}{g''(x_0)} = 0.25 - \frac{0.0625}{0.75} = 0.25 - 0.0833 = 0.1667.
\end{equation}
This is a better estimate of the true minimum $x^{\star} = 0$ than a gradient
step alone, illustrating how Newton's method leverages curvature information.

\subsection{Newton's Method with Hessian Damping}

In the multivariate setting, Newton's step solves the local quadratic model:
\begin{equation}
p_k = \arg\min_{p}\ f(x_k) + \nabla f(x_k)^T p + \tfrac{1}{2} p^T \nabla^2 f(x_k)\, p
    = \bigl(\nabla^2 f(x_k)\bigr)^{-1} \nabla f(x_k).
\end{equation}
The update $x_{k+1} = x_k - \alpha\, p_k$ with $\alpha < 1$ is a \emph{damped}
Newton step, necessary when the Hessian is not positive definite far from the
optimum or the quadratic approximation is inaccurate. The step size choices
reflect the varying quality of the quadratic approximation:
\begin{itemize}[nosep]
\item Benchmark~A ($\alpha = 1.0$): The loss is exactly quadratic, so
  the Newton quadratic model is perfect and a full step gives the exact minimiser.
\item Benchmark~B ($\alpha = 0.85$): The sinusoidal term introduces small
  non-quadratic corrections; a near-full step works because $|\sin(x_1)| \leq 1$
  is bounded, keeping the non-quadratic residual small.
\item Benchmark~C ($\alpha = 0.22$): The Rosenbrock Hessian changes rapidly
  (e.g., $h_{11} = 2 + 1200x_1^2 - 400x_2$ ranges from $\approx 2$ at
  $(-1,1)$ to $\approx 802$ at $(1,1)$), so the quadratic approximation is
  reliable only locally and a heavily damped step is required to avoid
  overshooting the valid region of the approximation.
\end{itemize}
Hessian regularisation $\nabla^2 f(x_k) + \lambda I$ (with $\lambda = 10^{-8}$)
ensures the system is always positive definite, providing a numerically robust
fallback to gradient descent ($p_k \approx g_k$ when $\lambda$ dominates).

Near a non-degenerate local minimum $x^{\star}$ (where $\nabla^2 f(x^{\star}) \succ 0$),
Newton's method achieves \textbf{quadratic convergence}:
\begin{equation}
\|x_{k+1} - x^{\star}\| \leq C \|x_k - x^{\star}\|^2,
\label{eq:quadratic_conv}
\end{equation}
for some constant $C > 0$ depending on the Hessian's Lipschitz constant.
The number of correct decimal digits \emph{doubles} at each step (e.g., from
2 significant digits to 4, then to 8), compared to gradient descent's linear
convergence which adds a fixed number of digits per step.

\begin{algorithm}[H]
\caption{Newton's Method with Damping}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Regularised Hessian}
    \State $p_k \gets H_k^{-1}\, g_k$ \Comment{Newton direction}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Quasi-Newton Approximations: BFGS and L-BFGS}

For problems where the Hessian is too expensive to compute, quasi-Newton methods
build an approximation $B_k \approx \nabla^2 f(x_k)$ from gradient differences alone.
The \textbf{BFGS update}~\cite{nocedal} (Broyden--Fletcher--Goldfarb--Shanno) uses
a rank-2 correction:
\begin{equation}
B_{k+1} = B_k - \frac{B_k s_k s_k^T B_k}{s_k^T B_k s_k} + \frac{y_k y_k^T}{y_k^T s_k},
\label{eq:bfgs}
\end{equation}
where $s_k = x_{k+1} - x_k$ (step vector) and $y_k = \nabla f(x_{k+1}) - \nabla f(x_k)$
(gradient difference). The update satisfies the \emph{secant condition}
$B_{k+1} s_k = y_k$, enforcing that the Hessian approximation is consistent with
the observed gradient change along the last step. This is analogous to fitting a
quadratic through two consecutive gradient observations.

Inverting $B_{k+1}$ via the Sherman--Morrison--Woodbury identity gives a direct
update for the inverse Hessian $H_k = B_k^{-1}$:
\begin{equation}
H_{k+1} = \left(I - \rho_k s_k y_k^T\right) H_k \left(I - \rho_k y_k s_k^T\right)
          + \rho_k s_k s_k^T, \qquad \rho_k = \frac{1}{y_k^T s_k},
\label{eq:bfgs_inv}
\end{equation}
requiring only $O(d^2)$ work (two rank-1 updates). BFGS achieves \emph{superlinear}
convergence near the optimum: $\|x_{k+1} - x^{\star}\| = o(\|x_k - x^{\star}\|)$,
faster than gradient descent's linear rate but slower than Newton's quadratic rate.
The superlinear rate arises because the BFGS approximation $H_k \to (\nabla^2 f(x^{\star}))^{-1}$
as $x_k \to x^{\star}$, so BFGS asymptotically mimics Newton.

\textbf{L-BFGS} (Limited-memory BFGS) further reduces storage to $O(md)$ by retaining
only the $m$ most recent curvature pairs $(s_j, y_j)_{j=k-m}^{k-1}$ instead of
the full $d \times d$ matrix $H_k$. The Newton direction $H_k \nabla f(x_k)$ is then
computed in $O(md)$ via a two-loop recursion. For $m = 5$--20 and $d = 10^6$, L-BFGS
uses megabytes of memory instead of terabytes, making it the standard method for
large-scale smooth unconstrained optimisation.

\subsection{Summary: Newton vs Gradient Descent}

Newton's method offers quadratic convergence near the optimum at the cost of
computing and inverting the Hessian~\cite{nocedal}. For $d$-dimensional problems, this
requires $O(d^3)$ work per iteration for exact linear system solutions (via
Cholesky decomposition), versus $O(d)$ for gradient descent. In the
2-dimensional setting here, this cost is negligible.
However, for the large-scale problems in modern machine learning ($d \sim 10^6$--$10^{12}$
parameters), exact Hessian methods are infeasible, motivating quasi-Newton methods
(L-BFGS~\eqref{eq:bfgs_inv}) that approximate the inverse Hessian from
$m$ most recent gradient differences, requiring only $O(md)$ storage and work.

\subsection{Part A: Finite Difference and Nesterov Random Search (Benchmark B)}

\subsubsection{Finite Difference Gradient Approximation}

The forward finite-difference approximation replaces each partial derivative with:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta}.
\label{eq:fd}
\end{equation}
The approximation error has two competing components:
\begin{equation}
\left|\frac{\partial f}{\partial x_i}(x) - \frac{f(x + \delta e_i) - f(x)}{\delta}\right|
= \underbrace{\frac{\delta}{2}\left|\frac{\partial^2 f}{\partial x_i^2}(x)\right|}_{\text{truncation error: }O(\delta)}
  + \underbrace{\frac{2\varepsilon_{\text{mach}}}{\delta}\cdot|f(x)|}_{\text{floating-point error: }O(\varepsilon_{\text{mach}}/\delta)}.
\label{eq:fd_error}
\end{equation}
The truncation error grows with $\delta$ (coarser approximation), while the
floating-point error grows as $\delta \to 0$ (catastrophic cancellation in
$f(x+\delta) - f(x)$). The total error is minimised at
$\delta^{\star} = \sqrt{2\varepsilon_{\text{mach}}|f|/|f''|}$.
For Benchmark~B near $x_0 = (-1, 4)$ (where $|f| \approx 9$ and $|f''| \approx 10$),
this gives $\delta^{\star} \approx \sqrt{2 \times 10^{-16} \times 9/10} \approx 4 \times 10^{-9}$.

In practice, $\delta = 10^{-5}$--$10^{-3}$ is commonly used for smooth functions,
balancing approximation quality against sensitivity to function evaluation noise.
The assignment setting $\delta = 0.05$ is in the \emph{truncation-dominated} regime
but with manageable error: the gradient magnitude at the starting point is
$\|\nabla f(-1,4)\| = \|(2(-1-1)+\cos(-1),\,10(4-2))\| = \|(-3.46,\,20)\| \approx 20.3$,
much larger than the truncation error $0.05/2 \cdot \max |f''| \approx 0.5 \cdot 10 = 0.25$.
By contrast, $\delta = 0.8$ produces a truncation error $\approx 4.0$, which can
mis-align the gradient direction significantly, explaining the poor convergence.
The gradient descent step uses $\alpha = 0.08$ for both FD settings, with 120 iterations.

A more accurate alternative is the \textbf{central difference} approximation:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x - \delta e_i)}{2\delta},
\label{eq:cd}
\end{equation}
with truncation error $O(\delta^2)$ (the odd-order Taylor terms cancel), compared to
$O(\delta)$ for the forward difference~\eqref{eq:fd}. This squared improvement means
central differences are accurate for $\delta$ 100$\times$ larger than the forward-difference
optimum. The cost is $2d$ evaluations per gradient (versus $d+1$ for forward differences).
The optimal step for central differences minimising total error~\eqref{eq:fd_error} is:
\begin{equation}
\delta^{\star}_{\text{CD}} = \left(\frac{3\varepsilon_{\text{mach}}\,|f|}{|f'''|}\right)^{1/3}
\approx (3 \times 10^{-16})^{1/3} \approx 7 \times 10^{-6}
\end{equation}
for typical function values. For this assignment's $\delta = 0.05$, the central difference
would produce truncation error $\approx (0.05)^2/6 \cdot |f'''| \approx 0.004$, compared to
forward difference error $\approx 0.25$ --- a 60$\times$ improvement at twice the cost.

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Sample $u_k \sim \mathcal{N}(0, I)$, normalise: $u_k \gets u_k / \|u_k\|$
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta u_k) - f(x_k)}{\delta}\, u_k$
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

Nesterov random search uses a random unit vector $u_k$ to form a directional
derivative estimate. The key statistical property is:
\begin{equation}
E_{u_k}[\hat{g}_k] = E_{u_k}\!\left[\frac{f(x_k + \delta u_k) - f(x_k)}{\delta}\, u_k\right]
= \nabla f(x_k) + O(\delta^2),
\end{equation}
making the update an asymptotically unbiased gradient estimator. Geometrically,
the outer product $u_k u_k^T$ has expectation $\frac{1}{d} I$ (for a uniformly
random unit vector on the sphere), so averaging $d$ random-direction estimates
recovers the full gradient. In $d$ dimensions, a single random search step
captures only $1/d$ of the gradient information per step, so convergence
requires approximately $d$ times more steps than exact gradient descent.
This explains why, for $d = 2$, the random search takes $\approx 2 \times$
more iterations but still converges --- the constant factor is small.
For $d \gg 1$, the method's advantage is its $O(1)$ FE cost per step.
This method requires only \emph{two} function evaluations per iteration (at $x_k$
and $x_k + \delta u_k$) regardless of dimension, making it attractive when
$d$ is very large or when the cost of a single function evaluation dominates.

\subsubsection{Nelder--Mead Simplex Method}

The Nelder--Mead algorithm maintains a simplex of $n+1 = 3$ vertices in
$\mathbb{R}^2$ and iteratively improves it through four operations:
\textbf{reflection} (reflect worst vertex through centroid of best $n$ vertices),
\textbf{expansion} (if reflection improved, extend further in that direction),
\textbf{contraction} (if reflection worsened, contract towards centroid),
and \textbf{shrink} (contract all vertices towards best vertex).
No gradient information is required; only function values at the simplex vertices.

The simplex geometry adapts to the landscape: elongated simplices explore
along promising directions, while contracted simplices refine near the minimum.
The standard parameters used here are reflection $\alpha_r = 1.0$,
expansion $\gamma = 2.0$, contraction $\rho = 0.5$, shrink $\sigma = 0.5$.
Settings: initial simplex step $= 0.35$, iterations $= 160$.

\subsection{Problem Setup and Optimality Conditions}

Minimise Benchmark~B subject to $x_1 \geq 0.5$, starting from the infeasible
point $x_0 = (0.2, 4.0)$:
\begin{equation}
\min_{x} f(x_1, x_2) = (x_1-1)^2 + 5(x_2-2)^2 + \sin(x_1) \quad
\text{subject to}\quad x_1 \geq 0.5.
\label{eq:q5_problem}
\end{equation}
Since the unconstrained minimiser is $x^{\star}_{\text{unc}} \approx (0.582, 2.0)$
and $0.582 > 0.5$, the constraint is \emph{inactive} at the optimal solution.
The constrained and unconstrained optima coincide: $x^{\star} = (0.582, 2.0)$
with $f^{\star} = 0.7244$.

The first-order KKT conditions for~\eqref{eq:q5_problem} are:
\begin{equation}
\nabla f(x^{\star}) + \mu^{\star}\, (-e_1) = 0, \quad
\mu^{\star} \geq 0, \quad
\mu^{\star}(0.5 - x_1^{\star}) = 0,
\end{equation}
where $e_1 = (1, 0)^T$ is the first coordinate vector and $\mu^{\star}$ is the
dual variable. Since $x_1^{\star} > 0.5$ (constraint inactive), complementary
slackness gives $\mu^{\star} = 0$, recovering $\nabla f(x^{\star}) = 0$.
This confirms that the constraint does not affect the solution here; it affects
only the optimisation \emph{path} from the infeasible starting point.

\begin{algorithm}[H]
\caption{Projected Gradient Descent}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, projection $\Pi_{\mathcal{F}}$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Unconstrained gradient step}
    \State $x_{k+1} \gets \Pi_{\mathcal{F}}(z_{k+1})$ \Comment{Project: $x_1 \leftarrow \max(0.5,\, x_1)$}
\EndFor
\end{algorithmic}
\end{algorithm}

Projected GD replaces infeasible gradient steps with their nearest feasible
projections. For the half-space $\mathcal{F} = \{x : x_1 \geq 0.5\}$,
the projection is simply $\Pi_{\mathcal{F}}(z) = (\max(0.5, z_1),\, z_2)^T$,
computed in $O(1)$. The projection operator is \emph{non-expansive}:
$\|\Pi_{\mathcal{F}}(z) - \Pi_{\mathcal{F}}(z')\| \leq \|z - z'\|$,
which ensures that PGD inherits the convergence guarantees of gradient descent
in the feasible set.

\begin{algorithm}[H]
\caption{Penalty Method}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, penalty weight $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $F_{\lambda}(x) \gets f(x) + \lambda \max(0,\, -x_1 + 0.5)$ \Comment{Penalised objective}
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_{\lambda}(x_k)$
\EndFor
\end{algorithmic}
\end{algorithm}

The penalty gradient is $\nabla F_{\lambda}(x) = \nabla f(x) + \lambda (-e_1)\, \mathbf{1}[x_1 < 0.5]$.
The penalty method converts the constrained problem into an unconstrained one
by adding a cost for constraint violation. The minimiser of $F_{\lambda}$ satisfies:
\begin{equation}
\nabla f(x^{\lambda}) - \lambda\, e_1\, \mathbf{1}[x_1^{\lambda} < 0.5] = 0.
\end{equation}
As $\lambda \to \infty$, the penalty drives $x_1^{\lambda} \to 0.5^+$ from above,
and the limiting solution satisfies the KKT conditions of the original problem
with dual variable $\mu^{\star} = \lim_{\lambda\to\infty} \lambda \cdot \mathbf{1}[x_1 < 0.5] = 0$
(since the constraint is inactive at $x_1^{\star} = 0.582$). In this case,
the unconstrained minimum is also the constrained minimum, so any $\lambda > 0$
eventually finds the correct solution; the question is only convergence speed.
Large $\lambda$ creates a gradient discontinuity at $x_1 = 0.5$ and stiffens
the effective Hessian of $F_{\lambda}$ near the boundary, requiring the reduced
step size $\alpha = 0.03$ for $\lambda = 4.5$.

Settings: Projected GD ($\alpha = 0.08$), Penalty with $\lambda \in \{0.15, 1.8, 4.5\}$
($\alpha = 0.05$ for $\lambda \leq 1.8$; $\alpha = 0.03$ for $\lambda = 4.5$),
unconstrained GD ($\alpha = 0.07$). All run for 100 iterations.

\textbf{Projected GD} enforces feasibility immediately at every iteration.
This is the fundamental advantage: feasibility is a hard constraint, not
negotiable. The cost is requiring a projection oracle, which for simple
half-space or box constraints is trivially $O(d)$ but can be expensive for
general constraint sets (e.g., semidefinite constraints require eigenvalue
decomposition).

\textbf{Penalty methods} trade exact feasibility for simplicity: only a modified
gradient is needed. The weight $\lambda$ controls the trade-off. Small $\lambda$
under-penalises violations; large $\lambda$ enforces feasibility but requires
smaller step sizes to maintain stability (here, $\alpha = 0.03$ for $\lambda = 4.5$
vs.\ $\alpha = 0.05$ for $\lambda \leq 1.8$). An improved approach is the
\emph{augmented Lagrangian} method, which updates both the penalty weight and
the Lagrange multiplier iteratively, achieving exact feasibility without the
ill-conditioning of pure penalty methods at finite $\lambda$.

The \textbf{augmented Lagrangian} (Method of Multipliers) for $\min f(x)$ s.t.\ $c(x) \leq 0$
augments the Lagrangian with a quadratic penalty:
\begin{equation}
\mathcal{L}_{\rho}(x, \mu) = f(x) + \mu\, c(x) + \frac{\rho}{2}\max(0,\, c(x))^2,
\label{eq:auglag}
\end{equation}
then alternates between minimising over $x$ and updating the multiplier:
\begin{equation}
x_{k+1} = \arg\min_x \mathcal{L}_{\rho}(x, \mu_k), \qquad
\mu_{k+1} = \max\!\bigl(0,\; \mu_k + \rho\, c(x_{k+1})\bigr).
\label{eq:auglag_update}
\end{equation}
Unlike the pure penalty method, the multiplier update means $\mathcal{L}_{\rho}$
converges to the true Lagrangian at finite $\rho$, avoiding the ill-conditioning
that arises as $\lambda \to \infty$ in~\eqref{alg:penalty}. For the half-space
constraint $c(x) = 0.5 - x_1 \leq 0$ with inactive optimum $x_1^{\star} = 0.582$,
the dual variable is $\mu^{\star} = 0$; the multiplier update quickly drives
$\mu_k \to 0$, recovering the unconstrained solution without any penalty effect,
while maintaining the quadratic convergence speed of the inner minimisation.
The augmented Lagrangian therefore achieves the \emph{exact solution} (zero constraint
violation) with a finite, fixed penalty weight $\rho$, making it the preferred method
for problems where feasibility is required but projection is expensive.

\subsection{Feasible Set and Linear Programme}

Feasible set: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\ -5 \leq x_2 \leq 10\}$.

\textbf{Linear Programme:} For $f(x) = a^T x$ with $a = [1, 2]^T$, the minimum
over $\mathcal{X}$ is obtained by minimising each coordinate independently,
since the feasible set is a box:
\begin{align}
x_1^{\star} &= 0.5 \quad (\text{lower bound, since } a_1 = 1 > 0), \nonumber\\
x_2^{\star} &= -5 \quad (\text{lower bound, since } a_2 = 2 > 0), \nonumber\\
f^{\star} &= 0.5 + 2(-5) = -9.5. \nonumber
\end{align}
This illustrates the fundamental theorem of linear programming: the optimal
solution of a linear objective over a bounded polytope is attained at a
\emph{vertex} (extreme point). For a box in $\mathbb{R}^d$, there are $2^d$
vertices; here $2^2 = 4$, and we can verify all four:
$(0.5, -5)$ gives $f = -9.5$ (minimum), $(5, -5)$ gives $4.5 - 10 = -5.5$,
$(0.5, 10)$ gives $20.5$, and $(5, 10)$ gives $25$.

\subsection{Frank--Wolfe Algorithm}

\begin{algorithm}[H]
\caption{Frank--Wolfe (Conditional Gradient)}
\label{alg:fw}
\begin{algorithmic}[1]
\Require Initial point $x_0 \in \mathcal{X}$, mixing parameter $\beta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_k \gets \arg\min_{x \in \mathcal{X}}\, \nabla f(x_k)^T x$ \Comment{Linear minimisation oracle (LMO)}
    \State $x_{k+1} \gets \beta\, x_k + (1 - \beta)\, z_k$ \Comment{Convex combination}
\EndFor
\end{algorithmic}
\end{algorithm}

The Frank--Wolfe algorithm~\cite{frankwolfe}, also known as the conditional
gradient method, was first proposed for quadratic programming and later
extended to general smooth convex objectives. The key feature is that each
iterate $x_{k+1}$ is a convex combination of $x_k \in \mathcal{X}$ and
$z_k \in \mathcal{X}$, so $x_{k+1} \in \mathcal{X}$ automatically ---
no projection is needed.
This is particularly valuable when projection is expensive but the linear
minimisation oracle (LMO) is cheap.

For box constraints, the LMO decomposes per coordinate:
\begin{equation}
(z_k)_i = \begin{cases} l_i & \text{if } (\nabla f(x_k))_i > 0 \\
u_i & \text{if } (\nabla f(x_k))_i \leq 0 \end{cases},
\label{eq:fw_lmo}
\end{equation}
requiring $O(d)$ operations. The \emph{Frank--Wolfe duality gap}
$g(x_k) = \nabla f(x_k)^T(x_k - z_k) \geq 0$ provides an upper bound on the
optimality gap $f(x_k) - f^{\star}$ and serves as a certificate of convergence.
For smooth convex $f$ with Lipschitz constant $L$, the convergence rate is
$O(LD^2/k)$ where $D = \max_{x,y \in \mathcal{X}}\|x - y\|$ is the diameter:
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2LD^2}{k+2}.
\label{eq:fw_rate}
\end{equation}
This $O(1/k)$ rate is slower than the $O(1/k^2)$ of projected gradient descent,
but each Frank--Wolfe iteration requires only an LMO rather than a projection.

\subsection{Interior vs Boundary Behaviour}

\textbf{Interior optimum:} Frank--Wolfe converges but exhibits a characteristic
zig-zag pattern. The LMO vertex $z_k$ jumps between extreme points of $\mathcal{X}$
as the gradient direction $\nabla f(x_k)$ oscillates near the interior optimum.
The Frank--Wolfe duality gap at each iterate provides a convergence certificate:
\begin{equation}
g(x_k) = \nabla f(x_k)^T(x_k - z_k) \geq f(x_k) - f^{\star} \geq 0.
\label{eq:duality_gap}
\end{equation}
For the interior problem $f(x) = \|x - (1,5)\|^2$, the gradient at the final
iterate $(x_k \approx (1.066, 4.932))$ with $\beta = 0.90$ is
$\nabla f \approx 2(0.066, -0.068)$. The LMO selects $z_k = (0.5, 10)$
(since both gradient components are small and oscillating), giving
$g(x_k) = 2(0.066, -0.068)^T((1.066, 4.932) - (0.5, 10)) = 2(0.066 \cdot 0.566 + (-0.068)(-5.068))$
$\approx 0.76$. This duality gap upper-bounds the suboptimality
$f(x_k) - f^{\star} = 0.0089$.
The convergence rate is $O(1/k)$ per~\eqref{eq:fw_rate}; for $L = 2$
(the Lipschitz constant of $\nabla f$) and $D = \|(0.5,-5) - (5,10)\| \approx 15.7$,
the bound gives $f(x_{180}) - f^{\star} \leq 2\cdot 2 \cdot 15.7^2/182 \approx 5.4$,
which is a loose but valid upper bound.

\textbf{Boundary optimum:} Frank--Wolfe is better suited to boundary optima.
When the optimum lies on the boundary at $(0.5, 0)$, the LMO~\eqref{eq:fw_lmo}
consistently selects vertices in the direction of $-(x_1, x_2)$: since
$\nabla f = 2(x_1, x_2)$ has both components positive (as $x_k \to (0.5, 0^+)$),
the LMO returns $(0.5, -5)$, which is close to the constrained optimum.
This alignment between the LMO direction and the optimal boundary point
leads to smoother convergence than the interior case, where the LMO
jumps between unrelated vertices.
However, the fixed $\beta = 0.93$ schedule does not allow the step size to
decay, resulting in residual oscillation around $f = 0.364 > f^{\star} = 0.25$
after 140 iterations. Using the decaying schedule
$\gamma_k = 2/(k+2)$ (so $\beta_k = 1 - \gamma_k = k/(k+2)$) would
guarantee the $O(1/k)$ rate per~\eqref{eq:fw_rate} and eliminate oscillation.

\section{Conclusion}
\label{sec:conclusion}
% ============================================================

This report has systematically evaluated six families of optimisation algorithms
across benchmark problems of increasing difficulty. The overarching theme is that
\emph{no single algorithm dominates all settings}: the best choice depends critically
on problem structure (curvature, conditioning, noise), available oracle information
(gradients, Hessians, or only function values), and computational constraints.
The key findings are:

\paragraph{Adaptive step-size methods (Question~\ref{sec:q1}):}
The Polyak step is theoretically optimal when $f^{\star}$ is known exactly
(achieving $f = 0.0094$ on Rosenbrock) but diverges catastrophically when
$f^{\star}$ is misspecified. Adagrad provides the most robust performance
via its monotonically decreasing per-coordinate step, matching GD on convex
benchmarks while adding implicit preconditioning. Heavy Ball significantly
outperforms GD on ill-conditioned problems (condition number $\kappa \approx 2000$)
by leveraging momentum, consistent with its theoretical speedup from
$O(\kappa)$ to $O(\sqrt{\kappa})$ iterations.

\paragraph{Momentum methods (Question~\ref{sec:q2}):}
Nesterov acceleration achieves the best first-order performance on Rosenbrock
($f = 0.479$) by building velocity along the consistent valley-floor direction,
consistent with its optimal $O(1/k^2)$ rate per~\eqref{eq:nesterov_rate}.
Adam, combining RMSprop scaling with momentum, matches Nesterov on well-conditioned
benchmarks but underperforms on Rosenbrock where the rapidly varying Hessian
limits the utility of historical second-moment estimates. Mini-batch SGD confirms
the fundamental variance--speed trade-off: smaller batches make faster progress
per epoch but exhibit higher noise near the minimum; high-noise data ($\sigma = 6$)
dominates and eliminates the batch-size advantage.

\paragraph{Newton's method (Question~\ref{sec:q3}):}
Newton's method delivers the most dramatic performance advantage, solving the
quadratic Benchmark~A in a single iteration and achieving $5.4\times$ lower
objective value than GD on Rosenbrock with only $25\%$ of the iterations.
The quadratic convergence~\eqref{eq:quadratic_conv} makes Newton the method of
choice when Hessian computation is feasible, but the $O(d^3)$ cost per
iteration limits applicability to small-scale problems.

\paragraph{Derivative-free methods (Question~\ref{sec:q4}):}
Finite-difference approximation with a good step size ($\delta = 0.05$)
achieves near-exact gradient quality at the cost of $d+1 = 3$ function
evaluations per step. A poor step size ($\delta = 0.8$) severely degrades
convergence due to large truncation error. Nesterov random search provides
a practical option when only function evaluations are available and $d$ is
very large (2 evaluations per step), but converges slowly due to directional
information loss. Grid search guarantees global coverage but is exponentially
costly with dimension.

\paragraph{Constrained optimisation (Question~\ref{sec:q5}):}
Projected gradient descent enforces feasibility exactly from the first iteration,
making it the preferred method when a fast projection oracle exists.
Penalty methods offer flexibility (no projection needed) but require careful
weight selection: too small $\lambda$ leaves residual infeasibility while
too large $\lambda$ creates ill-conditioning. The penalty strength should scale
with the gradient magnitude at the infeasible starting point.

\paragraph{Frank--Wolfe algorithm (Question~\ref{sec:q6}):}
Frank--Wolfe maintains feasibility automatically via convex combinations,
requiring only a linear minimisation oracle rather than a projection.
On interior optima it exhibits zig-zag convergence with a fixed step size,
caused by LMO vertex oscillations; a decaying step schedule would cure this.
On boundary optima, Frank--Wolfe is more naturally suited, as the LMO
consistently selects vertices near the optimal boundary point.

\paragraph{Rosenbrock benchmark ranking:}
For the hardest benchmark (Rosenbrock), the final objective values rank as:
Newton ($0.686$, 20~iter) $\gg$ Polyak ($0.009$, 120~iter, requires $f^{\star}$)
$>$ Nesterov ($0.479$, 150~iter) $>$ Adam ($1.579$, 150~iter)
$>$ Heavy Ball ($1.400$, 120~iter) $>$ Adagrad ($2.203$, 120~iter)
$>$ RMSprop ($3.120$, 120~iter) $\approx$ GD ($3.388$--$3.514$, 120--150~iter).
This ranking reflects the fundamental hierarchy: exact second-order information
(Newton) $\gg$ oracle knowledge of optimum (Polyak) $>$ accumulated momentum
in consistent direction (Nesterov) $>$ adaptive step with momentum (Adam,
Heavy Ball) $>$ adaptive step without momentum (Adagrad, RMSprop) $>$ fixed step
(GD).

\paragraph{Limitations:}
The benchmarks are two-dimensional, making Newton's method computationally
trivial and derivative-free methods (which scale poorly with $d$) appear
competitive. In realistic high-dimensional settings ($d \geq 100$), Newton
becomes infeasible, Nelder--Mead and grid search collapse, and the advantages
of Nesterov/Adam versus GD become more pronounced. The Rosenbrock function,
while highly ill-conditioned, is also smooth and deterministic; stochastic
settings (mini-batch gradients) would alter the method rankings significantly,
favouring Adam over Nesterov due to Adam's variance-reduction through second-moment
accumulation. These considerations motivate the separate stochastic gradient
analysis in Question~2.

\paragraph{Overall recommendation:}
For smooth convex problems with known gradient oracle and manageable dimension
($d < 10^4$): \textbf{Nesterov acceleration} offers optimal first-order
convergence rates. For large-scale and non-convex machine learning with
stochastic gradients: \textbf{Adam} with bias-corrected adaptive scaling.
For problems with low-dimensional structure or known optimal value:
\textbf{Newton with backtracking} or \textbf{Polyak step} respectively.
For derivative-free black-box optimisation in low dimensions: \textbf{Nelder--Mead}.
For constrained problems with simple constraint sets: \textbf{projected gradient
descent}, or Frank--Wolfe when linear minimisation is cheaper than projection.

def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        x = x - alpha * grad_fn(x)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Polyak Step Size},label={lst:polyak}]
def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adagrad},label={lst:adagrad}]
def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float)
    G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={RMSprop},label={lst:rmsprop}]
def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float)
    v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Heavy Ball / Polyak Momentum},label={lst:hb}]
def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x)
        z = beta * z + alpha * g
        x = x - z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Nesterov Momentum},label={lst:nesterov}]
def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z
        g = grad_fn(lookahead)
        z = beta_k * z - alpha * g
        x = x + z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adam Optimiser},label={lst:adam}]
def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t)
        v_hat = v_vec / (1 - beta2**t)
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Newton's Method with Damping},label={lst:newton}]
def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))
        try:
            p = np.linalg.solve(H_reg, g)
        except np.linalg.LinAlgError:
            p = g
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)
\end{lstlisting}

\begin{lstlisting}[caption={Nelder--Mead Simplex},label={lst:nm}]
def nelder_mead(loss_fn, x0, step, n_iters, alpha_r=1.0, gamma=2.0, rho=0.5, sigma=0.5):
    n = len(x0)
    simplex = np.zeros((n + 1, n))
    simplex[0] = x0.copy()
    for i in range(n):
        simplex[i + 1] = x0.copy()
        simplex[i + 1][i] += step
    f_vals = np.array([loss_fn(v) for v in simplex])
    centroid_hist = [np.mean(simplex, axis=0).copy()]
    f_best_hist = [np.min(f_vals)]
    for _ in range(n_iters):
        order = np.argsort(f_vals)
        simplex = simplex[order]; f_vals = f_vals[order]
        centroid = np.mean(simplex[:-1], axis=0)
        x_r = centroid + alpha_r * (centroid - simplex[-1])
        f_r = loss_fn(x_r)
        if f_vals[0] <= f_r < f_vals[-2]:
            simplex[-1] = x_r; f_vals[-1] = f_r
        elif f_r < f_vals[0]:
            x_e = centroid + gamma * (centroid - simplex[-1])
            f_e = loss_fn(x_e)
            if f_e < f_r: simplex[-1] = x_e; f_vals[-1] = f_e
            else: simplex[-1] = x_r; f_vals[-1] = f_r
        else:
            if f_r < f_vals[-1]:
                x_c = centroid + rho * (x_r - centroid)
                f_c = loss_fn(x_c)
                if f_c <= f_r: simplex[-1] = x_c; f_vals[-1] = f_c
                else:
                    for i in range(1, n+1):
                        simplex[i] = simplex[0]+sigma*(simplex[i]-simplex[0])
                        f_vals[i] = loss_fn(simplex[i])
            else:
                x_c = centroid + rho * (simplex[-1] - centroid)
                f_c = loss_fn(x_c)
                if f_c < f_vals[-1]: simplex[-1] = x_c; f_vals[-1] = f_c
                else:
                    for i in range(1, n+1):
                        simplex[i] = simplex[0]+sigma*(simplex[i]-simplex[0])
                        f_vals[i] = loss_fn(simplex[i])
        centroid_hist.append(np.mean(simplex, axis=0).copy())
        f_best_hist.append(np.min(f_vals))
    return np.array(centroid_hist), np.array(f_best_hist), simplex
\end{lstlisting}

\begin{lstlisting}[caption={Frank--Wolfe Algorithm},label={lst:fw}]
def frank_wolfe(grad_fn, loss_fn, x0, bounds, beta, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, z_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
\end{lstlisting}
