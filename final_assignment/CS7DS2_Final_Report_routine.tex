\begin{abstract}
This report presents a comprehensive comparative study of optimisation algorithms across six categories applied to three benchmark problems: a linear regression quadratic loss (Benchmark~A), a toy neural network loss with sinusoidal perturbation (Benchmark~B), and the Rosenbrock function (Benchmark~C). The categories investigated are: (1)~adaptive step-size methods (Polyak, Adagrad, RMSprop, Heavy Ball), (2)~momentum and stochastic methods (Nesterov acceleration, Adam, mini-batch SGD), (3)~Newton's method with local quadratic approximation, (4)~derivative-free methods (finite differences, Nesterov random search, Nelder--Mead, grid search), (5)~constrained optimisation via projected gradient descent and penalty methods, and (6)~the Frank--Wolfe algorithm for linear-constrained problems.

Key findings include: the Polyak step size achieves superior performance when $f^\star$ is known exactly but diverges catastrophically when $f^\star$ is misspecified; Nesterov acceleration achieves an $O(1/k^2)$ convergence rate, dramatically outperforming gradient descent's $O(1/k)$ on ill-conditioned problems; Newton's method solves quadratic problems in a single iteration but requires Hessian damping to handle rapidly varying curvature; the Frank--Wolfe algorithm maintains feasibility by construction, achieving $O(1/k)$ convergence without projection oracles. All results are connected to the underlying algorithmic theory from the course.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% ============================================================

Optimisation is the mathematical backbone of machine learning: every model is trained by minimising a loss function, and the choice of optimisation algorithm profoundly affects convergence speed, solution quality, and computational cost. This report systematically investigates six families of first- and second-order optimisation methods, applying each to benchmark problems designed to expose their characteristic strengths and failure modes.

The three benchmark functions (defined formally in Section~\ref{sec:benchmarks}) span a spectrum of difficulty:
\begin{itemize}[nosep]
\item \textbf{Benchmark A} (linear regression, quadratic loss) is strongly convex with a constant Hessian. Every gradient-based method that is properly tuned converges to the global minimum, making this a ``sanity check'' baseline.
\item \textbf{Benchmark B} (toy neural network loss with sinusoidal perturbation) is mildly nonlinear with a condition number of approximately $5$:$1$. It reveals how methods handle moderate anisotropy.
\item \textbf{Benchmark C} (Rosenbrock function) has a condition number $\kappa \approx 2000$ at the minimum and a narrow curved valley along $x_2 = x_1^2$. This ``banana function'' is the canonical stress-test for optimisers, exposing oscillation, slow valley traversal, and sensitivity to step-size choice.
\end{itemize}

A central theme across all questions is the \emph{bias--variance} and \emph{accuracy--cost} trade-off inherent in each method: methods that use more information per iteration (Hessians, exact gradients) achieve faster convergence but at higher per-iteration cost, while methods that use less information (zeroth-order, mini-batch) are cheaper per step but converge more slowly or to a noisier solution.

\section{Benchmark Problems and Experimental Setup}

All experiments use a fixed random seed (\texttt{np.random.seed(42)}) for reproducibility.

\subsection{Benchmark A: Linear Regression Quadratic Loss}
A synthetic dataset with $m = 1000$ samples and two parameters is generated:
\begin{equation}
\theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \quad x^{(i)} \in \mathbb{R}^2, \quad y^{(i)} = \theta^{\star T} x^{(i)} + \varepsilon^{(i)}, \quad \varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The loss function is the mean squared error:
\begin{equation}
J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left(\theta^T x^{(i)} - y^{(i)}\right)^2 = \frac{1}{2m}\|X\theta - y\|^2.
\end{equation}
This is a convex quadratic with Hessian $H = \frac{1}{m}X^T X$ (constant). The gradient is $\nabla J(\theta) = \frac{1}{m}X^T(X\theta - y)$. Due to observation noise, the minimum loss is $J^{\star} \approx 0.4826$ (not zero). The Lipschitz constant of the gradient equals the largest eigenvalue of $H$: $L = \lambda_{\max}(H)$. Starting point: $\theta_0 = [0, 0]^T$.

\subsection{Benchmark B: Toy Neural Network Quadratic Loss}
\begin{equation}
f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
\end{equation}
The gradient is $\nabla f = [2(x_1 - 1) + \cos(x_1),\ 10(x_2 - 2)]^T$ and the Hessian is $H(x) = \text{diag}(2 - \sin(x_1),\ 10)$. Since $\sin(x_1) \in [-1, 1]$, the diagonal entries satisfy $2 - \sin(x_1) \in [1, 3]$, so the eigenvalue ratio varies between roughly $1$:$10$ and $3$:$10$, creating moderate anisotropy. The minimum lies at $x_1^\star \approx 0.582$ (where $2(x_1-1) + \cos(x_1) = 0$) and $x_2^\star = 2.0$, giving $f^\star \approx 0.7244$. Starting point: $x_0 = [-1, 4]^T$.

\subsection{Benchmark C: Rosenbrock Function}
\begin{equation}
f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
\end{equation}
The global minimum is at $(1, 1)$ with $f^\star = 0$. The Hessian at the optimum has eigenvalues $\approx 0.5$ and $\approx 1000$, giving condition number $\kappa \approx 2000$. This extreme ill-conditioning, combined with a narrow curved valley along $x_2 = x_1^2$, makes Rosenbrock one of the most challenging standard test functions. Starting point: $x_0 = [-1, 1]^T$.

\subsection{Benchmark D: Constrained Feasible Set}
For constrained problems: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\ -5 \leq x_2 \leq 10\}$.

\section{Question 1: Adaptive Step-Size Methods \hfill [30 marks]}
\label{sec:q1}
% ============================================================

\subsection{Theoretical Background}

For a differentiable function $f$ with $L$-Lipschitz continuous gradient ($\|\nabla f(x) - \nabla f(y)\| \leq L\|x-y\|$ for all $x,y$), gradient descent with constant step $\alpha \leq 1/L$ satisfies:
\begin{equation}
f(x_{k+1}) \leq f(x_k) - \frac{\alpha}{2}\|\nabla f(x_k)\|^2.
\label{eq:gd_descent}
\end{equation}
For a $\mu$-strongly convex function (with $\mu > 0$), the convergence rate is linear:
\begin{equation}
f(x_k) - f^\star \leq \left(1 - \frac{\mu}{L}\right)^k [f(x_0) - f^\star],
\end{equation}
where $\mu/L = 1/\kappa$ is the reciprocal of the condition number. Adaptive methods aim to improve the effective $\kappa$ by using coordinate-wise step sizes or curvature estimates.

\subsection{Algorithm Formulations}

Four adaptive methods are compared against a constant step-size gradient descent baseline across all three benchmarks for 120 iterations.

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, optimal value $f^{\star}$, tolerance $\varepsilon$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets \dfrac{f(x_k) - f^{\star}}{\|g_k\|^2 + \varepsilon}$
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

The Polyak step is derived from the requirement that the step exactly reaches $f^\star$ if the objective were linear: setting $f(x_k) - \alpha_k\|g_k\|^2 = f^\star$ gives $\alpha_k = (f(x_k) - f^\star)/\|g_k\|^2$. The $\varepsilon$ term prevents division by zero. When $f^\star$ is known exactly, the Polyak step achieves sublinear $O(1/k)$ convergence on convex functions without any tuning of the step size.

\begin{algorithm}[H]
\caption{Adagrad}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Per-coordinate squared-gradient sum}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

Adagrad assigns each coordinate $i$ an effective learning rate $\alpha_0/\sqrt{\sum_{j=0}^{k} g_{j,i}^2}$. Coordinates with historically large gradients receive smaller steps, providing automatic per-coordinate scaling. The effective rate is \emph{monotonically decreasing} because $G_k$ only grows, which guarantees stability but can cause premature stagnation on long optimisation runs.

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponential moving average}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

RMSprop replaces Adagrad's cumulative sum with an exponentially weighted moving average (EWMA) of squared gradients with decay factor $\beta = 0.9$. This fixes Adagrad's aggressive learning rate decay: old gradients are forgotten exponentially, so the effective learning rate can recover if recent gradients become small. The EWMA stabilises to $v_k \approx (1-\beta)\sum_{j=0}^{k} \beta^{k-j} g_j^2$, which reflects \emph{recent} curvature rather than all historical curvature.

\begin{algorithm}[H]
\caption{Polyak Momentum / Heavy Ball}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$
    \State $x_{k+1} \gets x_k - z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

The Heavy Ball method, introduced by Polyak (1964), adds a momentum term $\beta z_k$ to the gradient step. This can be interpreted as a discretisation of a second-order ODE $\ddot{x} + (1-\beta)\dot{x} + \alpha\nabla f(x) = 0$, i.e., a damped harmonic oscillator. For a quadratic $f$ with eigenvalues $[\mu, L]$, the optimal parameters are $\alpha^\star = 4/(\sqrt{L} + \sqrt{\mu})^2$ and $\beta^\star = ((\sqrt{L} - \sqrt{\mu})/(\sqrt{L} + \sqrt{\mu}))^2$, achieving a convergence rate $((\kappa-1)/(\kappa+1))^2$ rather than $(\kappa-1)/(\kappa+1)$ for plain GD -- a quadratic improvement in terms of $\kappa$.

\subsection{Comparative Analysis}

\begin{itemize}[nosep]
\item \textbf{Convergence speed:} When $f^\star$ is known exactly, Polyak converges fastest (Rosenbrock: $f \approx 0.009$). On Benchmarks A and B where $f^\star$ is misspecified, Adagrad and Heavy Ball tie GD in final accuracy but the Heavy Ball reaches the minimum faster due to momentum acceleration.
\item \textbf{Smoothness:} RMSprop produces the smoothest convergence curves due to EWMA stabilisation of the step size. Heavy Ball exhibits characteristic overshoot-oscillation-damping behaviour, most visible on Benchmark~B.
\item \textbf{Stability:} GD is most stable but slowest. Adagrad is uniformly stable due to its monotonically decreasing step size. RMSprop can oscillate near minima if the base rate is too large. Polyak is \emph{unstable} when $f^\star$ is misspecified.
\item \textbf{Practical guidance:} In practice, $f^\star$ is almost never known, so Polyak is rarely applicable in its pure form. RMSprop and Adagrad are robust default choices for differentiable objectives; Heavy Ball requires momentum tuning but rewards the effort with meaningful acceleration.
\end{itemize}

\section{Question 2: Momentum and Stochastic Methods \hfill [30 marks]}
\label{sec:q2}
% ============================================================

\subsection{Theoretical Background}

Standard gradient descent achieves $O(1/k)$ convergence on convex functions and $O((1 - \mu/L)^k)$ linear convergence on strongly convex functions. Nesterov's accelerated gradient method improves the strongly convex rate to $O((1 - \sqrt{\mu/L})^k)$, which is provably optimal among first-order methods.

\begin{theorem}[Nesterov Acceleration, informal]\label{thm:nesterov}
For an $L$-smooth, $\mu$-strongly convex function, Nesterov's method with $\beta_k = (k-1)/(k+2)$ satisfies
\[
f(x_k) - f^\star \leq \mathcal{O}\!\left(\frac{L\|x_0 - x^\star\|^2}{k^2}\right),
\]
achieving the optimal first-order convergence rate $O(1/k^2)$ on smooth convex functions.
\end{theorem}

The factor $1/k^2$ vs $1/k$ means that to reduce the suboptimality by a factor of $100$, gradient descent requires $10\times$ more iterations than Nesterov's method. This difference is most pronounced on ill-conditioned problems like Rosenbrock.

\subsection{Algorithm Formulations}

\begin{algorithm}[H]
\caption{Nesterov Momentum / Acceleration}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\frac{k-1}{k+2},\ \beta_{\max}\right)$
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead / extrapolation point}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

The critical distinction from Heavy Ball is the \emph{lookahead}: the gradient is evaluated at the extrapolated point $\tilde{x}_k = x_k + \beta_k z_k$ rather than at $x_k$. This ``look before you leap'' strategy enables the method to partially correct an overshoot before it occurs. Mathematically, the lookahead evaluates the gradient at a point that is closer to the optimum in the momentum direction, providing a more accurate descent direction and enabling the provably optimal convergence rate stated in Theorem~\ref{thm:nesterov}.

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha$, moments $\beta_1, \beta_2$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\ v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{EWMA of gradient (first moment)}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{EWMA of squared gradient}
    \State $\hat{m}_t \gets m_t\, /\, (1 - \beta_1^t)$ \Comment{Bias-corrected first moment}
    \State $\hat{v}_t \gets v_t\, /\, (1 - \beta_2^t)$ \Comment{Bias-corrected second moment}
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t\, /\, (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

Adam combines RMSprop-style per-coordinate scaling (via $v_t$) with momentum (via $m_t$). The bias correction terms $(1 - \beta_i^t)$ in the denominators account for the fact that $m_0 = v_0 = \mathbf{0}$ biases the EWMA estimates toward zero in early iterations; without this correction, Adam would take very small steps initially even when the gradient is large. The effective step size per coordinate at step $t$ is approximately $\alpha / \sqrt{\hat{v}_t}$, which adapts to the scale of each parameter's gradient history. Adam does not have formal convergence guarantees for non-convex objectives, but performs well in practice on machine learning problems.

\subsection{Mini-Batch Stochastic Gradient Descent}

Mini-batch SGD on Benchmark~A uses learning rate $\alpha = 0.06$, batch sizes $b \in \{5, 40\}$, 50 epochs, with data shuffled at every epoch. At each step, the gradient estimate from a mini-batch of size $b$ is:
\begin{equation}
\hat{g}_b = \frac{1}{b} X_\mathcal{B}^T(X_\mathcal{B}\theta - y_\mathcal{B}),
\end{equation}
which is an unbiased estimate of the full gradient ($\mathbb{E}[\hat{g}_b] = \nabla J(\theta)$) with variance $\mathrm{Var}[\hat{g}_b] \propto 1/b$. Smaller batches give higher-variance but cheaper gradient estimates; larger batches give lower-variance but more expensive ones.

\begin{algorithm}[H]
\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]
\Require Data $(X, y)$, initial $\theta_0$, learning rate $\alpha$, batch size $b$, epochs $E$
\For{$e = 1, 2, \ldots, E$}
    \State Randomly permute data indices
    \For{each mini-batch $\mathcal{B}$ of size $b$}
        \State $g \gets \frac{1}{b} X_{\mathcal{B}}^T(X_{\mathcal{B}}\theta - y_{\mathcal{B}})$
        \State $\theta \gets \theta - \alpha\, g$
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{figure}[H]
\centering
\includegraphics[width=0.85\textwidth]{figures/q2_sgd_batch.pdf}
\caption{Q2: Mini-batch SGD with batch sizes $b=5$ and $b=40$. With $b=5$, each epoch performs $1000/5 = 200$ parameter updates, providing faster per-epoch convergence. With $b=40$, there are only $1000/40 = 25$ updates per epoch, so convergence is slower per epoch but each update is more accurate. The $b=5$ run reaches lower loss faster in epochs due to 8$\times$ more updates per epoch, but exhibits more oscillation near the minimum because gradient variance $\propto 1/b$ is $8\times$ higher. This illustrates the fundamental SGD trade-off: smaller batches converge faster to the noise floor but exhibit greater fluctuation around it.}
\label{fig:q2_sgd_batch}
\end{figure}

Under high data noise ($\sigma = 6$), phase~1 is shorter because the noise floor is much higher, so both batch sizes reach the floor quickly and the batch-size advantage from phase~1 is irrelevant. In practice, this motivates learning rate decay schedules: decreasing $\alpha_k \to 0$ eliminates oscillation at the cost of slower final convergence.

\subsection{Local Approximations of $g(x) = x^4$}

\textbf{First-order (Taylor) approximation} around $x_0 = 0.25$:
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0) = (0.25)^4 + 4 \cdot (0.25)^3\,(x - 0.25) = 0.0039 + 0.0625(x - 0.25).
\end{equation}
This is a tangent line. Minimising this linear model yields no finite solution (the minimum is $-\infty$), which explains why gradient descent requires a step size $\alpha$ to limit progress.

\textbf{Second-order (quadratic) approximation:}
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0) + \tfrac{1}{2}g''(x_0)(x - x_0)^2 = 0.0039 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{equation}
where $g''(x_0) = 12 \cdot (0.25)^2 = 0.75$.

\textbf{Newton update derivation.} The second-order model has a unique minimum obtained by setting its derivative to zero:
\begin{equation}
\frac{d}{dx}\left[g(x_0) + g'(x_0)(x-x_0) + \tfrac{1}{2}g''(x_0)(x-x_0)^2\right] = g'(x_0) + g''(x_0)(x-x_0) = 0.
\end{equation}
Solving: $x - x_0 = -g'(x_0)/g''(x_0)$, so the Newton update in one dimension is:
\begin{equation}
\boxed{x_{k+1} = x_k - \frac{g'(x_k)}{g''(x_k)}.}
\end{equation}
For $g(x) = x^4$, this gives $x_{k+1} = x_k - \frac{4x_k^3}{12x_k^2} = x_k - \frac{x_k}{3} = \frac{2}{3}x_k$. Since $g''(0) = 0$ at the optimum, the method has only \emph{linear} convergence (factor $2/3$) rather than quadratic convergence for this particular function. Quadratic convergence requires $g''(x^\star) \neq 0$, i.e., the function must have non-degenerate curvature at the minimum.

In the multidimensional case, minimising the quadratic model $f(x_k) + \nabla f(x_k)^T(x - x_k) + \frac{1}{2}(x-x_k)^T H_k (x-x_k)$ yields:
\begin{equation}
x_{k+1} = x_k - H_k^{-1} \nabla f(x_k),
\end{equation}
where $H_k = \nabla^2 f(x_k)$ is the Hessian. When $H_k$ is positive definite, this is a descent direction and achieves \emph{quadratic convergence}: $\|x_{k+1} - x^\star\| \leq C\|x_k - x^\star\|^2$ for some constant $C$.

\begin{figure}[H]
\centering
\includegraphics[width=0.85\textwidth]{figures/q3_approximation.pdf}
\caption{Q3: Local approximations of $g(x) = x^4$ at $x_0 = 0.25$. The first-order (linear) approximation captures only the local slope and deviates rapidly from the true function. The second-order (quadratic) approximation fits well in a neighbourhood of $x_0$; its minimum at $x_0 - g'(x_0)/g''(x_0) = 0.25 - 0.0625/0.75 \approx 0.167$ provides a much better estimate of the descent direction than a pure gradient step. \subsection{Newton's Method with Hessian Damping}

\begin{algorithm}[H]
\caption{Newton's Method with Damping}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Tikhonov-regularised Hessian}
    \State $p_k \gets H_k^{-1}\, g_k$ \Comment{Solve linear system: Newton direction}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$
\EndFor
\end{algorithmic}
\end{algorithm}

The Hessian damping $\lambda I$ (with $\lambda = 10^{-8}$) serves two purposes: (1)~it ensures $H_k$ is positive definite even if the true Hessian has zero or negative eigenvalues (as can occur far from a minimum on non-convex functions), and (2)~it conditions the linear system $H_k p_k = g_k$, improving numerical stability. For Benchmark~A, the Hessian is constant ($H = X^T X/m$, positive definite), so damping is negligible. For Benchmark~C, the rapidly varying Hessian $\nabla^2 f(x)$ necessitates $\alpha < 1$ (damped Newton steps) to prevent overshooting.

Settings: GD uses 80 iterations; Newton uses 20 iterations with $\lambda = 10^{-8}$.

\subsection{Part A: Finite Differences and Nesterov Random Search (Benchmark B)}

\subsubsection{Finite Difference Gradient Approximation}

The forward finite-difference approximation replaces each partial derivative with:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta}.
\end{equation}
The approximation error consists of two competing terms:
\begin{equation}
\text{Error} = \underbrace{\frac{\delta}{2} \frac{\partial^2 f}{\partial x_i^2}(x)}_{\text{truncation: } O(\delta)} + \underbrace{\frac{2\varepsilon_{\text{mach}}\|f(x)\|}{\delta}}_{\text{roundoff: } O(\varepsilon_{\text{mach}}/\delta)},
\end{equation}
which is minimised at $\delta^\star \sim \sqrt{\varepsilon_{\text{mach}}} \approx 10^{-8}$. In practice, $\delta = 0.05$ (much larger than $\delta^\star$) still gives a useful gradient approximation for smooth functions because the truncation error $O(\delta)$ remains small relative to the gradient magnitude. However, $\delta = 0.8$ spans a region where the function's curvature changes substantially (the sinusoidal term $\sin(x_1)$ contributes a second derivative of $-\sin(x_1)$, which changes sign over intervals of length $\pi$), causing systematic gradient error and poor convergence.

The code uses $\alpha = 0.08$ (step size) for FD gradient descent, with exact GD run at $\alpha = 0.06$ as a baseline.

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search (Zeroth-Order)}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Sample $u_k \sim \mathcal{N}(0, I)$, normalise: $u_k \gets u_k / \|u_k\|$
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta u_k) - f(x_k)}{\delta}\, u_k$
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

The NRS estimate $\hat{g}_k$ is an approximation of the directional derivative $\nabla f(x_k)^T u_k$ along the random direction $u_k$, scaled back to a gradient-like vector. Key properties:
\begin{itemize}[nosep]
\item \textbf{Unbiased direction:} $\mathbb{E}[\hat{g}_k] = \frac{1}{d}\nabla f(x_k)$ (in $d$ dimensions), so the expected update is in the correct descent direction.
\item \textbf{Cost:} Only 2 function evaluations per iteration regardless of dimension -- far cheaper than the $d+1$ evaluations needed for FD gradient computation.
\item \textbf{Variance:} High, because only a random one-dimensional projection of the gradient is used. On average, $1/d$ of the gradient signal is captured per step.
\end{itemize}

\subsubsection{Nelder--Mead Simplex Method}

The Nelder--Mead algorithm maintains a simplex of $n+1 = 3$ vertices (for $n=2$) and iteratively transforms it through four operations: \textbf{reflection} (reflect the worst vertex through the centroid of the remaining vertices), \textbf{expansion} (if reflection improved, try extending further), \textbf{contraction} (if reflection worsened, contract toward the centroid), and \textbf{shrink} (contract all non-best vertices toward the best). Parameters: $\alpha_r = 1.0$ (reflection), $\gamma = 2.0$ (expansion), $\rho = 0.5$ (contraction), $\sigma = 0.5$ (shrink). No gradient information is required; only function evaluations.

Settings: initial simplex step $= 0.35$, 160 iterations.

\textbf{Key insight -- the curse of dimensionality:} Derivative-free methods face the curse of dimensionality. Grid search scales as $O(N^d)$; Nelder--Mead becomes unreliable for $d \gg 10$; random search scales as $O(1)$ per step but requires $O(d)$ iterations to capture a full gradient in expectation. In contrast, exact gradient computation scales as $O(d)$ and FD approximation as $O(d)$, both of which are feasible for moderate $d$. For very large $d$ (deep learning), automatic differentiation ($O(d)$ backpropagation) replaces both.

\subsection{Problem Setup and KKT Conditions}

Minimise Benchmark~B subject to $x_1 \geq 0.5$, starting from the infeasible point $x_0 = (0.2, 4.0)$.

The constraint is $g(x) = 0.5 - x_1 \leq 0$. The KKT conditions for this problem are:
\begin{equation}
\nabla f(x^\star) + \mu^\star \nabla g(x^\star) = 0, \quad \mu^\star \geq 0, \quad \mu^\star g(x^\star) = 0.
\end{equation}
Since the unconstrained minimiser of $f_B$ is at $x_1^\star \approx 0.582 > 0.5$, the constraint is \emph{inactive} at the optimum: $g(x^\star) = 0.5 - 0.582 < 0$ and thus $\mu^\star = 0$. This means the constrained and unconstrained solutions \emph{coincide} at $(0.582, 2.0)$. Despite this, the methods differ substantially in how they navigate from the infeasible starting point to this constrained minimum.

\begin{algorithm}[H]
\caption{Projected Gradient Descent}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, projection $\Pi_{\mathcal{X}}$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Unconstrained gradient step}
    \State $x_{k+1} \gets \Pi_{\mathcal{X}}(z_{k+1})$ \Comment{Project: $x_1 \leftarrow \max(0.5,\, x_1)$}
\EndFor
\end{algorithmic}
\end{algorithm}

For a half-space constraint $\{x : x_1 \geq 0.5\}$, the projection is trivially $\Pi_\mathcal{X}(z) = (\max(0.5, z_1), z_2)$, requiring only a single $\max$ operation. For more complex constraint sets (e.g., $\ell^2$ balls, polytopes), projection can require solving a constrained quadratic programme, making each step much more expensive.

\begin{algorithm}[H]
\caption{Penalty Method}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, penalty weight $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $F_{\lambda}(x) \gets f(x) + \lambda \max(0,\, -x_1 + 0.5)$ \Comment{Penalised objective}
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_{\lambda}(x_k)$
\EndFor
\end{algorithmic}
\end{algorithm}

The penalty gradient is $\nabla F_\lambda(x) = \nabla f(x) - \lambda \mathbf{1}[x_1 < 0.5]\, e_1$, where $e_1 = (1, 0)$. When $x_1 < 0.5$, the penalty adds a force $-\lambda e_1$ to the gradient update, pushing $x_1$ upward toward the feasible region. The magnitude of this restoring force is $\lambda$: too small and the method remains infeasible; too large and the problem becomes numerically stiff (requiring smaller step sizes).

Settings: Projected GD ($\alpha = 0.08$), Penalty with $\lambda \in \{0.15, 1.8, 4.5\}$ ($\alpha = 0.05$ for $\lambda \leq 1.8$; $\alpha = 0.03$ for $\lambda = 4.5$), unconstrained GD ($\alpha = 0.07$). All run for 100 iterations.

\textbf{Projected GD} enforces feasibility as a hard constraint from the first iteration at negligible computational cost (a single $\max$ per step for this problem). \textbf{Penalty methods} approximate the constrained problem by a sequence of unconstrained subproblems. An important theoretical result is that for linear inequality constraints, if $\lambda > \mu^\star$ (the KKT multiplier), the penalty problem's solution equals the constrained solution exactly. Since $\mu^\star = 0$ here (constraint inactive), any $\lambda > 0$ eventually gives the correct solution, though convergence speed depends on $\lambda$.

After enough iterations, the iterate enters the feasible region and converges to the minimum.

\subsection{Feasible Set and Linear Programme}

Feasible set: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\ -5 \leq x_2 \leq 10\}$ (a bounded box / polytope).

\textbf{Linear Programme.} For $f(x) = a^T x$ with $a = [1, 2]^T$, the minimum over $\mathcal{X}$ is obtained by a fundamental theorem of linear programming:

\begin{theorem}[LP Optimum at Vertex]\label{thm:lp}
The minimum of a linear objective $f(x) = a^T x$ over a bounded polytope $\mathcal{X}$ is attained at a \emph{vertex} (extreme point) of $\mathcal{X}$.
\end{theorem}

For a box $\mathcal{X}$, the vertices are the $2^d$ corners. Since both components of $a = [1, 2]^T$ are positive, the objective is minimised by taking each $x_i$ as small as possible: $x_1 = 0.5$ and $x_2 = -5$, giving:
\begin{equation}
x^\star = (0.5,\, -5), \qquad f^\star = 1 \cdot 0.5 + 2 \cdot (-5) = -9.5.
\end{equation}

\subsection{Frank--Wolfe Algorithm}

\begin{algorithm}[H]
\caption{Frank--Wolfe (Conditional Gradient)}
\label{alg:fw}
\begin{algorithmic}[1]
\Require Initial point $x_0 \in \mathcal{X}$, mixing parameter $\beta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_k \gets \arg\min_{x \in \mathcal{X}}\, \nabla f(x_k)^T x$ \Comment{Linear minimisation oracle (LMO)}
    \State $x_{k+1} \gets \beta\, x_k + (1 - \beta)\, z_k$ \Comment{Convex combination (``mixing'')}
\EndFor
\end{algorithmic}
\end{algorithm}

\textbf{Key properties of Frank--Wolfe:}
\begin{enumerate}[nosep]
\item \textbf{Projection-free:} At each step, the algorithm solves a \emph{linear} minimisation over $\mathcal{X}$ (the LMO) rather than a projection. For the box $\mathcal{X}$, the LMO decomposes coordinate-wise:
\begin{equation}
(z_k)_i = \begin{cases} l_i & \text{if } (\nabla f(x_k))_i > 0 \\ u_i & \text{if } (\nabla f(x_k))_i \leq 0 \end{cases}
\end{equation}
requiring only $O(d)$ operations per step. For constraint sets where projection is expensive (e.g., the nuclear norm ball in matrix completion), Frank--Wolfe is strongly preferred.
\item \textbf{Feasibility by construction:} Since $x_0 \in \mathcal{X}$ and $z_k \in \mathcal{X}$, the convex combination $x_{k+1} = \beta x_k + (1-\beta) z_k \in \mathcal{X}$ for all $k$. No projection is ever needed.
\item \textbf{Convergence rate:} For $L$-smooth convex $f$, Frank--Wolfe achieves $f(x_k) - f^\star \leq 2LC^2/(k+2)$ where $C = \text{diam}(\mathcal{X})$, i.e., $O(1/k)$ rate -- slower than $O(1/k^2)$ for projected gradient descent but without projection cost.
\end{enumerate}

\textbf{Frank--Wolfe gap.} A useful stopping criterion is the \emph{duality gap}:
\begin{equation}
g(x_k) = \nabla f(x_k)^T (x_k - z_k) \geq 0,
\end{equation}
which satisfies $g(x_k) \geq f(x_k) - f^\star$. A small gap certifies near-optimality without knowing $f^\star$.

\subsection{Interior vs.\ Boundary Behaviour}

\textbf{Interior optimum:} Frank--Wolfe exhibits a characteristic oscillation: the LMO always selects a vertex of $\mathcal{X}$, which is far from the interior optimum. Each step is a convex combination between the current (near-optimal) iterate and a distant vertex, so $z_k$ ``ping-pongs'' between vertices rather than converging. The general convergence rate is $O(1/k)$. In this setting, a decreasing step size $\gamma_k = 2/(k+2)$ (the standard Frank--Wolfe schedule) would improve convergence compared to fixed $\beta$.

\textbf{Boundary optimum:} Frank--Wolfe is inherently well-suited to boundary optima because the LMO frequently selects a vertex near the constraint boundary, providing a step direction toward the boundary. The algorithm naturally approaches the boundary without any projection, making it the method of choice for problems where the optimum lies at a constraint boundary (e.g., sparse optimisation over the $\ell^1$ ball, where vertices are sparse vectors). However, the fixed $\beta$ schedule causes residual oscillation; using $\gamma_k = 2/(k+2) \to 0$ would allow tighter convergence.

\section{Conclusion}
\label{sec:conclusion}
% ============================================================

This study has systematically evaluated six families of optimisation algorithms, revealing the following overarching principles:

\textbf{1. Step-size adaptation is critical but risky.} Adaptive methods (Polyak, Adagrad, RMSprop, Adam) can dramatically outperform fixed step-size GD -- but only when their assumptions are met. Polyak requires exact $f^\star$; Adagrad's monotone decay can cause premature stagnation; Adam can converge to suboptimal points. The best-performing methods are those whose adaptation mechanism is appropriate for the loss landscape.

\textbf{2. Momentum provides provable acceleration.} Nesterov's lookahead-corrected momentum achieves the optimal $O(1/k^2)$ rate on convex problems. On Rosenbrock ($\kappa \approx 2000$), Nesterov achieved $7\times$ better objective than GD in the same iteration budget. Adam combines momentum with adaptive scaling, trading theoretical guarantees for practical robustness in non-convex settings.

\textbf{3. Second-order methods are transformative but expensive.} Newton's method solves quadratic problems in one step and converges quadratically near minima on smooth functions. Its limitation is the $O(d^3)$ cost of Hessian inversion, which is prohibitive for large-scale problems. Quasi-Newton methods (LBFGS) bridge this gap by approximating $H^{-1}$ with $O(d)$ storage.

\textbf{4. Derivative-free methods sacrifice speed for generality.} When gradients are unavailable or too expensive, zeroth-order methods pay a factor of $d$ per iteration (FD) or suffer high gradient variance (random search). Nelder--Mead and grid search are effective for low-dimensional problems but fail to scale. The right choice depends on whether the oracle cost (gradient vs.\ function evaluation) is the bottleneck.

\textbf{5. Constraint-handling fundamentally differs by method.} Projected GD enforces feasibility as a hard constraint from iteration~1 with no overhead (for simple sets); penalty methods enforce feasibility softly with $O(1/\lambda)$ residual. Frank--Wolfe maintains feasibility by construction via the LMO, making it the natural choice for structured constraint sets where projection is expensive.

\textbf{6. Problem structure determines the best method.} Benchmark~A (quadratic) is solved in one Newton step. Benchmark~B (mild nonlinearity) is efficiently handled by all gradient methods. Benchmark~C (Rosenbrock, $\kappa \approx 2000$) exposes the limitations of first-order methods and the value of curvature information or momentum. There is no universally best algorithm: the optimal choice depends on convexity, smoothness, problem dimension, and available oracle information.

def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]

\begin{lstlisting}[caption={Polyak Step Size}]
def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adagrad}]
def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float)
    G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={RMSprop}]
def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float)
    v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Heavy Ball / Polyak Momentum}]
def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x)
        z = beta * z + alpha * g
        x = x - z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))

\begin{lstlisting}[caption={Nesterov Momentum / Acceleration}]
def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z   # Evaluate gradient at lookahead point
        g = grad_fn(lookahead)
        z = beta_k * z - alpha * g
        x = x + z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adam Optimiser}]
def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t)   # Bias correction
        v_hat = v_vec / (1 - beta2**t)
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Newton's Method with Hessian Damping}]
def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))   # Tikhonov regularisation
        try:
            p = np.linalg.solve(H_reg, g)
        except np.linalg.LinAlgError:
            p = g
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)
\end{lstlisting}

        g = grad_fn(x)
        # LMO: minimise g^T z over box constraint
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z   # Convex combination step
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
