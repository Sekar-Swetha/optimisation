\begin{abstract}
This report presents a comprehensive comparative study of six categories of optimisation algorithms applied to three benchmark problems of increasing difficulty: a well-conditioned linear regression quadratic loss (Benchmark~A, $\kappa \approx 1.12$), a moderately anisotropic toy neural network loss (Benchmark~B, $\kappa \approx 6.9$), and the highly ill-conditioned Rosenbrock function (Benchmark~C, $\kappa \gg 200$). The six method families investigated are: (1)~\textbf{adaptive step-size methods}---Polyak, Adagrad, RMSprop, and Heavy Ball---which modulate the effective learning rate based on gradient history or function-value information; (2)~\textbf{momentum and stochastic methods}---Nesterov accelerated gradient and Adam---which achieve faster convergence by incorporating gradient history; (3)~\textbf{Newton's method and local quadratic approximations}, exploiting second-order curvature for superlinear convergence; (4)~\textbf{derivative-free optimisation}---finite-difference gradient descent, Nesterov random search, Nelder--Mead simplex, and grid search---which require no analytic gradients; (5)~\textbf{constrained optimisation} via projected gradient descent and penalty methods applied to a half-space constraint; and (6)~the \textbf{Frank--Wolfe conditional gradient algorithm} for box-constrained problems, maintaining feasibility via LP subproblems without projection.

Key quantitative findings: the Polyak step achieves $f = 0.0094$ on Rosenbrock (best Q1) when $f^{\star} = 0$ is correct, but diverges to $f = 2.72$ (A) and $24.07$ (B) when $f^{\star}$ is misspecified; Nesterov acceleration reaches $f = 0.479$ on Rosenbrock vs GD's $f = 3.388$ (7$\times$ improvement); Newton converges in 1 iteration on the quadratic (Benchmark~A) and 5 iterations on the near-quadratic (Benchmark~B), compared to 80 GD iterations; finite-difference GD with $\delta = 0.05$ matches analytic GD's trajectory, while $\delta = 0.8$ (10$\times$ larger) fails to converge; projected gradient descent enforces the constraint exactly from iteration 1, while penalty methods tolerate transient violations proportional to $1/\lambda$; and Frank--Wolfe with fixed $\beta = 0.93$ reaches $f = 0.364$ on the boundary-optimum problem (vs $f^{\star} = 0.25$), due to the fixed step size preventing decay to zero. The condition number $\kappa$ emerges as the dominant predictor of relative algorithm performance across all experiments.
\end{abstract}

\subsection{Theoretical Framework: Gradient Descent and the Quadratic Upper Bound}

A fundamental tool for analysing gradient descent is the \emph{quadratic upper bound model}: for an $L$-smooth function ($\|\nabla f(x) - \nabla f(y)\| \leq L\|x-y\|$ for all $x,y$), the descent lemma gives:
\begin{equation}
f(x - \alpha \nabla f(x)) \leq f(x) - \alpha\|\nabla f(x)\|^2 + \frac{\alpha^2 L}{2}\|\nabla f(x)\|^2 = f(x) - \alpha\left(1 - \frac{\alpha L}{2}\right)\|\nabla f(x)\|^2.
\end{equation}
Setting $\alpha = 1/L$ maximises the right-hand side decrease: each step decreases the function by at least $\frac{1}{2L}\|\nabla f(x)\|^2$. The Lipschitz constant $L$ (the largest Hessian eigenvalue $\lambda_{\max}$) thus determines the maximum safe step size $\alpha_{\max} = 2/L = 2/\lambda_{\max}$. For Benchmark~A: $L = \lambda_{\max} = 1.033$, $\alpha_{\max} = 1.94$; for Benchmark~B: $L \approx 10$, $\alpha_{\max} \approx 0.2$; for Benchmark~C: $L$ varies widely across the domain, making analysis difficult. All experimental step sizes are below their respective $\alpha_{\max}$ values.

\subsection{Benchmark A: Linear Regression Quadratic Loss}
A synthetic dataset with $m = 1000$ samples and $d = 2$ parameters is generated:
\begin{equation}
\theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \quad x^{(i)} \sim \mathcal{N}(0, I_2), \quad y^{(i)} = {\theta^{\star}}^T x^{(i)} + \varepsilon^{(i)}, \quad \varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The loss function is the mean squared error:
\begin{equation}
J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left(\theta^T x^{(i)} - y^{(i)}\right)^2 = \frac{1}{2m}\|X\theta - y\|^2.
\end{equation}
This is a \emph{strictly convex quadratic} with Hessian $H = \frac{1}{m}X^T X \succ 0$ (positive definite, constant). The gradient is $\nabla J(\theta) = \frac{1}{m}X^T(X\theta - y)$. The exact minimiser is the ordinary least-squares solution $\theta^{\star}_{\text{OLS}} = (X^TX)^{-1}X^Ty \approx [3.028, 4.017]^T$ (close to $[3, 4]^T$, with deviation due to finite observation noise). Due to observation noise $\varepsilon^{(i)} \sim \mathcal{N}(0,1)$, the minimum loss is $J^{\star} \approx 0.4826 \approx \frac{1}{2}\sigma^2 = 0.5$ (slightly below 0.5 due to finite-sample effects). The Hessian eigenvalues for this sample are $\lambda_{\min} \approx 0.925$ and $\lambda_{\max} \approx 1.033$, giving a condition number $\kappa = \lambda_{\max}/\lambda_{\min} \approx 1.12$---nearly perfectly conditioned. This means gradient descent converges at nearly the fastest possible rate $\rho = 1 - 1/\kappa \approx 0.11$ (approximately geometric decay with factor $0.11$ per step). The maximum stable step size is $\alpha_{\max} = 2/\lambda_{\max} \approx 1.94$; the baseline $\alpha = 0.08$ is well below this threshold. Starting point: $\theta_0 = [0, 0]^T$.

\subsection{Benchmark B: Toy Neural Network Loss}
\begin{equation}
f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
\label{eq:bench_B}
\end{equation}
The gradient is $\nabla f = [2(x_1 - 1) + \cos(x_1),\ 10(x_2 - 2)]^T$ and the Hessian is $H = \text{diag}(2 - \sin(x_1),\ 10)$. The Hessian is diagonal, so there is no cross-curvature; however, the $(1,1)$ entry varies with position, making the function mildly nonlinear. At the approximate minimum $x^{\star} \approx (0.582, 2.0)$, the eigenvalues are $(2 - \sin(0.582), 10) \approx (1.452, 10)$, giving a condition number $\kappa \approx 6.9$---moderate anisotropy. The global minimum value is $f^{\star} \approx 0.7244$. Starting point: $x_0 = [-1, 4]^T$.

\subsection{Benchmark C: Rosenbrock Function}
\begin{equation}
f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
\label{eq:rosenbrock}
\end{equation}
The global minimum is at $(1, 1)$ with $f^{\star} = 0$. The Hessian at the optimum has eigenvalues approximately $2$ and $401$ (corresponding to directions along and perpendicular to the curved valley), giving a condition number $\kappa \approx 200$. Away from the optimum, the condition number can be orders of magnitude larger. The function features a narrow, curved banana-shaped valley along $x_2 \approx x_1^2$, making descent along the valley floor very slow with first-order methods. Starting point: $x_0 = [-1, 1]^T$.

The Rosenbrock function can be decomposed as $f(x_1, x_2) = (1-x_1)^2 + 100(x_2 - x_1^2)^2$, which is a sum of two terms: a ``horizontal'' penalty $(1-x_1)^2$ that pushes $x_1 \to 1$, and a ``valley floor'' penalty $100(x_2 - x_1^2)^2$ that pushes the point onto the parabola $x_2 = x_1^2$. The valley floor penalty has coefficient 100, making it 100 times stronger than the horizontal penalty---explaining the 200:1 condition number and the characteristic elongation of contours perpendicular to the valley. A first-order method must simultaneously satisfy both constraints: getting onto the valley ($x_2 \approx x_1^2$) is fast (strong gradient), but advancing along the valley toward $(1,1)$ is slow (weak gradient of $(1-x_1)^2$ relative to the curvature). This two-timescale structure is what makes the Rosenbrock a canonical hard test case for optimisation algorithms.

\subsection{Theoretical Background}

Standard gradient descent $x_{k+1} = x_k - \alpha \nabla f(x_k)$ requires careful tuning of a fixed learning rate $\alpha$. Too large a rate causes divergence; too small a rate causes slow convergence. Adaptive step-size methods address this by automatically adjusting $\alpha$ based on either the current function value (Polyak) or accumulated gradient information (Adagrad, RMSprop). Momentum methods (Heavy Ball) add gradient history to build inertia.

\textbf{Convergence rates summary:} For an $L$-smooth, $\mu$-strongly convex function with condition number $\kappa = L/\mu$:
\begin{itemize}[nosep]
\item Gradient descent with constant $\alpha = 1/L$: geometric rate $\rho = 1 - \mu/L = 1 - 1/\kappa$; needs $O(\kappa \log(1/\varepsilon))$ iterations.
\item Polyak (exact $f^{\star}$): same asymptotic rate but adapts to local curvature.
\item Adagrad: $O(1/k)$ rate on convex objectives; diagonal preconditioning improves constants.
\item Heavy Ball (optimal parameters): geometric rate $\rho = (1 - 1/\sqrt{\kappa})^2$; needs $O(\sqrt{\kappa}\log(1/\varepsilon))$ iterations.
\end{itemize}
The Heavy Ball optimal rate of $O(\sqrt{\kappa}\log(1/\varepsilon))$ matches the Chebyshev lower bound for the quadratic case and is a $\sqrt{\kappa}$-fold improvement over plain GD---significant for large $\kappa$ (Rosenbrock) but negligible for small $\kappa$ (Benchmark A with $\kappa \approx 1.12$).

The \textbf{Polyak step size} is derived from the first-order Taylor approximation (Polyak, 1987). Setting $\delta = -\alpha_k \nabla f(x_k)$:
\begin{equation}
f(x_{k+1}) \approx f(x_k) - \alpha_k \|\nabla f(x_k)\|^2 \approx f^{\star}.
\end{equation}
Solving for $\alpha_k$ yields the Polyak formula. The step size is theoretically motivated: it scales inversely with the gradient magnitude, providing large steps when far from the minimum (large gradient) and small steps when close (small gradient). Adding $\varepsilon > 0$ prevents division by zero and modifies convergence near the minimum. As the course notes observe: with $\varepsilon = 0$, the Polyak step on $f = x^2$ with $f^{\star} = 0$ is constant ($\alpha = x^2/(2x)^2 = 1/4$); with $\varepsilon > 0$, the step decays to zero as $x \to 0$, which is necessary for convergence near the minimum. A \textbf{practical safeguard} (not used in this implementation) is to cap the step size: $\alpha_k \gets \min(\alpha_k, \alpha_{\max})$ to prevent the catastrophic growth seen when $f^{\star}$ is misspecified.

\textbf{Polyak convergence guarantee (exact $f^{\star}$):} For a convex function with exact $f^{\star}$, the Polyak step satisfies:
\begin{equation}
f(x_{k+1}) - f^{\star} \leq \left(1 - \frac{(f(x_k) - f^{\star})^2}{\|x_k - x^{\star}\|^2 \|g_k\|^2}\right)(f(x_k) - f^{\star}).
\end{equation}
The contraction factor depends on the ``sharpness'' ratio $(f(x_k) - f^{\star}) / (\|x_k - x^{\star}\| \cdot \|g_k\|)$. For strongly convex $f$ with constant $\mu$, this gives geometric convergence with rate $1 - \mu/\|g_k\|^2$. The misspecification case (using $\tilde{f}^{\star} < f^{\star}$) replaces $f(x_k) - f^{\star}$ with $f(x_k) - \tilde{f}^{\star}$, which stays bounded away from 0 as $x_k \to x^{\star}_{\text{OLS}}$, causing $\alpha_k \to \infty$.

\subsection{Algorithm Formulations}

Four adaptive methods are compared against a constant step-size gradient descent baseline across all three benchmarks for 120 iterations.

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, optimal value $f^{\star}$, tolerance $\varepsilon$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets \dfrac{f(x_k) - f^{\star}}{\|g_k\|^2 + \varepsilon}$  \Comment{Adaptive rate proportional to suboptimality gap}
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
\caption{Adagrad}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Accumulate squared gradients per coordinate}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

The effective learning rate for coordinate $i$ at step $k$ is $\alpha_0 / \sqrt{\sum_{t=1}^{k} g_{t,i}^2}$, which decays monotonically. Coordinates with consistently large gradients (steep directions) receive smaller effective rates, while sparse or shallow coordinates retain larger rates. This makes Adagrad well-suited for sparse gradient problems (e.g., NLP), but the monotonic decay can cause premature convergence on dense problems.

\textbf{Adagrad as diagonal preconditioning:} The update $x_{k+1} = x_k - D_k^{-1/2} g_k$ where $D_k = \text{diag}(G_k)$ is equivalent to gradient descent with a diagonal preconditioner. The ideal full-Hessian preconditioner is $H^{-1}$ (Newton's method), which corrects for all curvature anisotropy. Adagrad approximates $H^{-1}$ by its diagonal: $D_k^{-1/2} \approx \text{diag}(H)^{-1/2}$. For a quadratic objective with diagonal Hessian $H = \text{diag}(\lambda_1, \ldots, \lambda_d)$ and starting at $x_0 = 0$, the Adagrad effective rate at step $k$ for coordinate $i$ is $\alpha_0 / \sqrt{k \lambda_i^2 \|x_0 - x^{\star}\|_{e_i}^2}$, converging to the ratio $\sqrt{\lambda_j/\lambda_i}$ between coordinates $i$ and $j$---precisely the ideal preconditioning ratio. This explains the convergence of the step-size ratio to $\sqrt{\lambda_2/\lambda_1} \approx 2.63$ observed in Figure~\ref{fig:q1_percoord_B}.

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponential moving average of $g^2$}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

RMSprop corrects Adagrad's monotonic decay by replacing the cumulative sum with an exponential moving average (EMA) controlled by $\beta$. The EMA has an effective memory window of $1/(1-\beta)$ steps; with $\beta = 0.9$, this is approximately 10 steps. Older gradients are discounted exponentially, allowing the step size to recover when gradients suddenly become small.

\textbf{Why Adagrad converges exactly to $f^{\star}$ on Benchmark~A (unlike RMSprop):} Adagrad's accumulated $G_k = \sum_{t=0}^{k-1} g_t^2$ grows without bound as $k \to \infty$, so the effective step $\alpha_0/\sqrt{G_k} \to 0$. Since $x_k$ approaches $x^{\star}$, the gradient norms $\|g_k\| \to 0$, but $G_k$ accumulates all past squared gradients---including the large early gradients---so $G_k$ grows from large early values and does not vanish. This ensures $\alpha_0/\sqrt{G_k} \to 0$ even as gradients become small, causing the iterates to settle exactly at the minimum rather than oscillating. RMSprop's EMA $v_k = \beta v_{k-1} + (1-\beta)g_k^2$, by contrast, tracks the \emph{recent} gradient magnitude; near the minimum where $g_k \approx 0$, $v_k \to 0$, causing the effective rate $\alpha_0/\sqrt{v_k}$ to grow rather than decay, inducing the observed persistent oscillations.

\begin{algorithm}[H]
\caption{Polyak Momentum / Heavy Ball}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$  \Comment{Momentum: weighted sum of past gradients}
    \State $x_{k+1} \gets x_k - z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

The momentum term $z_{k+1} = \sum_{t=0}^{k} \beta^{k-t} \alpha \nabla f(x_t)$ is a geometrically-weighted sum of all past gradients. With $\beta = 0.9$, the effective step size is amplified by $\approx 1/(1-\beta) = 10$ in consistently downhill directions---equivalently, Heavy Ball uses an effective step size of $\alpha / (1-\beta)$ in a consistent gradient direction (course notation: \emph{``using 10$\alpha$ for $\beta = 0.9$''}). When $\beta = 0$, Heavy Ball reduces to standard gradient descent.

\textbf{Optimal Heavy Ball parameters:} For a strongly convex quadratic with eigenvalues $\lambda_{\min}$ and $\lambda_{\max}$, the optimal Heavy Ball parameters that minimise the convergence rate are:
\begin{equation}
\alpha^{\star} = \frac{4}{(\sqrt{\lambda_{\max}} + \sqrt{\lambda_{\min}})^2}, \quad \beta^{\star} = \left(\frac{\sqrt{\lambda_{\max}} - \sqrt{\lambda_{\min}}}{\sqrt{\lambda_{\max}} + \sqrt{\lambda_{\min}}}\right)^2 = \left(\frac{\sqrt{\kappa} - 1}{\sqrt{\kappa} + 1}\right)^2.
\end{equation}
For Benchmark~A ($\kappa = 1.12$): $\beta^{\star} \approx 0.003$ (negligible momentum). For Benchmark~B ($\kappa \approx 6.9$): $\beta^{\star} \approx 0.33$ (moderate momentum). For Benchmark~C ($\kappa \approx 200$): $\beta^{\star} \approx 0.81$ (high momentum). The empirical values $\beta \in \{0.88, 0.90, 0.86\}$ are significantly larger than the quadratic-optimal values, suggesting they are tuned for the nonlinear benchmark geometry rather than derived from theory. Nonetheless, the trend ($\beta$ roughly increasing with $\kappa$) is consistent with the theoretical prediction.

\subsection{Comparative Analysis}

\begin{itemize}[nosep]
\item \textbf{Convergence speed:} When $f^{\star}$ is known exactly, Polyak converges fastest (Rosenbrock: $f = 0.0094$). For the general case where $f^{\star}$ is unknown, Adagrad and Heavy Ball match or exceed GD.
\item \textbf{Smoothness:} RMSprop produces the smoothest convergence curves due to the EMA stabilising the step size. Heavy Ball exhibits characteristic overshoot followed by damped oscillation, typical of underdamped oscillatory systems.
\item \textbf{Stability:} GD baseline is most stable but slowest. Polyak is \emph{unstable} whenever $f^{\star}$ is misspecified. Adagrad is uniformly stable due to its monotonically decreasing step size, though this property causes premature stagnation on non-stationary or high-dimensional problems. Heavy Ball stability depends critically on the $(\alpha, \beta)$ pairing.
\item \textbf{Heavy Ball momentum across benchmarks:} The three momentum values $\beta \in \{0.88, 0.90, 0.86\}$ for benchmarks A, B, C respectively reflect a deliberate tradeoff between acceleration and stability. Benchmark~B ($\kappa \approx 6.9$) tolerates the highest $\beta = 0.90$ because its moderate anisotropy is consistent across the domain, allowing sustained momentum build-up without direction reversal. Benchmark~A ($\kappa \approx 1.12$) uses $\beta = 0.88$: the nearly circular landscape means momentum barely helps convergence speed but must be controlled to avoid numerical issues. Benchmark~C (Rosenbrock, $\kappa \gg 200$, rapidly varying Hessian) requires the lowest $\beta = 0.86$ because the valley's curvature changes direction continuously---high momentum would carry the iterate past turning points, causing the zig-zagging characteristic of Heavy Ball on ill-conditioned nonconvex problems. Analytically, for a strongly convex quadratic with condition number $\kappa$, the optimal Heavy Ball parameters are $\alpha^{\star} = 4/((\sqrt{\lambda_{\max}} + \sqrt{\lambda_{\min}})^2)$ and $\beta^{\star} = ((\sqrt{\kappa}-1)/(\sqrt{\kappa}+1))^2$; for $\kappa=1.12$, $\beta^{\star} \approx 0.003$, far below the empirical values---confirming that the nonlinear benchmarks require much higher momentum than the quadratic theory predicts.
\item \textbf{Theoretical connection:} The Polyak derivation shows that the step size $\alpha_k = (f(x_k) - f^{\star}) / \|\nabla f(x_k)\|^2$ attempts to reach $f^{\star}$ in a single gradient step using the linear approximation. When $f^{\star}$ is exact, this gives a contraction property; when $f^{\star}$ is underspecified (set too low), the step size over-shoots, causing oscillation and divergence.
\item \textbf{Practical implication:} In practice, exact $f^{\star}$ is rarely known, severely limiting Polyak's applicability. RMSprop and Adagrad are more robust choices for general machine learning problems. The most practically reliable choice across all three benchmarks is Heavy Ball with $\beta \approx 0.88$--$0.90$ for moderately ill-conditioned problems and $\beta \approx 0.86$ for highly nonlinear objectives.
\end{itemize}

\subsection{Theoretical Background}

Standard gradient descent achieves a convergence rate of $O(1/k)$ for convex Lipschitz functions and $O(\rho^k)$ (geometric/linear) for strongly convex functions with condition number $\kappa$, where $\rho = 1 - 1/\kappa$. For ill-conditioned problems, this geometric rate can be very slow. Nesterov acceleration improves the rate to $O(1/k^2)$ for convex functions---the \emph{optimal} first-order convergence rate---by using a momentum term that ``looks ahead'' in the gradient evaluation. Adam combines first-moment momentum (like Heavy Ball) with second-moment scaling (like RMSprop), providing both directional acceleration and per-coordinate adaptation.

\subsection{Algorithm Formulations}

\begin{algorithm}[H]
\caption{Nesterov Momentum / Acceleration}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\frac{k-1}{k+2},\ \beta_{\max}\right)$ \Comment{Scheduled momentum coefficient}
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead point (predict next position)}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$ \Comment{Momentum update with corrected gradient}
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

The key distinction from Heavy Ball (Section~\ref{sec:q1}) is the \emph{lookahead}: the gradient is evaluated at the predicted position $\tilde{x}_k = x_k + \beta_k z_k$ rather than the current position $x_k$. This allows Nesterov momentum to begin correcting its trajectory \emph{before} overshooting, which is what enables the improved $O(1/k^2)$ rate. The scheduled momentum coefficient $\beta_k = (k-1)/(k+2)$ increases from 0 towards 1, starting with conservative steps and building momentum gradually. Capping at $\beta_{\max}$ prevents the coefficient from approaching 1 too closely, which would cause oscillation.

\textbf{Why does the lookahead achieve $O(1/k^2)$?} Intuitively, standard gradient descent makes an error of $O(\alpha L \|x_k - x^{\star}\|)$ per step (proportional to the Lipschitz constant of the gradient times the step size). The lookahead gradient at $\tilde{x}_k$ better estimates the gradient of the function at the next position, reducing the ``wasted'' correction needed after an overshoot. Formally, for a convex function with $L$-Lipschitz gradient, Nesterov proved the bound $f(x_k) - f^{\star} \leq \frac{2L\|x_0 - x^{\star}\|^2}{(k+1)^2}$, vs $\frac{L\|x_0 - x^{\star}\|^2}{2k}$ for standard gradient descent. This $O(1/k^2)$ rate is \emph{optimal} for first-order methods on smooth convex functions---no algorithm using only gradient evaluations can guarantee faster convergence in the worst case.

\textbf{Comparison with Heavy Ball:} Heavy Ball uses $\nabla f(x_k)$ (current position gradient), while Nesterov uses $\nabla f(x_k + \beta_k z_k)$ (future position gradient). When the gradient at the lookahead is smaller than at $x_k$ (as happens near the minimum), Nesterov automatically reduces its step---a form of implicit step-size adaptation that prevents the oscillations seen in Heavy Ball on ill-conditioned problems.

\textbf{Why the $\beta_k$ schedule matters:} The specific schedule $\beta_k = (k-1)/(k+2)$ is not arbitrary---it arises from the analysis in Nesterov (1983) and ensures the Lyapunov function $V_k = (k+1)^2(f(x_k) - f^{\star}) + 2\|z_k\|^2/\alpha$ is non-increasing. This is the key to proving the $O(1/k^2)$ bound. A fixed $\beta$ (as in Heavy Ball) does not satisfy this Lyapunov condition, and indeed Heavy Ball's convergence rate is only $O(1/k)$ in general convex settings (matching standard gradient descent), despite appearing faster in practice on specific problems. The scheduled $\beta_k$ can be seen as ``investing'' in momentum gradually: it builds the oscillation-suppressing momentum only as the iterate becomes confident in its trajectory, which is provably optimal.

\textbf{Momentum restart strategies:} A practical limitation of Nesterov's scheduled $\beta_k$ on nonconvex problems is that the increasing momentum can carry the iterate through local minima or saddle points, restarting the oscillation. The \emph{function value restart} heuristic resets $\beta_k \gets 0$ (restart momentum) whenever $f(x_{k+1}) > f(x_k)$ (the objective increased). This preserves the $O(1/k^2)$ rate on convex problems while providing robustness on nonconvex ones. A variant that monitors the ``gradient correlation'' $\nabla f(\tilde{x}_k)^T z_k < 0$ (gradient and momentum disagree) also provides effective restarts. These restart strategies are widely used in practice and explain why Nesterov-like methods (FISTA for sparse regression, APG for structured problems) perform well on nonconvex applications despite the lack of convexity guarantees.

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha$, moments $\beta_1, \beta_2$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\ v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{First moment (EMA of gradients)}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{Second moment (EMA of squared gradients)}
    \State $\hat{m}_t \gets m_t\, /\, (1 - \beta_1^t)$ \Comment{Bias correction for first moment}
    \State $\hat{v}_t \gets v_t\, /\, (1 - \beta_2^t)$ \Comment{Bias correction for second moment}
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t\, /\, (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

Adam combines \textbf{two distinct mechanisms}: (1) gradient momentum via $m_t$ (analogous to Heavy Ball / Nesterov), which smooths gradient directions and accelerates in consistent descent directions; and (2) per-coordinate adaptive scaling via $v_t$ (analogous to RMSprop), which normalises the effective step size by recent gradient magnitude. The bias correction factors $(1-\beta_1^t)$ and $(1-\beta_2^t)$ account for the fact that $m_0 = v_0 = 0$, which biases early iterates toward zero without correction. With $\beta_2 = 0.999$, the second-moment memory window is $\approx 1000$ steps.

\textbf{Connection to RMSprop (Q1):} Adam can be understood as RMSprop with added gradient momentum. RMSprop suffers from persistent oscillations near the minimum (observed in Q1, Benchmark~A: $f = 0.5027$ vs $f^{\star} = 0.4826$) because the EMA-normalised step size $\alpha_0/\sqrt{v_\infty}$ remains non-negligible even at the minimum. Adam's first-moment term $m_t$ dampens this oscillation by smoothing the gradient direction---near the minimum, $m_t \to 0$ as gradients average to zero, effectively reducing the step size regardless of $v_t$. This explains why Adam typically converges more smoothly than pure RMSprop near the minimum while retaining per-coordinate adaptation far from it.

\textbf{Why Adam underperforms Nesterov on Rosenbrock:} Adam's per-coordinate scaling $\hat{m}_t / \sqrt{\hat{v}_t}$ normalises the gradient magnitude independently in each coordinate. On Rosenbrock, this has a counterproductive effect: near the curved valley floor, the dominant gradient component is perpendicular to the valley (the $x_2 - x_1^2$ direction), which is large and thus receives a small effective step in $x_2$; the along-valley component is small and thus receives a large effective step---but the large step conflicts with the valley's curved geometry, causing Adam to ``bounce'' off the valley walls rather than following the floor. Nesterov, without per-coordinate scaling, accumulates directional momentum along the consistent valley-floor direction, allowing the iterate to ``surf'' along the floor with increasing speed. This illustrates a fundamental limitation of adaptive coordinate-wise scaling: it destroys the directional correlation structure of the gradient trajectory that momentum methods exploit.

\subsection{Mini-Batch Stochastic Gradient Descent}

Mini-batch SGD on Benchmark~A uses learning rate $\alpha = 0.06$, batch sizes $b \in \{5, 40\}$, 50 epochs, with data randomly shuffled at every epoch.

\begin{algorithm}[H]
\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]
\Require Data $(X, y)$, initial $\theta_0$, learning rate $\alpha$, batch size $b$, epochs $E$
\For{$e = 1, 2, \ldots, E$}
    \State Randomly permute data indices $\{1, \ldots, m\}$
    \For{each mini-batch $\mathcal{B}$ of size $b$}
        \State $g_{\mathcal{B}} \gets \frac{1}{b} X_{\mathcal{B}}^T(X_{\mathcal{B}}\theta - y_{\mathcal{B}})$ \Comment{Stochastic gradient estimate}
        \State $\theta \gets \theta - \alpha\, g_{\mathcal{B}}$
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

The mini-batch gradient $g_{\mathcal{B}}$ is an \emph{unbiased estimate} of the full gradient: $\mathbb{E}[g_{\mathcal{B}}] = \nabla J(\theta)$. More precisely, $\mathbb{E}_{\mathcal{B}}[g_{\mathcal{B}}] = \frac{1}{m}X^T(X\theta - y) = \nabla J(\theta)$ since $\mathcal{B}$ is drawn uniformly from the data. The variance of this estimate decomposes as $\text{Var}[g_{\mathcal{B}}] = \frac{1}{b}\Sigma_g$ where $\Sigma_g = \frac{1}{m}\sum_i (\nabla J_i(\theta) - \nabla J(\theta))(\nabla J_i(\theta) - \nabla J(\theta))^T$ is the sample covariance of per-sample gradients. Under high noise ($\sigma^2 \to \infty$), $\Sigma_g \propto \sigma^2$, so both $b=5$ and $b=40$ give proportionally noisier gradient estimates. Each epoch with batch size $b$ performs $\lfloor m/b \rfloor$ gradient updates: $b=5$ gives 200 updates/epoch, $b=40$ gives 25 updates/epoch.

On a per-gradient-evaluation basis, SGD with small batches is far more efficient: 50 epochs × 200 updates = 10,000 gradient evaluations for $b=5$, vs 50 evaluations for full GD in 50 epochs. SGD reaches the noise floor in $\approx 5$ epochs while GD requires $\approx 30$ epochs---on a per-evaluation basis, SGD is approximately $30 \times 200 / 5 \times 1 = 1200\times$ more efficient. This is the core practical motivation for SGD in large-scale machine learning: gradient evaluations are expensive ($O(n)$ per full gradient), while mini-batch evaluations are cheap ($O(b)$), and convergence in total gradient evaluations (not epochs) matters most.

\subsection{SGD with Increased Noise}

The experiment is repeated with output noise scaled by a factor of 6: $y_{\text{noisy}}^{(i)} = \theta^{\star T}x^{(i)} + 6\varepsilon^{(i)}$, where $\varepsilon^{(i)} \sim \mathcal{N}(0,1)$.

\begin{figure}[H]
\centering
\includegraphics[width=\textwidth]{figures/q2_sgd_noisy.pdf}
\caption{Q2: Effect of noise on SGD convergence. Left: original noise ($\sigma = 1$). Right: high noise ($\sigma = 6$). Scaling the observation noise by 6 raises the noise variance by a factor of 36, which increases the irreducible loss floor by the same factor: the minimum achievable loss is $J^{\star} \propto \sigma^2$, so $J^{\star}_{\text{noisy}} \approx 36 \times 0.4826 \approx 17.4$. Under high noise, both batch sizes converge to approximately the same elevated floor ($J^{\star} \approx 17$--$18$). The relative advantage of smaller batches is diminished because the observation model noise (irreducible) dominates over the mini-batch sampling noise---adding more gradient updates per epoch brings no benefit when the gradient itself is corrupted by large observation noise.}
\label{fig:q2_sgd_noisy}

\textbf{Key insight on noise floor:} For a linear regression model with observation noise $\varepsilon \sim \mathcal{N}(0, \sigma^2)$, the minimum achievable mean squared error is $J^{\star} = \frac{\sigma^2}{2}$ (the Bayes/irreducible error). With $\sigma = 1$, $J^{\star} \approx 0.5$; with $\sigma = 6$, $J^{\star} \approx 18$. This floor arises from the data-generation process itself---not from the optimisation algorithm---and cannot be reduced by any estimator. Even the Oracle estimator $\theta^{\star} = [3, 4]^T$ achieves $J = \sigma^2/2$ due to the observation noise. Mathematically, $J(\theta_{\text{OLS}}) = \frac{1}{2m}\|X\theta_{\text{OLS}} - y\|^2 = \frac{1}{2m}\|P_{X^{\perp}}y\|^2 \approx \frac{\sigma^2}{2}$ where $P_{X^{\perp}}$ projects $y$ onto the orthogonal complement of the column space of $X$.

\textbf{Effect on relative batch-size performance:} Under high noise ($\sigma = 6$), the mini-batch gradient variance $\text{Var}[g_{\mathcal{B}}] = \sigma^2/(mb) \cdot \sigma^2_x$ contains two components: (1) observation noise variance $\propto \sigma^2/b$ and (2) model variance from $X_{\mathcal{B}}^T X_{\mathcal{B}}/b$. When $\sigma$ increases by $6\times$, the observation noise component increases by $36\times$, dwarfing the difference between $b=5$ and $b=40$. The relative advantage of smaller batches (more updates per epoch) disappears because the \emph{irreducible} noise from the observation model makes each gradient step equally noisy regardless of batch size. This explains why the two curves in the high-noise plot are almost superimposed, in contrast to the clear separation under low noise.

\textbf{Practical consequence:} This experiment demonstrates that batch size tuning is most beneficial when observation noise is low relative to model complexity. With high observation noise, the learning rate should be reduced (to take smaller, more conservative steps) and more epochs run, rather than adjusting the batch size. In deep learning practice, the ``batch size scaling rule'' (Goyal et al., 2017) states that doubling the batch size should approximately double the learning rate (linear scaling), because the signal-to-noise ratio in the gradient scales as $\sqrt{b}$ for batch size $b$---this rule applies when observation noise is low. Under high noise ($\sigma = 6$), this scaling breaks down because the gradient SNR $= \sigma_{\text{signal}} / \sigma_{\text{noise}} \approx \sqrt{b} \cdot \sigma_{\text{signal}} / \sigma = \sqrt{b}/6$ remains small even for large $b$, making linear learning rate scaling inappropriate.

\textbf{Stochastic approximation theory:} The SGD convergence rate for strongly convex functions is $\mathbb{E}[\|\theta_k - \theta^{\star}\|^2] = O(1/k)$ with fixed learning rate $\alpha$, or $O(\alpha)$ as $k \to \infty$ (convergence to a neighbourhood of size $O(\alpha \sigma^2/\mu)$ around $\theta^{\star}$). Decreasing learning rates $\alpha_k = c/k$ achieve true convergence $\mathbb{E}[\|\theta_k - \theta^{\star}\|^2] = O(1/k)$, but at the cost of slower initial progress. The observed noise floors in Figure~\ref{fig:q2_sgd_noisy} are consistent with the fixed-$\alpha$ regime, where convergence to a neighbourhood of size $\propto \sigma^2$ is guaranteed but exact convergence is not achievable.

\textbf{Variance reduction for SGD:} The $O(1/k)$ rate of SGD is fundamentally limited by gradient variance. \emph{Variance-reduced} methods (SVRG, SAGA, SAG) achieve \emph{linear} convergence $O(\rho^k)$ for strongly convex problems while maintaining the cheap per-iteration cost of SGD. SVRG (Stochastic Variance Reduced Gradient) periodically computes the full gradient $\nabla J(\theta)$ (called a ``snapshot'') and uses it to correct the mini-batch gradient: $\tilde{g}_k = g_{\mathcal{B}} - \nabla J_{\mathcal{B}}(\theta_{\text{snap}}) + \nabla J(\theta_{\text{snap}})$. This correction reduces the gradient variance to zero as $\theta \to \theta^{\star}$, enabling convergence to the exact minimum (not just a neighbourhood). While not implemented in this assignment, SVRG represents the theoretical optimum for finite-sum optimisation and bridges the gap between full GD's linear convergence and plain SGD's $O(1/k)$ rate.

\subsection{Theoretical Background: Local Approximations}

Gradient descent uses a first-order local model $f(x) \approx f(x_k) + \nabla f(x_k)^T(x - x_k)$ and steps in the direction that minimises this linear model (subject to a trust region controlled by $\alpha$). Newton's method instead uses a second-order model---a local quadratic approximation---and directly moves to the minimiser of the quadratic, achieving a much better descent step at the cost of computing and inverting the Hessian.

\subsection{Local Approximations of $g(x) = x^4$}

\textbf{First-order (Taylor) approximation} around $x_0 = 0.25$:
\begin{align}
g(x) &\approx g(x_0) + g'(x_0)(x - x_0) \notag \\
&= (0.25)^4 + 4(0.25)^3(x - 0.25) = 0.00391 + 0.0625(x - 0.25).
\end{align}
Setting this to zero gives the gradient-descent update direction but does not account for curvature.

\textbf{Second-order (quadratic) approximation:}
\begin{align}
g(x) &\approx g(x_0) + g'(x_0)(x - x_0) + \tfrac{1}{2}g''(x_0)(x - x_0)^2 \notag \\
&= 0.00391 + 0.0625(x - 0.25) + \tfrac{1}{2}(12 \times 0.25^2)(x - 0.25)^2 \notag \\
&= 0.00391 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{align}

\textbf{Newton update derivation:} Minimising the quadratic approximation by setting its derivative to zero:
\begin{equation}
g'(x_0) + g''(x_0)(x - x_0) = 0 \implies x^{\star} = x_0 - \frac{g'(x_0)}{g''(x_0)}.
\end{equation}
In $d$ dimensions, this generalises to the Newton step: $x_{k+1} = x_k - \alpha [\nabla^2 f(x_k)]^{-1}\, \nabla f(x_k)$.

\begin{figure}[H]
\centering
\includegraphics[width=0.85\textwidth]{figures/q3_approximation.pdf}
\caption{Q3: Local approximations of $g(x) = x^4$ at $x_0 = 0.25$. The first-order approximation (tangent line) captures only the local slope and deviates rapidly from the true function. The second-order approximation (parabola) captures the curvature and fits well in a neighbourhood of $x_0 = 0.25$. The minimum of the parabola is $x^{\star} = 0.25 - g'(0.25)/g''(0.25) = 0.25 - 0.0625/0.75 \approx 0.167$, providing a better estimate of the function's minimum than a gradient step alone, which motivates Newton's method.}
\label{fig:q3_approx}
\end{figure}

\subsection{Newton's Method with Damping}

\begin{algorithm}[H]
\caption{Newton's Method with Damping}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Tikhonov-regularised Hessian for positive definiteness}
    \State $p_k \gets H_k^{-1}\, g_k$ \Comment{Newton direction: solve linear system}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$
\EndFor
\end{algorithmic}
\end{algorithm}

Settings: GD uses 80 iterations; Newton uses 20 iterations; Hessian damping $\lambda = 10^{-8}$. The damping term $\lambda I$ regularises the Hessian to ensure positive definiteness, which is necessary near saddle points where $\nabla^2 f$ may be indefinite. With $\lambda = 10^{-8}$ and Hessian eigenvalues $\gg 10^{-8}$, the regularisation has negligible effect on the Newton direction while preventing numerical instability.

\textbf{Alternative to fixed $\alpha$: backtracking line search.} The fixed damping approach (using $\alpha = 0.22$ for Benchmark~C) is suboptimal: the correct step size varies as the algorithm progresses. A more principled approach is the \emph{Armijo backtracking line search}: start with $\alpha = 1$ (full Newton step) and halve until the sufficient decrease condition $f(x_k - \alpha p_k) \leq f(x_k) - c\alpha \cdot \nabla f(x_k)^T p_k$ holds (with $c \in (0, 1)$, typically $c = 10^{-4}$). This automatically adapts the step size to the local geometry without requiring manual tuning. The \emph{Wolfe conditions} additionally require the gradient to not decrease too quickly, ensuring sufficient curvature for quasi-Newton methods. The fixed $\alpha = 0.22$ used in this assignment is essentially a conservative estimate of what backtracking would select, traded for simplicity at the cost of some efficiency.

\textbf{Why Newton uses 5 iterations on Benchmark~B (not 1):} For a quadratic function with constant Hessian (Benchmark~A), the Newton step is globally exact in 1 iteration. For Benchmark~B, $H(x) = \text{diag}(2 - \sin(x_1), 10)$ varies with $x_1$. The quadratic approximation at $x_k$ is only locally accurate: the error in the quadratic model is $O(\|x_{k+1} - x_k\|^2 \cdot |H'|)$ where $H' = \nabla^3 f$ is the third derivative. For Benchmark~B, $|H'| \approx |\cos(x_1)| \leq 1$, meaning the quadratic model is accurate over a radius of $O(1/|H'|) = O(1)$ around $x_k$. Starting from $x_0 = [-1,4]$, the first Newton step moves about 2 units to $\approx (-0.2, 2.4)$; the next step covers $\approx 1$ unit; subsequent steps shrink rapidly---consistent with the observed 5-step convergence. The quadratic convergence basin (where Newton steps are self-correcting) is entered after $\approx 3$ steps, after which convergence is superlinear.

\textbf{Quasi-Newton methods:} Full Newton's method requires computing and inverting the $d\times d$ Hessian at each step---$O(d^3)$ per iteration. Quasi-Newton methods approximate $H_k^{-1}$ using curvature information from previous gradient evaluations, avoiding the $O(d^3)$ Hessian computation. The \textbf{BFGS} update maintains an approximation $B_k^{-1} \approx H_k^{-1}$ using the secant condition: $B_{k+1}(x_{k+1} - x_k) = \nabla f(x_{k+1}) - \nabla f(x_k)$. Each update costs $O(d^2)$, and BFGS achieves \emph{superlinear} convergence (between linear and quadratic), making it the method of choice for medium-scale problems ($d \leq 10^4$). \textbf{L-BFGS} (limited-memory BFGS) stores only the most recent $m$ curvature pairs, requiring $O(md)$ memory and $O(md)$ per iteration, enabling application to large-scale problems ($d \leq 10^7$). These quasi-Newton methods bridge the gap between first-order methods (Q1--Q2) and full Newton (Q3).

\textbf{Theoretical note on quadratic convergence:} Near a strongly convex minimum $x^{\star}$, Newton's method satisfies the quadratic convergence bound:
\begin{equation}
\|x_{k+1} - x^{\star}\| \leq \frac{L_H}{2\mu}\|x_k - x^{\star}\|^2,
\end{equation}
where $L_H$ is the Lipschitz constant of $\nabla^2 f$ and $\mu > 0$ is the strong convexity constant. This means once $\|x_k - x^{\star}\| < 2\mu/L_H$ (the ``quadratic convergence basin''), the error contracts superlinearly: the number of correct decimal digits roughly doubles at each step. This ``self-amplifying'' property makes Newton far superior to gradient descent once in the basin. However, outside the basin (far from the minimum), Newton steps can overshoot---hence the need for damping $\alpha < 1$ (as used in Benchmark~C with $\alpha = 0.22$). The constant $C = L_H/(2\mu)$ relates to the Hessian's change rate and strong convexity: for the Rosenbrock, both quantities are large near $(1,1)$, requiring more damping.

\textbf{Why does Newton solve quadratics exactly in one step?} For $f(\theta) = \frac{1}{2}\theta^T H \theta - b^T\theta$ with constant $H \succ 0$, the quadratic approximation at any $\theta_k$ is \emph{globally exact}: $f(\theta) = f(\theta_k) + \nabla f(\theta_k)^T(\theta - \theta_k) + \frac{1}{2}(\theta-\theta_k)^T H (\theta-\theta_k)$. Setting $\theta_{k+1} = \theta_k - H^{-1}\nabla f(\theta_k)$ jumps directly to the global minimum. This is exactly the quadratic case seen in Benchmark~A.

\textbf{Relationship to conjugate gradient:} Newton's method on a quadratic is equivalent to the Conjugate Gradient (CG) method's one-step property: CG on a quadratic with $d$ variables terminates exactly in at most $d$ steps, and for rank-$r$ problems in $r$ steps. Here, Benchmark~A has a rank-2 system ($d=2$), so CG would also terminate in exactly 2 steps (or 1 step if the starting residual is an eigenvector of $H$). Newton's use of the \emph{exact} Hessian inverse explains why it achieves this in 1 step regardless of the starting point, while CG would need up to 2 steps---Newton is strictly faster when the Hessian is available analytically.

\textbf{Role of damping in Benchmark~C:} At the starting point $(-1, 1)$, the Rosenbrock Hessian is $H(-1,1) = \begin{bmatrix} 2 + 1200 - 400 & -400 \\ -400 & 200 \end{bmatrix} = \begin{bmatrix} 802 & -400 \\ -400 & 200 \end{bmatrix}$. This has eigenvalues $\approx 6$ and $\approx 996$, giving the Newton direction $p = H^{-1}g$ a very small component in the 996-eigenvalue direction (the full Newton step would be tiny in this direction) and a larger component in the 6-eigenvalue direction. The full Newton step from $(-1,1)$ has $\alpha = 1$, but the step $p = H^{-1}g$ may be large in the 6-eigenvalue direction if $g$ has large projection there, causing the iterate to cross the valley. Damping $\alpha = 0.22$ reduces this to a safe step size.

\textbf{Newton decrement as a stopping criterion:} The quantity $\lambda^2(x_k) = g_k^T H_k^{-1} g_k$ (Newton decrement squared) provides an estimate of the duality gap: $f(x_k) - f^{\star} \approx \frac{1}{2}\lambda^2(x_k)$ when close to the minimum. This makes it a principled stopping criterion---more reliable than gradient norm, which depends on the Hessian's condition number. In practice, $\lambda^2 < 10^{-6}$ is a common stopping threshold.

\textbf{Scale invariance:} The Newton decrement $\lambda(x) = \sqrt{g^T H^{-1} g}$ is invariant to linear transformations of the coordinate system: if we reparametrise $y = Ax$, the decrement computed in $y$-coordinates equals that in $x$-coordinates. This is because the transformation $A$ modifies both $g$ (by $A^{-T}$) and $H$ (by $A^T H A$), and the product $g^T H^{-1} g$ is unchanged. By contrast, the gradient norm $\|g\|$ is coordinate-dependent: for Benchmark~C at the starting point, $\|\nabla f(-1,1)\| \approx 400$, while near the minimum $\|\nabla f(0.99, 0.98)\| \approx 2$---a 200-fold range. The Newton decrement $\lambda(-1,1)$ and $\lambda(0.99,0.98)$ are directly comparable, giving 0.5 (outside quadratic basin) and $10^{-5}$ (inside basin), respectively, providing an interpretable convergence measure independent of the function's scaling.

\textbf{Phase transition in convergence:} Newton's method exhibits a well-known two-phase behaviour. In the \emph{damped phase} (while $\lambda > \eta$ for some threshold $\eta < 1$), each iteration reduces $f$ by a constant amount, giving \emph{linear} convergence. In the \emph{quadratic phase} (once $\lambda \leq \eta$), convergence is superlinear (quadratic). The transition from damped to quadratic phase is visible in the Newton decrement plot: the initial rapid decline of $\lambda^2$ is linear convergence; the precipitous drop to machine zero at later iterations is quadratic convergence.

\subsection{Part A: Finite Difference and Nesterov Random Search (Benchmark B)}

\subsubsection{Finite Difference Gradient Approximation}

The forward finite-difference approximation replaces each partial derivative with a finite difference:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta}, \quad i = 1, \ldots, d.
\end{equation}
The truncation error from the Taylor expansion is $O(\delta)$: expanding $f(x + \delta e_i) = f(x) + \delta \frac{\partial f}{\partial x_i}(x) + \frac{\delta^2}{2}\frac{\partial^2 f}{\partial x_i^2}(x) + O(\delta^3)$, so the approximation error is $\frac{\delta}{2}|f''_i(x)| + O(\delta^2)$. Floating-point round-off contributes $O(\varepsilon_{\text{machine}} |f|/\delta)$. The total error is minimised at $\delta_{\text{opt}} \sim \sqrt{\varepsilon_{\text{machine}} |f| / |f''|} \approx \sqrt{10^{-16} \cdot 1 / 10} \approx 3 \times 10^{-8}$ for Benchmark~B near the minimum (with $|f| \approx 0.7$, $|f''| \approx 10$). In practice, a larger $\delta \approx 0.05$ is used to avoid precision issues in the objective evaluation, trading a larger truncation error ($\approx 0.05/2 \times 10 = 0.25$ for $x_2$, smaller for $x_1$) for numerical stability. The fact that $\delta = 0.05$ still tracks exact GD closely (Figure~\ref{fig:q4_fval_B}) shows this tradeoff is acceptable here. Central differences $\frac{f(x + \delta e_i) - f(x - \delta e_i)}{2\delta}$ would improve accuracy to $O(\delta^2)$ with the same function-evaluation count, but the code uses forward differences for simplicity.

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search (Zeroth-Order)}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation radius $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Sample $u_k \sim \mathcal{N}(0, I_d)$, normalise: $\hat{u}_k \gets u_k / \|u_k\|$ \Comment{Random unit vector on $S^{d-1}$}
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta \hat{u}_k) - f(x_k)}{\delta}\, \hat{u}_k$ \Comment{Directional derivative estimate}
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

This zeroth-order method estimates a \emph{directional} derivative along a random unit vector $\hat{u}_k$. Formally, $\mathbb{E}_{\hat{u}}[\hat{g}_k] = \frac{1}{d}\nabla f(x_k)$---the expected update direction equals $\nabla f / d$ (correct up to scaling), but the variance is $\text{Var}[\hat{g}_k] \propto \|\nabla f\|^2 / d$---the signal-to-noise ratio in each iteration decreases with dimension $d$. The method requires only \textbf{two function evaluations per iteration}, independent of $d$, making it highly advantageous for large-scale black-box optimisation. The cost per iteration of exact gradient descent scales as $O(d)$ function evaluations (for finite-difference approximation), while Nesterov random search costs $O(1)$ per iteration but converges much more slowly.

\textbf{Expected convergence rate:} For a convex, $L$-smooth function, Nesterov random search achieves convergence rate $O(L d^2 / k)$ (suboptimality scales with $d^2/k$), compared to $O(L/k)$ for exact gradient descent. This $d^2$ penalty means that for $d = 2$ (our benchmarks), NRS is only $4\times$ slower per iteration than exact GD in terms of per-iteration information. For $d = 1000$, NRS would require $10^6\times$ more iterations---confirming that it is only viable for large $d$ when gradient computation is prohibitively expensive (not the case here, but representative of real-world black-box scenarios).

\subsubsection{Nelder--Mead Simplex Method}

The Nelder--Mead algorithm maintains a simplex of $n+1 = 3$ vertices in $\mathbb{R}^2$. At each iteration, the vertices are sorted by objective value, and the worst vertex (highest $f$) is updated by one of four operations:

\begin{enumerate}[nosep]
\item \textbf{Reflection} ($\alpha_r = 1.0$): $x_r = c + \alpha_r(c - x_{\text{worst}})$ where $c$ is the centroid of the remaining vertices. If $f(x_r)$ is better than the second-worst, accept $x_r$.
\item \textbf{Expansion} ($\gamma = 2.0$): If $x_r$ is better than the current best, try $x_e = c + \gamma(c - x_{\text{worst}})$; accept the better of $x_r, x_e$.
\item \textbf{Outside/Inside Contraction} ($\rho = 0.5$): If neither reflection nor expansion improved enough, contract either outside ($x_c = c + \rho(x_r - c)$) or inside ($x_c = c + \rho(x_{\text{worst}} - c)$).
\item \textbf{Shrink} ($\sigma = 0.5$): If contraction fails, shrink all vertices except the best toward the best vertex.
\end{enumerate}

Settings: initial simplex step $= 0.35$ from $x_0 = [-1, 1]^T$, 160 iterations.

\textbf{Summary:} For smooth, low-dimensional problems where gradients are available, exact GD or FD GD with small $\delta$ is strongly preferred. For high-dimensional black-box problems, Nesterov random search's $O(1)$ per-iteration cost is advantageous despite slow convergence. Nelder--Mead is well-suited for low-dimensional ($d \leq 5$) noisy or non-smooth problems where gradients are unreliable. Grid search provides global guarantees but is only practical for $d \leq 2$.

\textbf{Theoretical dimension-dependence:} The number of function evaluations required to achieve $\varepsilon$-accuracy scales as $O(d/\varepsilon)$ for FD GD (linear in $d$, since $d+1$ evaluations per gradient step), $O(1/\varepsilon)$ for Nesterov random search (dimension-independent per-step cost, but convergence rate degrades with $d$ in terms of total function evaluations for fixed $\varepsilon$), and $O((1/\varepsilon)^{d/2})$ for grid search (exponential in $d$). This explains why gradient-based methods are preferred in high dimensions: they exploit the smooth structure of $f$ through the gradient, while black-box methods treat $f$ as an arbitrary function.

\textbf{Relationship between FD and analytical gradients in practice:} The key insight from the Benchmark~B experiment ($\delta = 0.05$ vs $\delta = 0.8$) is that the finite-difference step $\delta$ plays the role of a local smoothing scale. When $\delta$ is much smaller than the function's characteristic variation scale, the approximation is accurate. When $\delta$ is comparable to or larger than this scale, the gradient estimate is corrupted. For Benchmark~B with $f(x) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1)$, the curvature scale is $O(1/\max(\text{eigenvalues})) = O(1/10) = 0.1$. Thus $\delta = 0.05 < 0.1$ is in the accurate regime, while $\delta = 0.8 \gg 0.1$ is in the inaccurate regime---consistent with the observed convergence failure.

\textbf{FD and Newton's method:} Newton's method (Question~3) uses the \emph{exact} second derivative $H_k = \nabla^2 f(x_k)$. Finite-difference Newton would approximate the Hessian as $H_{ij} \approx [f(x + \delta e_i + \delta e_j) - f(x + \delta e_i) - f(x + \delta e_j) + f(x)] / \delta^2$, requiring $(d+1)^2/2 \approx d^2/2$ function evaluations (for the symmetric Hessian)---compared to $d+1$ for gradient approximation. For $d = 2$, FD Newton needs $\approx 4$ evaluations per step to approximate the $2 \times 2$ Hessian, vs 3 for the gradient. For $d = 100$, FD Newton needs $\approx 5050$ evaluations vs 101---a $50\times$ overhead. This highlights why Newton methods are restricted to problems with analytically computable Hessians or where Hessian-vector products can be computed efficiently via automatic differentiation.

\textbf{Information-theoretic perspective on derivative-free methods:} At a fundamental level, derivative-free methods are challenged by the curse of dimensionality in \emph{information} content. Each function evaluation reveals $O(1)$ bits of information about $f$'s gradient; full gradient methods reveal $O(d)$ bits per evaluation. Nesterov random search's directional derivative estimate reveals $O(1)$ bits (one direction out of $O(d)$ needed), requiring $O(d)$ times as many iterations as full gradient descent to achieve the same precision---consistent with its slower convergence observed in Figure~\ref{fig:q4_fval_B}. This lower bound on zeroth-order complexity is not a limitation of any specific algorithm, but an information-theoretic constraint: without gradient information, one cannot identify the steepest descent direction with fewer than $O(d)$ function evaluations in the worst case.

\subsection{Problem Setup}

Minimise Benchmark~B (Eq.~\eqref{eq:bench_B}) subject to the half-space constraint $x_1 \geq 0.5$:
\begin{equation}
\min_{x \in \mathcal{X}_5} f(x_1, x_2), \qquad \mathcal{X}_5 = \{x \in \mathbb{R}^2 : x_1 \geq 0.5\}.
\end{equation}
Starting from the \emph{infeasible} initial point $x_0 = (0.2, 4.0)$.

\textbf{Key observation:} The unconstrained minimum of Benchmark~B is at $x^{\star} \approx (0.582, 2.0)$, which satisfies $x_1^{\star} = 0.582 > 0.5$---the minimum lies \emph{inside} the feasible set. Therefore, the constrained and unconstrained minima coincide: $f^{\star}_{\text{constrained}} = f^{\star}_{\text{unconstrained}} \approx 0.7244$. The constraint is inactive at the optimum. This makes the problem a useful test of how methods handle infeasible starting points and transient constraint violations, even when the constraint does not ultimately restrict the solution.

\begin{algorithm}[H]
\caption{Projected Gradient Descent (PGD)}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial point $x_0$ (possibly infeasible), step size $\alpha$, projection $\Pi_{\mathcal{X}_5}$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Unconstrained gradient step}
    \State $x_{k+1} \gets \Pi_{\mathcal{X}_5}(z_{k+1}) = [\max(0.5,\, z_{k+1,1}),\ z_{k+1,2}]^T$ \Comment{Project onto feasible set}
\EndFor
\end{algorithmic}
\end{algorithm}

The projection $\Pi_{\mathcal{X}_5}$ is a \textbf{hard constraint}: it enforces $x_1 \geq 0.5$ at every iteration without exception. For the half-space, projection is a simple clipping operation. For more complex constraint sets (e.g., $\ell_2$ balls, linear equalities), projection can be computationally expensive.

\textbf{Convergence of PGD:} For a convex, $L$-smooth function $f$ with global minimum $x^{\star} \in \mathcal{X}$, projected gradient descent with step size $\alpha = 1/L$ satisfies:
\begin{equation}
f(x_k) - f^{\star} \leq \frac{L \|x_0 - x^{\star}\|^2}{2k},
\end{equation}
the same $O(1/k)$ rate as unconstrained GD. The projection does not worsen the convergence rate because the non-expansiveness of $\Pi_{\mathcal{X}}$ ($\|\Pi_{\mathcal{X}}(a) - \Pi_{\mathcal{X}}(b)\| \leq \|a-b\|$) preserves the descent property. For the half-space $\{x_1 \geq 0.5\}$, the projection is: $\Pi_{\mathcal{X}_5}(z) = [\max(0.5, z_1), z_2]^T$---a non-expansive operator with closed-form evaluation in $O(1)$. With step size $\alpha = 0.08$ (well below $2/L \approx 2/10 = 0.2$ for Benchmark~B at $\kappa \approx 6.9$), convergence is guaranteed.

\begin{algorithm}[H]
\caption{Penalty Method (Gradient Descent on Penalised Objective)}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, penalty weight $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $F_{\lambda}(x) \gets f(x) + \lambda \max(0,\, 0.5 - x_1)$ \Comment{Penalised objective}
    \State $\nabla F_{\lambda}(x) \gets \nabla f(x) + \lambda [-\mathbf{1}_{x_1 < 0.5},\ 0]^T$ \Comment{Subgradient}
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_{\lambda}(x_k)$
\EndFor
\end{algorithmic}
\end{algorithm}

The penalty function $\lambda \max(0, 0.5 - x_1)$ is a \textbf{soft constraint}: it adds a cost for constraint violation proportional to the violation magnitude and the weight $\lambda$. Using the course's penalty framework, the indicator function $I_{\mathcal{X}_5}(x) = 0$ if $x_1 \geq 0.5$, $= +\infty$ otherwise (hard constraint) is approximated by the continuous convex penalty $Q_{\mathcal{X}_5}(x) = \lambda \max(0, 0.5 - x_1)$ which equals 0 in the feasible set and $\lambda \cdot d(x, \mathcal{X}_5)$ outside it, where $d(x, \mathcal{X}_5) = \max(0, 0.5 - x_1)$ is the distance from $x$ to the feasible set. The gradient of the penalty is $-\lambda$ in the $x_1$ direction when $x_1 < 0.5$ (pushing toward feasibility) and 0 when $x_1 \geq 0.5$ (no penalty for feasible points). Note: the penalty gradient is only a \emph{subgradient} (the penalty is not differentiable at $x_1 = 0.5$), but this is numerically handled cleanly as the set $\{x_1 = 0.5\}$ has measure zero.

\textbf{Hyperparameter settings:} Projected GD: $\alpha = 0.08$. Penalty methods: $\lambda \in \{0.15, 1.8, 4.5\}$ with $\alpha = 0.05$ for $\lambda \leq 1.8$ and $\alpha = 0.03$ for $\lambda = 4.5$ (reduced to handle the steeper penalised gradient). Unconstrained GD: $\alpha = 0.07$. All methods run for 100 iterations.

\textbf{Explanation of final values:} Since the unconstrained minimum $(0.582, 2.0)$ is feasible, all methods ultimately converge to the same final point after 100 iterations (given appropriate step sizes). The differences lie in the \emph{trajectory} and \emph{rate of feasibility enforcement}:

\begin{itemize}[nosep]
\item \textbf{Projected GD:} Enforces feasibility as a hard constraint from iteration 1. This is the fundamental advantage: feasibility is guaranteed at every step. The projection cost for a half-space is $O(1)$ (a max operation), but for complex constraint sets (e.g., Lorentz cone, semidefinite cone) projection can dominate the per-iteration cost.

\item \textbf{Penalty methods:} Trade exact feasibility for simplicity---only a modified gradient is needed, no projection oracle. The weight $\lambda$ controls the penalty-feasibility tradeoff. Small $\lambda$ gives a smooth objective but tolerates violations; large $\lambda$ enforces feasibility but causes numerical ill-conditioning. Concretely, the penalised Hessian for the linear penalty $F_\lambda(x) = f(x) + \lambda\max(0, 0.5 - x_1)$ has the same eigenvalues as $\nabla^2 f$ in the feasible region ($x_1 \geq 0.5$), but in the infeasible region ($x_1 < 0.5$) the Hessian gains an additional contribution from the active penalty subgradient step structure. For a \emph{quadratic} penalty $\frac{\lambda}{2}\max(0, 0.5 - x_1)^2$, the Hessian in the infeasible region would be $\nabla^2 f + \lambda e_1 e_1^T$, shifting the minimum eigenvalue from $\lambda_{\min}(\nabla^2 f) \approx 1.45$ to itself but the maximum eigenvalue from $\approx 10$ to $10 + \lambda$---giving condition number $\kappa(\lambda) \approx (10 + \lambda)/1.45$. With $\lambda = 4.5$, $\kappa \approx 10$; with $\lambda = 100$, $\kappa \approx 76$---requiring step sizes below $2/(10 + \lambda)$ for stability. This explains the step size reduction from $\alpha = 0.05$ to $\alpha = 0.03$ when $\lambda$ increases from 1.8 to 4.5. The fundamental limitation of penalty methods: as $\lambda \to \infty$, the condition number grows as $O(\lambda)$, forcing $\alpha \to 0$ at rate $O(1/\lambda)$, and the number of iterations needed to achieve feasibility scales as $O(\lambda)$ per unit of $\lambda$ increase.

\item \textbf{Unconstrained GD:} Reaches the correct final value but traverses the infeasible region, which would be unacceptable in applications where feasibility must be maintained throughout (e.g., safety-critical control, probability distributions).

\item \textbf{Augmented Lagrangian (not implemented here):} A more powerful alternative to pure penalty methods is the Augmented Lagrangian method (also called Method of Multipliers), which augments the Lagrangian with a quadratic penalty term:
\begin{equation}
\mathcal{L}_{\text{aug}}(x, \mu) = f(x) - \mu(x_1 - 0.5) + \frac{\lambda}{2}\max(0, 0.5 - x_1)^2.
\end{equation}
By updating the Lagrange multiplier $\mu_{k+1} = \mu_k - \lambda(x_{k+1} - 0.5)$ after each inner minimisation, the augmented Lagrangian achieves exact constraint enforcement without requiring $\lambda \to \infty$---the multiplier update corrects for the residual infeasibility that pure penalty methods leave. This resolves the fundamental limitation of penalty methods (condition number growing with $\lambda$) while maintaining the simplicity of not requiring explicit projection. The Alternating Direction Method of Multipliers (ADMM) is a further extension that decomposes the augmented Lagrangian into smaller subproblems---widely used in distributed optimisation and sparse regression.
\end{itemize}

\subsection{KKT Optimality Conditions}

For this constrained problem, the first-order Karush--Kuhn--Tucker (KKT) conditions characterise the optimal solution. The Lagrangian is:
\begin{equation}
\mathcal{L}(x, \mu) = f(x_1, x_2) - \mu(x_1 - 0.5), \quad \mu \geq 0.
\end{equation}
The KKT stationarity condition requires $\nabla_{x} \mathcal{L} = 0$:
\begin{align}
\frac{\partial f}{\partial x_1} - \mu &= 0 \implies [2(x_1 - 1) + \cos(x_1)] = \mu, \\
\frac{\partial f}{\partial x_2} &= 0 \implies 10(x_2 - 2) = 0 \implies x_2 = 2.
\end{align}
The complementary slackness condition requires $\mu(x_1 - 0.5) = 0$. Since the unconstrained minimum has $x_1^{\star} \approx 0.582 > 0.5$, the constraint is \emph{inactive} at the optimum: $x_1^{\star} - 0.5 = 0.082 > 0$. Complementary slackness then forces $\mu = 0$. Substituting back gives the unconstrained stationarity condition, confirming that the constrained and unconstrained minima coincide. If instead the constraint were active ($x_1^{\star} = 0.5$), the Lagrange multiplier $\mu$ would equal the constraint force at the boundary.

\textbf{Sensitivity interpretation of $\mu$:} Even though $\mu = 0$ at the current optimum, the Lagrange multiplier has a precise economic interpretation: $\mu$ measures the sensitivity of the optimal value to a marginal relaxation of the constraint. Specifically, $\partial f^{\star}/\partial b = -\mu$ where $b$ is the right-hand side of the constraint $x_1 \geq b$. With $b = 0.5$ and $x_1^{\star} = 0.582$, there is ``slack'' of 0.082 and the constraint can be tightened by up to 0.082 (to $b = 0.582$) without affecting the optimal value: $\mu = 0$ correctly reflects this insensitivity. If the constraint were instead $x_1 \geq 0.7$ (tighter than $x_1^{\star}$), the optimum would shift to the boundary $x_1^{\star} = 0.7$ with $x_2^{\star} = 2$, giving $f^{\star} = (0.7 - 1)^2 + 0 + \sin(0.7) = 0.09 + 0.644 = 0.734$, and the Lagrange multiplier would be $\mu = 2(0.7 - 1) + \cos(0.7) = -0.6 + 0.765 = 0.165 > 0$, indicating that tightening the constraint by $\delta b$ increases the optimal cost by $0.165\delta b$.

\textbf{Strong duality:} For this problem with a convex objective and a linear (affine) constraint, Slater's condition holds (the feasible interior is non-empty: $x_1 > 0.5$ is achievable), guaranteeing strong duality: $\min_x \max_{\mu \geq 0} \mathcal{L}(x, \mu) = \max_{\mu \geq 0} \min_x \mathcal{L}(x, \mu)$. The duality gap is zero, so the KKT conditions are not merely necessary but also sufficient for global optimality.

\section{Question 6: Linear Programmes and Frank--Wolfe Algorithm \hfill [30 marks]}
\label{sec:q6}

\subsection{Theoretical Background}

The Frank--Wolfe (FW) algorithm, also known as the conditional gradient method, solves constrained optimisation by replacing the projection step of projected gradient descent with a \emph{linear minimisation oracle}. The key motivating observation (from course lecture Week~9b) is that \emph{the minimum of a linear function over a convex polytope always lies at a vertex}: for $f(x) = a^T x$, the minimiser over the box $\mathcal{X}$ is always a corner, regardless of $a$. FW exploits this by linearising $f$ around $x_k$ and solving the resulting LP at each step. Instead of projecting an unconstrained step onto $\mathcal{X}$, FW minimises a first-order approximation to $f$ over $\mathcal{X}$ at each iteration:
\begin{equation}
z_k = \arg\min_{x \in \mathcal{X}}\; \nabla f(x_k)^T x,
\end{equation}
then takes a convex combination $x_{k+1} = \beta x_k + (1-\beta) z_k$ (equivalently, $x_{k+1} = x_k + (1-\beta)(z_k - x_k)$). Since both $x_k \in \mathcal{X}$ and $z_k \in \mathcal{X}$, and $\mathcal{X}$ is convex, the new iterate $x_{k+1}$ is automatically feasible---\textbf{no projection is needed}. This makes FW advantageous when projection is expensive (e.g., projection onto the nuclear norm ball requires SVD).

\textbf{Convergence rate:} FW achieves $O(1/k)$ suboptimality for smooth convex $f$ with a standard step-size schedule $\gamma_k = 2/(k+2)$. This is slower than the $O(1/k^2)$ rate of projected Nesterov acceleration, but FW's projection-free property compensates for this disadvantage in many settings.

\subsection{Feasible Set and Linear Programme}

Feasible set: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\ -5 \leq x_2 \leq 10\}$ (an axis-aligned box/rectangle).

\textbf{Linear Programme:} For $f(x) = a^T x$ with $a = [1, 2]^T$, the minimum over $\mathcal{X}$ is obtained by minimising each coordinate independently (due to the box structure):
\begin{equation}
\min_{x \in \mathcal{X}} (x_1 + 2x_2) = \min_{0.5 \leq x_1 \leq 5} x_1 + \min_{-5 \leq x_2 \leq 10} 2x_2 = 0.5 + 2(-5) = -9.5.
\end{equation}
The solution is $x^{\star} = (0.5, -5)$. This illustrates the \textbf{fundamental theorem of linear programming}: the minimum (or maximum) of a linear objective over a convex polytope (bounded polyhedron) is always attained at a vertex. For the box $\mathcal{X}$, the vertices are the four corners: $(0.5, -5)$, $(5, -5)$, $(5, 10)$, $(0.5, 10)$. Since $a_1 = 1 > 0$ and $a_2 = 2 > 0$, both gradient components favour lower bounds, placing the minimum at $(0.5, -5)$.

\textbf{LP duality:} The dual of this LP is: $\max b^T y$ s.t.\ $A^Ty = a$, $y \geq 0$, where $A$ encodes the box constraints. For the box $0.5 \leq x_1 \leq 5$, $-5 \leq x_2 \leq 10$, strong duality gives the optimal dual value $= -9.5$. The dual variables correspond to shadow prices for each bound: the active bounds ($x_1 = 0.5$, $x_2 = -5$) have positive dual variables (the bounds are binding and tightening them would increase the cost), while the inactive bounds ($x_1 \leq 5$, $x_2 \leq 10$) have zero dual variables. This LP duality framework connects the Frank--Wolfe oracle to the broader theory of constrained optimisation.

\subsection{Frank--Wolfe Algorithm Implementation}

\begin{algorithm}[H]
\caption{Frank--Wolfe / Conditional Gradient (Fixed $\beta$)}
\label{alg:fw}
\begin{algorithmic}[1]
\Require Initial feasible point $x_0 \in \mathcal{X}$, mixing parameter $\beta \in (0,1)$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_k \gets \arg\min_{x \in \mathcal{X}}\, \nabla f(x_k)^T x$ \Comment{Linear minimisation oracle (LMO)}
    \State $x_{k+1} \gets \beta\, x_k + (1 - \beta)\, z_k$ \Comment{Convex combination; maintains $x_{k+1} \in \mathcal{X}$}
\EndFor
\end{algorithmic}
\end{algorithm}

For box constraints, the LP subproblem decomposes per coordinate in $O(d)$ operations:
\begin{equation}
(z_k)_i = \begin{cases} l_i & \text{if } (\nabla f(x_k))_i > 0 \\ u_i & \text{if } (\nabla f(x_k))_i \leq 0 \end{cases}
\quad \text{(lower bound } l_i, \text{ upper bound } u_i\text{)}.
\end{equation}
This is because minimising a linear function $\nabla f(x_k)^T x$ over $[l_i, u_i]$ in coordinate $i$ independently selects the bound with opposite sign to the gradient component.

\textbf{Note:} The implementation uses a fixed $\beta$ (equivalent to step size $1 - \beta$) rather than the standard $\gamma_k = 2/(k+2)$ schedule. Fixed $\beta$ simplifies the algorithm but does not guarantee the $O(1/k)$ convergence rate; the standard schedule would be more principled.

\subsection{Interior vs Boundary Behaviour}

\textbf{Frank--Wolfe gap as convergence diagnostic:} The FW gap $g_k = \nabla f(x_k)^T (x_k - z_k)$ provides both a stopping criterion and an upper bound on suboptimality. For the interior case at convergence ($x_k \approx (1,5)$, $\nabla f \approx 0$): $g_k \approx 0$---confirming the iterate satisfies the KKT condition $\nabla f(x^{\star})^T(x - x^{\star}) \geq 0$ for all $x \in \mathcal{X}$ (first-order optimality for constrained convex problems). For the boundary case at the current iterate $x_k \approx (0.5, -0.3)$: $\nabla f = [1.0, -0.6]$, $z_k = (0.5, 10)$ (since $(\nabla f)_2 = -0.6 < 0$ selects the upper bound $x_2 = 10$). The gap $g_k = \nabla f^T(x_k - z_k) = [1.0, -0.6]^T[(0.5, -0.3) - (0.5, 10)] = [1.0, -0.6]^T[0, -10.3] = 6.18 > 0$, indicating $10.3/k$ suboptimality bound---consistent with the observed gap of $0.114$ and the oscillatory convergence.

\textbf{Interior optimum:} Frank--Wolfe converges but exhibits a characteristic ``zig-zag'' pattern caused by $z_k$ alternating between opposite vertices. The convex combination $x_{k+1} = \beta x_k + (1-\beta)z_k$ averages these jumps, providing geometric convergence with rate $\beta$ per step. The general convergence rate with the standard schedule is $O(1/k)$. Smaller $\beta$ (larger steps toward $z_k$) can be faster initially but introduces more oscillation near the optimum due to the vertex-jumping behaviour.

\textbf{Boundary optimum:} Frank--Wolfe is particularly well-suited to boundary optima because $z_k$ frequently selects the vertex closest to the unconstrained minimum, consistently steering the iterate toward the boundary. The iterate naturally approaches the boundary without needing explicit projection. To understand \emph{why} the fixed-$\beta = 0.93$ schedule does not reach $f^{\star} = 0.25$ ($f = 0.364$ after 140 iterations, gap $= 0.114$): each step moves only $(1-\beta) = 7\%$ of the way toward the LP vertex $z_k = (0.5, -5)$ (since $\nabla f = [2x_1, 2x_2]$ is positive near the constrained minimum $(0.5, 0)$, selecting the lower-left vertex). As the iterate approaches $(0.5, 0)$, successive LP vertices oscillate: once $x_2 < 0$ the oracle selects $z_2 = -5$; once $x_2 > 0$ it selects $z_2 = -5$ again (since $2x_2 > 0$). The $x_2$ component converges to zero from above while the effective step $(1-\beta) = 0.07$ remains constant, requiring $\log(1/\epsilon)/\log(1/\beta) = \log(1/\epsilon)/\log(1/0.93) \approx 14 \log(1/\epsilon)$ iterations to reduce the gap below $\epsilon$---geometrically slow. The standard schedule $\gamma_k = 2/(k+2)$ with $\sum_{k} \gamma_k = \infty$ and $\gamma_k \to 0$ would guarantee $f(x_k) - f^{\star} \to 0$ at rate $O(1/k)$; with fixed $\beta = 0.93$ and 140 iterations, geometric convergence at rate $\beta^k = 0.93^{140} \approx 4 \times 10^{-5}$ only applies to the distance to the boundary, not to the objective gap (which depends on $x_2$ convergence to 0, not just $x_1$ convergence to 0.5).

\textbf{Frank--Wolfe gap (duality gap):} A natural convergence diagnostic for FW is the \emph{Frank--Wolfe gap} $g_k = \nabla f(x_k)^T(x_k - z_k)$, which measures the improvement possible by moving toward the LP vertex. When $g_k = 0$, the iterate satisfies the first-order KKT conditions (it is a constrained stationary point). For the interior optimum case, $g_k \to 0$ confirms convergence. The gap provides both a stopping criterion and an upper bound on the suboptimality: $f(x_k) - f^{\star} \leq g_k$ for convex $f$.

\textbf{Theoretical comparison with Projected GD:} Projected GD on this problem achieves $O(1/k^2)$ (Nesterov-accelerated) or $O(1/k)$ (standard) convergence, but requires projecting onto $\mathcal{X}$ at each step. For the box $\mathcal{X}$, projection is $O(d)$ (coordinate clipping)---the same cost as the FW oracle. For more complex constraint sets, projection can be much more expensive (e.g., projection onto the positive semidefinite cone costs $O(d^3)$, while the FW oracle can sometimes be done in $O(d^2)$).

\textbf{Curvature constant:} The $O(1/k)$ FW convergence bound for smooth convex $f$ is $f(x_k) - f^{\star} \leq \frac{2C_f}{k+2}$, where $C_f = \sup_{\gamma \in [0,1],\, x \in \mathcal{X},\, z \in \mathcal{X}} \frac{2}{\gamma^2}(f(x + \gamma(z-x)) - f(x) - \gamma\nabla f(x)^T(z-x))$ is the curvature constant of $f$ over $\mathcal{X}$. For the interior-optimum problem $f(x) = (x_1 - 1)^2 + (x_2 - 5)^2$ with $L = 2$ (Hessian is $2I$) and $\text{diam}(\mathcal{X}) = \sqrt{(5-0.5)^2 + (10-(-5))^2} \approx 15.7$, one can compute $C_f \leq L \cdot \text{diam}(\mathcal{X})^2 / 2 \approx 2 \cdot 246 / 2 \approx 246$. This gives the convergence bound $f(x_{100}) - f^{\star} \leq 2 \times 246 / 102 \approx 4.8$---a very loose bound due to the large domain, yet the actual gap is $\approx 0.009$, showing the bound is conservative. The tightness of the curvature constant bound scales with $\text{diam}(\mathcal{X})^2$, which highlights that FW's $O(1/k)$ rate becomes impractical for large domains: the constant hidden in $O(1/k)$ grows quadratically with the domain diameter.

\textbf{Connection to LP relaxations:} The FW subproblem $\min_{z \in \mathcal{X}} \nabla f(x_k)^T z$ is a Linear Programme. Each FW iteration solves a fresh LP to determine the descent direction---this is equivalent to finding the ``supporting hyperplane'' direction of the feasible set in the gradient direction. For the box constraint, this LP has closed-form solution (coordinate-wise sign selection). For richer constraint sets such as the simplex $\Delta^d = \{x : \sum_i x_i = 1, x_i \geq 0\}$, the LP selects a single basis vector (the most negative gradient coordinate), which makes FW equivalent to coordinate-wise steepest descent on the simplex---a property exploited in sparse recovery and distribution optimisation.

\subsection{Key Observations Across All Questions}

\textbf{1. Effect of condition number:} Methods' relative performance is strongly influenced by the condition number $\kappa$ of the Hessian. Benchmark~A ($\kappa \approx 1.12$ for the sample $X^TX/m$---nearly perfectly conditioned) poses virtually no challenge for any method: even plain GD converges in very few iterations. Benchmark~B ($\kappa \approx 6.9$ at the minimum) favours adaptive or momentum methods that can handle the 7:1 curvature ratio. Benchmark~C ($\kappa \gg 200$ throughout the domain---the Hessian's largest eigenvalue can reach $10^4$ near the starting point) dramatically amplifies differences: Newton's curvature information provides a $5 \times$ speedup in iterations (Q3), and Nesterov acceleration provides a $7 \times$ reduction in final objective value (Q2) compared to standard GD.

\textbf{2. Polyak step: the oracle problem:} The Polyak step requires exact knowledge of $f^{\star}$---information unavailable in most practical problems. When $f^{\star}$ is correct (Benchmark~C, $f^{\star} = 0$), it achieves the best convergence among all Q1 methods. When misspecified (Benchmarks~A and~B), it causes catastrophic divergence. This illustrates a fundamental challenge: the ``oracle'' availability of $f^{\star}$ is what makes Polyak optimal in theory, but its absence in practice limits applicability.

\textbf{3. Adam vs Nesterov:} Adam (combining momentum and per-coordinate scaling) and Nesterov (pure momentum with lookahead) both outperform GD. On well-conditioned or moderately anisotropic problems (Benchmarks~A, B), their performance is comparable. On the highly anisotropic Rosenbrock (Benchmark~C), Nesterov significantly outperforms Adam ($f = 0.479$ vs $1.578$) because the consistent direction of the Rosenbrock valley allows momentum to build compounding acceleration, while Adam's per-coordinate normalisation disrupts this.

\textbf{4. Newton's second-order advantage:} Newton's method achieves dramatically faster convergence whenever the Hessian is available and the problem is smooth. The one-step quadratic convergence on Benchmark~A is theoretically expected and experimentally confirmed. For nonlinear problems, damping ($\alpha < 1$) is essential to prevent overshooting in regions where the Hessian varies rapidly (Benchmark~C: $\alpha = 0.22$). The computational cost (Hessian computation + linear solve, $O(d^3)$) limits Newton to low- to medium-dimensional problems.

\textbf{5. Derivative-free methods: accuracy vs cost tradeoff:} Finite-difference approximations with appropriate $\delta$ match exact gradient descent at $d+1$ function evaluations per step. Nesterov random search sacrifices accuracy (single random projection) for constant cost (2 FEs per step), benefiting very high-dimensional or expensive black-box problems. Nelder--Mead and grid search are purely zeroth-order and are restricted to low-dimensional problems.

\textbf{6. Constrained methods: hard vs soft constraints:} Projected gradient descent enforces the constraint as a hard invariant from the first iteration. Penalty methods enforce it softly, with accuracy proportional to $\lambda$. For the specific test problem (where the unconstrained minimum is feasible), both approaches reach the same final point, but projected GD maintains feasibility throughout while penalty methods tolerate transient violations. The large-$\lambda$ penalty requires step size reduction to maintain stability---a fundamental tension in penalty methods between constraint enforcement and optimisation stability.

\textbf{7. Frank--Wolfe: projection-free feasibility:} The Frank--Wolfe algorithm maintains feasibility at every iteration through convex combinations, without explicit projection. Its $O(1/k)$ convergence rate (with the standard step-size schedule) is slower than projected gradient methods, but the projection-free property makes it compelling for constraint sets where projection is expensive. The fixed-$\beta$ implementation used here suffers from oscillation near the optimum, which the standard $\gamma_k = 2/(k+2)$ schedule would mitigate.

\textbf{8. The first-order oracle barrier:} A unifying theme across this assignment is Nesterov's \emph{complexity lower bound} for first-order methods: no algorithm using only $k$ gradient evaluations can guarantee better than $O(1/k^2)$ suboptimality for smooth convex functions (or $O(\rho^k)$ for strongly convex functions with condition number $\kappa$, where $\rho = 1 - 1/\sqrt{\kappa}$ is the optimal rate). Nesterov's accelerated method achieves this bound, making it \emph{unimprovable} within the first-order oracle model. Newton's method breaks this barrier by using second-order oracle queries (Hessian evaluations), achieving quadratic convergence---an $O(d^3)$ cost per iteration buys an exponential improvement in convergence rate once inside the quadratic basin.

\textbf{9. Robustness vs optimality:} The assignment reveals a persistent tradeoff between algorithmic robustness and theoretical optimality. Polyak step size is optimal when $f^{\star}$ is known but catastrophically fragile otherwise. Nesterov acceleration achieves the theoretical optimum for convex functions but can be sensitive to step size choice on nonconvex problems. Adam combines the robustness of per-coordinate adaptation with momentum but sacrifices convergence guarantees on nonconvex problems (no known rate better than $O(1/\sqrt{k})$ without additional assumptions). This robustness-optimality spectrum is a fundamental characteristic of optimisation algorithm design: practitioners must identify their problem's structure and choose accordingly.

\subsection{Recommendations for Practitioners}

\begin{enumerate}[nosep]
\item \textbf{First, measure the condition number:} Compute or estimate $\kappa$ before selecting an algorithm. For $\kappa < 5$: plain GD suffices. For $5 \leq \kappa < 50$: Nesterov or Adam. For $\kappa \geq 50$: Newton's method (if $d$ is small) or L-BFGS (if $d$ is large but Hessian-vector products are available).

\item \textbf{For well-conditioned smooth problems ($\kappa < 5$):} Any gradient method works; Adam or Nesterov provides the best tradeoff of speed and robustness. For a quadratic objective, a single Newton step is exact regardless of condition number.

\item \textbf{For ill-conditioned smooth problems ($\kappa \gg 1$):} Use Newton's method (with line search or trust region) if $d \leq 1000$ and the Hessian is computable. Otherwise, L-BFGS (limited-memory quasi-Newton) approximates the inverse Hessian with $O(md)$ storage for $m$ recent vectors. For pure first-order methods, Nesterov provides the optimal $O(\sqrt{\kappa}\log(1/\varepsilon))$ rate; avoid Adam on Rosenbrock-like problems with curved valleys.

\item \textbf{For black-box problems (no analytic gradients):} Use forward finite-difference GD with $\delta \approx \sqrt{f_{\text{scale}} \cdot \varepsilon_{\text{machine}}/|f''|}$ if $d \leq 100$. Use Nesterov random search for $d > 100$ (only 2 function evaluations per iteration). Nelder--Mead is suitable for $d \leq 10$ with noisy or non-smooth objectives.

\item \textbf{For constrained problems:} (a) If the constraint set allows cheap projection ($\ell_2$ balls, boxes, simplices), use projected Nesterov. (b) If projection is expensive (nuclear norm ball, positive-semidefinite cone), use Frank--Wolfe with the standard $\gamma_k = 2/(k+2)$ schedule. (c) If the constraint is soft (penalty acceptable), use penalty or augmented Lagrangian methods with increasing $\lambda$.

\item \textbf{For noisy/stochastic objectives:} Mini-batch SGD with batch size $b \approx \sigma^2 / \sigma^2_{\text{signal}}$ (balance noise and signal). Use Adam or RMSprop with decreasing learning rate; avoid fixed learning rate SGD for final convergence. With very high noise, reduce learning rate rather than increasing batch size.

\item \textbf{On step-size choice:} Always choose $\alpha < 2/L$ for gradient methods (where $L$ is the Lipschitz constant of $\nabla f$, or use line search). For momentum methods, reduce $\alpha$ by a factor of $(1-\beta)$ relative to GD. The conservative defaults $\alpha = 0.001$ (Adam) and $\alpha = 0.01$ (SGD) often work but may be suboptimal.
\end{enumerate}

def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        x = x - alpha * grad_fn(x)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)

\begin{lstlisting}[caption={Polyak Step Size}]
def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adagrad}]
def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float)
    G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={RMSprop}]
def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float)
    v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Heavy Ball / Polyak Momentum}]
def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x)
        z = beta * z + alpha * g
        x = x - z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Nesterov Accelerated Gradient}]
def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z        # look-ahead position
        g = grad_fn(lookahead)             # gradient at look-ahead
        z = beta_k * z - alpha * g
        x = x + z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adam Optimiser}]
def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t)   # bias-corrected 1st moment
        v_hat = v_vec / (1 - beta2**t)   # bias-corrected 2nd moment
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Newton's Method with Damping}]
def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))   # Tikhonov regularisation
        try:
            p = np.linalg.solve(H_reg, g)       # Newton direction
        except np.linalg.LinAlgError:
            p = g                                # fallback to gradient
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)
\end{lstlisting}

\begin{lstlisting}[caption={Frank--Wolfe Algorithm (Fixed Step)}]
def frank_wolfe(grad_fn, loss_fn, x0, bounds, beta, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, z_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        # Linear minimisation oracle: choose vertex of box
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z   # convex combination (feasible)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
\end{lstlisting}
