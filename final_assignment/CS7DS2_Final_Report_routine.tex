\begin{abstract}
This report presents a comprehensive comparative study of six families of optimisation algorithms applied to three canonical benchmark problems: a linear regression quadratic loss (Benchmark A), a toy neural-network loss with sinusoidal perturbation (Benchmark B), and the Rosenbrock function (Benchmark C). The methods investigated span: \textbf{adaptive step-size} methods (Polyak, Adagrad, RMSprop, Heavy Ball); \textbf{accelerated/stochastic} methods (Nesterov acceleration, Adam, mini-batch SGD); \textbf{second-order} methods (Newton with Hessian damping); \textbf{derivative-free} approaches (finite differences, Nesterov random search, Nelder--Mead simplex, grid search); \textbf{constrained optimisation} via projected gradient descent and quadratic penalty; and the \textbf{Frank--Wolfe} algorithm for linearly-constrained problems. Key findings: (i) the Polyak step diverges when the true minimum $f^\star$ is misspecified, since the step size grows as $\alpha_k \to (f^\star_{\rm true} - \tilde{f}^\star)/\varepsilon \gg 1$ when $\|\nabla f\| \to 0$; (ii) on the ill-conditioned Rosenbrock function ($\kappa\approx 2508$), Newton's method with 20 iterations outperforms gradient descent with 80 iterations by a factor of 5.4$\times$ in objective value reduction; (iii) Nesterov acceleration achieves $f=0.479$ on Rosenbrock versus Adam's $f=1.578$, demonstrating that momentum scheduling is critical for ill-conditioned problems; (iv) on Benchmark B ($L=10$, $\mu=1.45$, $\kappa\approx 6.9$), GD requires $\approx 32$ iterations to reduce error by $10^{-4}$ while Nesterov requires only $\approx 12$, consistent with their respective $\rho_{\rm GD}\approx 0.747$ and $\rho_{\rm Nes}\approx 0.449$ per-step rates; (v) projected gradient descent enforces feasibility from the first iterate as a hard constraint, whereas penalty methods require $\lambda \geq 4.5$ to achieve near-zero constraint violation within 100 iterations. Each method is evaluated on convergence speed, trajectory behaviour, stability, and computational cost.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% ============================================================

Optimisation lies at the heart of modern machine learning: training a model reduces to minimising a loss function, and the choice of optimiser fundamentally determines both convergence speed and solution quality. This assignment investigates six families of methods across three benchmark problems of increasing difficulty, from the perfectly-conditioned quadratic (Benchmark A, $\kappa \approx 1$) to the highly ill-conditioned Rosenbrock banana valley (Benchmark C, $\kappa \approx 2000$).

The algorithms studied progress from the simplest (constant-step gradient descent) to increasingly sophisticated strategies that exploit curvature information (Newton), reduce gradient variance (mini-batch SGD), enforce feasibility (projected gradient), or require no derivatives at all (Nelder--Mead). Understanding \emph{why} one method outperforms another on a given problem class---not merely \emph{that} it does---is the central goal of this study.

Throughout, two theoretical quantities inform the analysis. For a twice-differentiable function $f:\mathbb{R}^n \to \mathbb{R}$ with $\mu$-strongly-convex and $L$-smooth Hessian (i.e.\ $\mu I \preceq \nabla^2 f(x) \preceq LI$), the \textbf{condition number} $\kappa = L/\mu$ governs first-order convergence rates: gradient descent converges as $\|x_k - x^\star\|^2 \leq \left(\frac{\kappa-1}{\kappa+1}\right)^{2k}\|x_0 - x^\star\|^2$, while Nesterov acceleration improves this to $\left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^{2k}$. The three benchmarks span a wide range of condition numbers:

A (Quadratic) & 1.12 & 0.056 & 0.057 & 3 & 3 \\

On Benchmark A where $\kappa \approx 1.12$, all first-order methods converge rapidly; on Rosenbrock where $\kappa \approx 2508$, GD would require over 36{,}000 iterations to reduce error by $10^{-4}$, whereas Nesterov needs only 233. \subsection{Benchmark A: Linear Regression Quadratic Loss}

A synthetic dataset with $m = 1000$ samples and $n=2$ parameters is generated:
\begin{equation}
  \theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \quad
  x^{(i)} \sim \mathcal{N}(0, I_2), \quad
  y^{(i)} = {\theta^{\star}}^{\!T} x^{(i)} + \varepsilon^{(i)}, \quad
  \varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The loss function is the mean squared error (MSE):
\begin{equation}
  J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left(\theta^T x^{(i)} - y^{(i)}\right)^2
            = \frac{1}{2m}\|X\theta - y\|^2.
\end{equation}
The gradient and Hessian are:
\begin{equation}
  \nabla J(\theta) = \frac{1}{m}X^T(X\theta - y), \qquad
  H = \nabla^2 J(\theta) = \frac{1}{m}X^TX \quad \text{(constant)}.
\end{equation}
Because $H$ is constant and positive semi-definite, this is a \emph{convex quadratic}. The Lipschitz constant is $L = \lambda_{\max}(H) \approx 1.033$ and the strong-convexity constant is $\mu = \lambda_{\min}(H) \approx 0.925$, giving $\kappa = L/\mu \approx 1.12$ --- a well-conditioned problem. Due to observation noise $\varepsilon^{(i)}\sim\mathcal{N}(0,1)$, the irreducible minimum is $J^{\star} \approx 0.4826$ (the OLS noise floor), not zero. Starting point: $\theta_0 = [0, 0]^T$.

\subsection{Benchmark B: Toy Neural Network Loss}
\begin{equation}
  f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
  \label{eq:benchmark_B}
\end{equation}
The gradient is $\nabla f = [2(x_1 - 1) + \cos(x_1),\ 10(x_2 - 2)]^T$ and the Hessian is:
\begin{equation}
  H(x) = \begin{pmatrix} 2 - \sin(x_1) & 0 \\ 0 & 10 \end{pmatrix}.
\end{equation}
The eigenvalues of $H$ vary with position: the $(1,1)$ entry $2-\sin(x_1)$ ranges in $[1, 3]$ while the $(2,2)$ entry is the fixed constant $10$. The condition number varies between approximately $10/3 \approx 3.3$ and $10/1 = 10$, creating \emph{moderate anisotropy}. The minimum is obtained by solving $2(x_1^\star - 1) + \cos(x_1^\star) = 0$ (numerically) and $x_2^\star = 2$ (algebraically), yielding $x^\star \approx (0.5824, 2.0)$ with $f^\star \approx 0.7244$. At the minimum, $H(x^\star) = \text{diag}(1.45, 10)$ and $\kappa \approx 6.9$. Starting point: $x_0 = [-1, 4]^T$.

\subsection{Benchmark C: Rosenbrock Function}
\begin{equation}
  f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
  \label{eq:rosenbrock}
\end{equation}
The gradient is:
\begin{equation}
  \nabla f = \begin{bmatrix}
    -2(1 - x_1) - 400 x_1(x_2 - x_1^2) \\
    200(x_2 - x_1^2)
  \end{bmatrix},
\end{equation}
and the Hessian is:
\begin{equation}
  H(x) = \begin{pmatrix} 2 + 1200x_1^2 - 400x_2 & -400x_1 \\ -400x_1 & 200 \end{pmatrix}.
\end{equation}
At the global minimum $(1,1)$ ($f^\star = 0$), the Hessian eigenvalues are approximately $0.40$ and $1002$, giving $\kappa \approx 2508$. This extreme ill-conditioning, combined with a narrow curved valley along $x_2 = x_1^2$, makes Rosenbrock the canonical stress-test for optimisation algorithms. Starting point: $x_0 = [-1, 1]^T$.

\begin{remark}
The Rosenbrock condition number $\kappa \approx 2508$ means the GD convergence factor is $\rho_{\rm GD} = (\kappa-1)/(\kappa+1) \approx 0.9992$, so each iteration reduces the error by only $0.08\%$. Reaching $10^{-4}$ accuracy from $\|x_0 - x^\star\| = 2\sqrt{2}$ would require over 36{,}000 iterations --- far beyond the 80--200 budgeted.
\end{remark}

\section{Question 1: Adaptive Step-Size Methods \hfill [30 marks]}
\label{sec:q1}
% ============================================================

\subsection{Algorithm Formulations}

Four adaptive methods are compared against a constant step-size gradient descent (GD) baseline across all three benchmarks for 120 iterations. The baseline GD update is:
\begin{equation}
  x_{k+1} = x_k - \alpha \nabla f(x_k).
\end{equation}

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, optimal value $f^{\star}$, tolerance $\varepsilon$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets \dfrac{f(x_k) - f^{\star}}{\|g_k\|^2 + \varepsilon}$
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

The Polyak step size is theoretically motivated by the bound $f(x_{k+1}) \leq f^\star + \frac{\|g_k\|^2}{4\alpha_k}$ for any descent step; choosing $\alpha_k = (f(x_k) - f^\star)/\|g_k\|^2$ minimises the right-hand side, making $f(x_{k+1}) \leq f^\star + (f(x_k) - f^\star)/4$, which is optimal for the Polyak--\L ojasiewicz class of functions.

\begin{algorithm}[H]
\caption{Adagrad}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Per-coordinate accumulation of squared gradients}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

Adagrad adapts the learning rate \emph{per coordinate}: coordinates with historically large gradients receive smaller updates. The effective learning rate $\alpha_k^{(i)} = \alpha_0/\sqrt{G_k^{(i)} + \varepsilon}$ is \emph{monotonically decreasing}, which guarantees progress on convex problems but can prematurely freeze learning on non-stationary objectives.

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponential moving average of squared gradients}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

RMSprop differs from Adagrad by replacing the full sum $G_k$ with an exponential moving average $v_k$. This prevents the effective learning rate from decaying to zero, making it suitable for non-stationary objectives. With $\beta = 0.9$, recent gradients receive weight $(1-0.9) = 0.1$ per step, giving an effective window of approximately $1/(1-\beta) = 10$ steps.

\begin{algorithm}[H]
\caption{Polyak Momentum / Heavy Ball}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$
    \State $x_{k+1} \gets x_k - z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

Heavy Ball builds a velocity vector $z_k$ that accumulates past gradients. For a strongly convex quadratic with condition number $\kappa = L/\mu$, the optimal heavy-ball parameters are:
\begin{equation}
  \alpha^\star = \frac{4}{(\sqrt{L}+\sqrt{\mu})^2}, \qquad
  \beta^\star = \left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^2,
\end{equation}
yielding the optimal first-order convergence rate $\rho^\star = \left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^k$. For Benchmark A ($\kappa \approx 1.12$), the optimal $\beta^\star \approx 0.003$ is tiny, so momentum provides little benefit --- consistent with the observation that GD and Heavy Ball converge at similar speeds on Benchmark A. For Benchmark B ($\kappa \approx 6.9$), $\beta^\star \approx 0.42$ provides significant acceleration. The experimentally tuned values ($\beta = 0.88$--$0.90$) are higher than the optimal quadratic values, which works because the non-quadratic structure of Benchmarks B and C allows heavier momentum without instability.

\subsection{The Polyak Divergence Mechanism}

\begin{proposition}[Polyak divergence under misspecification]
Let $f:\mathbb{R}^n\to\mathbb{R}$ be $L$-smooth and let the Polyak step use $\tilde{f}^\star < f^\star_{\rm true}$. Then for any iterate $x_k$ with $f(x_k) \to f^\star_{\rm true}$ and $\|\nabla f(x_k)\| \to 0$:
\begin{equation}
  \alpha_k = \frac{f(x_k) - \tilde{f}^\star}{\|\nabla f(x_k)\|^2 + \varepsilon}
           \;\longrightarrow\; \frac{f^\star_{\rm true} - \tilde{f}^\star}{\varepsilon} \;\gg\; 1,
\end{equation}
so the step size grows unboundedly (as $\varepsilon \to 0$), causing oscillations or divergence.
\end{proposition}

\textbf{Key finding:} The Polyak step size is highly sensitive to the accuracy of $f^{\star}$. On Benchmark A, $f^\star_{\rm true} \approx 0.4826$ but $\tilde{f}^\star = 0$ is specified. As $\theta \to \theta_{\rm OLS}$, the numerator $f(\theta) - 0 \approx 0.48$ remains large while $\|\nabla f\|^2 \to 0$, so $\alpha_k$ grows unboundedly. On Benchmark C where $f^\star = 0$ is the true minimum, Polyak achieves the best result.

\subsection{Comparative Analysis}

\begin{itemize}[nosep]
\item \textbf{Convergence speed:} When $f^{\star}$ is known exactly, Polyak converges fastest (Rosenbrock: $f = 0.009$). Otherwise, Heavy Ball and Adagrad match or exceed the GD baseline across all benchmarks.
\item \textbf{Smoothness:} RMSprop produces the smoothest convergence curves due to exponential averaging of squared gradients. Heavy Ball shows characteristic overshoot followed by damped oscillation.
\item \textbf{Stability:} Constant-step GD is most stable but slowest. Polyak is \emph{unstable} when $f^{\star}$ is misspecified. Adagrad is uniformly stable due to its monotonically decreasing step, though it may stall on long-horizon problems.
\item \textbf{Practical guidance:} In practice, exact $f^{\star}$ is rarely available, limiting Polyak's applicability. RMSprop and Adam (see Section~\ref{sec:q2}) are the most robust choices for deep learning, while Heavy Ball is theoretically optimal for well-conditioned quadratics.
\end{itemize}

\subsection{Algorithm Formulations}

\begin{algorithm}[H]
\caption{Nesterov Momentum / Accelerated Gradient}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\frac{k-1}{k+2},\ \beta_{\max}\right)$ \Comment{Adaptive momentum coefficient}
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead point}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

The critical distinction from Heavy Ball (Algorithm~\ref{alg:heavyball}) is the \emph{lookahead}: the gradient is evaluated at the extrapolated point $\tilde{x}_k = x_k + \beta_k z_k$ rather than at $x_k$. This allows Nesterov momentum to ``look ahead'' and correct its trajectory before overshooting. The adaptive schedule $\beta_k = (k-1)/(k+2)$ is the canonical choice that achieves the optimal $O(1/k^2)$ convergence rate on convex functions, compared to $O(1/k)$ for standard GD.

\begin{theorem}[Nesterov convergence, convex case]
Let $f$ be convex and $L$-smooth. Nesterov's accelerated gradient method with $\alpha = 1/L$ and $\beta_k = (k-1)/(k+2)$ satisfies:
\begin{equation}
  f(x_k) - f^\star \leq \frac{2L\|x_0 - x^\star\|^2}{(k+1)^2},
\end{equation}
versus $O(1/k)$ for gradient descent, an improvement by a factor of $O(k)$.
\end{theorem}

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha$, moments $\beta_1, \beta_2$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\ v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{First-moment (mean) estimate}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{Second-moment (variance) estimate}
    \State $\hat{m}_t \gets m_t\, /\, (1 - \beta_1^t)$ \Comment{Bias correction for first moment}
    \State $\hat{v}_t \gets v_t\, /\, (1 - \beta_2^t)$ \Comment{Bias correction for second moment}
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t\, /\, (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

Adam combines RMSprop's per-coordinate adaptive scaling (via $v_t$) with momentum (via $m_t$), inheriting advantages of both. The bias corrections prevent early iterates from being biased towards zero (since $m_0 = v_0 = 0$, without correction $m_1 = (1-\beta_1)g_1$ is far from the true first moment). The effective update is $\alpha \cdot \hat{m}_t/\sqrt{\hat{v}_t} \approx \alpha \cdot \text{sign}(g_t)$ elementwise at the start, providing normalised steps.

\subsection{Mini-Batch Stochastic Gradient Descent}

Mini-batch SGD on Benchmark A uses learning rate $\alpha = 0.06$, batch sizes $b \in \{5, 40\}$, and 50 epochs, with data shuffled at every epoch.

\begin{algorithm}[H]
\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]
\Require Data $(X, y)$, initial $\theta_0$, learning rate $\alpha$, batch size $b$, epochs $E$
\For{$e = 1, 2, \ldots, E$}
    \State Randomly permute data indices
    \For{each mini-batch $\mathcal{B}$ of size $b$}
        \State $g \gets \frac{1}{b} X_{\mathcal{B}}^T(X_{\mathcal{B}}\theta - y_{\mathcal{B}})$ \Comment{Stochastic gradient estimate}
        \State $\theta \gets \theta - \alpha\, g$
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

Each mini-batch gradient $\hat{g}_b$ is an unbiased estimator of the full gradient:
$\mathbb{E}[\hat{g}_b] = \nabla J(\theta)$, but with variance $\text{Var}[\hat{g}_b] \approx \sigma^2_{\rm grad}/b$. Smaller batches reduce computation per epoch but increase gradient variance, leading to a \emph{noise floor}: SGD cannot converge below $O(\alpha \sigma^2_{\rm grad}/b)$ with constant step size.

On Rosenbrock, the Hessian is highly non-diagonal (the off-diagonal term $H_{12} = -400x_1 \approx -400$ at the optimum), so a diagonal preconditioner cannot capture the dominant curvature direction. Nesterov, by contrast, accumulates momentum in the correlated direction along the valley floor, which is precisely the direction that needs acceleration.

\subsection{Local Approximations of $g(x) = x^4$}

\textbf{Taylor expansions} around $x_0 = 0.25$ with $g'(x) = 4x^3$ and $g''(x) = 12x^2$:

\textbf{First-order (tangent line):}
\begin{equation}
  T_1(x) = g(x_0) + g'(x_0)(x - x_0) = 0.0039 + 0.0625(x - 0.25).
\end{equation}

\textbf{Second-order (local parabola):}
\begin{equation}
  T_2(x) = g(x_0) + g'(x_0)(x - x_0) + \tfrac{1}{2}g''(x_0)(x - x_0)^2 = 0.0039 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{equation}

The \textbf{Newton step} minimises $T_2$: setting $T_2'(x) = 0$ gives:
\begin{equation}
  x^\star_{T_2} = x_0 - \frac{g'(x_0)}{g''(x_0)} = 0.25 - \frac{0.0625}{0.75} \approx 0.167,
\end{equation}
which is a better estimate of the true minimiser $x^\star = 0$ than the gradient step $x_0 - \alpha g'(x_0)$ with any fixed $\alpha$. For $g(x) = x^4$, Newton's method has superlinear convergence: starting from $x_0 = 0.25$, the sequence is $0.25 \to 0.167 \to 0.083 \to 0.028 \to \cdots$.

\subsection{Newton's Method with Hessian Damping}

\begin{algorithm}[H]
\caption{Newton's Method with Hessian Regularisation}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Tikhonov-regularised Hessian}
    \State $p_k \gets H_k^{-1}\, g_k$ \Comment{Newton direction}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$ \Comment{Damped Newton step}
\EndFor
\end{algorithmic}
\end{algorithm}

The Hessian damping $\lambda I$ (Tikhonov regularisation) serves two purposes: (i) it ensures $H_k + \lambda I \succ 0$ even when $H_k$ is singular or indefinite (as near saddle points), and (ii) it controls the step size: the damped direction $p_k = (H_k + \lambda I)^{-1}g_k$ interpolates between the Newton direction ($\lambda \to 0$) and the gradient direction ($\lambda \to \infty$). With $\lambda = 10^{-8}$, regularisation has negligible effect unless $H_k$ is near-singular.

\textbf{Settings:} GD uses 80 iterations; Newton uses only 20 iterations with $\lambda = 10^{-8}$.

\subsection{Theoretical Convergence Rates}

\begin{theorem}[Quadratic convergence of Newton's method]
Let $f$ be twice continuously differentiable with $L$-Lipschitz Hessian and $\mu$-strongly-convex near $x^\star$. Then Newton's method with $\alpha = 1$ satisfies, for $\|x_k - x^\star\|$ sufficiently small:
\begin{equation}
  \|x_{k+1} - x^\star\| \leq \frac{L}{2\mu}\|x_k - x^\star\|^2.
\end{equation}
This \emph{quadratic convergence} means each iteration approximately doubles the number of correct decimal digits, compared to the \emph{linear convergence} $\|x_{k+1} - x^\star\| \leq \frac{\kappa-1}{\kappa+1}\|x_k - x^\star\|$ of gradient descent.
\end{theorem}

The observed update magnitude plot (Figure~\ref{fig:q3_update}) confirms this: Newton's update magnitude decreases super-linearly (approximately parabolic on the log scale), while GD's decreases linearly.

\subsection{Part A: Finite Difference Approximation and Nesterov Random Search (Benchmark B)}

\subsubsection{Finite Difference Gradient Approximation}

The forward finite-difference (FD) approximation replaces each partial derivative with:
\begin{equation}
  \frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta} = \frac{\partial f}{\partial x_i}(x) + \frac{\delta}{2}\frac{\partial^2 f}{\partial x_i^2}(x) + O(\delta^2),
\end{equation}
where $e_i$ is the $i$-th standard basis vector. The approximation error has two components:
\begin{itemize}[nosep]
\item \textbf{Truncation error:} $O(\delta)$ from Taylor expansion --- larger $\delta$ means larger gradient error.
\item \textbf{Round-off error:} $O(\varepsilon_{\rm machine}/\delta)$ from floating-point cancellation --- smaller $\delta$ amplifies this.
\end{itemize}
The optimal $\delta$ minimises the total error: $\delta^\star \sim \sqrt{\varepsilon_{\rm machine}} \approx 10^{-8}$ for IEEE double precision. The assignment tests $\delta = 0.05$ (near-optimal for this problem) and $\delta = 0.8$ (large truncation error). Each FD gradient evaluation requires $n+1 = 3$ function evaluations (one for $f(x)$, one per coordinate).

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search (Zeroth-Order Method)}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Sample $u_k \sim \mathcal{N}(0, I_n)$, normalise: $u_k \gets u_k / \|u_k\|$
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta u_k) - f(x_k)}{\delta}\, u_k$ \Comment{Stochastic directional-derivative estimate}
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

This zeroth-order method estimates the directional derivative along a single random direction $u_k$, requiring only \emph{two} function evaluations per iteration regardless of dimension $n$. The estimator is biased: $\mathbb{E}[\hat{g}_k] = \frac{n}{\delta}\mathbb{E}[f(x+\delta u)u] \approx \nabla f(x)$ for small $\delta$ by the Stein lemma, but has variance $O(n \cdot \|\nabla f\|^2)$ --- larger in higher dimensions, explaining slow convergence on practical problems.

\subsubsection{Results and Analysis}

At the starting point $x_0 = [-1, 4]^T$, the exact gradient is $\nabla f(x_0) \approx [-3.46,\ 20.0]^T$ with $\|\nabla f(x_0)\| \approx 20.3$. The finite-difference gradient errors are:
\begin{itemize}[nosep]
\item Good FD ($\delta = 0.05$): approximate gradient $\approx [-3.39,\ 20.25]^T$, absolute error $= 0.26$ (relative $1.3\%$).
\item Poor FD ($\delta = 0.8$): approximate gradient $\approx [-2.40,\ 24.0]^T$, absolute error $= 4.14$ (relative $20.4\%$).
\end{itemize}
The dominant error for $\delta = 0.8$ is in the $x_1$ direction, where the nonlinear term $\cos(x_1)$ changes by $\cos(-1) - \cos(-0.2) \approx 0.54 - 0.98 = -0.44$ over the interval $[-1, -0.2]$, producing a finite-difference error of order $\delta \cdot |g''(x_0)| \approx 0.8 \times 5.9 \approx 4.7$, consistent with the observed error.

\subsection{Part B: Derivative-Free Methods on Rosenbrock (Benchmark C)}

\subsubsection{Nelder--Mead Simplex Method}

The Nelder--Mead algorithm maintains a simplex of $n+1 = 3$ vertices in $\mathbb{R}^2$ and iteratively transforms it through four operations. Let $x_1, x_2, x_3$ be the simplex vertices ordered $f(x_1) \leq f(x_2) \leq f(x_3)$ and $c = (x_1 + x_2)/2$ their centroid (excluding the worst):
\begin{enumerate}[nosep,label=\arabic*.]
\item \textbf{Reflection:} $x_r = c + \alpha_r(c - x_3)$, $\alpha_r = 1$. Accept if $f(x_1) \leq f(x_r) < f(x_2)$.
\item \textbf{Expansion:} If $f(x_r) < f(x_1)$, try $x_e = c + \gamma(c - x_3)$, $\gamma = 2$.
\item \textbf{Contraction:} If $f(x_r) \geq f(x_2)$, try $x_c = c + \rho(x_3 - c)$, $\rho = 0.5$.
\item \textbf{Shrink:} If contraction fails, set $x_i \leftarrow x_1 + \sigma(x_i - x_1)$, $\sigma = 0.5$, for all $i > 1$.
\end{enumerate}
No gradient information is required. Settings: initial simplex step $= 0.35$, 160 iterations.

\subsection{Problem Setup}

Minimise Benchmark B (Equation~\eqref{eq:benchmark_B}) subject to the half-space constraint $x_1 \geq 0.5$, starting from the infeasible point $x_0 = (0.2, 4.0)$.

The constrained optimum is at $x^\star_c = (0.582, 2.0)$ with $f(x^\star_c) \approx 0.7244$, which happens to coincide with the unconstrained optimum since $x^\star_{unc} = (0.582, 2.0)$ satisfies $x_1^\star > 0.5$ --- the constraint is \emph{inactive} at the true minimum. The difficulty here lies in the infeasible starting point and the convergence path through the infeasible region.

\begin{algorithm}[H]
\caption{Projected Gradient Descent (PGD)}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, projection $\Pi_{\mathcal{X}}$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Unconstrained gradient step}
    \State $x_{k+1} \gets \Pi_{\mathcal{X}}(z_{k+1})$ \Comment{Project back: $(x_1, x_2) \mapsto (\max(0.5, x_1), x_2)$}
\EndFor
\end{algorithmic}
\end{algorithm}

For the half-space $\mathcal{X} = \{x : x_1 \geq 0.5\}$, the projection is $\Pi_{\mathcal{X}}(z)_1 = \max(0.5, z_1)$, $\Pi_{\mathcal{X}}(z)_2 = z_2$ --- a simple clipping operation.

\begin{algorithm}[H]
\caption{Penalty Method}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, penalty weight $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $F_{\lambda}(x) \gets f(x) + \lambda \max(0,\, 0.5 - x_1)$ \Comment{Penalised objective}
    \State $\nabla F_\lambda(x) \gets \nabla f(x) + \lambda \cdot (-e_1) \cdot \mathbf{1}[x_1 < 0.5]$ \Comment{Subgradient of penalty}
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_{\lambda}(x_k)$
\EndFor
\end{algorithmic}
\end{algorithm}

\textbf{Settings:} PGD ($\alpha = 0.08$); penalty with $\lambda \in \{0.15, 1.8, 4.5\}$ (step sizes $\alpha = 0.05$ for $\lambda \leq 1.8$; $\alpha = 0.03$ for $\lambda = 4.5$); unconstrained GD ($\alpha = 0.07$). All run for 100 iterations.

\subsection{Comparative Discussion}

\textbf{Projected Gradient Descent} enforces feasibility as a hard constraint at every iteration via the projection step. The fundamental advantage is \emph{guaranteed feasibility}: $x_k \in \mathcal{X}$ for all $k \geq 1$, even from an infeasible starting point. For the half-space $x_1 \geq 0.5$, projection reduces to a $\max$ operation with cost $O(1)$. For complex convex sets (e.g.\ the spectral norm ball, the Birkhoff polytope), projection can be expensive or require iterative procedures.

\textbf{Penalty methods} are simpler to implement (no projection oracle needed) but enforce feasibility only approximately. The penalised objective is $F_\lambda(x) = f(x) + \lambda c(x)$ where $c(x) = \max(0, 0.5 - x_1)$. As $\lambda \to \infty$, the minimiser of $F_\lambda$ converges to the constrained minimiser of $f$, but the Lipschitz constant of $\nabla F_\lambda$ grows with $\lambda$, requiring smaller step sizes for stability (here, $\alpha = 0.03$ for $\lambda = 4.5$ vs.\ $\alpha = 0.05$ for $\lambda = 1.8$).

\textbf{Augmented Lagrangian} (not implemented here) improves upon the basic penalty method by adding a dual variable $\mu$ updated via $\mu_{k+1} = \mu_k + \lambda c(x_k)$, enabling convergence to exact feasibility at finite $\lambda$ without the ill-conditioning of large penalty coefficients.

\textbf{KKT conditions:} At the constrained minimum $x^\star_c$, the KKT conditions require $\nabla f(x^\star_c) + \mu^\star \nabla c(x^\star_c) = 0$ with $\mu^\star \geq 0$ (dual variable) and $\mu^\star c(x^\star_c) = 0$ (complementary slackness). Since the constraint is inactive ($x_1^\star = 0.582 > 0.5$), complementary slackness gives $\mu^\star = 0$, and the unconstrained stationarity condition $\nabla f(x^\star_c) = 0$ holds.

\subsection{Feasible Set and Linear Programme}

The feasible set is the axis-aligned box: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\ -5 \leq x_2 \leq 10\}$.

\textbf{Linear Programme:} Minimise $f(x) = a^Tx = x_1 + 2x_2$ (with $a = [1, 2]^T$) over $\mathcal{X}$.

Since both components of $a$ are positive, the gradient $\nabla f = a$ points in the direction of increasing $f$, so the minimum is at the lower bounds in each coordinate:
\begin{equation}
  x^{\star} = \begin{pmatrix} 0.5 \\ -5 \end{pmatrix}, \qquad f^{\star} = 0.5 + 2(-5) = -9.5.
\end{equation}
This illustrates the \textbf{fundamental theorem of linear programming}: the minimum of a linear objective over a bounded polytope is attained at a vertex. For the box $\mathcal{X}$ with $2^2 = 4$ vertices, the LP solution is found by inspection in $O(d)$ time.

\subsection{Frank--Wolfe Algorithm}

\begin{algorithm}[H]
\caption{Frank--Wolfe (Conditional Gradient)}
\label{alg:fw}
\begin{algorithmic}[1]
\Require Initial point $x_0 \in \mathcal{X}$, mixing parameter $\beta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_k \gets \arg\min_{z \in \mathcal{X}}\, \nabla f(x_k)^T z$ \Comment{Linear minimisation oracle (LMO)}
    \State $x_{k+1} \gets \beta\, x_k + (1 - \beta)\, z_k$ \Comment{Convex combination, $x_{k+1} \in \mathcal{X}$}
\EndFor
\end{algorithmic}
\end{algorithm}

For box constraints, the LP subproblem decomposes per coordinate in $O(d)$:
\begin{equation}
  (z_k)_i = \begin{cases} l_i & \text{if } (\nabla f(x_k))_i > 0 \\ u_i & \text{if } (\nabla f(x_k))_i \leq 0 \end{cases}
\end{equation}
where $[l_i, u_i]$ are the box bounds. The FW iterate is always a convex combination of feasible points (since $x_0 \in \mathcal{X}$ and $z_k \in \mathcal{X}$), so \textbf{no projection is needed}: $x_{k+1} \in \mathcal{X}$ by construction.

\begin{theorem}[Frank--Wolfe convergence rate]
Let $f$ be convex and $L$-smooth over $\mathcal{X}$ with diameter $D = \max_{x,y \in \mathcal{X}}\|x-y\|$. Frank--Wolfe with step size $\gamma_k = 2/(k+2)$ satisfies:
\begin{equation}
  f(x_k) - f^\star \leq \frac{2LD^2}{k+2} = O(1/k).
\end{equation}
This $O(1/k)$ rate is \emph{slower} than projected GD's $O(\rho^k)$ linear rate, but requires only a linear minimisation oracle rather than a projection oracle.
\end{theorem}

\textbf{Note on the fixed-$\beta$ schedule:} This implementation uses a fixed $\beta$ (equivalently, a fixed step size $\gamma = 1 - \beta$ towards $z_k$) rather than the standard $\gamma_k = 2/(k+2)$ schedule. With fixed $\gamma$, the iterates satisfy $x_{k+1} = (1-\gamma)^{k+1}x_0 + \gamma\sum_{j=0}^{k}(1-\gamma)^{k-j}z_j$, a geometric moving average of the LP solutions. Figure~\ref{fig:q6_beta_comparison} shows that the choice of $\beta$ has a non-trivial effect: small $\beta$ (large step towards $z_k$) converges faster initially but oscillates more near the optimum, while large $\beta$ (small steps) converges more smoothly to a better final value.

\subsection{Interior vs.\ Boundary Behaviour}

\textbf{Interior optimum:} Frank--Wolfe exhibits the characteristic oscillatory ``zig-zag'' pattern. Each LMO selects a vertex of $\mathcal{X}$ determined by the gradient direction, which changes as $x_k$ moves. The convex combination gradually averages these LP solutions, but the oscillating $z_k$ introduces noise. The theoretical $O(1/k)$ rate (with decaying $\gamma_k$) is demonstrated qualitatively. Smaller $\beta$ (larger steps towards $z_k$) is faster initially but creates more oscillation near the optimum.

\textbf{Boundary optimum:} Frank--Wolfe is naturally suited to boundary optima because $z_k$ consistently selects the vertex closest to the constrained optimum, pulling the iterate towards the boundary. The method converges without explicit projection. However, the fixed $\beta$ schedule (as opposed to the optimal $\gamma_k = 2/(k+2)$) limits the asymptotic convergence rate: with $\gamma_k = 2/(k+2)$, the $O(1/k)$ rate would be achieved, and the boundary case could more efficiently approach $f^\star = 0.25$.

\textbf{FW vs.\ Projected GD:} The key advantage of FW is the \emph{linear oracle}: for complex sets (nuclear norm ball, flow polytope, spectrahedra), a linear minimisation is often tractable while projection is not. The disadvantage is slower convergence ($O(1/k)$ vs.\ $O(\rho^k)$). For the simple box constraint studied here, projected GD would converge significantly faster.

\subsection{Benchmark A (Linear Regression, $\kappa \approx 1$): Well-Conditioned Quadratic}

On this benchmark, the function is a globally convex quadratic with near-unit condition number. All methods (except mis-specified Polyak) converge to the noise floor $J^\star \approx 0.4826$ within 120--150 iterations. Newton converges in a single step (exact OLS solution). The irreducible floor prevents all first-order methods from reaching $J = 0$. Key lesson: for well-conditioned problems, all first-order methods are roughly equivalent; second-order methods offer no qualitative advantage beyond their one-step convergence guarantee.

\subsection{Benchmark B (Toy Neural Network, $\kappa \approx 3$--$10$): Moderate Anisotropy}

With moderate condition number, method differences begin to emerge. All momentum methods (Nesterov, Adam, Heavy Ball) outperform vanilla GD in iteration count. Newton converges in $\approx 5$ steps. The sinusoidal perturbation $\sin(x_1)$ makes this non-purely-quadratic but still highly smooth, so Newton's advantage is preserved. Key lesson: moderate anisotropy is easily handled by adaptive methods; Newton dominates when Hessian evaluation is affordable.

\textbf{Key observations:}
\begin{enumerate}[nosep]
\item \textbf{Polyak with correct $f^\star$} achieves the best first-order result, but requires oracle knowledge of $f^\star = 0$ which is only available for this benchmark by design.
\item \textbf{Nesterov acceleration} outperforms Adam on Rosenbrock: the $O(1/k^2)$ momentum schedule builds consistent acceleration along the valley, while Adam's coordinate-wise scaling is less effective for the highly correlated Hessian structure.
\item \textbf{Newton} achieves excellent results in only 20 iterations (vs.\ 80--150 for first-order methods), confirming its quadratic convergence advantage near the optimum.
\item \textbf{First-order methods} are severely limited by the $\kappa \approx 2000$ condition number: GD requires $\alpha < 2/\lambda_{\max} \approx 0.002$, resulting in extremely conservative steps.
\end{enumerate}

\subsection{Constrained Methods (Question 5)}

Projected GD is unequivocally superior when a cheap projection oracle exists: it guarantees feasibility from step 1 and converges at the same rate as unconstrained GD. The penalty method's main advantage is simplicity and compatibility with any unconstrained solver. In practice, augmented Lagrangian methods combine the best of both worlds and are preferred in modern constrained optimisation software.

\subsection{Frank--Wolfe (Question 6)}

Frank--Wolfe offers a principled approach to constrained optimisation for structured constraint sets. Its $O(1/k)$ convergence rate is weaker than projected GD's linear rate, but the linear oracle requirement is often computationally much cheaper. The algorithm is particularly valuable for atomic norms (nuclear norm, $\ell_1$ norm) where projection is expensive but LMO (a singular-value decomposition or sorting step) is tractable.

\begin{lstlisting}[caption={Gradient Descent and Polyak Step Size}]
def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        x = x - alpha * grad_fn(x)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)

def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)

def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float); G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x); G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)

def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float); v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)

def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float); z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x); z = beta * z + alpha * g; x = x - z
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)

def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float); z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z
        g = grad_fn(lookahead)
        z = beta_k * z - alpha * g; x = x + z
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)

def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t); v_hat = v_vec / (1 - beta2**t)
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))
        try: p = np.linalg.solve(H_reg, g)
        except np.linalg.LinAlgError: p = g
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)

def frank_wolfe(grad_fn, loss_fn, x0, bounds, beta, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, z_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z
        x_hist.append(x.copy()); f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
\end{lstlisting}
