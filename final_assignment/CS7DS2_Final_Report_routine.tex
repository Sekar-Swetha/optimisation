\begin{abstract}
This report presents a comprehensive comparative study of first-order, second-order, derivative-free, and constrained optimisation algorithms applied to three canonical benchmark problems: a linear regression quadratic loss (Benchmark A), a toy neural network loss with sinusoidal perturbation (Benchmark B), and the Rosenbrock function (Benchmark C). Six classes of methods are investigated: (1)~adaptive step-size methods including the Polyak rule, Adagrad, RMSprop, and the Heavy Ball method; (2)~momentum-based and stochastic methods encompassing Nesterov acceleration, Adam, and mini-batch SGD; (3)~Newton's method with local quadratic approximations; (4)~derivative-free approaches including finite-difference gradient descent, Nesterov random search, the Nelder--Mead simplex method, and grid search; (5)~constrained optimisation via projected gradient descent and penalty methods; and (6)~the Frank--Wolfe conditional gradient algorithm for linearly constrained problems. Each method is evaluated empirically across all applicable benchmarks and analysed in terms of convergence speed, trajectory behaviour, computational cost per iteration, and sensitivity to hyperparameters. Theoretical convergence guarantees are stated and connected to observed experimental behaviour. Key findings include: the critical dependence of the Polyak step on accurate knowledge of $f^\star$; the $O(1/k^2)$ advantage of Nesterov acceleration over $O(1/k)$ gradient descent for smooth convex functions; Newton's single-step convergence on quadratics and its dramatically superior performance on ill-conditioned problems; the dimension-independent oracle cost of randomised zeroth-order methods; and the projection-free nature of Frank--Wolfe making it suitable for structured constraint sets.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% ============================================================

Optimisation is the mathematical backbone of modern data analysis and machine learning. Every trained model --- from linear regression to deep neural networks --- is the solution to an optimisation problem of the form
\[
  x^\star \in \arg\min_{x \in \mathcal{X}}\; f(x),
\]
where $f : \mathbb{R}^d \to \mathbb{R}$ is the objective (loss) and $\mathcal{X} \subseteq \mathbb{R}^d$ is the feasible set ($\mathcal{X} = \mathbb{R}^d$ for unconstrained problems). The choice of algorithm, step size, and stopping criterion determines whether a model trains in seconds or hours, and whether it converges to a useful solution at all.

This report investigates the algorithmic landscape of first-order, second-order, derivative-free, and constrained optimisation methods, studying their behaviour on three benchmark functions that capture different structural properties: a well-conditioned convex quadratic, a mildly non-convex function with moderate anisotropy, and the Rosenbrock function with extreme ill-conditioning and a narrow curved valley.

The experiments are organised into six questions corresponding to distinct methodological families:
\begin{enumerate}[nosep]
  \item \textbf{Q1}: Adaptive step-size methods --- adapting the learning rate to the local geometry without requiring Hessian information.
  \item \textbf{Q2}: Momentum methods and stochastic gradient descent --- accelerating convergence using gradient history.
  \item \textbf{Q3}: Newton's method --- exploiting second-order curvature information for faster convergence.
  \item \textbf{Q4}: Derivative-free optimisation --- optimising without access to analytical or automatic gradients.
  \item \textbf{Q5}: Constrained optimisation --- handling feasibility constraints via projection and penalty approaches.
  \item \textbf{Q6}: Linear programmes and the Frank--Wolfe algorithm --- exploiting the structure of linearly constrained problems.
\end{enumerate}

All experiments use \texttt{numpy} with seed \texttt{42} for reproducibility, and figures are saved as vector-format PDF files in the \texttt{figures/} directory.

\subsection{Notation and Definitions}

Throughout this report we use the following notation.

\begin{definition}[$L$-smoothness]
A differentiable function $f$ is \emph{$L$-smooth} (has $L$-Lipschitz gradient) if
$\|\nabla f(x) - \nabla f(y)\| \leq L\|x - y\|$ for all $x, y$.
Equivalently, $f(y) \leq f(x) + \nabla f(x)^T(y-x) + \tfrac{L}{2}\|y-x\|^2$.
\end{definition}

\begin{definition}[$\mu$-strong convexity]
A differentiable function $f$ is \emph{$\mu$-strongly convex} if
$f(y) \geq f(x) + \nabla f(x)^T(y-x) + \tfrac{\mu}{2}\|y-x\|^2$ for all $x, y$.
\end{definition}

The \emph{condition number} $\kappa = L/\mu$ measures the difficulty of optimisation: large $\kappa$ implies slow gradient descent convergence.

\subsection{Benchmark A: Linear Regression Quadratic Loss}
A synthetic dataset with $m = 1000$ samples and two parameters is generated:
\begin{equation}
\theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \quad x^{(i)} \sim \mathcal{N}(0, I_2), \quad y^{(i)} = \theta^{\star T} x^{(i)} + \varepsilon^{(i)}, \quad \varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The loss function is the mean squared error:
\begin{equation}
J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left(\theta^T x^{(i)} - y^{(i)}\right)^2 = \frac{1}{2}\theta^T H \theta - b^T\theta + c,
\end{equation}
where $H = X^TX/m$, $b = X^Ty/m$, and $c = y^Ty/(2m)$. This is a strictly convex quadratic. The gradient is $\nabla J(\theta) = H\theta - b = X^T(X\theta - y)/m$ and the Hessian is $H$ (constant). Since $X \in \mathbb{R}^{1000 \times 2}$ with i.i.d.\ $\mathcal{N}(0,1)$ entries, by the law of large numbers $H \approx I_2$, giving smoothness constant $L \approx \lambda_{\max}(H) \approx 1$ and strong convexity $\mu \approx \lambda_{\min}(H) \approx 1$, so $\kappa \approx 1$. Due to observation noise, the minimum loss is $J^\star \approx 0.4826$ (not zero), achieved at the OLS estimator $\hat\theta = H^{-1}b$. Starting point: $\theta_0 = [0, 0]^T$.

\subsection{Benchmark B: Toy Neural Network Quadratic Loss}
\begin{equation}
f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
\end{equation}
The gradient is $\nabla f = [2(x_1 - 1) + \cos(x_1),\ 10(x_2 - 2)]^T$ and the Hessian is $H(x) = \mathrm{diag}(2 - \sin(x_1),\ 10)$. Because $\sin(x_1) \in [-1, 1]$, the curvature in $x_1$ is bounded in $[1, 3]$, giving $L = 10$ and local strong convexity $\mu \approx 1$ near the minimum, so $\kappa \approx 10$. The function is non-convex globally (the $\sin$ term creates multiple local minima for large $|x_1|$) but is locally strongly convex near its minimum.

The unconstrained minimum lies where $\partial f/\partial x_1 = 2(x_1 - 1) + \cos(x_1) = 0$ and $x_2 = 2$. Solving numerically (bisection on $h(x) = 2x-2+\cos x$) gives $x_1^\star \approx 0.582$, so $x^\star \approx (0.582,\, 2.0)$ with $f^\star = (0.582-1)^2 + \sin(0.582) \approx 0.1745 + 0.5490 \approx 0.7235$. Starting point: $x_0 = [-1, 4]^T$. The value $f \approx 0.7244$ consistently observed in experiments represents near-convergence within the iteration budget, not exact convergence to $f^\star$.

\subsection{Benchmark C: Rosenbrock Function}
\begin{equation}
f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
\end{equation}
The global minimum is at $(1, 1)$ with $f^\star = 0$. Note that while Rosenbrock is non-convex globally (e.g.\ $\nabla^2 f$ can be indefinite), from the starting point $(-1, 1)$ all gradient methods descend toward the same global minimum without getting trapped in local minima; this is because Rosenbrock has no spurious local minima --- the global minimum is the unique critical point. The Hessian at the optimum is
\[
H(1,1) = \begin{bmatrix} 802 & -400 \\ -400 & 200 \end{bmatrix},
\]
with eigenvalues $\lambda_1 \approx 1001.6$ and $\lambda_2 \approx 0.40$, giving condition number $\kappa \approx 2504$. This extreme ill-conditioning, combined with a narrow curved valley along $x_2 = x_1^2$, makes Rosenbrock one of the canonical hard test functions. Note that Rosenbrock is \emph{not} convex globally: $\nabla^2 f$ can be indefinite away from the optimum. Starting point: $x_0 = [-1, 1]^T$.

\begin{remark}[Rosenbrock valley geometry]
The Rosenbrock function's difficulty arises from its curved narrow valley. The level sets of $f(x_1, x_2) = 100(x_2 - x_1^2)^2 + (1-x_1)^2$ are elongated and curved, following the parabola $x_2 = x_1^2$. Along the valley floor (where $x_2 \approx x_1^2$), the second-order behaviour in the \emph{transverse} direction (perpendicular to the valley) has curvature $\approx 200$ (the $x_2$ curvature), while along the valley \emph{floor} the curvature is $\approx 2$ (from the $(1-x_1)^2$ term), giving the $500:1$ anisotropy. This means any descent method must take very small steps to avoid overshooting the valley walls, while simultaneously needing to traverse the long, gently sloping floor from $(-1, 1)$ to $(1, 1)$. The coupling between $x_1$ and $x_2$ through the term $100(x_2 - x_1^2)^2$ means per-coordinate step adaptation (Adam, Adagrad) is less effective than whole-vector momentum (Nesterov), since the gradient in $x_2$ depends on $x_1$ and vice versa --- the ``natural'' coordinate system is curvilinear (along/across the valley), not aligned with the standard axes.
\end{remark}

\section{Question 1: Adaptive Step-Size Methods \hfill [30 marks]}
\label{sec:q1}
% ============================================================

\subsection{Theoretical Background}

For gradient descent with constant step size $\alpha$, the convergence rate on an $L$-smooth $\mu$-strongly convex function is:
\begin{theorem}[GD convergence, strongly convex]\label{thm:gd}
If $f$ is $L$-smooth and $\mu$-strongly convex and $\alpha \in (0, 2/(L+\mu))$, then
\[
  f(x_k) - f^\star \;\leq\; \left(1 - \frac{2\alpha\mu L}{\mu + L}\right)^k (f(x_0) - f^\star).
\]
The optimal step $\alpha = 2/(\mu+L)$ achieves rate $\left(\frac{\kappa - 1}{\kappa + 1}\right)^2$ per iteration.
\end{theorem}

This theorem predicts slow convergence for large $\kappa$: on Rosenbrock ($\kappa \approx 2504$), GD makes progress proportional to $(1 - 2/2505)^k \approx e^{-k/1252}$, requiring thousands of iterations.

Adaptive step-size methods aim to overcome this by using gradient history to estimate the local curvature without explicitly computing the Hessian.

\begin{remark}[Step-size selection from the Lipschitz constant]
Theory requires $\alpha \leq 2/(\mu + L) \approx 1/L$ for guaranteed convergence. From our benchmark Lipschitz constants:
\begin{itemize}[nosep]
  \item Benchmark A ($L \approx 1$): $\alpha^{\max} \approx 1$. We use $\alpha = 0.08$, which is conservative but safe and allows comparison with other benchmarks.
  \item Benchmark B ($L = 10$): $\alpha^{\max} \approx 0.1$. We use $\alpha = 0.06$, within the stable range.
  \item Benchmark C ($L \approx 1001.6$ at the optimum): $\alpha^{\max} \approx 0.002$. We use $\alpha = 0.0012$, safely below the threshold. A larger step $\alpha = 0.003 > 2/L$ would cause divergence on GD.
\end{itemize}
The fact that Benchmark C requires steps $\approx 1000\times$ smaller than Benchmark A, despite all three functions having the same gradient descent update formula, is the key reason for the dramatically different number of effective steps in 120 iterations.
\end{remark}

\begin{theorem}[Polyak step convergence]\label{thm:polyak}
If $f$ is $L$-smooth and $\mu$-strongly convex with known $f^\star$, the Polyak step $\alpha_k = (f(x_k) - f^\star)/\|\nabla f(x_k)\|^2$ satisfies
\[
  f(x_k) - f^\star \;\leq\; \left(1 - \frac{\mu}{L}\right)^k (f(x_0) - f^\star).
\]
This matches the optimal fixed-step rate $(1-\mu/L)^k$, which equals the best possible rate for any first-order method with known $f^\star$ and $L$, $\mu$. However, if $f^\star$ is \emph{misspecified} as $\tilde f^\star \neq f^\star_{\mathrm{true}}$, convergence is not guaranteed and $\alpha_k \to \infty$ as $\|\nabla f(x_k)\| \to 0$ while $f(x_k) - \tilde f^\star \not\to 0$.
\end{theorem}

\begin{remark}[Practical Polyak variants]
In practice, $f^\star$ is often unknown. Several extensions address this: (1)~\emph{$\varepsilon$-estimate:} use a lower bound $\tilde{f}^\star \leq f^\star$ with a tolerance offset; (2)~\emph{interpolation condition:} when using SGD with Polyak step, batch stochasticity itself provides a natural correction; (3)~\emph{SPS (Stochastic Polyak Step):} in the interpolation regime (neural networks with sufficient capacity, where $f_i(x^\star) = 0$ for all training samples), each sample satisfies $f^\star_i = 0$ and the Polyak step can be applied per-sample. In our experiments, $f^\star = 0$ is correct for Benchmark C but wrong for A and B (where the observation noise creates a non-zero floor).
\end{remark}

\subsection{Algorithm Formulations}

Four adaptive methods are compared against a constant step-size gradient descent baseline across all three benchmarks for 120 iterations.

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, optimal value $f^{\star}$, tolerance $\varepsilon$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets \dfrac{f(x_k) - f^{\star}}{\|g_k\|^2 + \varepsilon}$ \Comment{Tolerance $\varepsilon$ prevents division by zero}
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
\caption{Adagrad}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Cumulative sum of squared gradients}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$ \Comment{Per-coordinate adaptive scaling}
\EndFor
\end{algorithmic}
\end{algorithm}

Adagrad scales each coordinate by the inverse square root of all past squared gradients. Coordinates with historically large gradients receive smaller effective step sizes, implementing automatic coordinate-wise learning rate decay. Formally, the effective step at iteration $k$ for coordinate $i$ is:
\begin{equation}
  (\alpha_k)_i = \frac{\alpha_0}{\sqrt{(G_k)_i} + \varepsilon}, \quad (G_k)_i = \sum_{j=0}^{k-1} (g_j)_i^2.
\end{equation}
This achieves online regret $O(\sqrt{T})$ for convex Lipschitz functions, which is optimal among online algorithms. Crucially, the implicit per-coordinate curvature adaptation mirrors diagonal preconditioning: if coordinate $i$ has consistently large gradients (high effective curvature), its step is suppressed, while sparse or infrequently updated coordinates receive larger steps. The key limitation is that $G_k$ grows monotonically without bound, so $(\alpha_k)_i \to 0$ for all $i$ as $k \to \infty$. This can cause premature stagnation on strongly convex problems where sustained gradient norms prevent adequate final convergence.

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponential moving average of squared gradients}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

RMSprop (Tieleman \& Hinton, 2012) addresses Adagrad's vanishing step problem by replacing the cumulative sum with an exponential moving average (EMA) with decay factor $\beta = 0.9$. The EMA gives weight $(1-\beta)\beta^j$ to the gradient from $j$ steps ago, exponentially forgetting stale information. This allows the effective step size to remain non-vanishing in stationary regimes.

\begin{algorithm}[H]
\caption{Polyak Momentum / Heavy Ball}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$ \Comment{Accumulate momentum}
    \State $x_{k+1} \gets x_k - z_{k+1}$ \Comment{Update with momentum}
\EndFor
\end{algorithmic}
\end{algorithm}

The Heavy Ball method adds a momentum term $z_k$ that accumulates a velocity vector from past gradient directions. Physically, the iterate behaves like a ball rolling under gradient force with friction coefficient $(1 - \beta)$. For quadratic objectives, the optimal $\beta = (\sqrt{\kappa}-1)^2/(\sqrt{\kappa}+1)^2$ achieves convergence rate $(\sqrt{\kappa}-1)/(\sqrt{\kappa}+1)$, much faster than GD's $({\kappa}-1)/({\kappa}+1)$ rate. Unlike Nesterov momentum, Heavy Ball does not use a lookahead gradient and has no proven acceleration guarantee for general convex functions.

\begin{remark}[Optimal Heavy Ball momentum and condition number]
For a quadratic $f(x) = \frac{1}{2}x^TH x - b^Tx$ with eigenvalues $\lambda_{\min} = \mu$ and $\lambda_{\max} = L$, the Heavy Ball method with step $\alpha = (2/(\sqrt{L}+\sqrt{\mu}))^2$ and momentum $\beta = \left(\frac{\sqrt{L}-\sqrt{\mu}}{\sqrt{L}+\sqrt{\mu}}\right)^2$ achieves the spectral rate:
\[
  \rho_{\mathrm{HB}}^\star = \left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^2 = \left(1 - \frac{2}{\sqrt{\kappa}+1}\right)^2 \approx 1 - \frac{4}{\sqrt{\kappa}}.
\]
Compare this to GD's optimal rate $\rho_{\mathrm{GD}} = (\kappa-1)/(\kappa+1) \approx 1 - 2/\kappa$. The Heavy Ball rate decays as $O(1/\sqrt{\kappa})$ rather than $O(1/\kappa)$ per iteration --- the same asymptotic improvement as Nesterov, but only guaranteed for quadratics.

For our benchmarks: $\kappa_A \approx 1$ (no gain from momentum), $\kappa_B \approx 10$ gives $\rho^\star_B \approx 0.52$ vs GD $\approx 0.82$ (big speedup), $\kappa_C \approx 2504$ gives $\rho^\star_C \approx 0.92$ vs GD $\approx 0.9996$ (massive speedup for quadratics; observed improvement in Table~\ref{tab:q1_final} confirms this trend even on the non-quadratic Rosenbrock).
\end{remark}

\textbf{Key finding:} The Polyak step size has a dramatic dependence on the accuracy of $f^{\star}$. Mathematically, when $\|\nabla f(x_k)\| \to 0$ but $f(x_k) \not\to f^{\star}_{\mathrm{true}}$ (because $f^\star$ is misspecified), the step grows without bound: $\alpha_k = (f(x_k) - \tilde{f}^\star)/\|\nabla f(x_k)\|^2 \to \infty$, causing divergence. When $f^\star$ is exact (Benchmark C), Polyak achieves faster convergence than any other method by automatically computing the theoretically optimal step $\alpha_k^\star = (f(x_k) - f^\star)/\|\nabla f(x_k)\|^2$.

On Rosenbrock (large $\kappa$), momentum accumulation along the curved valley helps, but Heavy Ball's non-lookahead gradient can cause instability on strongly non-quadratic objectives. This explains why Heavy Ball outperforms GD on Benchmark C but by less than Nesterov (Q2).

\item \textbf{Smoothness:} RMSprop produces the smoothest convergence curves due to exponential averaging. Heavy Ball shows characteristic overshoot followed by damped oscillation in the final convergence phase.

\item \textbf{Stability:} GD is most stable but slowest. Polyak is unstable when $f^{\star}$ is misspecified. Adagrad is uniformly stable (monotonically decreasing step size guarantees descent) but may stagnate prematurely. RMSprop can oscillate near the minimum due to a non-vanishing effective step.

\item \textbf{Practical recommendation:} Exact $f^{\star}$ is rarely known in practice, limiting Polyak's applicability. For data science applications where robustness is paramount, RMSprop or Adam (Q2) are preferred. When the problem structure suggests the optimal value is known (e.g.\ feasibility problems, or via duality), the Polyak step is theoretically optimal.
\end{itemize}

\subsection{Theoretical Background}

Gradient descent achieves at best an $O(1/k)$ convergence rate on smooth convex functions. Nesterov (1983) showed this rate is optimal among first-order methods for non-strongly-convex problems, but \emph{also} showed a simple modification achieves the improved rate $O(1/k^2)$:

\begin{theorem}[Nesterov acceleration]\label{thm:nesterov}
For an $L$-smooth convex function $f$, Nesterov's accelerated gradient method with step $\alpha = 1/L$ satisfies
\[
  f(x_k) - f^\star \;\leq\; \frac{2L\|x_0 - x^\star\|^2}{(k+1)^2} \;=\; O(1/k^2).
\]
This $O(1/k^2)$ rate is optimal for first-order methods on smooth convex functions.
\end{theorem}

For a strongly convex function with condition number $\kappa$, momentum methods can achieve a linear rate with factor $r_{\mathrm{Nesterov}} = (\sqrt{\kappa}-1)/(\sqrt{\kappa}+1)$ per iteration, compared to $r_{\mathrm{GD}} = (\kappa-1)/(\kappa+1)$ for gradient descent. For large $\kappa$:
\begin{equation}
  r_{\mathrm{Nesterov}} = \frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1} \approx 1 - \frac{2}{\sqrt{\kappa}}, \qquad r_{\mathrm{GD}} \approx 1 - \frac{2}{\kappa}.
\end{equation}
The number of iterations to reduce the error by factor $\epsilon^{-1}$ is $O(\sqrt{\kappa}\log(1/\epsilon))$ for Nesterov vs $O(\kappa\log(1/\epsilon))$ for GD. For $\kappa = 2504$, Nesterov requires $\sqrt{2504} \approx 50\times$ fewer iterations than GD for the same accuracy (see Fig.~\ref{fig:theory_rates} in Section~\ref{sec:conclusion} for a visualisation). In practice on Benchmark C (150 iterations), Nesterov reaches $f = 0.479$ vs GD's $f = 3.388$, consistent with meaningful acceleration despite the non-convex Rosenbrock landscape.

\subsection{Algorithm Formulations}

\begin{algorithm}[H]
\caption{Nesterov Momentum / Acceleration}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\frac{k-1}{k+2},\ \beta_{\max}\right)$ \Comment{Adaptive momentum increasing towards $\beta_{\max}$}
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead point}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$ \Comment{Gradient at lookahead}
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

The critical distinction from Heavy Ball is the \emph{lookahead}: the gradient is evaluated at $\tilde{x}_k = x_k + \beta_k z_k$ rather than $x_k$. This ``corrects'' the trajectory before overshooting. The adaptive schedule $\beta_k = (k-1)/(k+2) \to 1$ increases momentum gradually from 0, matching the theoretical requirement for the $O(1/k^2)$ rate. The cap $\beta_{\max}$ prevents instability when the schedule exceeds the stability bound.

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha$, moments $\beta_1, \beta_2$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\ v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{First moment (gradient EMA)}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{Second moment (squared gradient EMA)}
    \State $\hat{m}_t \gets m_t\, /\, (1 - \beta_1^t)$ \Comment{Bias-corrected first moment}
    \State $\hat{v}_t \gets v_t\, /\, (1 - \beta_2^t)$ \Comment{Bias-corrected second moment}
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t\, /\, (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

Adam (Kingma \& Ba, 2015) unifies two ideas: (1)~RMSprop's per-coordinate adaptive scaling via EMA of $g^2$, and (2)~Polyak-style gradient momentum via EMA of $g$. The unified update performs an approximately normalised gradient step:
\begin{equation}
  x_{t+1} \approx x_t - \alpha \cdot \frac{\mathbb{E}[g_t]}{\sqrt{\mathbb{E}[g_t^2]} + \varepsilon},
\end{equation}
with the ratio bounded in magnitude by 1, so the effective step per coordinate is always at most $\alpha$.

The bias-correction terms $(1-\beta_1^t)^{-1}$ and $(1-\beta_2^t)^{-1}$ are critical at early iterations. At $t=1$ with $\beta_2 = 0.999$, the uncorrected $v_1 = (1-0.999)g_1^2 = 0.001g_1^2$ underestimates the true squared gradient by $1000\times$, giving an effective step $\sqrt{1000}\approx 32\times$ too large without correction. As $t \to \infty$, both corrections approach 1 and Adam reduces to RMSprop with gradient momentum. The convention $\beta_1 < \beta_2$ (here 0.80 vs 0.999) ensures the gradient EMA adapts faster than the variance EMA, giving responsive gradient direction with stable curvature estimates.

\begin{remark}[Adam's convergence and AMSGrad]
Reddi et al.\ (2018) showed that Adam can \emph{fail to converge} on simple convex online problems, because the exponential moving average of $g_t^2$ can decrease (if gradients alternate between large and small), causing the effective step $\alpha/\sqrt{\hat{v}_t}$ to \emph{increase} over time in some coordinate --- violating the descent property. This non-monotone step behaviour can prevent convergence to the optimum on non-smooth convex problems. The fix, \emph{AMSGrad}, replaces $\hat{v}_t$ with a monotone maximum: $\hat{v}_t^{\max} = \max(\hat{v}_{t-1}^{\max}, \hat{v}_t)$, ensuring the effective step never increases. In practice on smooth strongly convex problems (as in our experiments), Adam does converge; the non-convergence is a pathological case involving oscillating stochastic gradients. Nevertheless, in training large language models, careful Adam hyperparameter tuning (especially $\epsilon$ to prevent division by near-zero values) remains critical.
\end{remark}

\subsection{Mini-Batch Stochastic Gradient Descent}

Mini-batch SGD on Benchmark A uses learning rate $\alpha = 0.06$, batch sizes $b \in \{5, 40\}$, 50 epochs, with data shuffled uniformly at each epoch.

\begin{algorithm}[H]
\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]
\Require Data $(X, y)$, initial $\theta_0$, learning rate $\alpha$, batch size $b$, epochs $E$
\For{$e = 1, 2, \ldots, E$}
    \State Randomly permute data indices $\sigma$
    \For{$i = 0, b, 2b, \ldots$} \Comment{Mini-batch loop over permuted data}
        \State $\mathcal{B} \gets \{\sigma(i), \ldots, \sigma(i+b-1)\}$
        \State $g \gets \frac{1}{b} X_{\mathcal{B}}^T(X_{\mathcal{B}}\theta - y_{\mathcal{B}})$ \Comment{Stochastic gradient estimate}
        \State $\theta \gets \theta - \alpha\, g$
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

The mini-batch gradient is an unbiased estimate of the full gradient: $\mathbb{E}[g_{\mathcal{B}}] = \nabla J(\theta)$. Its variance is $\mathbb{V}[g_{\mathcal{B}}] = \sigma^2_g / b$, where $\sigma^2_g$ is the per-sample gradient variance. A smaller batch $b$ gives more updates per epoch (each update costs less) but higher gradient variance; a larger $b$ provides lower-variance estimates at the cost of fewer updates per epoch.

\begin{proposition}[SGD convergence to neighbourhood]\label{prop:sgd}
For an $L$-smooth strongly convex objective with batch size $b$ and step size $\alpha \leq 1/L$, SGD satisfies
\[
  \mathbb{E}[f(\theta_k) - f^\star] \;\leq\; (1 - \alpha\mu)^k (f(\theta_0) - f^\star) + \frac{\alpha L \sigma^2_g}{2\mu b},
\]
where $\sigma^2_g$ is the per-sample gradient variance. The iterates converge linearly to a neighbourhood of size $O(\alpha \sigma^2_g / b)$ around $f^\star$. Larger batch $b$ shrinks this neighbourhood; smaller step $\alpha$ also shrinks it but slows convergence.
\end{proposition}

This explains the noise-floor phenomenon observed in Fig.~\ref{fig:q2_sgd_noisy}: increasing $\sigma$ raises $\sigma^2_g \propto \sigma^2$, directly expanding the irreducible noise floor that SGD converges to.

\begin{remark}[Epoch complexity and learning rate decay]
Define an \emph{epoch} as one pass through all $m$ data points; each epoch contains $m/b$ gradient updates. The total gradient evaluations to reach accuracy $\epsilon$ is:
\begin{itemize}[nosep]
  \item \textbf{Full GD}: each epoch = 1 update; need $O(\kappa \log(1/\epsilon))$ updates = $O(\kappa \log(1/\epsilon))$ epochs.
  \item \textbf{Mini-batch SGD with fixed $\alpha$}: converges to a noise floor $C(\alpha, b) = \alpha L \sigma^2_g / (2\mu b)$. Reaching accuracy $\epsilon > C$ requires $O(\kappa \log(1/(\epsilon - C)))$ updates. If $\epsilon < C$, fixed-step SGD cannot achieve this accuracy.
  \item \textbf{Mini-batch SGD with decaying $\alpha_k = \alpha_0/k$}: achieves $O(1/k)$ convergence at the cost of slower later iterations. The optimal rate requires $\alpha_k = 1/(\mu k)$.
\end{itemize}
The fundamental insight is that SGD with fixed step size trades convergence precision for reduced per-iteration cost. For Benchmark A with $m = 1000$ data points: full GD costs $1000$ function evaluations per step; mini-batch SGD with $b = 5$ costs $5$ evaluations per step, running $m/b = 200$ steps per epoch. When the model capacity matches the data noise (as here), both converge to the same floor $J^\star \approx 0.4826$, and the mini-batch approach processes $200\times$ more gradient steps per data pass.
\end{remark}

\centering
\includegraphics[width=0.85\textwidth]{figures/q2_sgd_batch.pdf}
\caption{Q2: Mini-batch SGD with different batch sizes on Benchmark A. With $b = 5$, each epoch performs $m/b = 200$ updates; with $b = 40$, only 25 updates per epoch. Per Proposition~\ref{prop:sgd}, both methods converge to a neighbourhood of size $O(\alpha\sigma^2_g/b)$ around $J^\star$. Since the observation noise dominates the mini-batch noise for this problem (the per-sample residual variance $\approx 1$, independent of $b$), both batch sizes converge to approximately the same floor $J^\star \approx 0.4826$ --- the irreducible loss due to observation noise. \label{fig:q2_sgd_batch}
\end{figure}

\begin{remark}[Variance reduction: SVRG and SAGA]
Proposition~\ref{prop:sgd} reveals a fundamental limitation of fixed-step SGD: it converges only to a neighbourhood of radius $O(\alpha\sigma^2_g/b)$ around $f^\star$, not to $f^\star$ itself. \emph{Variance reduction methods} eliminate this noise floor while maintaining cheap per-iteration cost:
\begin{itemize}[nosep]
  \item \textbf{SVRG} (Johnson \& Zhang, 2013): Periodically computes the full gradient $\tilde{g} = \nabla f(x_s)$ at a snapshot $x_s$. The update is $\hat{g}_k = \nabla f_i(x_k) - \nabla f_i(x_s) + \tilde{g}$, which is unbiased with variance $O(\|x_k - x_s\|^2) \to 0$ as $x_k \to x^\star$. SVRG achieves \emph{linear convergence} to $f^\star$ (not just a neighbourhood) at an epoch cost of $O((m + \kappa)\log(1/\epsilon))$ gradient evaluations.
  \item \textbf{SAGA} (Defazio et al., 2014): Maintains a table of the $m$ most recent per-sample gradients. The variance of the SAGA estimator goes to zero as the iterate converges. SAGA has the same asymptotic rate as SVRG but is better suited for streaming settings (no snapshot epoch required).
\end{itemize}
For Benchmark A with $m=1000$, $\kappa \approx 1$: SVRG needs $O((1000+1)\log(1/\epsilon)) \approx 1000\log(1/\epsilon)$ per-sample gradient evaluations, comparable to full-batch GD ($1000$ evaluations per step $\times$ $\log(1/\epsilon)$ steps). Variance reduction becomes most beneficial for large $m$ with moderate $\kappa$: SVRG's $O(m + \kappa)$ vs SGD's $O(m\kappa)$ epoch cost gives a $\kappa$-factor speedup.
\end{remark}

\section{Question 3: Newton's Method and Local Approximation \hfill [30 marks]}
\label{sec:q3}
% ============================================================

\subsection{Theoretical Background}

Newton's method minimises the local second-order Taylor model of $f$ at each iteration:
\begin{equation}
  m_k(d) = f(x_k) + \nabla f(x_k)^T d + \tfrac{1}{2} d^T \nabla^2 f(x_k)\, d.
\end{equation}
The minimiser of $m_k$ over $d$ is the Newton direction $p_k = -[\nabla^2 f(x_k)]^{-1} \nabla f(x_k)$, and the update is $x_{k+1} = x_k + \alpha p_k$.

\begin{theorem}[Newton's method, quadratic convergence]\label{thm:newton}
If $f$ is twice continuously differentiable and the Hessian $\nabla^2 f$ is $M$-Lipschitz near $x^\star$, then with full step $\alpha = 1$, Newton's method satisfies
\[
  \|x_{k+1} - x^\star\| \;\leq\; \frac{M}{2\mu} \|x_k - x^\star\|^2,
\]
for $x_k$ sufficiently close to $x^\star$ (specifically within the \emph{region of quadratic convergence} $\|x_k - x^\star\| < 2\mu/M$). This \emph{quadratic convergence} means the number of correct digits doubles at each iteration, compared to linear convergence for gradient descent.
\end{theorem}

\begin{remark}[Global vs local convergence]
Theorem~\ref{thm:newton} is a \emph{local} result. When $x_0$ is far from $x^\star$ (e.g.\ on Rosenbrock starting from $(-1, 1)$, far from $(1,1)$), the Hessian may be indefinite or poorly conditioned, and full Newton steps ($\alpha = 1$) can diverge. This motivates \emph{damped} Newton with $\alpha < 1$: the damping sacrifices the quadratic convergence rate near the optimum but guarantees global descent. For the Rosenbrock function, the Hessian $\nabla^2 f$ at $(-1, 1)$ has $h_{11} = 2 + 1200(-1)^2 - 400(1) = 802$, $h_{12} = 400$, giving an eigenvalue $\approx 1202$, so the Newton step is well-defined but large; hence $\alpha = 0.22$ is required for stability.
\end{remark}

\begin{remark}[One-step convergence for quadratics]
For a quadratic objective $f(\theta) = \frac{1}{2}\theta^T H \theta - b^T\theta$, the Newton step with $\alpha = 1$ satisfies
\[
  \theta_1 = \theta_0 - H^{-1}(H\theta_0 - b) = H^{-1}b = \theta^\star
\]
regardless of $\theta_0$. Newton's method finds the exact minimiser in a \emph{single iteration} for any quadratic function. This is why Benchmark A (linear regression) is solved exactly in one step.
\end{remark}

\begin{remark}[Affine invariance]
Newton's method is \emph{affine invariant}: the sequence of iterates is unchanged under affine reparametrisations of the problem. This means Newton is unaffected by the condition number $\kappa$ in the neighbourhood of the optimum, unlike gradient descent whose convergence rate degrades as $\kappa \to \infty$.
\end{remark}

\subsection{Local Approximations of $g(x) = x^4$}

At $x_0 = 0.25$, $g(x_0) = 0.0039$, $g'(x_0) = 4 \times 0.25^3 = 0.0625$, $g''(x_0) = 12 \times 0.25^2 = 0.75$.

\textbf{First-order (linear) approximation:}
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0) = 0.0039 + 0.0625(x - 0.25).
\end{equation}
This captures only the local slope; it diverges rapidly from $g(x)$ away from $x_0$ and has no minimum (being linear).

\textbf{Second-order (quadratic) approximation:}
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0) + \tfrac{1}{2}g''(x_0)(x - x_0)^2 = 0.0039 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{equation}
The Newton update minimises this parabola, yielding:
\begin{equation}
x_{\mathrm{Newton}} = x_0 - \frac{g'(x_0)}{g''(x_0)} = 0.25 - \frac{0.0625}{0.75} = 0.25 - 0.0833 = 0.1667.
\end{equation}
This is a large step toward the true minimum at $x^\star = 0$, much larger than a gradient step $x_0 - \alpha g'(x_0)$ for typical $\alpha$.

\subsection{Newton's Method Algorithm}

\begin{algorithm}[H]
\caption{Damped Newton's Method}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Tikhonov regularisation ensures positive definiteness}
    \State $p_k \gets H_k^{-1}\, g_k$ \Comment{Solve $H_k p_k = g_k$ via \texttt{numpy.linalg.solve}}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$ \Comment{Damped step $\alpha < 1$ for non-quadratic objectives}
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Newton Decrement and Progress Certificate}

\begin{remark}[Newton decrement as a stopping criterion]
The \emph{Newton decrement} $\lambda(x_k) = \sqrt{\nabla f(x_k)^T [\nabla^2 f(x_k)]^{-1} \nabla f(x_k)}$ measures the magnitude of the Newton step and provides a tight bound on the suboptimality:
\[
  f(x_k) - f^\star \leq \tfrac{1}{2}\lambda(x_k)^2.
\]
This gives a primal certificate without knowing $f^\star$: halt when $\lambda(x_k)^2/2 \leq \epsilon$. Unlike gradient norm $\|\nabla f(x_k)\|$, the Newton decrement is \emph{affine invariant} (unchanged under coordinate reparametrisations) and accounts for the local curvature. For Benchmark A (quadratic), $\lambda(x_0)^2/2 = f(x_0) - f^\star$ exactly, so one step reduces $\lambda$ to zero. For Benchmark C, even with $\alpha = 0.22$, the decrement decreases rapidly in early iterations as the Hessian guides large curvature-corrected steps.
\end{remark}

\subsection{Computational Cost Comparison}

Newton's method has a higher per-iteration cost than gradient descent:
\begin{itemize}[nosep]
\item \textbf{GD}: $O(d)$ for gradient computation, $O(d)$ for the update step.
\item \textbf{Newton}: $O(d^2)$ for Hessian storage, $O(d^2)$ for Hessian computation, $O(d^3)$ for solving $H_k p_k = g_k$ via Gaussian elimination (or $O(d^2)$ for triangular systems after Cholesky factorisation).
\end{itemize}
For $d = 2$ these differences are negligible, and Newton's 1 iteration versus GD's 80 gives an $80\times$ reduction in total work. For large-scale problems ($d \sim 10^6$--$10^9$ in deep learning), exact Newton is impractical due to $O(d^2)$ storage and $O(d^3)$ solve cost. Practical alternatives include:
\begin{itemize}[nosep]
\item \textbf{L-BFGS}: Approximates $H_k^{-1}$ using the last $m$ gradient differences, with $O(md)$ storage and $O(md)$ solve cost per step.
\item \textbf{Gauss-Newton}: Approximates the Hessian of a least-squares objective as $J^TJ$ (where $J$ is the Jacobian), avoiding second-order derivatives entirely.
\item \textbf{Hessian-free Newton (truncated CG)}: Solves the Newton system inexactly using conjugate gradient, requiring only Hessian-vector products (computable in $O(d)$ via automatic differentiation) rather than the full Hessian.
\end{itemize}

\begin{remark}[Iteration complexity: Newton vs first-order methods]
For a $\mu$-strongly convex $L$-smooth function with $M$-Lipschitz Hessian, reaching $\epsilon$-accuracy ($f(x_k) - f^\star \leq \epsilon$) requires:
\begin{itemize}[nosep]
  \item \textbf{GD}: $O(\kappa \log(1/\epsilon))$ iterations, each costing $O(d)$ $\Rightarrow$ total $O(\kappa d \log(1/\epsilon))$.
  \item \textbf{Newton} (local phase): $O(\log\log(1/\epsilon))$ iterations (double-exponential convergence), each costing $O(d^3)$ $\Rightarrow$ total $O(d^3 \log\log(1/\epsilon))$.
  \item \textbf{Newton} (global phase from damped Newton): $O(\kappa \cdot f_0/\mu)$ damped steps to enter the local convergence region, each $O(d^3)$.
\end{itemize}
For $d = 2$ and $\kappa = 2504$: GD needs $2504\log(1/\epsilon)$ iterations vs Newton's effectively $O(1)$ once in the local region (e.g., 5 iterations for $\epsilon = 10^{-6}$ vs GD's $\approx 35{,}000$). This shows why Newton is dramatically faster for small-to-medium $d$ but the advantage reverses for large $d$ where $O(d^3)$ per step dominates.
\end{remark}

\subsection{Part A: Finite Difference and Nesterov Random Search (Benchmark B)}

\subsubsection{Finite Difference Gradient Approximation}

When analytical gradients are unavailable (e.g.\ for black-box simulators or non-differentiable models), the gradient can be approximated via finite differences:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta} = \frac{\partial f}{\partial x_i}(x) + O(\delta) + O\!\left(\frac{\varepsilon_{\mathrm{mach}}}{\delta}\right).
\label{eq:fd}
\end{equation}

\begin{proposition}[FD error bound]\label{prop:fd}
The forward finite-difference approximation has total error
\[
  \left|\frac{f(x + \delta e_i) - f(x)}{\delta} - \frac{\partial f}{\partial x_i}(x)\right| \;\leq\; \frac{M\delta}{2} + \frac{2\varepsilon_{\mathrm{mach}}}{\delta},
\]
where $M$ bounds the second derivative and $\varepsilon_{\mathrm{mach}} \approx 10^{-16}$ is machine epsilon. The total error is minimised at $\delta^\star = \sqrt{4\varepsilon_{\mathrm{mach}}/M} \approx \sqrt{4 \times 10^{-16}/M}$. For $M \approx 1$, this gives $\delta^\star \approx 2 \times 10^{-8}$.
\end{proposition}

The experiment tests $\delta = 0.05$ (close to good: $2\times$ the optimal for typical curvature) and $\delta = 0.8$ (poor: truncation error $O(0.8) \approx 0.4$ is comparable to the gradient itself). Forward FD requires $d+1 = 3$ function evaluations per gradient estimate for $d=2$.

\begin{remark}[Centered finite differences: second-order accuracy]
The \emph{centered} finite difference approximation
\[
  \frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x - \delta e_i)}{2\delta}
\]
achieves $O(\delta^2)$ truncation error (compared to $O(\delta)$ for forward FD), by cancelling the first-order Taylor error. The total error bound becomes:
\[
  \text{error} \leq \frac{M_3 \delta^2}{6} + \frac{2\varepsilon_{\mathrm{mach}}}{\delta},
\]
where $M_3$ bounds the third derivative. The optimal $\delta^\star = (3\varepsilon_{\mathrm{mach}}/M_3)^{1/3} \approx 10^{-5}$ achieves a minimum error $\approx 10^{-11}$, four orders of magnitude smaller than forward FD's $\approx 10^{-8}$. The cost is $2d = 4$ evaluations per gradient (vs $d+1 = 3$ for forward FD). For our experiments, $\delta = 0.05$ with forward FD gives truncation error $\approx 10\times0.05/2 = 0.25$ per coordinate; centered FD would give $\approx 10\times0.05^2/6 \approx 0.004$ --- an $\approx 60\times$ improvement at only $33\%$ more function evaluations. In practice, whenever function evaluations are cheap, centered differences should be preferred.
\end{remark}

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search (Zeroth-Order)}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Sample $u_k \sim \mathcal{N}(0, I)$, normalise: $\hat{u}_k \gets u_k / \|u_k\|$ \Comment{Uniform direction on unit sphere}
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta \hat{u}_k) - f(x_k)}{\delta}\, \hat{u}_k$ \Comment{Directional derivative estimate}
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

This zeroth-order method estimates only a single directional derivative $\nabla f(x_k)^T \hat{u}_k$, requiring only \textbf{2 function evaluations per iteration}, regardless of dimension $d$. This makes it \emph{dimension-independent} in oracle cost per step --- a key advantage for high-dimensional problems. The estimate is an unbiased estimator of the gradient scaled by the projection variance: $\mathbb{E}[\hat{g}_k] = \frac{1}{d}\nabla f(x_k)$ (up to normalisation), so convergence is slower by a factor of $d$ relative to exact gradient methods.

\begin{remark}[Dimension dependence of zeroth-order methods]
For an $L$-smooth convex function in $\mathbb{R}^d$, Nesterov \& Spokoiny (2017) proved that the randomised gradient estimator $\hat{g}_k = \frac{d}{2\delta}[f(x+\delta u)-f(x-\delta u)]u$ (two-point, dimension-scaled) satisfies:
\[
  \mathbb{E}[\hat{g}_k] = \nabla f_\delta(x), \qquad \mathbb{E}\|\hat{g}_k - \nabla f(x)\|^2 \leq d\,\frac{L^2\delta^2}{4} + \frac{4d^2\varepsilon_{\mathrm{mach}}^2}{\delta^2},
\]
where $f_\delta(x) = \mathbb{E}_{u}[f(x+\delta u)]$ is a smoothed surrogate. To achieve $\epsilon$-accuracy requires $O(d/\epsilon)$ iterations (vs $O(1/\epsilon)$ for exact gradient methods). The \emph{oracle complexity} --- total function evaluations --- is $O(d/\epsilon)$ for zeroth-order vs $O(1/\epsilon)$ for first-order: an additional factor of $d$. For our $d=2$ problem this overhead is minimal, but for $d=10^6$ (modern neural networks), the gap makes zeroth-order methods impractical for general optimisation.
\end{remark}

\subsection{Discussion: When to Use Derivative-Free Methods}

Derivative-free optimisation is necessary when: (1) the objective is computed by a simulation, solver, or physical experiment with no differentiable model; (2) the function is non-differentiable; or (3) automatic differentiation infrastructure is unavailable. The key trade-off versus gradient-based methods is oracle efficiency: with exact gradients, each evaluation provides $O(d)$ bits of information about the objective; with function-only oracles, each evaluation provides $O(1)$ bits. This fundamental information gap is why derivative-free methods require many more iterations for the same accuracy, particularly in high dimensions. In practice, for $d \leq 5$--10, Nelder--Mead or pattern search are effective; for higher dimensions, randomised methods or evolutionary strategies are preferred.

\section{Question 5: Constrained Optimisation \hfill [30 marks]}
\label{sec:q5}

\subsection{Problem Formulation}

Minimise Benchmark B subject to $x_1 \geq 0.5$:
\begin{equation}
\min_{x \in \mathbb{R}^2}\; f(x_1, x_2) = (x_1-1)^2 + 5(x_2-2)^2 + \sin(x_1), \quad \text{subject to}\quad x_1 \geq 0.5.
\end{equation}
Starting point: $x_0 = (0.2, 4.0)$ (infeasible, since $0.2 < 0.5$). The feasible set is $\mathcal{C} = \{x : x_1 \geq 0.5\}$ (a half-space).

\subsubsection{KKT Conditions}

The KKT conditions for this inequality-constrained problem are: there exists $\mu \geq 0$ such that
\begin{align}
  \nabla f(x^\star) + \mu \nabla g(x^\star) &= 0, \quad g(x) := 0.5 - x_1 \leq 0 \\
  \mu g(x^\star) &= 0 \quad \text{(complementary slackness)}
\end{align}
Since $\nabla g = (-1, 0)^T$, the stationarity condition gives $[2(x_1^\star - 1) + \cos(x_1^\star) - \mu,\; 10(x_2^\star - 2)] = 0$.

The unconstrained minimum at $x_1^\star \approx 0.582 > 0.5$ is \emph{feasible}. Therefore the constraint is \emph{inactive} ($g(x^\star) < 0$), complementary slackness forces $\mu = 0$, and the KKT conditions reduce to $\nabla f(x^\star) = 0$. The constrained and unconstrained minima \emph{coincide}. Algorithms that enforce feasibility throughout converge to this same point; those that tolerate infeasibility (penalty methods) must be driven there by a sufficiently strong penalty.

\begin{remark}[Slater's condition and KKT necessity]
The KKT conditions are necessary for optimality under a \emph{constraint qualification} (CQ). The most commonly used CQ for inequality constraints is \emph{Slater's condition}: there exists a strictly feasible point $\bar{x}$ with $g(\bar{x}) < 0$ (i.e.\ $\bar{x}_1 > 0.5$). For our problem, any $x$ with $x_1 > 0.5$ satisfies Slater's condition, so the KKT conditions are both necessary and sufficient (since $f$ is locally convex near $x^\star$) for the constrained minimum. This guarantees that our KKT analysis correctly identifies $x^\star$. Without a CQ (e.g.\ for problems where all feasible points lie on the active constraint boundary), the KKT multipliers may not exist even at the minimum, making the KKT system uninformative. For linear constraints (as in Frank--Wolfe's box constraint), Slater's condition always holds as long as the feasible set has non-empty interior.
\end{remark}

\begin{algorithm}[H]
\caption{Projected Gradient Descent}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, projection $\Pi_{\mathcal{C}}$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Gradient step (possibly infeasible)}
    \State $x_{k+1} \gets \Pi_{\mathcal{C}}(z_{k+1}) = \max(0.5,\; z_{k+1}[1]) \cdot e_1 + z_{k+1}[2] \cdot e_2$
\EndFor
\end{algorithmic}
\end{algorithm}

The projection onto $\mathcal{C} = \{x : x_1 \geq 0.5\}$ is simply $\Pi_{\mathcal{C}}(z) = (\max(0.5, z_1),\; z_2)$, a single \texttt{max} operation. For strongly convex $f$ restricted to $\mathcal{C}$, projected GD with step $\alpha \leq 1/L$ achieves linear convergence to $x^\star$.

\begin{algorithm}[H]
\caption{Penalty Method}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, penalty weight $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $F_{\lambda}(x) \gets f(x) + \lambda\, \max(0,\, 0.5 - x_1)$ \Comment{Linear penalty for constraint violation}
    \State $\nabla F_\lambda(x) \gets \nabla f(x) - \lambda \mathbf{1}[x_1 < 0.5]\, e_1$ \Comment{Subgradient}
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_{\lambda}(x_k)$
\EndFor
\end{algorithmic}
\end{algorithm}

The penalty term $\lambda \max(0, 0.5 - x_1)$ adds cost proportional to the constraint violation. As $\lambda \to \infty$, the minimiser of $F_\lambda$ converges to the constrained minimiser $x^\star$. The convergence rate is $\|x^\star(\lambda) - x^\star\| = O(1/\lambda)$, requiring increasingly large $\lambda$ for high accuracy; this motivates Augmented Lagrangian methods, which add a quadratic term to improve the accuracy-penalty trade-off.

Settings: Projected GD ($\alpha = 0.08$); Penalty with $\lambda \in \{0.15, 1.8, 4.5\}$ ($\alpha = 0.05$ for $\lambda \leq 1.8$, $\alpha = 0.03$ for $\lambda = 4.5$); unconstrained GD ($\alpha = 0.07$). All methods run for 100 iterations.

\subsection{Comparative Discussion}

\textbf{Projected GD} enforces feasibility as a hard constraint at every iteration via the projection operator. Key properties: (1) iterates are always feasible, enabling early stopping with a valid solution; (2) the method inherits the convergence rate of unconstrained GD once inside the feasible set; (3) since the unconstrained minimum $(x_1^\star \approx 0.582) > 0.5$ is feasible, projected GD converges to the same point as unconstrained GD, with the projection becoming inactive after the first iteration. The cost is a projection oracle; for half-space constraints this is $O(1)$, but for semidefinite or combinatorial constraint sets, projection can be as hard as the original problem.

\textbf{Key observation:} Once the penalty method iterate becomes feasible ($x_1^{(k)} \geq 0.5$), the penalty term $\lambda\max(0, 0.5 - x_1)$ equals zero and its gradient is zero. The penalty method's update then becomes \emph{identical} to unconstrained gradient descent on $f$. This means: (i)~for $\lambda = 0.15$, the trajectory may have a long infeasible phase and only reaches feasibility slowly; (ii)~once feasible, all penalty methods (regardless of $\lambda$) converge identically to the unconstrained minimum. The role of $\lambda$ is therefore entirely about how quickly the initial infeasible region is escaped.

\textbf{Penalty methods} trade exact feasibility for implementation simplicity: only the gradient of $F_\lambda = f + \lambda\max(0, g)$ is needed. Increasing $\lambda$ improves accuracy but introduces two competing issues. First, larger $\lambda$ makes $F_\lambda$ less smooth: the linear penalty $\lambda\max(0, g)$ is not differentiable at $g = 0$ (i.e.\ at the constraint boundary $x_1 = 0.5$), so subgradient methods are required and smaller step sizes are needed for stability. Second, for very large $\lambda$, the condition number of the penalised problem grows, slowing the gradient method's convergence rate. The resulting trade-off requires careful $\lambda$ tuning: too small gives infeasible solutions; too large creates a stiff problem requiring tiny steps.

A \emph{quadratic penalty} $F_\lambda(x) = f(x) + \lambda\max(0, g(x))^2$ is smooth (differentiable everywhere) and better conditioned, but requires $\lambda \to \infty$ more slowly to achieve high accuracy. The \emph{augmented Lagrangian method} (ALM) improves on both by maintaining dual variables $\nu_k$ and solving a sequence of problems:
\[
  x_{k+1} = \arg\min_x\; f(x) + \nu_k g(x) + \frac{\lambda}{2}\max(0, g(x))^2,
\]
with $\nu_{k+1} = \nu_k + \lambda \max(0, g(x_{k+1}))$. ALM achieves exact feasibility with bounded $\lambda$, avoiding the ill-conditioning of pure penalty approaches.

\begin{remark}[KKT violation as a dual residual]
The linear penalty gradient $-\lambda \cdot \mathbf{1}[x_1 < 0.5]$ at a feasibility violation is precisely the KKT stationarity error. When the penalty method converges to an infeasible point $x^\infty$ with $g(x^\infty) > 0$, it satisfies the stationarity condition of the penalised problem: $\nabla f(x^\infty) - \lambda \nabla g(x^\infty) = 0$, which is the KKT condition with multiplier $\mu = \lambda$. However, complementary slackness ($\mu g(x^\infty) = 0$) is violated since $g(x^\infty) > 0$ and $\lambda > 0$. The infeasibility gap $g(x^\infty) = O(1/\lambda)$ vanishes as $\lambda \to \infty$, but the associated growth in the penalty's Lipschitz constant ($\propto \lambda$) forces step sizes $\alpha = O(1/\lambda)$, requiring $O(\lambda)$ gradient steps --- explaining why large $\lambda$ converges accurately but slowly. The ALM avoids this by updating $\nu_k$ to correctly estimate the KKT multiplier, so the penalty term needs only $\lambda$ large enough to ensure local convexity, not to drive infeasibility to zero.
\end{remark}

\subsection{Theoretical Background}

\begin{theorem}[Frank--Wolfe convergence]\label{thm:fw}
For an $L$-smooth convex function $f$ and compact convex set $\mathcal{X}$ with diameter $D = \max_{x,y \in \mathcal{X}}\|x-y\|$, the Frank--Wolfe algorithm with step sizes $\gamma_k = 2/(k+2)$ satisfies
\[
  f(x_k) - f^\star \;\leq\; \frac{2LD^2}{k+2} \;=\; O(1/k).
\]
This $O(1/k)$ rate is slower than projected gradient descent's linear rate for strongly convex $f$, but Frank--Wolfe requires only a \emph{linear minimisation oracle} over $\mathcal{X}$ rather than a projection oracle, which is computationally cheaper for many structured constraint sets.
\end{theorem}

The \emph{Frank--Wolfe gap} $h_k = \max_{z \in \mathcal{X}} \nabla f(x_k)^T (x_k - z)$ is a primal certificate of optimality: $h_k = 0$ iff $x_k$ is the constrained minimiser. It can be computed for free at each iteration as a byproduct of the LP subproblem.

\subsection{Feasible Set and Linear Programme}

Feasible set: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\ -5 \leq x_2 \leq 10\}$, with diameter $D = \sqrt{(5-0.5)^2 + (10-(-5))^2} = \sqrt{20.25 + 225} = \sqrt{245.25} \approx 15.66$.

\textbf{Linear Programme:} For $f(x) = a^T x$ with $a = [1, 2]^T$, the minimum over $\mathcal{X}$ is obtained by independent coordinate-wise optimisation. Since both components of $a$ are positive, the objective decreases as each $x_i$ decreases, so the minimum is at the lower bounds:
\begin{equation}
x^{\star} = (0.5,\, -5), \qquad f^{\star} = 0.5 + 2(-5) = -9.5.
\end{equation}
This illustrates the fundamental theorem of linear programming: for any LP over a bounded polytope, the minimum is attained at a vertex (extreme point). The feasible box has $2^2 = 4$ vertices; $x^\star$ is identified by checking which vertex minimises $a^Tx$.

\caption{Q6-I: The feasible box $\mathcal{X}$ (blue rectangle) and level curves of the linear objective $f(x) = x_1 + 2x_2$. The level curves are parallel hyperplanes; the minimum over $\mathcal{X}$ is achieved at the vertex $(0.5, -5)$ where these hyperplanes are lowest. This geometric fact --- LP optima occur at vertices --- is the foundation of the simplex method and motivates Frank--Wolfe, which repeatedly optimises a linear model over $\mathcal{X}$.}

\subsection{Frank--Wolfe Algorithm}

\begin{algorithm}[H]
\caption{Frank--Wolfe (Conditional Gradient) with Fixed Mixing Parameter}
\label{alg:fw}
\begin{algorithmic}[1]
\Require Initial feasible $x_0 \in \mathcal{X}$, mixing parameter $\beta \in (0,1)$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $z_k \gets \arg\min_{z \in \mathcal{X}}\, g_k^T z$ \Comment{Linear minimisation oracle (LP step)}
    \State $x_{k+1} \gets \beta\, x_k + (1 - \beta)\, z_k$ \Comment{Fixed-weight convex combination}
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{remark}[Implementation note]
The standard Frank--Wolfe algorithm uses decaying step sizes $\gamma_k = 2/(k+2)$, i.e.\ $x_{k+1} = (1-\gamma_k)x_k + \gamma_k z_k$. Here a fixed mixing parameter $\beta$ (constant $1 - \gamma_k$) is used instead. The fixed-$\beta$ variant does not achieve the $O(1/k)$ rate of Theorem~\ref{thm:fw} but converges to a neighbourhood of the optimum and allows comparison of convergence speed across different values of $\beta$.
\end{remark}

For box constraints, the LP subproblem decomposes per coordinate with $O(d)$ operations:
\begin{equation}
(z_k)_i = \begin{cases} l_i & \text{if } (\nabla f(x_k))_i > 0 \\[2pt] u_i & \text{if } (\nabla f(x_k))_i \leq 0 \end{cases}
\end{equation}
In contrast, projecting onto a general convex set can require solving a QP. For structured sets like the simplex, spectrahedron, or nuclear norm ball, the LP oracle is often available in closed form at $O(d\log d)$ or $O(d^2)$ cost, while projection is much more expensive.

\subsection{Interior Optimum: $f(x) = (x_1 - 1)^2 + (x_2 - 5)^2$}

The unconstrained minimum $(1, 5)$ lies inside $\mathcal{X} = [0.5, 5] \times [-5, 10]$. Starting from $x_0 = (1, 1)$ with $\beta = 0.90$, we can trace the first two iterations explicitly. At $x_0 = (1, 1)$: $\nabla f(x_0) = (0, -8)$. Since $g_1 = 0 \leq 0$ and $g_2 = -8 \leq 0$, the LP oracle selects $z_0 = (u_1, u_2) = (5, 10)$ (upper bounds). Then $x_1 = 0.90(1, 1) + 0.10(5, 10) = (1.4, 1.9)$. At $x_1$: $\nabla f = (0.8, -6.2)$. Now $g_1 = 0.8 > 0$ so $z_1^{(1)} = l_1 = 0.5$; $g_2 = -6.2 \leq 0$ so $z_1^{(2)} = u_2 = 10$. Thus $z_1 = (0.5, 10)$, jumping to the opposite corner. This alternation between $(5, 10)$ and $(0.5, 10)$ as the sign of $g_1$ switches is the mechanism behind the zig-zag. Two mixing parameters are tested: $\beta = 0.90$ (step size $1-\beta = 0.10$) and $\beta = 0.985$ (step size $0.015$).

\subsection{Interior vs Boundary Behaviour}

\textbf{Interior optimum:} Frank--Wolfe exhibits the characteristic zig-zag convergence where $z_k$ oscillates between opposite vertices of $\mathcal{X}$. The $O(1/k)$ convergence rate (with decaying step sizes, Theorem~\ref{thm:fw}) is slower than projected gradient descent's linear rate. In practice for interior optima, projected gradient descent is preferred when projection is cheap.

\textbf{Boundary optimum:} Frank--Wolfe is particularly well suited to boundary optima because the LP oracle naturally selects the vertex closest to the direction of the constrained optimum, guiding iterates toward the boundary. For constraint sets where boundary optima are common --- $\ell_1$ balls promoting sparsity, trace-norm balls promoting low rank, or flow polytopes in network optimisation --- Frank--Wolfe is preferred because: (1) the LP oracle is cheap and exploits problem structure; (2) the boundary-vertex attraction provides implicit regularisation (sparse solutions emerge naturally); and (3) no projection is required.

\textbf{Frank--Wolfe gap as a stopping criterion:} The Frank--Wolfe gap $h_k = g_k^T (x_k - z_k)$ is computed for free at each iteration and provides a valid upper bound on the primal gap: $f(x_k) - f^\star \leq h_k$. This gives a practical, anytime stopping criterion --- halt when $h_k \leq \epsilon$ for desired accuracy $\epsilon$. In contrast, projected gradient descent requires an estimate of $f^\star$ or a separate dual certificate for such a guarantee.

\begin{remark}[Frank--Wolfe gap: worked example]
For the interior case $f(x) = (x_1-1)^2 + (x_2-5)^2$ on $\mathcal{X} = [0.5,5]\times[-5,10]$, at $x_0 = (1, 1)$: $\nabla f(x_0) = (0, -8)$. The LP oracle selects $z_0 = (5, 10)$ (upper bounds, since both gradient components are $\leq 0$ for $x_2$). The FW gap is:
\[
  h_0 = \nabla f(x_0)^T(x_0 - z_0) = (0)(1-5) + (-8)(1-10) = 0 + 72 = 72.
\]
This tells us $f(x_0) - f^\star \leq 72$. Indeed $f(x_0) = 0 + 16 = 16$ and $f^\star = 0$, so the true gap is 16 and the FW bound (72) is valid but not tight. After many iterations as $x_k \to (1, 5)$: $\nabla f(x_k) \to 0$, so $h_k \to 0$ --- the gap tightens as we approach the optimum. The gap is tight (equals the true gap) when $x_k = x^\star$; it is loose at early iterations when the gradient is large and the LP oracle selects a far vertex. For the boundary case $f(x) = x_1^2 + x_2^2$ with $x^\star = (0.5, 0)$: the FW gap at convergence measures how far the last LP solution is from the current iterate along the gradient direction, providing a certificate that the boundary minimum has been found.
\end{remark}

\textbf{Practical recommendation:} The decaying step-size schedule $\gamma_k = 2/(k+2)$ should be preferred over fixed $\beta$ for convergence guarantees. In our boundary case, the fixed $\beta = 0.93$ leaves a gap $f = 0.364$ vs $f^\star = 0.25$ that would be closed by allowing smaller steps in later iterations.

\begin{remark}[Frank--Wolfe vs projected gradient: oracle complexity comparison]
For a box-constrained problem as in Q6, both Frank--Wolfe and projected gradient descent achieve linear convergence to $f^\star$ for strongly convex $f$ (PGD) and $O(1/k)$ for only convex $f$ (FW). However, the \emph{per-iteration cost} differs:
\begin{itemize}[nosep]
  \item \textbf{Projected GD}: LP step costs $O(d)$; projection onto box also costs $O(d)$ (per-coordinate clipping). Both are equally cheap for box constraints.
  \item \textbf{Frank--Wolfe}: LP step costs $O(d)$; no projection needed. But for a nuclear norm ball $\{X : \|X\|_* \leq 1\}$ (rank-$r$ matrix $X \in \mathbb{R}^{p\times q}$), the LP oracle (computing the top singular vectors of $\nabla f$) costs $O(pqr)$ via truncated SVD vs projection (which requires a full SVD at $O(pq\min(p,q))$). This makes FW $O(\min(p,q)/r)$ times cheaper per iteration for low-rank matrices --- a critical advantage in collaborative filtering.
\end{itemize}
For our box constraint, both methods are equally cheap per iteration, and PGD's superior convergence rate (linear vs $O(1/k)$) makes it preferable. Frank--Wolfe's advantage emerges only for structured constraint sets where the LP oracle is substantially cheaper than projection.
\end{remark}

\subsection{Key Conclusions}

\textbf{Benchmark A (quadratic, $\kappa \approx 1$):} All gradient methods converge to the same floor $J^\star \approx 0.4826$; Newton reaches it in one step. The near-unit condition number makes this benchmark easy for all first-order methods.

\textbf{Benchmark B (mildly ill-conditioned, $\kappa \approx 10$):} Momentum methods (Nesterov, Adam, Heavy Ball) offer modest but noticeable advantages over GD. Newton's curvature information provides the most efficient path in only 20 iterations. The moderate anisotropy distinguishes methods that adapt to the coordinate-wise curvature (Adam, Adagrad) from those that treat all directions equally (GD).

\textbf{Benchmark C (Rosenbrock, $\kappa \approx 2504$):} This is the decisive benchmark. Newton's method dramatically outperforms all first-order methods on a per-iteration basis. Among first-order methods: Polyak (with correct $f^\star = 0$) converges best ($f = 0.009$), followed by Nesterov ($f = 0.479$). GD barely makes progress ($f = 3.39$) due to the stringent stability constraint $\alpha < 2/L \approx 0.002$. This confirms the theoretical prediction: for large $\kappa$, first-order methods converge as $(1-2/(\kappa+1))^k \approx e^{-2k/\kappa}$, requiring $O(\kappa)$ iterations, while Newton is insensitive to $\kappa$ near the optimum.

\textbf{Adaptive step sizes:} The Polyak step size is theoretically optimal when $f^\star$ is known, but practically fragile: misspecification of $f^\star$ leads to divergence (Benchmarks A and B). Adagrad and RMSprop are more robust for practical applications. Adagrad's monotone decay suits sparse gradient settings (e.g.\ NLP); RMSprop's exponential forgetting is better for stationary objectives where long-term gradient history is misleading.

\textbf{Theoretical vs.\ practical advantage of Nesterov over Adam:} On our benchmarks, Nesterov outperforms Adam on Benchmark C ($f = 0.479$ vs $1.578$). However, in large-scale deep learning, Adam is overwhelmingly preferred despite Nesterov's stronger theoretical guarantee. This is because: (1)~real neural networks have non-convex, non-smooth objectives where Nesterov's convergence theory does not apply; (2)~Adam's per-coordinate scaling implicitly handles the extreme gradient scale variation across layers (weight matrices vs.\ bias vectors); (3)~Adam's bias correction prevents the large initial step that Nesterov's rising momentum can produce in early iterations. These results serve as a reminder that theoretical rates on convex benchmarks do not always predict practical performance in non-convex settings.

\textbf{Second-order methods:} Newton's method provides the best convergence on all benchmarks when appropriately damped, achieving accuracy in 20 iterations that first-order methods fail to reach in 150. For small-to-medium scale problems where Hessian computation is feasible, Newton or quasi-Newton (L-BFGS) methods should be the first choice.

\textbf{Derivative-free methods:} Finite differences with small $\delta$ closely match gradient descent performance at $d+1$ function evaluations per step. Nelder--Mead and random search are valuable when analytical gradients are unavailable, at the cost of slower convergence and limited scalability to high dimensions.

\textbf{Constrained optimisation:} Projected gradient descent provides hard constraint satisfaction from the first iteration, at the cost of a projection oracle. Penalty methods are simpler to implement but require careful tuning of $\lambda$: too small yields residual infeasibility; too large creates a poorly conditioned landscape requiring smaller step sizes.

\textbf{Frank--Wolfe:} The projection-free nature of Frank--Wolfe makes it attractive for structured constraint sets (nuclear norm, simplex, flow polytopes) where LP oracles are cheaper than projections. The characteristic $O(1/k)$ rate is sufficient for many practical applications, and the LP vertices naturally attract iterates towards sparse solutions.

\subsection{Practical Recommendations}

For data science practitioners:
\begin{itemize}[nosep]
\item For well-conditioned, large-scale problems: \textbf{Adam} or \textbf{RMSprop} offer the best robustness without requiring $f^\star$ or second-order information.
\item For small-scale, well-conditioned problems with known Hessian: \textbf{Newton's method} in 5--20 iterations.
\item For well-conditioned problems with known optimal value: \textbf{Polyak step size} achieves optimal convergence.
\item For highly ill-conditioned problems ($\kappa \gg 1$): \textbf{Nesterov momentum} provides the best first-order guarantee; \textbf{Newton} if second-order information is accessible.
\item For black-box objectives: \textbf{Nelder--Mead} (low dimension), \textbf{Nesterov random search} (high dimension, parallel budget).
\item For linearly constrained problems: \textbf{Frank--Wolfe} when the LP oracle is cheap; \textbf{projected gradient descent} otherwise.
\end{itemize}

def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        x = x - alpha * grad_fn(x)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Polyak Step Size}]
def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adagrad}]
def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float)
    G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={RMSprop}]
def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float)
    v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Heavy Ball / Polyak Momentum}]
def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x)
        z = beta * z + alpha * g
        x = x - z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Nesterov Momentum}]
def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z
        g = grad_fn(lookahead)
        z = beta_k * z - alpha * g
        x = x + z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adam Optimiser}]
def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t)
        v_hat = v_vec / (1 - beta2**t)
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Damped Newton's Method}]
def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))
        try:
            p = np.linalg.solve(H_reg, g)
        except np.linalg.LinAlgError:
            p = g
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)
\end{lstlisting}

\begin{lstlisting}[caption={Nelder--Mead Simplex}]
def nelder_mead(loss_fn, x0, step, n_iters, alpha_r=1.0, gamma=2.0, rho=0.5, sigma=0.5):
    n = len(x0)
    simplex = np.zeros((n + 1, n))
    simplex[0] = x0.copy()
    for i in range(n):
        simplex[i + 1] = x0.copy()
        simplex[i + 1][i] += step
    f_vals = np.array([loss_fn(v) for v in simplex])
    centroid_hist = [np.mean(simplex, axis=0).copy()]
    f_best_hist = [np.min(f_vals)]
    for _ in range(n_iters):
        order = np.argsort(f_vals)
        simplex = simplex[order]; f_vals = f_vals[order]
        centroid = np.mean(simplex[:-1], axis=0)
        x_r = centroid + alpha_r * (centroid - simplex[-1])
        f_r = loss_fn(x_r)
        if f_vals[0] <= f_r < f_vals[-2]:
            simplex[-1] = x_r; f_vals[-1] = f_r
        elif f_r < f_vals[0]:
            x_e = centroid + gamma * (centroid - simplex[-1])
            f_e = loss_fn(x_e)
            if f_e < f_r: simplex[-1] = x_e; f_vals[-1] = f_e
            else: simplex[-1] = x_r; f_vals[-1] = f_r
        else:
            if f_r < f_vals[-1]:
                x_c = centroid + rho * (x_r - centroid)
                f_c = loss_fn(x_c)
                if f_c <= f_r: simplex[-1] = x_c; f_vals[-1] = f_c
                else:
                    for i in range(1, n+1):
                        simplex[i] = simplex[0]+sigma*(simplex[i]-simplex[0])
                        f_vals[i] = loss_fn(simplex[i])
            else:
                x_c = centroid + rho * (simplex[-1] - centroid)
                f_c = loss_fn(x_c)
                if f_c < f_vals[-1]: simplex[-1] = x_c; f_vals[-1] = f_c
                else:
                    for i in range(1, n+1):
                        simplex[i] = simplex[0]+sigma*(simplex[i]-simplex[0])
                        f_vals[i] = loss_fn(simplex[i])
        centroid_hist.append(np.mean(simplex, axis=0).copy())
        f_best_hist.append(np.min(f_vals))
    return np.array(centroid_hist), np.array(f_best_hist), simplex
\end{lstlisting}

\begin{lstlisting}[caption={Frank--Wolfe Algorithm}]
def frank_wolfe(grad_fn, loss_fn, x0, bounds, beta, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, z_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
\end{lstlisting}
