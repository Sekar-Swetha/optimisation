\begin{abstract}
This report presents a comprehensive comparative study of optimisation algorithms applied
to three benchmark problems: a linear regression quadratic loss (Benchmark~A), a toy
neural-network loss with sinusoidal perturbation (Benchmark~B), and the notoriously
ill-conditioned Rosenbrock function (Benchmark~C). Six families of methods are
investigated: (1)~adaptive step-size rules (Polyak, Adagrad, RMSprop, Heavy Ball);
(2)~accelerated and stochastic methods (Nesterov, Adam, mini-batch SGD); (3)~second-order
methods (Newton's method and local quadratic approximation); (4)~derivative-free approaches
(finite differences, Nesterov random search, Nelder--Mead, grid search);
(5)~constrained optimisation via projected gradient descent and penalty methods; and
(6)~the Frank--Wolfe conditional-gradient algorithm for linearly constrained problems.
Each method is analysed in terms of convergence rate, trajectory geometry, numerical
stability, and computational cost, with results tied back to theoretical guarantees where
available. All experiments are conducted in Python with a fixed random seed
(\texttt{np.random.seed(42)}) for reproducibility.
\end{abstract}

\subsection{Benchmark A: Linear Regression Quadratic Loss}

A synthetic dataset with $m = 1000$ samples and two parameters is generated:
\begin{equation}
\theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \qquad
x^{(i)} \sim \mathcal{N}(0, I_2), \qquad
y^{(i)} = {\theta^{\star}}^T x^{(i)} + \varepsilon^{(i)}, \qquad
\varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The mean squared error loss function is:
\begin{equation}
J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left(\theta^T x^{(i)} - y^{(i)}\right)^2
          = \frac{1}{2m}\|X\theta - y\|^2.
\end{equation}
This is a convex quadratic: $J(\theta) = \frac{1}{2}\theta^T H \theta - b^T\theta + c$, where
$H = \frac{1}{m}X^T X$ (positive definite), $b = \frac{1}{m}X^T y$.  The gradient is
$\nabla J(\theta) = \frac{1}{m}X^T(X\theta - y)$ and the Hessian is $H$ (constant).

The ordinary least-squares (OLS) minimiser is
$\theta^{\text{OLS}} = H^{-1}b \approx (3.028,\, 4.017)^T$.  Due to observation noise, the
irreducible minimum loss is
\begin{equation}
J^{\star} = J(\theta^{\text{OLS}}) \approx 0.4826,
\end{equation}
\emph{not zero}; this distinction is critical for the Polyak step size (Section~\ref{sec:q1}).
Starting point: $\theta_0 = [0,\, 0]^T$.

\subsection{Benchmark B: Toy Neural Network Loss}

\begin{equation}
f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
\end{equation}
The gradient is $\nabla f = [2(x_1 - 1) + \cos(x_1),\ 10(x_2 - 2)]^T$ and the Hessian is
$H(x) = \operatorname{diag}(2 - \sin(x_1),\, 10)$. The minimum satisfies the stationarity
condition $2(x_1^{\star}-1)+\cos(x_1^{\star})=0$, $x_2^{\star} = 2$. Solving numerically (via
Newton's method applied to $g'(x_1)=0$):
\begin{equation}
x^{\star} \approx (0.5824,\, 2.0000), \qquad f^{\star} \approx 0.7244.
\end{equation}
The eigenvalue ratio of the Hessian at $x^{\star}$ is approximately
$(2-\sin(0.5824)) : 10 \approx 1.45:10$, giving a condition number $\kappa \approx 6.897$.
This moderate anisotropy distinguishes Benchmark~B from the purely quadratic Benchmark~A.
Starting point: $x_0 = [-1,\, 4]^T$.
\begin{remark}
The contour figures display the optimal point marker at $(0.61, 2.0)$ rather than
$(0.5824, 2.0)$ due to a rounding in the plotting code.  The true minimiser is
$x_1^{\star} \approx 0.5824$ (found by Newton's method applied to the stationarity condition
$2(x_1-1)+\cos(x_1) = 0$); this should be understood when interpreting trajectory endpoints.
\end{remark}

\subsection{Benchmark C: Rosenbrock Function}

\begin{equation}
f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
\end{equation}
The global minimum is at $x^{\star} = (1, 1)$ with $f^{\star} = 0$. The Hessian at the
optimum is:
\begin{equation}
H(1,1) = \begin{bmatrix} 802 & -400 \\ -400 & 200 \end{bmatrix},
\end{equation}
with eigenvalues $\lambda_1 \approx 0.502$ and $\lambda_2 \approx 1001.5$, yielding a
condition number
\begin{equation}
\kappa(H) = \frac{\lambda_{\max}}{\lambda_{\min}} \approx \frac{1001.5}{0.502} \approx 2508.
\end{equation}
This extreme ill-conditioning (the highest of all three benchmarks by more than two
orders of magnitude), combined with the narrow curved valley along $x_2 = x_1^2$,
makes Rosenbrock one of the most challenging standard test functions. Gradient methods with
a fixed step size $\alpha$ are constrained by the stability condition
$\alpha < 2/\lambda_{\max} \approx 0.002$, while progress along the valley is governed by
$\lambda_{\min} \approx 0.5$, resulting in extremely slow convergence. Starting point:
$x_0 = [-1,\, 1]^T$.

\subsection{Background: Smoothness and Strong Convexity}
\label{sec:theory_background}

The convergence guarantees cited throughout this report rely on two standard assumptions:

\begin{definition}[$L$-smoothness]
A differentiable function $f$ is \emph{$L$-smooth} if $\|\nabla f(x) - \nabla f(y)\| \leq
L\|x - y\|$ for all $x, y$.  Equivalently, $\nabla^2 f(x) \preceq LI$ (bounded curvature).
This implies the descent lemma: $f(y) \leq f(x) + \nabla f(x)^T(y-x) + \frac{L}{2}\|y-x\|^2$.
\end{definition}

\begin{definition}[$\mu$-strong convexity]
A function $f$ is \emph{$\mu$-strongly convex} if $\nabla^2 f(x) \succeq \mu I > 0$ for all $x$,
i.e., $f(y) \geq f(x) + \nabla f(x)^T(y-x) + \frac{\mu}{2}\|y-x\|^2$.  This ensures a unique
minimiser $x^{\star}$.
\end{definition}

The \emph{condition number} $\kappa = L/\mu$ determines the curvature ratio and governs
convergence: $\kappa \approx 1.117$ (Benchmark~A), $\kappa \approx 6.897$ (Benchmark~B),
$\kappa \approx 2508$ (Benchmark~C).  For GD with $\alpha = 1/L$, the linear convergence
factor is $(1 - 1/\kappa)^k$; for Nesterov the factor is $(1 - 1/\sqrt{\kappa})^k$ --- both
verified empirically across the three benchmarks.

\subsection{Algorithm Formulations and Theoretical Motivation}

Four adaptive step-size methods are compared against a constant step-size gradient descent
baseline across all three benchmarks for 120 iterations.

\paragraph{Gradient Descent baseline.}
The update is $x_{k+1} = x_k - \alpha \nabla f(x_k)$ with fixed step
$\alpha$.  For a $\mu$-strongly convex, $L$-smooth function this converges at a linear
(geometric) rate:
\begin{equation}
f(x_k) - f^{\star} \leq \left(1 - \frac{\mu}{L}\right)^k \bigl(f(x_0)-f^{\star}\bigr)
= \left(1 - \frac{1}{\kappa}\right)^k \bigl(f(x_0)-f^{\star}\bigr),
\end{equation}
where $\kappa = L/\mu$ is the condition number.  For Rosenbrock $\kappa \approx 2508$,
requiring $\ln(0.5)/\ln(1-1/\kappa) \approx \kappa \ln 2 \approx 1738$ iterations
to halve the error --- motivating all adaptive strategies explored below.

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, known optimal value $f^{\star}$, tolerance $\varepsilon > 0$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets \dfrac{f(x_k) - f^{\star}}{\|g_k\|^2 + \varepsilon}$
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{proposition}[Polyak convergence]
For a convex function $f$ with minimum $f^{\star}$, the Polyak step satisfies
$f(x_k) - f^{\star} \leq \frac{C}{k}$ for some $C$ depending on the initial distance to
the optimum, when $f^{\star}$ is known exactly and $\varepsilon = 0$.
\end{proposition}

The step size $\alpha_k = (f(x_k)-f^{\star})/\|\nabla f(x_k)\|^2$ arises from
minimising the \emph{one-step progress bound}.  For a GD step $x^+ = x - \alpha g$, we have
\begin{equation}
f(x^+) \leq f(x) - \alpha\|g\|^2 + \tfrac{L}{2}\alpha^2\|g\|^2
= f(x) - \alpha\|g\|^2\!\left(1 - \tfrac{L\alpha}{2}\right).
\end{equation}
Minimising the right side over $\alpha$ gives $\alpha^{\star}_{\text{bound}} = 1/L$, but
substituting the stronger assumption $f(x) - f^{\star} \leq \frac{1}{2\mu}\|g\|^2$
(from strong convexity) into $f(x^+) \leq f^{\star} + \frac{L}{2}\|x - \alpha g - x^{\star}\|^2$
and minimising over $\alpha$ yields $\alpha_k = (f(x_k)-f^{\star})/\|g_k\|^2$.
This requires exact knowledge of $f^{\star}$; when $f^{\star}$ is misspecified,
$\alpha_k \to \infty$ as $\|g_k\| \to 0$ while
$f(x_k) - f^{\star}_{\text{specified}}$ remains bounded away from zero.
Practically, $f^{\star}$ can sometimes be estimated or set to 0 in ML problems where the
true minimum is unknown --- this works well when $f^{\star} \approx 0$ (e.g., classification
losses), but causes instability when the irreducible minimum is nonzero (as in Benchmark~A
where $f^{\star} = 0.4826$ due to the observation noise floor).

\begin{algorithm}[H]
\caption{Adagrad}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0} \in \mathbb{R}^d$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Per-coordinate squared-gradient accumulation}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

Adagrad automatically assigns smaller step sizes to frequently updated coordinates and
larger steps to rarely updated ones. The effective per-coordinate rate after $k$ steps is
$\alpha_0/\sqrt{\sum_{t\leq k} g_{t,i}^2}$, which decays at rate $O(1/\sqrt{k})$.
Adagrad's theoretical motivation comes from online learning: it achieves an \emph{adaptive
regret bound}
\begin{equation}
\sum_{t=1}^k [f(x_t) - f^{\star}] \leq \frac{\|x_0 - x^{\star}\|^2}{2\alpha_0}
\sum_{i=1}^d \sqrt{\sum_{t=1}^k g_{t,i}^2},
\end{equation}
which can be significantly tighter than non-adaptive regret when some coordinates have
much smaller cumulative gradient magnitudes than others (e.g., in sparse NLP tasks).
For dense problems where $\sum_t g_{t,i}^2$ grows uniformly across coordinates, the
adaptive benefit disappears and the monotone decay of steps becomes a liability.

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta \in (0,1)$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0} \in \mathbb{R}^d$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponential moving average of $g^2$}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

RMSprop corrects Adagrad's vanishing step problem by replacing the cumulative sum of squared
gradients with an exponential moving average controlled by $\beta$.
The effective memory window is approximately $1/(1-\beta)$ iterations (e.g., $\beta=0.9
\Rightarrow$ window $\approx 10$ iterations), keeping the step size stable.
In the limit $\beta \to 0$, the exponential average reduces to $v_k = (1-\beta)\sum_{t \leq k}
\beta^{k-t} g_t^2 \to g_k^2$ (pure current gradient), recovering gradient normalisation;
as $\beta \to 1$, $v_k$ becomes a slow-moving estimate of $\mathbb{E}[g^2]$.
The choice $\beta = 0.9$ (used here) is standard and provides a balanced trade-off between
responsiveness and stability.  Note that for very small $\beta$ (e.g., $\beta \approx 0$),
RMSprop reverts to a behaviour similar to Adagrad on a short window, retaining Adagrad's
problem of rapid step-size decay if gradients are consistently large.

\begin{algorithm}[H]
\caption{Polyak Momentum / Heavy Ball}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta \in [0,1)$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$
    \State $x_{k+1} \gets x_k - z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

The momentum variable $z_{k+1}$ accumulates a weighted sum of all past gradients, attenuating
oscillations across the short axis while accelerating progress along the long axis.
Since $z_{k+1} = \alpha(\nabla f(x_k) + \beta\nabla f(x_{k-1}) + \beta^2 \nabla f(x_{k-2}) + \cdots)$,
the geometric series sums to effective scaling $\alpha/(1-\beta)$: with $\beta = 0.9$
this is effectively $10\alpha$, matching the intuition that momentum provides a
tenfold amplification of the base step size in directions of persistent gradient sign.
For a quadratic $f$ with eigenvalues $[\mu, L]$, the optimal Heavy Ball parameters achieve a
convergence rate of $O((\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1})^k)$, which is significantly
faster than vanilla GD's $O((1-1/\kappa)^k)$.

\subsection{Why Momentum Helps: Eigenvalue Analysis}

For a quadratic $f(x) = \frac{1}{2}x^T H x$, diagonalise $H = Q\Lambda Q^T$ and let
$y_k = Q^T(x_k - x^{\star})$ be the error in the eigenbasis.  GD decouples across
eigenmodes: $y_{k+1}^{(i)} = (1 - \alpha\lambda_i)y_k^{(i)}$.  Each mode contracts at rate
$|1 - \alpha\lambda_i|$; for optimal $\alpha = 2/(\lambda_{\min}+\lambda_{\max})$, the
slowest mode contracts at rate $(\kappa-1)/(\kappa+1) \approx 1 - 2/\kappa$.

Heavy Ball with optimal parameters achieves $(\sqrt{\kappa}-1)/(\sqrt{\kappa}+1) \approx
1 - 2/\sqrt{\kappa}$, which for $\kappa = 2508$ means:
\[
\text{GD}: 1 - 2/2508 \approx 0.9992, \qquad
\text{HB}: 1 - 2/\sqrt{2508} \approx 0.9601.
\]
The momentum parameter effectively transforms the convergence factor from $1-O(1/\kappa)$ to
$1-O(1/\sqrt{\kappa})$, which is the same improvement Nesterov achieves through the lookahead
but with a provable $O(1/k^2)$ global rate.

\subsection{Comparative Analysis}
\label{sec:q1_analysis}

\begin{itemize}[nosep, leftmargin=*]
\item \textbf{Polyak step:} Theoretically optimal when $f^{\star}$ is known exactly (as on
Rosenbrock, where it achieves the best result $f \approx 0.009$).  Catastrophically unstable
when $f^{\star}$ is misspecified, because the step-size formula has a structural singularity
as $\|\nabla f\| \to 0$.  This limits its practical utility to problems where $f^{\star}$ is
known analytically (e.g., regression with known noise-free target).

\item \textbf{Adagrad:} Uniformly stable across all benchmarks.  Per-coordinate scaling
helps on anisotropic surfaces (Benchmarks B and C) by assigning more conservative rates to
coordinates with large gradients.  The limitation is the monotonically decaying step:
Adagrad was designed for sparse gradient problems (e.g., NLP) where some coordinates are
rarely updated; on dense problems its step vanishes and progress stalls.
Notably, even with careful tuning of $\alpha_0$, Adagrad does not improve over a well-tuned
constant step-size GD on the Rosenbrock function (consistent with course analysis): the
monotone denominator growth $\sqrt{\sum_{t\leq k} g_{t,i}^2}$ accumulates large gradient
contributions during the early steep descent to the valley, leaving an insufficient effective
step for the slow progress phase inside the valley.

\item \textbf{RMSprop:} Addresses Adagrad's vanishing step by using an exponential moving
average (controlled by $\beta = 0.9$).  The result is a method that forgets old gradient
information and adapts to the local landscape --- beneficial in non-stationary settings.
However, the very small $\alpha_0 = 0.0035$ on Rosenbrock limits its progress; with $\beta = 0.9$
the effective step memory window is $\approx 10$ iterations and the plateau in step size
$v_k \approx \mathbb{E}[g^2]$ converges to the time-average squared gradient, which is
large on Rosenbrock (large gradients near the steep walls outside the valley), suppressing
the step and making RMSprop competitive with GD but no better.

\item \textbf{Heavy Ball:} Outperforms GD on all benchmarks where the step is stable.
For quadratic functions, the optimal Heavy Ball parameters achieve the theoretically fastest
first-order convergence rate for the class $\mathcal{SC}(\mu, L)$. The momentum term
effectively reduces oscillation across narrow directions by cancelling alternating gradient
components. On Rosenbrock, the speedup is substantial ($3.51 \to 1.40$).

\item \textbf{Convergence speed ranking on Rosenbrock:} Polyak (with correct $f^{\star}$)
$\gg$ Heavy Ball $\gg$ Adagrad $\gg$ RMSprop $\approx$ GD.  This ordering
reflects the increasing difficulty of second-order information access: Polyak implicitly uses
global loss information ($f^{\star}$), Heavy Ball accumulates gradient history, Adagrad
adapts per coordinate, while GD uses only the current gradient.
\end{itemize}

\subsection{Key Finding from Q1}

The central lesson from Q1 is the \textbf{information vs adaptivity trade-off}:
methods that exploit problem structure (Polyak with $f^{\star}$, Heavy Ball accumulating
gradient history) outperform methods that adapt blindly (RMSprop, Adagrad) on
ill-conditioned landscapes.  On well-conditioned problems (Benchmark~A, $\kappa \approx 1.1$),
all methods are essentially equivalent and the choice is inconsequential.  On hard problems
(Rosenbrock, $\kappa \approx 2508$), the ranking Polyak $\gg$ Heavy Ball $\gg$ Adagrad
$\approx$ RMSprop $\approx$ GD is a direct consequence of decreasing access to
structural problem information.  This motivates the next question's exploration of
momentum and acceleration as ways to extract more value from the gradient signal alone.

\subsection{Algorithm Formulations and Theoretical Background}

\begin{algorithm}[H]
\caption{Nesterov Momentum / Acceleration}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\dfrac{k-1}{k+2},\; \beta_{\max}\right)$
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead point}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$ \Comment{Update momentum using lookahead gradient}
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{proposition}[Nesterov convergence rate]
For a convex $L$-smooth function $f$, Nesterov accelerated gradient descent achieves
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2L\|x_0 - x^{\star}\|^2}{(k+1)^2},
\end{equation}
an $O(1/k^2)$ rate, compared to GD's $O(1/k)$.  For $\mu$-strongly convex functions the
improvement is from $O((1-\mu/L)^k)$ to $O((1-\sqrt{\mu/L})^k)$.
\end{proposition}

The critical distinction from Heavy Ball is the \emph{lookahead}: the gradient is evaluated at
$\tilde{x}_k = x_k + \beta_k z_k$ rather than $x_k$.  This ``correction before the step''
allows Nesterov momentum to self-correct its trajectory before overshooting, resulting in
the provable $O(1/k^2)$ rate which is \emph{optimal} among first-order methods for smooth
convex optimisation.

The schedule $\beta_k = (k-1)/(k+2)$ is carefully constructed: initially $\beta_1 = 0$
(pure gradient step), then $\beta_k \nearrow 1$ as $k \to \infty$.  This gradual increase
prevents momentum from being too aggressive in early iterations when the iterate may be far
from the minimum and the gradient direction is changing rapidly.
When the same $\beta_k$ schedule is applied to Heavy Ball (gradient evaluated at $x_k$,
not the lookahead $\tilde{x}_k$), the empirical performance of the two methods is very
similar --- the provable $O(1/k^2)$ guarantee comes precisely from the lookahead evaluation,
not from the $\beta_k$ schedule alone.

The parameter $\beta_{\max}$ caps the momentum at 0.90--0.92 across benchmarks.  Without
this cap, $\beta_k = (k-1)/(k+2) \to 1$ could lead to instability when the iterate enters
a region of high curvature.  The cap trades the theoretical $O(1/k^2)$ rate (which requires
$\beta_k \to 1$) for practical stability: with $\beta_{\max} = 0.90$ the asymptotic rate
is that of Heavy Ball with $\beta = 0.90$, but the early-phase acceleration still provides
significant speedup over fixed $\beta$.

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha$, moment parameters $\beta_1, \beta_2 \in [0,1)$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\; v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{Exponential moving average of gradient}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{Exponential moving average of $g^2$}
    \State $\hat{m}_t \gets m_t\, /\, (1 - \beta_1^t)$ \Comment{Bias-corrected first moment}
    \State $\hat{v}_t \gets v_t\, /\, (1 - \beta_2^t)$ \Comment{Bias-corrected second moment}
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t\, /\, (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

Adam is precisely \textbf{RMSprop with Heavy Ball momentum}: it combines
(1) an exponential moving average of \emph{gradients} ($m_t$, the Heavy Ball component)
with (2) an exponential moving average of \emph{squared gradients} ($v_t$, the RMSprop
component).  More concretely:
\begin{enumerate}[nosep]
\item \textbf{Heavy Ball component} (via $m_t$): exponential moving average of gradients
      with decay $\beta_1$.  The effective gradient memory window is $\approx 1/(1-\beta_1)$
      iterations; for $\beta_1 = 0.9$ this is $\sim 10$ iterations, providing momentum similar
      to Heavy Ball with $\beta_1/(1-\beta_1) = 9$ times the baseline step.
\item \textbf{RMSprop component} (via $v_t$): normalises each coordinate by
      an estimate of its second moment, suppressing large-gradient coordinates and boosting
      small-gradient ones.  The bias correction $(1-\beta_i^t)$ ensures accurate estimates
      at early iterations when $m_0 = v_0 = 0$, which is particularly important in the first
      $\sim 1/(1-\beta_i)$ iterations.
\end{enumerate}
The effective per-coordinate step size is bounded:
$\alpha_t^{(i)} = \alpha \,|\hat{m}_t^{(i)}|/(\sqrt{\hat{v}_t^{(i)}} + \varepsilon) \in
(-\alpha, \alpha)$, providing natural gradient clipping.
The choice of $\beta_1$ matters significantly: the default $\beta_1 = 0.9$ can be suboptimal
for some problems (as confirmed by the non-default values $\beta_1 \in \{0.80, 0.82\}$
required here), reflecting that the optimal gradient memory window is problem-dependent.

\subsection{Why Adam Suits Benchmark~B}

Benchmark~B has a diagonal Hessian $H = \mathrm{diag}(2 - \sin(x_1),\, 10)$ at $x^{\star}$,
with curvature ratio $\approx 7$.  Adam's second moment $v_t^{(i)} \approx \mathbb{E}[g_i^2]$
estimates this diagonal Hessian: $v_t^{(1)} \approx (1.45)^2 \approx 2.1$ and
$v_t^{(2)} \approx (10)^2 = 100$ (roughly, near $x^{\star}$).  The effective
Adam step $\alpha/\sqrt{v_t^{(i)}}$ then becomes $\alpha/1.45$ in the $x_1$ direction and
$\alpha/10$ in the $x_2$ direction, \emph{approximately inverting the curvature} and
preconditioning the step as a diagonal approximation to $H^{-1}$.  This explains
Adam's faster convergence on Benchmark~B relative to GD with a fixed scalar step.

\subsection{Mini-Batch Stochastic Gradient Descent on Benchmark~A}
\label{sec:q2_sgd}

Mini-batch SGD replaces the exact gradient with a stochastic estimate computed over a
random subset of data.  The mini-batch gradient is an \emph{unbiased} estimator of the
full gradient:
\begin{equation}
\mathbb{E}_{\mathcal{B}}[\hat{g}_{\mathcal{B}}] = \nabla J(\theta), \qquad
\mathrm{Var}[\hat{g}_{\mathcal{B}}^{(i)}] = \frac{\sigma_i^2}{b},
\end{equation}
where $\sigma_i^2$ is the per-sample gradient variance in coordinate $i$ and $b$ is the
batch size.  Larger batches reduce variance but perform fewer parameter updates per epoch.

\paragraph{Sampling strategy.} The implementation uses \emph{shuffle-then-partition}: at
the start of each epoch, the $m = 1000$ data indices are randomly permuted, then divided
into contiguous mini-batches.  This is the standard practice in deep learning.  Sampling
\emph{with replacement} (i.i.d.\ mini-batches) gives the same variance in expectation but
may repeat samples within an epoch.  Sampling in \emph{fixed order} (no shuffling) would
be harmful if data were class-ordered --- each mini-batch would see only one class and the
gradient estimate would be severely biased.  For this assignment's i.i.d.\ Gaussian data,
the ordering does not matter.

\begin{algorithm}[H]
\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]
\Require Data $(X, y)$, initial $\theta_0$, learning rate $\alpha$, batch size $b$, epochs $E$
\For{$e = 1, 2, \ldots, E$}
    \State Randomly permute data indices $\{1, \ldots, m\}$ into $\pi$
    \For{$i = 0, b, 2b, \ldots$ (each mini-batch $\mathcal{B}_i = \{\pi_{i+1}, \ldots, \pi_{i+b}\}$)}
        \State $g_{\mathcal{B}} \gets \frac{1}{b} X_{\mathcal{B}}^T(X_{\mathcal{B}}\theta - y_{\mathcal{B}})$
        \State $\theta \gets \theta - \alpha\, g_{\mathcal{B}}$
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{figure}[H]
\centering
\includegraphics[width=0.88\textwidth]{figures/q2_sgd_batch.pdf}
\caption{Q2: Mini-batch SGD on Benchmark~A ($\alpha = 0.06$, 50 epochs). With $b = 5$,
each epoch performs $m/b = 200$ weight updates; with $b = 40$, only $m/b = 25$ updates.

\begin{remark}
The crossover point where larger batch $b=40$ becomes preferable to $b=5$ is when the
variance-reduction benefit of $b=40$ (factor of $40/5 = 8$ lower gradient noise) outweighs
the iteration-count disadvantage (8$\times$ fewer updates per epoch).  For a quadratic
loss, the optimal batch size balances $b$ (updates/epoch) against $1/\sqrt{b}$ (gradient
noise reduction), giving $b^{\star} \propto \sqrt{m}$ under some conditions.  With $m=1000$
and the low noise level here, the small-batch regime ($b=5$) dominates because gradient
variance is low relative to the step size.
\end{remark}

\subsection{Q2 Conclusion and Transition to Second-Order Methods}

Nesterov acceleration achieves the theoretical optimum among first-order methods for convex
$L$-smooth functions, with convergence $O(1/k^2)$ vs GD's $O(1/k)$ and a factor of
$\sqrt{\kappa}$ improvement in the linear rate for strongly convex problems.  Despite this,
even Nesterov achieves only $f \approx 0.479$ on Rosenbrock after 150 iterations, with the
true minimum $f^{\star} = 0$ still far away.  The fundamental barrier is the first-order
oracle: no first-order method can do better than $O(1/\sqrt{\kappa})$ convergence factor
per step for $\mu$-strongly convex functions (Nesterov lower bound).

This motivates \textbf{second-order methods} (Section~\ref{sec:q3}), which access the
Hessian $\nabla^2 f$ and can achieve quadratic convergence near $x^{\star}$, completely
bypassing the condition number bottleneck.  The price is $O(d^3)$ per step rather than
$O(d)$, which for $d = 2$ (our benchmarks) is negligible but becomes decisive at scale.

\subsection{Local Polynomial Approximations of $g(x) = x^4$}
\label{sec:q3_local}

The Taylor expansion of $g(x) = x^4$ about $x_0 = 0.25$ motivates Newton's method.
Computing derivatives: $g(x_0) = 0.25^4 = 0.00390625$, $g'(x_0) = 4(0.25)^3 = 0.0625$,
$g''(x_0) = 12(0.25)^2 = 0.75$.

\textbf{First-order (linear) approximation:}
\begin{equation}
T_1(x) = g(x_0) + g'(x_0)(x - x_0) = 0.003906 + 0.0625(x - 0.25).
\end{equation}
The minimum of $T_1$ is unbounded (a line cannot be minimised), showing that first-order
information alone does not define a Newton step.

\textbf{Second-order (quadratic) approximation:}
\begin{equation}
T_2(x) = g(x_0) + g'(x_0)(x - x_0) + \tfrac{1}{2}g''(x_0)(x-x_0)^2
        = 0.003906 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{equation}
Setting $T_2'(x) = 0$ gives the \textbf{Newton update}:
\begin{equation}
x_{\text{Newton}} = x_0 - \frac{g'(x_0)}{g''(x_0)} = 0.25 - \frac{0.0625}{0.75} = 0.25 - 0.0\overline{8} \approx 0.1667.
\end{equation}
In the multivariable case this generalises to $x_{k+1} = x_k - \alpha [\nabla^2 f(x_k)]^{-1} \nabla f(x_k)$.

\begin{figure}[H]
\centering
\includegraphics[width=0.88\textwidth]{figures/q3_approximation.pdf}
\caption{Q3: Local approximations of $g(x) = x^4$ at $x_0 = 0.25$.  The first-order
approximation (blue dashed line) captures only the local slope; it is tangent at $x_0$

\end{figure}

\subsection{Newton's Method}
\label{sec:q3_newton}

\begin{algorithm}[H]
\caption{Newton's Method with Hessian Damping}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Tikhonov-regularised Hessian ensures positive definiteness}
    \State $p_k \gets H_k^{-1}\, g_k$ \Comment{Newton direction: solves $H_k p_k = g_k$}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$
\EndFor
\end{algorithmic}
\end{algorithm}

The Newton direction $p_k = H_k^{-1} g_k$ minimises the local quadratic model of $f$ around
$x_k$.  Viewed differently, Newton's method is \emph{gradient descent with a per-coordinate
step derived from the Hessian}: the update $x_{k+1} = x_k - \alpha H_k^{-1} g_k$ applies
a different scaling to each gradient component, determined by the local curvature.  When
$H_k$ is diagonal (as for Benchmark~B near $x^{\star}$), Newton's update is
$\Delta x_i = -\alpha g_i / H_{ii}$, exactly analogous to Adam's $\Delta x_i = -\alpha \hat{m}_i /
\sqrt{\hat{v}_i}$ --- but with the true diagonal curvature $H_{ii}$ rather than an
exponentially-smoothed estimate $\sqrt{\hat{v}_i} \approx \sqrt{H_{ii}^2}$.
Near the minimiser, Newton's method exhibits \textbf{quadratic convergence}:
\begin{equation}
\|x_{k+1} - x^{\star}\| \leq C\|x_k - x^{\star}\|^2,
\end{equation}
meaning the number of correct decimal digits roughly doubles per iteration --- converging
from $10^{-2}$ error to $10^{-4}$, then $10^{-8}$, then $10^{-16}$ (machine precision)
in just three additional steps.

The \textbf{Newton decrement} $\lambda(x_k) = \sqrt{g_k^T H_k^{-1} g_k}$ satisfies
$f(x_k) - f(x_{k+1}^{\mathrm{Newton}}) \approx \frac{1}{2}\lambda(x_k)^2$ (the predicted
decrease in the quadratic model), and provides a natural stopping criterion:
halt when $\lambda(x_k)^2/2 < \varepsilon$.

The damping $\lambda_{\mathrm{damp}} = 10^{-8}$ ensures $H_k + \lambda_{\mathrm{damp}} I \succ 0$
even when $\nabla^2 f(x_k)$ is indefinite or near-singular (which can occur on Rosenbrock
away from the minimum, where the Hessian has a near-zero eigenvalue along the valley).

\begin{remark}[Practical Newton variants]
The \textbf{trust region} approach replaces the fixed damped step $\alpha < 1$ with an
adaptive step that expands when the quadratic model accurately predicts the actual
decrease and contracts when it does not.  This provides more principled control than
a fixed $\alpha$.
\textbf{L-BFGS} (Limited-memory BFGS) avoids computing the Hessian entirely by building
a rank-$m$ approximation from the last $m$ gradient difference pairs
$\{(s_k = x_{k+1} - x_k, y_k = g_{k+1} - g_k)\}_{k}$.  For moderate-scale problems
($d$ up to $\sim 10^6$), L-BFGS is the default second-order method (used by
\texttt{scipy.optimize} and \texttt{sklearn}'s L-BFGS solver).
\end{remark}

\subsection{Part~A: Finite Difference Approximation and Nesterov Random Search}

\subsubsection{Finite-Difference Gradient Approximation}

The forward finite-difference formula approximates each partial derivative:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta},
\end{equation}
where $e_i$ is the $i$-th standard basis vector.  The approximation error has two competing components:
\begin{itemize}[nosep]
\item \textbf{Truncation error}: $\bigl|\frac{f(x+\delta e_i) - f(x)}{\delta} - \frac{\partial f}{\partial x_i}(x)\bigr|
      = O(\delta \|f''\|)$ from higher-order Taylor terms ($f(x+\delta e_i) = f(x) + \delta
      \partial_{x_i} f + \frac{\delta^2}{2}\partial_{x_i}^2 f + \cdots$).
\item \textbf{Floating-point error}: $O(\varepsilon_{\text{mach}}\,|f|/\delta)$ because
      $f(x+\delta e_i)$ is computed with relative error $\varepsilon_{\text{mach}} \approx
      2.2 \times 10^{-16}$; the $1/\delta$ factor amplifies round-off when $\delta$ is small.
\end{itemize}
Balancing both components: $\delta \|f''\| \sim \varepsilon_{\text{mach}} |f| / \delta$ gives
$\delta^{\star} = \sqrt{\varepsilon_{\text{mach}} |f| / \|f''\|} \approx \sqrt{\varepsilon_{\text{mach}}} \approx
10^{-8}$.  The \emph{central difference} formula ($[f(x+\delta e_i) - f(x-\delta e_i)]/(2\delta)$)
achieves $O(\delta^2)$ truncation error with $\delta^{\star} \approx \varepsilon_{\text{mach}}^{1/3}
\approx 10^{-5.3}$, offering better accuracy for the same $\delta$.

The assignment uses $\delta = 0.05$ (acceptable; truncation-dominated but gradient direction
accurate) and $\delta = 0.8$ (poor; step $\delta = 0.8$ is much larger than the lengthscale
of gradient variation near the minimum, so the approximated direction is qualitatively wrong).

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search (Zeroth-Order)}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Draw $u_k \sim \mathcal{N}(0, I_d)$; normalise $u_k \gets u_k / \|u_k\|$ (random unit vector)
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta u_k) - f(x_k)}{\delta}\, u_k$ \Comment{Directional derivative estimate}
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

This zeroth-order method requires only \emph{two function evaluations per iteration},
regardless of dimension.  The estimate $\hat{g}_k$ is an unbiased estimator of the
directional derivative in direction $u_k$, but not of the full gradient.  Its convergence
rate is therefore much slower: $O(d/\sqrt{k})$ for convex functions compared to $O(1/k)$
for exact GD.  On Benchmark~B ($d = 2$), this limitation is less severe, but oscillations
persist throughout.

\subsection{Part~B: Derivative-Free Methods on Benchmark~C}

\subsubsection{Nelder--Mead Simplex Method}

The Nelder--Mead algorithm maintains a simplex of $n+1 = 3$ vertices in $\mathbb{R}^2$ and
iteratively transforms it through four geometric operations:
\begin{enumerate}[nosep]
\item \textbf{Reflection} ($\alpha_r = 1.0$): move the worst vertex through the centroid of
      the remaining vertices.
\item \textbf{Expansion} ($\gamma = 2.0$): if reflection succeeded, try extending further.
\item \textbf{Outside contraction} ($\rho = 0.5$): if reflection was worse, contract outside
      the centroid.
\item \textbf{Inside contraction / Shrink} ($\sigma = 0.5$): if all else fails, contract the
      entire simplex towards the best vertex.
\end{enumerate}
No gradient information is required.  Initial simplex step: $0.35$; iterations: $160$.

\begin{remark}[Nelder--Mead theoretical properties]
Unlike gradient-based methods, Nelder--Mead has \emph{no general convergence guarantee}
in $\mathbb{R}^d$ for $d \geq 2$.  It can converge to non-stationary points or stagnate
if the simplex degenerates.  Empirically, however, it performs well on smooth low-dimensional
problems ($d \leq 10$) and is widely used in practice (e.g., SciPy's \texttt{fmin}).
On Rosenbrock, the simplex's ability to \emph{rotate and elongate} to align with the valley
floor allows effective progress without gradient computation --- a key advantage over finite
differences when the function landscape has strong directional structure not aligned with
coordinate axes.
\end{remark}

\subsubsection{Grid Search}

Grid search evaluates the objective on a uniform $55 \times 55 = 3{,}025$ grid over
$x_1 \in [-2, 2]$, $x_2 \in [-1, 3]$.  The grid spacing is:
\begin{equation}
\Delta x_1 = \frac{4}{54} \approx 0.0741, \qquad \Delta x_2 = \frac{4}{54} \approx 0.0741.
\end{equation}
The best grid point is $(1.037,\, 1.074)$ with $f = 0.00156$, located $\|x_{\mathrm{best}} -
x^{\star}\| \approx 0.083$ from the true minimum $(1,1)$, consistent with the grid
resolution $\sqrt{2} \cdot \Delta x \approx 0.105$.

\begin{remark}[Grid search and the curse of dimensionality]
Grid search achieves accuracy $\|\hat{x} - x^{\star}\|_\infty \leq \Delta x/2$ at a
cost of $N^d$ function evaluations, where $N$ points per dimension and $\Delta x = \text{range}/N$.
To achieve the same $\Delta x \approx 0.074$ accuracy in $d = 10$ dimensions would require
$55^{10} \approx 2.5 \times 10^{17}$ evaluations --- infeasible.  For $d \geq 4$, grid
search becomes impractical for any reasonable accuracy; random search or quasi-random
(Sobol/Halton) designs provide $O(N^{-1/d})$ accuracy with much smaller $N$.
\end{remark}

\subsection{Problem Setup and Methods}

Minimise Benchmark~B subject to $x_1 \geq 0.5$, starting from the infeasible point
$x_0 = (0.2, 4.0)$.  The unconstrained minimum of $f$ is at $(0.582, 2.0)$, which already
satisfies $x_1 = 0.582 > 0.5$, so the constraint is \emph{inactive} at the solution.
Nonetheless, starting from an infeasible point tests how quickly each method restores
feasibility.

\begin{algorithm}[H]
\caption{Projected Gradient Descent}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, projection $\Pi_{\mathcal{C}}$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Unconstrained gradient step}
    \State $x_{k+1} \gets \Pi_{\mathcal{C}}(z_{k+1})$ \Comment{Project: $x_1 \leftarrow \max(0.5,\, x_1)$}
\EndFor
\end{algorithmic}
\end{algorithm}

The projection onto $\mathcal{C} = \{x: x_1 \geq 0.5\}$ is simply $\Pi_{\mathcal{C}}(z) =
(\max(0.5, z_1), z_2)$, computable in $O(1)$.

\begin{proposition}[Projected GD convergence]
For a $\mu$-strongly convex, $L$-smooth function $f$ with minimiser $x^{\star} \in \mathcal{C}$,
projected gradient descent with step $\alpha \leq 1/L$ satisfies:
\begin{equation}
\|x_{k+1} - x^{\star}\|^2 \leq (1 - \mu\alpha)\|x_k - x^{\star}\|^2,
\end{equation}
the same linear rate as unconstrained GD.  When the constraint is inactive at $x^{\star}$
(as in Q5 where $x_1^{\star} = 0.582 > 0.5$), the projection becomes inactive after a
finite number of iterations and the algorithm behaves identically to unconstrained GD.
\end{proposition}

\begin{remark}[FISTA: Nesterov acceleration for PGD]
Nesterov acceleration extends naturally to projected gradient descent as the
\textbf{FISTA} (Fast Iterative Shrinkage-Thresholding Algorithm) update:
\begin{equation}
\tilde{x}_k = x_k + \tfrac{k-1}{k+2}(x_k - x_{k-1}), \qquad
x_{k+1} = \Pi_{\mathcal{C}}(\tilde{x}_k - \alpha \nabla f(\tilde{x}_k)),
\end{equation}
achieving $O(1/k^2)$ convergence for the constrained problem.  By contrast, no clean
Nesterov extension exists for Adam or RMSprop in the projected gradient framework.
\end{remark}

\begin{algorithm}[H]
\caption{Penalty Method (Gradient Descent on Penalised Objective)}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, penalty weight $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $F_{\lambda}(x) \gets f(x) + \lambda \max(0,\, -x_1 + 0.5)$ \Comment{Penalised objective}
    \State Compute $\nabla F_{\lambda}(x_k)$: gradient of $f$ plus $-\lambda \cdot \mathbf{1}[x_1 < 0.5]\cdot e_1$
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_{\lambda}(x_k)$
\EndFor
\end{algorithmic}
\end{algorithm}

The penalty method replaces the hard constraint with a soft penalty term, trading exact
feasibility for a simpler unconstrained update.  As $\lambda \to \infty$ the penalised
minimiser $x^{\star}(\lambda)$ converges to the constrained minimiser $x^{\star}_c$, with
\begin{equation}
\|x^{\star}(\lambda) - x^{\star}_c\| = O(1/\lambda).
\end{equation}
However, large $\lambda$ makes the penalised objective increasingly ill-conditioned: the
effective condition number of $F_\lambda$ near the constraint boundary scales as
$\kappa(F_\lambda) \sim 1 + \lambda/\mu_f$, requiring proportionally smaller step sizes
for stability (here $\alpha = 0.03$ for $\lambda = 4.5$, vs $\alpha = 0.05$ for $\lambda = 1.8$).
This fundamental tension in exact penalty methods motivates the \textbf{augmented Lagrangian}
approach (not implemented here), which adds a Lagrange multiplier estimate to avoid the
ill-conditioning while maintaining convergence to the exact constrained minimiser.

\textbf{Parameter settings:} Projected GD ($\alpha = 0.08$); Penalty with $\lambda \in
\{0.15, 1.8, 4.5\}$ ($\alpha = 0.05$ for $\lambda \leq 1.8$, $\alpha = 0.03$ for $\lambda
= 4.5$); Unconstrained GD ($\alpha = 0.07$).  All run for 100 iterations.

\begin{itemize}[nosep, leftmargin=*]
\item \textbf{Projected GD} enforces feasibility exactly from the first iteration.  This is
      the principal advantage of projection: constraints become hard invariants.  The cost
      is requiring a tractable projection oracle; for $\mathcal{C} = \{x_1 \geq 0.5\}$ this
      is trivial ($\max$ operation), but general convex sets may require solving a quadratic
      programme at each step.

\item \textbf{Penalty methods} approximate feasibility via the objective gradient, requiring
      no separate projection but at the cost of inexact constraint satisfaction.  The trade-off
      between $\lambda$ (feasibility enforcement strength) and $\alpha$ (step size) is
      fundamental: large $\lambda$ enforces feasibility faster but requires proportionally
      smaller $\alpha$ for stability, so the net convergence speed gain diminishes.

\item \textbf{Key insight:} In this problem the unconstrained minimum already lies in the
      feasible set, so all methods eventually find the same solution.  In problems where the
      constrained optimum is on the boundary, projected GD would maintain feasibility
      throughout while navigating along the boundary, whereas penalty methods would converge
      to a nearby interior point (which approaches the constrained optimum as $\lambda \to
      \infty$).

\item \textbf{Alternative: change of variables.} The constraint $x_1 \geq 0.5$ can be
      eliminated via the substitution $x_1 = 0.5 + e^{z_1}$ (always $\geq 0.5$) and
      running unconstrained GD on $(z_1, x_2)$.  This avoids the projection oracle entirely.
      However, the transformation changes the Hessian structure and can worsen the condition
      number (the Jacobian of the map $z_1 \mapsto e^{z_1}$ introduces coordinate-dependent
      scaling).  For simple constraints like half-spaces, projection is generally preferable.
\end{itemize}

\subsection{Feasible Set and Linear Programme}

Feasible set: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\; -5 \leq
x_2 \leq 10\}$ (a compact box polytope with 4 vertices).

\textbf{Linear Programme:} Minimise $f(x) = a^T x$ with $a = [1, 2]^T$ over $\mathcal{X}$.
Since $f$ is linear, its minimum over a compact convex set is attained at an \emph{extreme
point} (vertex) of $\mathcal{X}$.  Since both components of $a$ are positive, minimising
$f$ means choosing the smallest feasible values of both coordinates:
\begin{equation}
x^{\star} = (0.5,\; -5), \qquad f^{\star} = 1 \cdot 0.5 + 2 \cdot (-5) = -9.5.
\end{equation}
This illustrates the \textbf{fundamental theorem of linear programming}: the optimal
solution of any LP over a bounded polytope is attained at a vertex.

\centering
\includegraphics[width=0.88\textwidth]{figures/q6_lp.pdf}
\caption{Q6-I: Feasible region $\mathcal{X}$ (blue box) and linear objective contours
$f(x) = x_1 + 2x_2 = c$.  The contour lines are parallel (slope $-1/2$); moving in the
direction of decreasing $c$ (south-west) exits the feasible region at the lower-left
corner $(0.5, -5)$.  The optimal value $f^{\star} = -9.5$ is attained exclusively at this
vertex.  This geometric picture motivates why the Frank--Wolfe linear oracle always returns
a vertex of $\mathcal{X}$.}
\label{fig:q6_lp}
\end{figure}

\subsection{Frank--Wolfe Algorithm}

\begin{algorithm}[H]
\caption{Frank--Wolfe (Conditional Gradient)}
\label{alg:fw}
\begin{algorithmic}[1]
\Require Initial point $x_0 \in \mathcal{X}$, mixing parameter $\beta \in (0,1)$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_k \gets \arg\min_{x \in \mathcal{X}}\, \nabla f(x_k)^T x$ \Comment{Linear minimisation oracle (LMO)}
    \State $x_{k+1} \gets \beta\, x_k + (1 - \beta)\, z_k$ \Comment{Convex combination: stays in $\mathcal{X}$}
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{proposition}[Frank--Wolfe convergence]
For a convex $L$-smooth function on a compact set with diameter $D$, Frank--Wolfe satisfies
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2LD^2}{k+2},
\end{equation}
an $O(1/k)$ rate.  This is slower than projected gradient descent's $O(1/k^2)$ (Nesterov)
but requires only a linear oracle rather than a projection oracle.
\end{proposition}

For box constraints $\mathcal{X}$, the LMO decomposes per coordinate:
\begin{equation}
(z_k)_i = \begin{cases} \ell_i & \text{if } [\nabla f(x_k)]_i > 0, \\ u_i & \text{if } [\nabla f(x_k)]_i \leq 0, \end{cases}
\end{equation}
where $[\ell_i, u_i] = [0.5, 5]$ for $i=1$ and $[-5, 10]$ for $i=2$.  This selects the
vertex of $\mathcal{X}$ that most decreases the linear model, computable in $O(d)$ time.
Crucially, $x_{k+1} = \beta x_k + (1-\beta) z_k$ is a convex combination of two points
in $\mathcal{X}$, guaranteeing \emph{iterates remain feasible without any projection step}.

\subsection{Interior Optimum: $f(x) = (x_1 - 1)^2 + (x_2 - 5)^2$}
\label{sec:q6_interior}

The unconstrained minimum $(1, 5)$ lies strictly inside $\mathcal{X}$ (since $0.5 < 1 < 5$
and $-5 < 5 < 10$).

\subsection{Frank--Wolfe Gap and Primal-Dual Certificate}

A key advantage of Frank--Wolfe is the availability of a \textbf{primal duality gap} as a
convergence certificate.  At each iteration, the Frank--Wolfe gap is:
\begin{equation}
g_k = \nabla f(x_k)^T (x_k - z_k) = \max_{v \in \mathcal{X}} \nabla f(x_k)^T (x_k - v) \geq f(x_k) - f^{\star},
\end{equation}
since $z_k$ is the LP minimiser.  Thus $g_k \geq 0$ is an upper bound on the suboptimality
gap, computable at each iteration \emph{without knowledge of $f^{\star}$}.  When $g_k < \varepsilon$,
we are guaranteed $f(x_k) - f^{\star} \leq \varepsilon$.

For the interior case at the final iterate $x_{180} \approx (0.997, 5.067)$ with $\beta = 0.985$:
$\nabla f(x_{180}) = (2(0.997-1), 2(5.067-5)) \approx (-0.006, 0.134)$.  The LMO selects
$z = (5, -5)$ (since $[\nabla f]_1 < 0 \to z_1 = u_1 = 5$, $[\nabla f]_2 > 0 \to z_2 = \ell_2 = -5$).
The gap is $g_{180} = (-0.006)(0.997-5) + (0.134)(5.067-(-5)) \approx 0.024 + 1.350 = 1.374$,
confirming that $f(x_{180}) - f^{\star} = 0.0046 \leq g_{180} = 1.374$ (the gap is loose because
the LP solution $z$ is far from $x_{180}$ in the $x_2$ direction, due to the oscillation of $z_2$).
This certificate is not available for projected gradient descent or penalty methods,
making Frank--Wolfe particularly attractive for certifying solution quality in practice.

\subsection{Interior vs Boundary Behaviour: Key Differences}

\begin{itemize}[nosep, leftmargin=*]
\item \textbf{Interior optimum:} Frank--Wolfe converges at an $O(1/k)$ rate, and the LP
      oracle oscillates between vertices as the iterate crosses the optimum.  The ``zig-zag''
      near the interior minimum is a known fundamental limitation of Frank--Wolfe; it arises
      because the LP oracle can only return extreme points of $\mathcal{X}$, not the interior
      optimum itself.  The fixed $\beta$ schedule (constant step fraction) means this
      oscillation persists.  Using a diminishing step schedule $\gamma_k = 2/(k+2)$ would
      guarantee the optimal $O(1/k)$ convergence rate to the interior minimum.

\item \textbf{Boundary optimum:} Frank--Wolfe is \emph{better suited} to boundary optima
      because the LP oracle naturally selects the vertex closest to the constrained minimiser.
      The iterate approaches the boundary monotonically in $x_1$ (since $z_1 = 0.5$ at
      every step), without any need for projection.  However, the $x_2$ component still
      exhibits oscillation because $z_2$ alternates between $\pm 5$ as $x_2$ approaches 0.
      Despite residual oscillation, the boundary case exemplifies Frank--Wolfe's main
      advantage: \emph{constraint satisfaction without a projection oracle}.

\item \textbf{Comparison with projected GD:} Projected GD on the same problem would
      converge at $O(1/k^2)$ (Nesterov) or $O(1/k)$ (standard), faster than Frank--Wolfe
      but requiring the projection operator.  Frank--Wolfe's advantage is its \emph{linear
      oracle}, which is computationally cheaper for complex constraint sets (e.g., nuclear
      norm balls, flow polytopes) where projection is hard but linear minimisation is easy.
\end{itemize}

\paragraph{Overall observations:}
\begin{enumerate}[nosep, leftmargin=*]
\item \textbf{Rosenbrock is the discriminating benchmark.} On Benchmarks~A and~B all
      first-order methods (except Polyak with wrong $f^{\star}$) converge to the true minimum;
      the differences are only in speed.  On Rosenbrock ($\kappa \approx 2508$), the
      advantage of accelerated methods is dramatic: Nesterov ($f = 0.479$) vs GD ($f = 3.51$)
      after 150 iterations represents a 7$\times$ improvement in objective value.
      The theoretical halving times --- approximately 1738 iterations for GD vs 34 for
      Nesterov acceleration --- explain why 150 iterations produces such a large gap.

\item \textbf{Second-order information is transformative.} Newton's method on Benchmark~A
      converges in \emph{one} step; this is impossible for any first-order method.  On
      Rosenbrock with only 20 iterations, Newton achieves $f = 0.686$ vs GD's $f = 3.73$
      in 80 iterations.  The cost is $O(d^2)$ per step for the Hessian and $O(d^3)$ for the
      linear solve, which becomes prohibitive for large $d$.

\item \textbf{Correct $f^{\star}$ knowledge gives the best rate.} The Polyak step with
      exact $f^{\star} = 0$ on Rosenbrock achieves $f = 0.009$ in 120 iterations, better than
      all other first-order methods with more iterations.  This highlights the power of
      problem-specific information, but also the brittleness: misspecification causes
      divergence.

\item \textbf{Constraint handling methods:} Projected GD achieves exact feasibility
      immediately.  Frank--Wolfe (Q6) maintains feasibility automatically through convex
      combinations without a projection oracle.  Penalty methods offer a simpler
      implementation but require careful $\lambda$ tuning and never exactly satisfy
      constraints at finite $\lambda$.

\item \textbf{Information hierarchy governs algorithm power.} Across all methods, the
      ordering of information access is:
      \[
      \underbrace{f^{\star}}_{\text{Polyak}} \succ
      \underbrace{\nabla^2 f}_{\text{Newton}} \succ
      \underbrace{\nabla f}_{\text{GD/Nesterov}} \succ
      \underbrace{f \text{ only}}_{\text{Nelder--Mead, Grid}}.
      \]
      Each level of additional information enables a qualitatively better convergence rate:
      $O(1/k)$ (Polyak) vs $O((1-1/\sqrt{\kappa})^k)$ (Nesterov) vs $O((1-1/\kappa)^k)$ (GD)
      vs $O(d/\sqrt{k})$ (random search).  The experiment consistently confirms this hierarchy:
      methods with more information converge faster on all benchmarks, with the gap most
      pronounced on the ill-conditioned Rosenbrock.

\item \textbf{Practical takeaways.} For well-conditioned convex problems (Benchmark~A,
      $\kappa < 2$), any method works quickly; the choice is largely irrelevant beyond
      avoiding implementation bugs.  For moderately ill-conditioned problems (Benchmark~B,
      $\kappa \approx 7$), adaptive methods (Adam, RMSprop) help but all first-order methods
      converge.  For highly ill-conditioned or nonconvex problems (Benchmark~C, $\kappa \approx
      2508$), the choice of method is decisive: Newton or Polyak (with correct $f^{\star}$)
      are preferable; among first-order methods, Nesterov acceleration is the clear winner.
\end{enumerate}

def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        x = x - alpha * grad_fn(x)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Polyak Step Size}]
def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adagrad}]
def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float)
    G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={RMSprop}]
def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float)
    v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Heavy Ball / Polyak Momentum}]
def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x)
        z = beta * z + alpha * g
        x = x - z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)

\begin{lstlisting}[caption={Nesterov Acceleration}]
def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z       # evaluate gradient at lookahead point
        g = grad_fn(lookahead)
        z = beta_k * z - alpha * g
        x = x + z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adam Optimiser}]
def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t)      # bias correction
        v_hat = v_vec / (1 - beta2**t)
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Newton's Method with Damped Hessian}]
def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))   # Tikhonov regularisation
        try:
            p = np.linalg.solve(H_reg, g)       # Newton direction
        except np.linalg.LinAlgError:
            p = g
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)
\end{lstlisting}

\begin{lstlisting}[caption={Frank--Wolfe with Box Linear Oracle}]
def frank_wolfe(grad_fn, loss_fn, x0, bounds, beta, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, z_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        # Box LMO: select vertex minimising g^T z over the box
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z    # convex combination
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
\end{lstlisting}
