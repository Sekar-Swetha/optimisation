\begin{abstract}
This report evaluates optimisation algorithms across six categories on three benchmark problems designed to span the difficulty spectrum: a convex quadratic linear regression loss (Benchmark~A, $\kappa \approx 1.12$, near-isotropic), a mildly non-convex toy neural network objective with sinusoidal perturbation (Benchmark~B, $\kappa \approx 3.5$--$6.9$), and the highly ill-conditioned Rosenbrock function (Benchmark~C, $\kappa \approx 2508$), whose narrow curved valley challenges all first-order methods.

The central finding is that the condition number $\kappa = L/\mu$ is the single most important determinant of algorithm performance: methods that are indistinguishable on Benchmark~A diverge by two orders of magnitude on Benchmark~C. Among adaptive step-size methods (Q1), Polyak achieves the best Rosenbrock convergence ($f = 0.0094$) when $f^{\star}$ is correctly specified, but diverges catastrophically on benchmarks where $f^{\star}$ is misspecified. Among momentum methods (Q2), Nesterov's $O(1/k^2)$ rate achieves $f = 0.479$ on Rosenbrock --- a $7\times$ improvement over gradient descent's $f = 3.39$ --- but since Rosenbrock is non-convex, the convex bound $2L\|x_0-x^{\star}\|^2/(k+1)^2 \approx 0.352$ is not guaranteed to hold. Newton's method (Q3) converges in a single iteration on the quadratic loss (Benchmark~A) and reaches $f = 0.0005$ on Rosenbrock in 50 iterations via quadratic convergence. Among derivative-free methods (Q4), Nelder--Mead achieves machine precision ($f \approx 10^{-9}$) on Rosenbrock by adapting its simplex to the valley geometry --- surpassing all gradient methods tested. For the constrained problem (Q5), the constraint $x_1 \geq 0.5$ is inactive at the unconstrained minimum ($x_1^{\star} \approx 0.582$), so all methods converge to the same feasible optimum and the comparison highlights trajectory behaviour. The Frank--Wolfe algorithm (Q6) maintains feasibility by construction through an $O(d)$ LP oracle, at the cost of a slower $O(1/k)$ convergence rate.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% ============================================================

Optimisation is the mathematical backbone of modern machine learning: training neural networks, fitting regression models, and solving constrained resource allocation problems all reduce to minimising or maximising an objective function. The choice of algorithm significantly impacts convergence speed, computational cost, and whether the method finds a good solution at all.

The fundamental challenge is balancing three competing demands: \emph{per-iteration cost} (computation per step), \emph{convergence rate} (how quickly the error decreases), and \emph{robustness} (convergence under realistic conditions). Gradient descent, the simplest first-order method, is cheap per iteration but slow on ill-conditioned problems. Second-order methods (Newton) converge quadratically but require computing and inverting the $d \times d$ Hessian matrix. Adaptive methods (Adagrad, Adam) lie between these extremes, using gradient history to approximate curvature at $O(d)$ cost. The condition number $\kappa = L/\mu$ (Definition~\ref{def:smooth_sc}) quantifies this difficulty: GD requires $O(\kappa)$ iterations while Nesterov's accelerated method requires only $O(\sqrt{\kappa})$, a $44.7\times$ speedup at $\kappa = 2000$.

This report systematically evaluates algorithms across the six major categories studied in CS7DS2. The three benchmarks span the full difficulty spectrum: Benchmark~A (linear regression, $\kappa \approx 1.12$) is the canonical convex quadratic where all methods perform well; Benchmark~B (toy neural network, $\kappa \approx 3.5$--$6.9$) introduces mild non-convexity; and Benchmark~C (Rosenbrock, $\kappa \approx 2508$) is the main discriminator --- a non-convex function whose narrow curved valley defeats algorithms that do not exploit curvature information, with methods spanning two orders of magnitude in final objective value (Table~\ref{tab:full_comparison}).

All experiments use Python/NumPy with a fixed random seed (\texttt{np.random.seed(42)}) for reproducibility. Complete source code is in \texttt{CS7DS2\_Final\_Code\_25336453.py}.

\section{Benchmark Problems and Experimental Setup}
\label{sec:benchmarks}
% ============================================================

All experiments use a fixed random seed (\texttt{np.random.seed(42)}) for reproducibility. The three benchmark functions and a constrained feasible set are defined as follows.

\subsection{Benchmark A: Linear Regression Quadratic Loss}
A synthetic dataset with $m = 1000$ samples and two parameters is generated:
\begin{equation}
\theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \quad x^{(i)} \sim \mathcal{N}(0, I_2), \quad y^{(i)} = \theta^{\star T} x^{(i)} + \varepsilon^{(i)}, \quad \varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The loss function is the mean squared error:
\begin{equation}
J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left(\theta^T x^{(i)} - y^{(i)}\right)^2 = \frac{1}{2m}\|X\theta - y\|^2.
\end{equation}
This is a strongly convex quadratic with constant Hessian $H = \frac{1}{m}X^T X \succ 0$ and gradient $\nabla J(\theta) = \frac{1}{m}X^T(X\theta - y)$. The OLS solution found numerically is $\theta^{\star}_{\text{OLS}} \approx (3.028, 4.017)^T$, deviating slightly from $\theta^{\star}$ due to the finite sample and noise. The condition number of $H$ is $\kappa(H) = \lambda_{\max}/\lambda_{\min} \approx 1.033/0.925 \approx 1.12$: the Hessian is near-isotropic because $X \sim \mathcal{N}(0, I_2)$ and $m = 1000 \gg d = 2$, so $H \approx I_2$ by the law of large numbers. This makes Benchmark~A extremely easy to optimise. The irreducible noise floor is $J^{\star} \approx 0.4826$. Starting point: $\theta_0 = [0, 0]^T$.

\subsection{Benchmark B: Toy Neural Network Loss}
\begin{equation}
\label{eq:bench_b}
f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
\end{equation}
The gradient is $\nabla f = [2(x_1 - 1) + \cos(x_1),\ 10(x_2 - 2)]^T$ and the Hessian is $H(x) = \operatorname{diag}(2 - \sin(x_1),\ 10)$. The sinusoidal term makes this non-convex: $H_{11} = 2 - \sin(x_1) \in [1, 3]$, so $H$ is positive definite but curvature varies. The minimiser in $x_2$ is $x_2^{\star} = 2$, and $x_1^{\star}$ solves the transcendental equation $2(x_1 - 1) + \cos(x_1) = 0$, yielding $x_1^{\star} \approx 0.582$. The minimum value is $f^{\star} \approx 0.7244$. The condition number varies spatially: at the minimum $\kappa \approx 10/(2 - \sin(0.582)) \approx 6.9$; at the starting point $x_0 = (-1,4)$: $H_{11} = 2 - \sin(-1) \approx 2.841$, so $\kappa \approx 10/2.841 \approx 3.5$. The range $\kappa \approx 3.5$--$6.9$ produces moderate anisotropy. Starting point: $x_0 = [-1, 4]^T$.

\subsection{Benchmark C: Rosenbrock Function}
\begin{equation}
\label{eq:rosenbrock}
f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
\end{equation}
The global minimum is at $(1, 1)$ with $f^{\star} = 0$. The Hessian at the optimum is
\begin{equation}
H(1,1) = \begin{bmatrix} 802 & -400 \\ -400 & 200 \end{bmatrix},
\end{equation}
with $\operatorname{tr}(H) = 1002$ and $\det(H) = 802 \times 200 - (-400)^2 = 400$. The eigenvalues are
\begin{equation}
\lambda = \frac{1002 \pm \sqrt{1002^2 - 4 \times 400}}{2} = \frac{1002 \pm \sqrt{1{,}002{,}404}}{2} \approx \frac{1002 \pm 1001.20}{2},
\end{equation}
giving $\lambda_{\max} \approx 1001.6$ and $\lambda_{\min} \approx 0.40$, hence $\kappa = \lambda_{\max}/\lambda_{\min} \approx 2508$ --- extreme ill-conditioning. This creates a narrow curved valley along $x_2 \approx x_1^2$. Notably, $\kappa$ is the same at $x_0 = (-1,1)$: the trace and determinant of $H$ are invariant under sign change of $x_1$, since $h_{11} = 2 + 1200x_1^2 - 400x_2$ and $h_{12} = -400x_1$ enter the determinant only through $h_{12}^2 = 160000$, independent of the sign of $x_1$. Methods that do not account for curvature must use tiny step sizes to maintain stability, making progress along the valley extremely slow. Starting point: $x_0 = [-1, 1]^T$.

\section{Question 1: Adaptive Step-Size Methods \hfill [30 marks]}
\label{sec:q1}

\subsection{Background and Motivation}

\begin{definition}[$L$-Smoothness and $\mu$-Strong Convexity]
\label{def:smooth_sc}
A differentiable function $f : \mathbb{R}^d \to \mathbb{R}$ is:
\begin{itemize}[nosep]
\item \textbf{$L$-smooth} if $\|\nabla f(x) - \nabla f(y)\| \leq L\|x - y\|$ for all $x, y$ (equivalently, $\nabla^2 f(x) \preceq LI$ when $f$ is twice differentiable). This ensures that the quadratic upper bound $f(y) \leq f(x) + \nabla f(x)^T(y-x) + \frac{L}{2}\|y-x\|^2$ holds globally.
\item \textbf{$\mu$-strongly convex} if $f(y) \geq f(x) + \nabla f(x)^T(y-x) + \frac{\mu}{2}\|y-x\|^2$ for all $x, y$ (equivalently, $\nabla^2 f(x) \succeq \mu I$). This ensures a unique minimiser and a quadratic lower bound on the objective.
\end{itemize}
The \textbf{condition number} $\kappa = L/\mu$ determines convergence speed: large $\kappa$ means the curvature landscape is very anisotropic, requiring many small steps. For Benchmark~A: $L = \lambda_{\max}(H) \approx 1.033$, $\mu = \lambda_{\min}(H) \approx 0.925$, $\kappa \approx 1.12$. For Benchmark~C at $x_0$: $L \approx 1001.6$, $\mu \approx 0.40$, $\kappa \approx 2508$.
\end{definition}

Gradient descent with a fixed step size $\alpha$ converges at rate $O(L\|x_0 - x^{\star}\|^2 / k)$ for $L$-smooth convex functions, where $\alpha \leq 1/L$ is required for stability (from the $L$-smooth upper bound). For strongly convex functions, the rate is geometric:

\begin{theorem}[Gradient Descent Linear Rate]
\label{thm:gd_linear}
For an $L$-smooth, $\mu$-strongly convex function $f$, gradient descent with $\alpha = 2/(L + \mu)$ satisfies
\begin{equation}
\label{eq:gd_rate}
f(x_k) - f^{\star} \leq \left(\frac{\kappa - 1}{\kappa + 1}\right)^{2k} (f(x_0) - f^{\star}), \quad \kappa = L/\mu.
\end{equation}
The optimal (oracle) rate $\left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^{2k}$ from Nesterov's accelerated method improves the exponent from $O(\kappa)$ to $O(\sqrt{\kappa})$ iterations to $\varepsilon$ accuracy.
\end{theorem}

For $\kappa = 2000$, Eq.~\eqref{eq:gd_rate} gives rate $0.9990^{2k}$: to reach $10^{-6}$ accuracy from $f(x_0) - f^{\star} = 1$, requires $k \approx 27,624$ iterations, versus $k \approx 618$ for Nesterov --- a $44.7\times$ speedup (Figure~\ref{fig:theory_cond}, top-right). However, choosing $\alpha$ requires knowledge of the Lipschitz constant $L$, and a single global step size is suboptimal when coordinates have very different curvatures. Adaptive methods address this by adjusting the effective step size based on observed gradient information.

\subsection{Algorithm Formulations}

Four adaptive methods are compared against a constant step-size gradient descent baseline across all three benchmarks for 120 iterations.

\begin{definition}[Polyak Step Size]
Given a lower bound $f^{\star}$ on the optimal value, the Polyak step size is
\begin{equation}
\label{eq:polyak}
\alpha_k = \frac{f(x_k) - f^{\star}}{\|\nabla f(x_k)\|^2 + \varepsilon},
\end{equation}
where $\varepsilon > 0$ is a small regularisation constant preventing division by zero.
\end{definition}

\begin{theorem}[Polyak Convergence]
\label{thm:polyak}
For an $L$-smooth convex function with $f^{\star}$ known exactly, the Polyak step satisfies
\begin{equation}
\min_{k \leq K} \|\nabla f(x_k)\|^2 \leq \frac{2L(f(x_0) - f^{\star})}{K+1}.
\end{equation}
When $f^{\star}$ is misspecified (e.g., $f^{\star} = 0$ while the true minimum is positive), $\alpha_k \to \infty$ as $\|\nabla f(x_k)\| \to 0$ and $f(x_k) \to f^{\star}_{\text{true}} > 0$, causing divergence.
\end{theorem}

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, optimal value $f^{\star}$, tolerance $\varepsilon$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets (f(x_k) - f^{\star}) / (\|g_k\|^2 + \varepsilon)$
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
\caption{Adagrad}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Cumulative squared gradient sum}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

Adagrad assigns a smaller effective step size to frequently-updated coordinates (large $G_i$) and a larger step to rarely-updated ones, automatically adapting to the local curvature. The effective step for coordinate $i$ is $\alpha_0/\sqrt{\sum_{j=0}^{k} g_{j,i}^2}$, which decays monotonically. This guarantees stability but limits long-term learning --- a limitation that RMSprop addresses.

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponentially-weighted moving average}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

RMSprop replaces Adagrad's cumulative sum with an exponential moving average (decay $\beta = 0.9$), so old squared gradients are ``forgotten'' at rate $(1-\beta)$ per iteration. This allows the effective step size to recover if gradients become small, preventing Adagrad's premature learning rate decay.

\begin{algorithm}[H]
\caption{Heavy Ball (Polyak Momentum)}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$
    \State $x_{k+1} \gets x_k - z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

Heavy Ball maintains a velocity $z_k$ that accumulates gradient directions, allowing the iterate to build momentum in persistent descent directions. For strongly convex quadratics, the optimal parameters
\begin{equation}
\alpha^{\star} = \frac{4}{(\sqrt{L}+\sqrt{\mu})^2}, \quad \beta^{\star} = \left(\frac{\sqrt{L}-\sqrt{\mu}}{\sqrt{L}+\sqrt{\mu}}\right)^2,
\end{equation}
achieve the optimal linear rate $\left(1-\sqrt{\mu/L}\right)^{2k} = \left(\frac{\sqrt{\kappa}-1}{\sqrt{\kappa}+1}\right)^{2k}$, matching Nesterov's accelerated rate on quadratics. For Benchmark~A ($\kappa \approx 1.12$, $L \approx 1.033$, $\mu \approx 0.925$): $\alpha^{\star} \approx 1.02$ and $\beta^{\star} \approx 0.001$, with optimal rate $\approx 0.00076$ per iteration (Figure~\ref{fig:hb_analysis}). In practice, the used step $\alpha = 0.045 \ll \alpha^{\star}$ is much smaller, leading to a suboptimal rate but ensuring stability on all three benchmarks. However, Heavy Ball's convergence guarantee holds \emph{only for quadratic functions} --- on non-convex Rosenbrock, the optimal quadratic parameters may not be stable, and the used parameters $(\alpha=0.0008, \beta=0.86)$ are tuned empirically.

The condition number $\kappa$ of the problem is the primary determinant of method performance. On Benchmark~A ($\kappa \approx 1.12$), all methods converge extremely rapidly: the optimal GD step $\alpha^{\star} = 2/(L+\mu) \approx 1.02$ gives rate $((1.12-1)/(1.12+1))^k = 0.057^k$, reaching $10^{-6}$ accuracy in $\sim 5$ iterations. In practice the step sizes used ($\alpha = 0.06$--$0.08$) are much smaller than optimal, giving a sub-optimal rate $(1-\alpha\mu)^k \approx 0.926^k$ and convergence in $\sim 40$ iterations --- but the low $\kappa$ means even conservative step sizes work well. On Benchmark~C ($\kappa \approx 2508$, $L \approx 1002$, $\mu \approx 0.40$), GD's convergence rate $(1 - 1/\kappa)^k \approx (1 - 1/2508)^k = 0.9996^k$ requires $k \approx \kappa \ln 2 \approx 1738$ iterations just to halve the error, and the stability bound requires $\alpha \leq 2/L \approx 2/1002 \approx 0.002$, leaving essentially no room to exploit the low-curvature valley direction (whose $\lambda_{\min} \approx 0.40$ requires an effective step of $\sim 1/0.40 = 2.5$ to make unit-distance progress, far larger than the stability-limited step). Per-coordinate adaptation (Adagrad, RMSprop) and momentum (Heavy Ball) provide meaningful improvement, but as Figure~\ref{fig:rosenbrock_cond} shows, the condition number worsens along the trajectory, compounding the difficulty.

\begin{remark}[Why Adagrad Helps on Rosenbrock]
On Rosenbrock, the two gradient coordinates have very different magnitudes: the $x_1$-gradient is $\sim 400\times$ larger than the $x_2$-gradient along the valley. Adagrad's per-coordinate accumulation $G_{k,i} = \sum_{j=0}^k g_{j,i}^2$ automatically assigns a smaller effective rate to $x_1$ (large gradient, large $G_{k,1}$) and a larger rate to $x_2$ (small gradient, small $G_{k,2}$), partially compensating for the curvature imbalance. This is the same mechanism that makes Adagrad effective for sparse gradients in NLP.
\end{remark}

\begin{remark}[Why RMSprop Fails to Reach the Noise Floor on Benchmark~A]
On Benchmark~A ($\kappa \approx 1.12$), RMSprop converges to $\approx 0.5027$ (above the noise floor $J^{\star} \approx 0.4826$). The mechanism: the exponential moving average of squared gradients $v_k = 0.9v_{k-1} + 0.1g_k^2$ stabilises at a non-zero value proportional to the squared gradient at the noise floor, giving a non-vanishing effective step size $\alpha_{\mathrm{eff}} = \alpha_0 / \sqrt{v_\infty}$. This persistent step causes continuous oscillation around the minimum, preventing exact convergence. With a decaying base rate $\alpha_0 \to 0$ or learning rate warmup/cooldown, RMSprop would converge to $J^{\star}$. The same effect does not arise for Adagrad because its cumulative sum $G_k \to \infty$ causes $\alpha_{\mathrm{eff}} \to 0$, guaranteeing convergence.
\end{remark}

\subsection{Background}

Nesterov's accelerated gradient method achieves the optimal $O(1/k^2)$ convergence rate for smooth convex minimisation, provably faster than the $O(1/k)$ rate of gradient descent. Adam combines momentum with per-coordinate adaptive scaling, combining the advantages of both Nesterov-style acceleration and RMSprop.

\subsection{Algorithm Formulations}

\begin{algorithm}[H]
\caption{Nesterov Momentum / Acceleration}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\frac{k-1}{k+2},\ \beta_{\max}\right)$ \Comment{Adaptive momentum schedule}
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead point}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{theorem}[Nesterov Acceleration]
\label{thm:nesterov}
For an $L$-smooth convex function $f$ with $f^{\star} = \min f$, the Nesterov method with step $\alpha = 1/L$ and $\beta_k = (k-1)/(k+2)$ satisfies
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2L\|x_0 - x^{\star}\|^2}{(k+1)^2} = O(1/k^2),
\end{equation}
which is optimal (no first-order method can achieve a better worst-case rate for this problem class).
\end{theorem}

The crucial difference from Heavy Ball is that Nesterov evaluates the gradient at the \emph{lookahead point} $\tilde{x}_k = x_k + \beta_k z_k$ rather than the current iterate $x_k$. This look-ahead allows the method to ``correct'' its trajectory before overshooting, providing the $O(1/k^2)$ guarantee absent from Heavy Ball.

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha$, moments $\beta_1, \beta_2$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\ v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{First moment (EMA of gradients)}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{Second moment (EMA of sq.\ grads)}
    \State $\hat{m}_t \gets m_t / (1 - \beta_1^t)$ \Comment{Bias correction (critical for early iters)}
    \State $\hat{v}_t \gets v_t / (1 - \beta_2^t)$
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t / (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

Adam uses $\beta_1 = 0.8$--$0.82$ (momentum) and $\beta_2 = 0.999$ (second-moment decay). The bias corrections in steps 6--7 are critical in early iterations: without correction, $m_1 = (1-\beta_1)g_1$ is biased towards zero, leading to artificially small first steps. The effective per-coordinate step size is $\alpha_i^{\text{eff}}(t) = \alpha / \sqrt{\hat{v}_{t,i} + \varepsilon^2} \cdot \sqrt{(1-\beta_2^t)/(1-\beta_1^t)^2}$, which adapts per-coordinate like RMSprop while also incorporating momentum. Figure~\ref{fig:adaptive_lr} analyses how Adagrad, RMSprop, and Adam adapt their effective step sizes over time on Benchmark~B.

\begin{remark}[Quantitative Effect of Adam Bias Correction]
\label{rem:adam_bias}
At iteration $t = 1$ with $\beta_1 = 0.82$ and $\beta_2 = 0.999$, the biased estimates are $m_1 = (1-\beta_1)g_1 = 0.18\, g_1$ and $v_1 = (1-\beta_2)g_1^2 = 0.001\, g_1^2$. The Adam update without bias correction uses
\begin{equation}
x_2 \gets x_1 - \alpha \frac{m_1}{\sqrt{v_1} + \varepsilon} \approx x_1 - \alpha \frac{0.18\,g_1}{\sqrt{0.001}\,|g_1|} = x_1 - \frac{0.18}{0.0316}\, \alpha\, \text{sign}(g_1),
\end{equation}
giving effective step magnitude $\approx 5.7\alpha$ per coordinate --- nearly $6\times$ the intended learning rate. With bias correction: $\hat{m}_1 = m_1/(1-\beta_1) = g_1$ and $\hat{v}_1 = v_1/(1-\beta_2) = g_1^2$, so $\hat{m}_1/\sqrt{\hat{v}_1} = g_1/|g_1| = \text{sign}(g_1)$ and the effective step is exactly $\alpha$. Thus, bias correction \emph{prevents} overaggressive first steps caused by the simultaneous small-initialisation of both $m_t$ and $v_t$ (the ratio $m_1/\sqrt{v_1}$ is inflated because $v_1 \ll m_1^2$ when $\beta_2 \gg \beta_1$). By $t = 50$: $1-\beta_1^{50} \approx 1 - 0.82^{50} \approx 0.9999$ and $1-\beta_2^{50} = 1-0.999^{50} \approx 0.049$, giving correction ratio $\approx 0.222$, still material. Bias correction becomes negligible ($< 5\%$ effect on step size) only after $t \approx 1/(1-\beta_2) = 1000$ iterations for $\beta_2 = 0.999$ (Figure~\ref{fig:adam_bias}).
\end{remark}

\subsection{Nesterov Momentum Schedule}

Figure~\ref{fig:nest_schedule} illustrates the momentum schedule $\beta_k = \min((k-1)/(k+2), \beta_{\max})$ and compares the theoretical rate of Nesterov versus GD using the illustrative value $\kappa = 2000$ (close to Rosenbrock's $\kappa \approx 2508$).

For $\kappa = 2000$ (conservative Rosenbrock estimate; actual $\kappa \approx 2508$ gives similar conclusions), the quantitative rate comparison is striking. GD's linear rate $(1 - 1/\kappa)^k = 0.9995^k$ satisfies:
\begin{equation}
(0.9995)^{150} = e^{150 \ln(0.9995)} \approx e^{-0.075} \approx 0.928,
\end{equation}
meaning 150 GD iterations reduce the error by only $7.2\%$ --- a tiny improvement. By contrast, Nesterov's $O(1/k^2)$ bound gives:
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2L\|x_0 - x^{\star}\|^2}{(k+1)^2}.
\end{equation}
With $\|x_0 - x^{\star}\|^2 = \|(-1,1)-(1,1)\|^2 = 4$ and local Lipschitz estimate $L \approx 1002$ at $x_0$, after $k = 150$ iterations:
\begin{equation}
\frac{2 \times 1002 \times 4}{(150+1)^2} = \frac{8016}{22801} \approx 0.352.
\end{equation}

\begin{remark}[Nesterov's Bound on Non-Convex Rosenbrock]
\label{rem:nesterov_nonconvex}
The upper bound $0.352$ applies rigorously only to \emph{convex} $L$-smooth functions; Rosenbrock is non-convex. Indeed, the observed $f(x_{150}) - f^{\star} = 0.479 > 0.352$ indicates the non-convex landscape makes the problem harder than the convex prediction. The Nesterov theorem (Theorem~\ref{thm:nesterov}) requires $f$ to be $L$-smooth \emph{globally}, but Rosenbrock's Hessian entries $h_{11} = 2 + 1200x_1^2 - 400x_2$ are unbounded, so $L$ is only locally defined. For convex functions, Nesterov achieves $O(1/k^2)$; for non-convex objectives, the best known worst-case rate is $O(1/k)$ for convergence to a first-order critical point ($\|\nabla f\|^2 \leq \varepsilon$), not to a global minimum. The $7\times$ improvement of Nesterov over GD on Rosenbrock is thus an empirical demonstration that momentum is beneficial in near-convex regions of the trajectory (inside the valley), not a consequence of the convex $O(1/k^2)$ guarantee.
\end{remark}

The $\sim$7$\times$ improvement of Nesterov over GD on Rosenbrock is a direct consequence of momentum accumulation along the flat valley direction, effectively increasing the per-iteration progress on the low-curvature axis. The quadratic ($1/k^2$) versus linear ($(1-1/\kappa)^k$) rate gap compounds significantly at high condition numbers, as quantified in Figure~\ref{fig:theory_cond}.

\subsection{Mini-Batch Stochastic Gradient Descent}

\begin{theorem}[SGD Convergence with Diminishing Step Size]
\label{thm:sgd}
For an $L$-smooth convex function with bounded gradient variance $\sigma^2 = \mathbb{E}[\|g_\mathcal{B} - \nabla f(x)\|^2] \leq \sigma^2_{\max}$, SGD with step $\alpha_k = c/\sqrt{k}$ satisfies
\begin{equation}
\mathbb{E}[f(\bar{x}_K)] - f^{\star} \leq \frac{L c^2 \sigma^2_{\max}}{2} \cdot \frac{\log K + 1}{\sqrt{K}} + \frac{\|x_0 - x^{\star}\|^2}{c\sqrt{K}},
\end{equation}
where $\bar{x}_K = \frac{1}{K}\sum_{k=0}^{K-1} x_k$ is the iterate average. With a \emph{fixed} step $\alpha = c$, SGD converges to a neighbourhood: $\liminf_{K \to \infty} \mathbb{E}[f(x_K)] - f^{\star} \leq c L \sigma^2_{\max} / (2\mu)$ for $\mu$-strongly convex $f$, confirming that fixed $\alpha$ cannot reach $f^{\star}$ exactly.
\end{theorem}

For Benchmark~A ($\mu = \lambda_{\min}(H) \approx 0.925$, $L \approx 1.033$), with fixed $\alpha = 0.06$ and mini-batch variance $\sigma^2_b = \sigma^2_{\text{obs}}/b$ where $\sigma^2_{\text{obs}} = 1$ (observation noise), the convergence neighbourhood is approximately $c L \sigma^2 / (2\mu b) \approx 0.06 \times 1.033 / (2 \times 0.925 \times b)$: for $b = 5$ this is $\approx 0.033$, and for $b = 40$ it is $\approx 0.0042$. Both are below the irreducible noise floor $J^{\star} \approx 0.4826$, confirming that mini-batch variance is not the binding constraint on convergence --- the irreducible noise floor is.

Mini-batch SGD on Benchmark~A uses $\alpha = 0.06$, batch sizes $b \in \{5, 40\}$, $E = 50$ epochs, with data shuffled each epoch.

\begin{algorithm}[H]
\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]
\Require Data $(X, y)$, initial $\theta_0$, learning rate $\alpha$, batch size $b$, epochs $E$
\For{$e = 1, 2, \ldots, E$}
    \State Randomly permute data indices $\{1, \ldots, m\}$
    \For{each mini-batch $\mathcal{B}$ of size $b$}
        \State $g_\mathcal{B} \gets \frac{1}{b} X_{\mathcal{B}}^T(X_{\mathcal{B}}\theta - y_{\mathcal{B}})$
        \State $\theta \gets \theta - \alpha\, g_\mathcal{B}$
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{remark}[Bias--Variance Tradeoff in SGD]
Each mini-batch gradient $g_\mathcal{B}$ is an unbiased estimator of the full gradient $\nabla J(\theta)$, with variance $\operatorname{Var}(g_\mathcal{B}) = \operatorname{Var}(g_i)/b$ where $g_i$ is a single sample gradient. Smaller batches provide noisier but cheaper gradient estimates: $b=5$ executes $m/b = 200$ updates per epoch, while $b=40$ executes only 25. The benefit of smaller batches (more updates per epoch) is offset by higher gradient variance, which creates persistent oscillation near the minimum.
\end{remark}

\subsection{SGD with Increased Noise}

The output noise is scaled by factor 6 ($\sigma = 6$ vs $\sigma = 1$). For the linear regression model $y = X\theta + \varepsilon$ with $\varepsilon \sim \mathcal{N}(0, \sigma^2 I)$, the Bayes-optimal loss is
\begin{equation}
J^{\star}(\sigma) = \frac{\sigma^2}{2} \cdot \frac{m - d}{m} \approx \frac{\sigma^2}{2} \quad \text{for } m \gg d,
\end{equation}
so scaling $\sigma$ by 6 raises the irreducible floor by $6^2 = 36$: $J^{\star}(\sigma{=}6) \approx 36 \times 0.4826 \approx 17.4$.

The three methods play complementary roles in modern optimisation:

\begin{itemize}[nosep]
\item \textbf{Nesterov} is the theoretically optimal first-order method for smooth convex objectives, requiring only gradient evaluations at $O(d)$ memory cost. Its $O(1/k^2)$ rate is provably unimprovable by any deterministic first-order method (lower complexity bound from Nesterov~[5]). However, it requires knowledge of the global Lipschitz constant $L$ for the step size, and provides no convergence guarantee for non-convex objectives beyond convergence to a first-order critical point at rate $O(1/\sqrt{k})$.

\item \textbf{Adam} combines Nesterov-style momentum ($\beta_1$) with per-coordinate scaling ($\beta_2$), adapting to curvature without knowing $L$. While Adam lacks convergence guarantees for non-convex objectives (AMSGrad, Reddi et al.~2018, fixes the non-convergence counterexample using a maximum second-moment), it is the dominant optimiser in deep learning due to its robustness and per-coordinate adaptivity. On the near-quadratic benchmarks in this study, Adam converges reliably but does not outperform Nesterov.

\item \textbf{Mini-batch SGD} enables processing of $m \gg 1000$ data points by using only $b$ samples per step, reducing per-iteration cost from $O(md)$ to $O(bd)$. The inherent stochasticity acts as implicit regularisation and helps escape sharp minima in non-convex objectives. The fundamental limitation is the fixed-step noise floor (Theorem~\ref{thm:sgd}): convergence to $f^{\star}$ requires $\alpha_k \to 0$, but decaying steps slow later-stage convergence.
\end{itemize}

\begin{remark}[When to Prefer Adam over Nesterov in Practice]
\label{rem:adam_vs_nesterov}
Despite Nesterov's theoretical optimality, Adam is preferred in practice for several reasons: (1) Adam requires no knowledge of $L$ or $\mu$, eliminating the need for line search or hyperparameter grid search for the step size; (2) the per-coordinate scaling compensates for the large curvature variation typical in deep networks (where different layers may have curvatures differing by $10^6\times$); (3) with mini-batch gradients, the bias correction in Adam ensures stable effective step sizes despite varying gradient statistics across batches. Nesterov is preferred when the objective is known to be strongly convex (e.g., $\ell_2$-regularised linear models), when $L$ can be estimated cheaply, or when exact convergence to a global minimum is required.
\end{remark}

\subsection{Local Approximations of $g(x) = x^4$}

Newton's method is motivated by minimising the local second-order Taylor approximation of $f$ at each iterate.

\textbf{First-order approximation} around $x_0 = 0.25$:
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0) = 0.0039 + 0.0625(x - 0.25).
\end{equation}

\textbf{Second-order approximation:}
\begin{equation}
g(x) \approx g(x_0) + g'(x_0)(x - x_0) + \tfrac{1}{2}g''(x_0)(x - x_0)^2 = 0.0039 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{equation}

The Newton step minimises the second-order approximation, yielding the update
\begin{equation}
\label{eq:newton_update_1d}
x_{k+1} = x_k - \frac{g'(x_k)}{g''(x_k)}.
\end{equation}
For $g(x) = x^4$: $g'(x) = 4x^3$ and $g''(x) = 12x^2$, so the Newton step is $x_{k+1} = x_k - (4x_k^3)/(12x_k^2) = x_k - x_k/3 = (2/3)x_k$, contracting linearly towards zero from any $x_0 \neq 0$. (Quadratic convergence requires the function to be locally quadratic, which $x^4$ is not at $x=0$ since $g''(0)=0$.)

The second-order approximation (parabola) captures curvature and provides a much better fit near $x_0$. \subsection{Newton's Method}

\begin{algorithm}[H]
\caption{Newton's Method with Hessian Damping}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Regularised Hessian ensures positive definiteness}
    \State Solve $H_k p_k = g_k$ \Comment{Newton direction}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{theorem}[Quadratic Convergence of Newton's Method]
\label{thm:newton_quad}
Suppose $f$ is twice continuously differentiable, $\nabla^2 f$ is Lipschitz continuous with constant $M$, and $\nabla^2 f(x^{\star}) \succ 0$ at the minimiser $x^{\star}$. Then for $x_0$ sufficiently close to $x^{\star}$, Newton's method with $\alpha = 1$ satisfies
\begin{equation}
\|x_{k+1} - x^{\star}\| \leq \frac{M}{2\mu} \|x_k - x^{\star}\|^2,
\end{equation}
where $\mu = \lambda_{\min}(\nabla^2 f(x^{\star}))$. This quadratic rate means the number of correct digits doubles at each iteration.
\end{theorem}

\begin{remark}
Damping ($\alpha < 1$ or $\lambda > 0$) is necessary when $x_k$ is far from $x^{\star}$: the quadratic approximation may be inaccurate, and the full Newton step can overshoot. Here $\lambda = 10^{-8}$ ensures the regularised Hessian $H_k + \lambda I$ is positive definite (avoiding negative-curvature directions), and $\alpha < 1$ on non-quadratic functions prevents overshooting.
\end{remark}

Settings: GD uses 80 iterations; Newton uses 20 iterations with Hessian damping $\lambda = 10^{-8}$.

\begin{proposition}[Newton's Method on Quadratic Functions]
\label{prop:newton_quadratic}
For the quadratic objective $J(\theta) = \frac{1}{2}\theta^T H \theta - b^T \theta + c$ with $H \succ 0$, Newton's method with $\alpha = 1$ converges in \textbf{exactly one iteration} from any starting point $\theta_0$:
\begin{equation}
\theta_1 = \theta_0 - H^{-1}(H\theta_0 - b) = H^{-1}b = \theta^{\star}.
\end{equation}
This follows because the Newton direction $p_0 = H^{-1}\nabla J(\theta_0) = H^{-1}(H\theta_0 - b) = \theta_0 - \theta^{\star}$ points exactly from $\theta_0$ to the minimiser, and a full step $\alpha = 1$ reaches $\theta^{\star}$ exactly.
\end{proposition}

\subsection{Part A: Finite Difference and Nesterov Random Search (Benchmark B)}

\subsubsection{Finite Difference Gradient Approximation}

When the gradient is unavailable, it can be approximated using function values alone. The forward finite-difference approximation for the $i$-th coordinate:
\begin{equation}
\label{eq:fd}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta}.
\end{equation}
The approximation has a mixed error:
\begin{equation}
\left|\frac{\partial f}{\partial x_i}(x) - \frac{f(x + \delta e_i) - f(x)}{\delta}\right| = \underbrace{\frac{\delta}{2}\left|\frac{\partial^2 f}{\partial x_i^2}(x)\right|}_{\text{truncation error, } O(\delta)} + \underbrace{\frac{2\varepsilon_{\text{mach}}}{\delta}}_{\text{round-off error, } O(1/\delta)}.
\end{equation}
The optimal $\delta$ minimises the total error: setting the truncation and round-off terms equal gives $\delta^{\star} = \sqrt{4\varepsilon_{\text{mach}} / |f''|}$. For Benchmark~B at $x=(0,3)$, $|f''| = |2-\sin(0)| = 2$, so $\delta^{\star} = \sqrt{2\varepsilon_{\text{mach}}} \approx 2 \times 10^{-8}$. The quantitative errors for the experimentally used values are:
\begin{itemize}[nosep]
\item $\delta = 0.05$: truncation $\approx 0.05/2 \times |f''| = 0.05$ per coordinate; relative gradient error $\approx 2\%$. Good approximation.
\item $\delta = 0.8$: truncation $\approx 0.8/2 \times |f''| = 0.8$ per coordinate; relative gradient error $\approx 32\%$. Corrupts descent direction.
\end{itemize}
Figure~\ref{fig:fd_error} confirms this U-shaped error vs $\delta$ curve, showing the optimal near $10^{-4}$ and the two experiment points on opposite sides.

\begin{figure}[H]
\centering
\includegraphics[width=0.85\textwidth]{figures/fd_error_analysis.pdf}
\caption{Q4A: Finite difference gradient error $\|\hat{g}_{\delta} - g\|$ vs step size $\delta$ on Benchmark~B at test point $x = (0, 3)$. The characteristic U-shaped curve reflects the trade-off between truncation error ($O(\delta)$, dominant for large $\delta$) and round-off error ($O(\varepsilon_{\text{mach}}/\delta)$, dominant for small $\delta$). The optimal $\delta^{\star} \approx 10^{-4}$ achieves minimum error $\approx 10^{-8}$. The experimentally used $\delta = 0.05$ gives error $\approx 0.017$ (good) while $\delta = 0.8$ gives error $\approx 0.27$ (poor) --- the figure confirms these are on opposite sides of the optimal. Actual gradient magnitude $\|g\| \approx 2.5$, so relative errors are $\approx 0.7\%$ vs $\approx 11\%$ respectively.}

\end{figure}

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search (Zeroth-Order)}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Sample $u_k \sim \mathcal{N}(0, I_d)$, normalise: $\hat{u}_k \gets u_k / \|u_k\|$
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta \hat{u}_k) - f(x_k)}{\delta}\, \hat{u}_k$ \Comment{Directional derivative estimate}
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

This zeroth-order method uses only 2 function evaluations per iteration, regardless of dimension $d$. The estimator $\hat{g}_k$ provides an unbiased estimate of a smoothed gradient:
\begin{equation}
\mathbb{E}_u\!\left[\frac{f(x + \delta \hat{u}) - f(x)}{\delta}\, \hat{u}\right] = \frac{1}{\delta}\mathbb{E}_u[f(x + \delta \hat{u})\hat{u}] = \nabla f_\delta(x) + O(\delta^2),
\end{equation}
where $f_\delta(x) = \mathbb{E}_u[f(x + \delta u)]$ is a Gaussian-smoothed version of $f$ with $f_\delta \to f$ as $\delta \to 0$. The variance of $\hat{g}_k$ is $\operatorname{Var}(\hat{g}_k) \approx d\, \|\nabla f\|^2$ (for a single direction out of $d$), which is $d$ times larger than for a single FD evaluation with full gradient. This high variance is the fundamental cost of using only 2 evaluations per step: the gradient signal is compressed into a single direction, requiring $O(d)$ more steps to average out the noise.

\begin{remark}[Dimensional Cost of Zeroth-Order Methods]
\label{rem:zo_cost}
For a $d$-dimensional problem, FD-GD uses $d+1$ function evaluations per step and constructs an $\varepsilon$-approximate gradient; convergence requires $O(1/\varepsilon)$ steps, giving total cost $O((d+1)/\varepsilon)$. Nesterov random search uses only 2 evaluations per step but has $O(d/\varepsilon)$ convergence (each direction samples only $1/d$ of the gradient), giving total cost $O(2d/\varepsilon) = O(d/\varepsilon)$ --- the same asymptotic dependence on $d$ as FD-GD. However, for $d=2$ (our case), both require only 3 evaluations per effective gradient step, so the practical difference is negligible. For $d = 10^6$ (neural networks), FD-GD requires $10^6 + 1$ evaluations per step while Nesterov random search still uses just 2 --- this is the key advantage in the high-dimensional regime.
\end{remark}

\subsubsection{Nelder--Mead Simplex Method}

The Nelder--Mead algorithm maintains a simplex of $n+1 = 3$ vertices in $\mathbb{R}^2$ and iteratively transforms it through four operations: \textbf{reflection} ($\alpha_r = 1$, move worst vertex through centroid), \textbf{expansion} ($\gamma = 2$, extend if reflection improved), \textbf{contraction} ($\rho = 0.5$, pull toward centroid if reflection worsened), and \textbf{shrink} ($\sigma = 0.5$, contract all vertices toward best). These operations are selected by comparing function values at the simplex vertices, requiring no gradient computation.

\begin{remark}[Why Nelder--Mead Excels on Rosenbrock]
The key insight is that the Nelder--Mead simplex \emph{adapts its shape} to the local landscape (Figure~\ref{fig:q4_nm_simplex}). On Rosenbrock's narrow curved valley, the simplex naturally elongates along the valley direction: reflection repeatedly moves the worst vertex (off the valley) to the opposite side of the centroid (along the valley), while contraction shrinks towards the best vertex (deepest in the valley). The simplex's aspect ratio (longest/shortest edge) grows from $1.41$ (iteration 0, near-equilateral) to $\mathbf{15.98}$ (iteration 60), then contracts to $\sim 3$ as the simplex homes in on the minimum. This implicit curvature adaptation is why Nelder--Mead reaches $f \approx 10^{-9}$ (machine precision with 200 iterations) --- a performance that gradient methods cannot match without Hessian information. Gradient methods are \emph{trapped} by the condition number: the step size required for stability along the high-curvature direction ($\lambda_{\max} \approx 800$) provides almost no progress along the low-curvature direction ($\lambda_{\min} \approx 10^{-12}$). The simplex has no such constraint.
\end{remark}

Settings: initial simplex step $= 0.35$, 160--200 iterations. Standard parameters ($\alpha_r = 1$, $\gamma = 2$, $\rho = 0.5$, $\sigma = 0.5$) are the default Nelder--Mead configuration.

The key trade-off is between gradient information quality and computational cost. \begin{remark}[Practical Guidelines for Method Selection]
\begin{itemize}[nosep]
\item \textbf{Use exact gradient methods} when the gradient is available (e.g., via automatic differentiation in PyTorch/JAX). The cost of implementing automatic differentiation is far outweighed by the convergence benefits.
\item \textbf{Use finite differences} when the gradient is not available but the function is cheap to evaluate and $d$ is moderate ($d \leq 1000$). Choose $\delta$ in the range $[10^{-5}, 10^{-2}]$ based on the function's smoothness.
\item \textbf{Use Nesterov random search or evolution strategies} when $d$ is large, the gradient is unavailable, and function evaluations are expensive (e.g., physical simulations, black-box APIs).
\item \textbf{Use Nelder--Mead} when $d \leq 10$, the function may be non-smooth, and high precision is required (it reaches machine precision on Rosenbrock).
\item \textbf{Use grid search} only for global search with $d \leq 3$ and when function evaluations are cheap.
\end{itemize}
\end{remark}

\subsection{Problem Setup}

The problem is to minimise Benchmark~B (Equation~\eqref{eq:bench_b}) subject to the constraint $x_1 \geq 0.5$, starting from the infeasible point $x_0 = (0.2, 4.0)$.

\begin{remark}[Constraint Activity at the Optimum]
\label{rem:inactive}
The unconstrained minimiser of Benchmark~B is $x^{\star} = (x_1^{\star}, 2) \approx (0.582, 2)$ with $x_1^{\star} \approx 0.582 > 0.5$. Since the unconstrained minimum already satisfies the constraint, the constraint is \textbf{inactive} at the optimum. Consequently, the constrained and unconstrained problems share the same solution: all methods that converge to the unconstrained minimum will automatically satisfy the constraint. The interesting comparison is therefore about \emph{trajectory behaviour} --- how quickly and reliably methods reach the feasible optimal point starting from the infeasible $x_0$.
\end{remark}

\subsubsection{KKT Conditions}

The Karush--Kuhn--Tucker (KKT) conditions for this problem state that at the constrained optimum $x^{\star}$:
\begin{align}
\nabla f(x^{\star}) + \mu^{\star} \nabla (-x_1 + 0.5) &= 0, \\
\mu^{\star}(-x_1^{\star} + 0.5) &= 0 \quad \text{(complementary slackness)}, \\
\mu^{\star} &\geq 0, \quad x_1^{\star} \geq 0.5.
\end{align}
Since $x_1^{\star} \approx 0.582 > 0.5$, complementary slackness gives $\mu^{\star} = 0$, and the KKT conditions reduce to $\nabla f(x^{\star}) = 0$ --- the unconstrained optimality condition. This confirms the constraint is inactive.

\begin{algorithm}[H]
\caption{Projected Gradient Descent}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, projection $\Pi_{\mathcal{X}}$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Unconstrained gradient step}
    \State $x_{k+1} \gets \Pi_{\mathcal{X}}(z_{k+1})$ \Comment{Projection: $x_1 \leftarrow \max(0.5,\, x_1)$}
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
\caption{Penalty Method}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, penalty weight $\lambda$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $F_\lambda(x) \gets f(x) + \lambda \max(0,\, 0.5 - x_1)$ \Comment{Penalised objective}
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_\lambda(x_k)$
\EndFor
\end{algorithmic}
\end{algorithm}

Settings: Projected GD ($\alpha = 0.08$), penalty with $\lambda \in \{0.15, 1.8, 4.5\}$ ($\alpha = 0.05$ for $\lambda \leq 1.8$; $\alpha = 0.03$ for $\lambda = 4.5$), unconstrained GD ($\alpha = 0.07$). All run for 100 iterations.

\subsection{Comparative Discussion}

\textbf{Projected Gradient Descent:} Enforces feasibility as a hard constraint at every iteration via the projection $\Pi_\mathcal{X}(x) = (\max(0.5, x_1), x_2)^T$. When the feasible set $\mathcal{X}$ is a simple half-space, projection is a single $\max$ operation. For general convex sets, the projection may require solving a quadratic programme.

\textbf{Penalty Methods:} Replace the constrained problem with an unconstrained surrogate $F_\lambda(x) = f(x) + \lambda P(x)$ where $P(x) = \max(0, 0.5-x_1)$ is the constraint violation. As $\lambda \to \infty$, the solution of the penalised problem converges to the constrained solution, but larger $\lambda$ requires smaller step sizes for stability. For this specific problem, since the constraint is inactive at the solution, the penalty term vanishes at convergence for any $\lambda > 0$.

\textbf{Limitation of Penalty Methods:} The $L^1$ penalty $\lambda \max(0, 0.5-x_1)$ is non-smooth at $x_1 = 0.5$. Its (sub)gradient is $-\lambda \mathbf{1}[x_1 < 0.5]$ in the $x_1$ direction, causing a discrete jump at the boundary. This can cause gradient oscillation for iterates near $x_1 = 0.5$. A smooth alternative is the $L^2$ penalty $\lambda \max(0, 0.5-x_1)^2$, with gradient $-2\lambda\max(0, 0.5-x_1)$ --- continuous at the boundary. The \emph{augmented Lagrangian} method combines a Lagrange multiplier estimate $\hat\mu$ with a quadratic penalty:
\begin{equation}
\mathcal{L}_\lambda(x, \hat\mu) = f(x) + \hat\mu (-x_1 + 0.5) + \frac{\lambda}{2}\max(0,\, 0.5-x_1)^2,
\end{equation}
with dual variable update $\hat\mu_{t+1} = \max(0,\, \hat\mu_t - \lambda \cdot \max(0, 0.5-x_1^t))$. Since the constraint is inactive at the solution ($x_1^{\star} \approx 0.582 > 0.5$), the dual ascent converges to $\hat\mu^{\star} = 0$ (matching the KKT condition $\mu^{\star} = 0$ from complementary slackness). This achieves exact feasibility at finite $\lambda$ (unlike pure penalty methods which need $\lambda \to \infty$) while maintaining smooth gradient structure.

\begin{remark}[Active vs Inactive Constraints in Practice]
\label{rem:constraint_activity}
The inactive constraint in Q5 ($x_1^{\star} \approx 0.582 > 0.5$) produces an ideal scenario where all methods converge to the same unconstrained minimum. In practice, determining whether a constraint is active \emph{before} solving the problem is non-trivial. The augmented Lagrangian method handles both cases correctly: if the constraint were active (e.g., if the unconstrained minimum were at $x_1^{\star} < 0.5$), the dual variable would converge to a positive value $\hat{\mu}^{\star} > 0$, reflecting the KKT condition $\mu^{\star}(-x_1^{\star} + 0.5) = 0$ with the constraint binding. The penalty method would also converge to the constrained minimum, but at larger $\lambda$ the step size requirements become increasingly restrictive. Projected GD is the most robust to constraint activity changes: the projection oracle $\Pi_\mathcal{X}$ behaves identically whether the constraint is active or not.
\end{remark}

\subsection{Feasible Set and Linear Programme}

Feasible set: $\mathcal{X} = \{x \in \mathbb{R}^2 : 0.5 \leq x_1 \leq 5,\, -5 \leq x_2 \leq 10\}$ (box-constrained polytope with 4 extreme points / vertices).

\textbf{Linear Programme:} For $f(x) = a^T x$ with $a = [1, 2]^T$, minimise over $\mathcal{X}$:
\begin{equation}
\min_{x \in \mathcal{X}} x_1 + 2x_2.
\end{equation}
Since both components of $a$ are positive, the minimum is attained by taking each coordinate at its lower bound:
\begin{equation}
x^{\star} = (0.5,\, -5), \qquad f^{\star} = 0.5 + 2(-5) = -9.5.
\end{equation}
This is an instance of the \emph{fundamental theorem of linear programming}: the optimum of a linear objective over a bounded polytope is always attained at a vertex (extreme point). The proof is straightforward: if $x^{\star}$ is in the interior of $\mathcal{X}$, moving in the direction of $-a$ improves the objective while remaining feasible, contradicting optimality. The Frank--Wolfe algorithm exploits this by reducing each iteration to finding the best vertex (the LP oracle), rather than minimising over all of $\mathcal{X}$.

\begin{remark}[Why Box LP Oracles are $O(d)$]
\label{rem:lp_oracle}
For a box constraint $\mathcal{X} = \{x : l_i \leq x_i \leq u_i, i = 1,\ldots,d\}$, the LP oracle $\arg\min_{z \in \mathcal{X}} c^T z$ decomposes per coordinate: $(z^{\star})_i = l_i$ if $c_i > 0$, else $u_i$. This requires $O(d)$ comparisons --- the same cost as computing a gradient. By contrast, projecting onto a general convex set $\mathcal{X}$ requires solving $\min_{z \in \mathcal{X}} \|z - y\|^2$, which is $O(d \log d)$ for simplex constraints, $O(d\sqrt{d})$ for nuclear norm balls (via SVD), or intractable for combinatorial constraint sets. This cost difference is why Frank--Wolfe is preferred over projected gradient descent for structured constraints.
\end{remark}

\subsection{Frank--Wolfe Algorithm}

\begin{algorithm}[H]
\caption{Frank--Wolfe (Conditional Gradient)}
\label{alg:fw}
\begin{algorithmic}[1]
\Require Initial point $x_0 \in \mathcal{X}$, mixing parameter $\beta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_k \gets \arg\min_{x \in \mathcal{X}}\, \nabla f(x_k)^T x$ \Comment{LP oracle: linear minimisation over $\mathcal{X}$}
    \State $x_{k+1} \gets \beta\, x_k + (1 - \beta)\, z_k$ \Comment{Convex combination, stays in $\mathcal{X}$}
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{theorem}[Frank--Wolfe Convergence]
\label{thm:fw}
For an $L$-smooth convex function $f$ over a convex set $\mathcal{X}$ with diameter $D = \sup_{x,y \in \mathcal{X}} \|x - y\|$, the Frank--Wolfe algorithm with step size $\gamma_k = 2/(k+2)$ satisfies
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2LD^2}{k+2} = O(1/k).
\end{equation}
\end{theorem}

\begin{remark}[Fixed vs Decaying Frank--Wolfe Step]
In this implementation, a fixed mixing parameter $\beta$ replaces the standard decaying step $\gamma_k = 1 - \beta = 2/(k+2)$. With the decaying schedule, the iterate $x_k$ is a convex combination $x_k = \sum_{j=0}^{k} w_{k,j} z_j$ of the LP oracle outputs, and the $O(1/k)$ bound (Theorem~\ref{thm:fw}) applies. With fixed $\beta$, the effective step $1-\beta$ is constant and the iterate satisfies $x_{k+1} = \beta x_k + (1-\beta) z_k$, which is a first-order linear system in $x_k - x^{\star}$; convergence requires $(1-\beta)\|z_k - x^{\star}\| \to 0$, which holds only if $z_k \to x^{\star}$. For interior optima, $z_k$ oscillates between boundary vertices, so fixed $\beta$ introduces a persistent oscillation bias of magnitude $O(1-\beta)$. The Frank--Wolfe gap $g_k = \nabla f(x_k)^T (x_k - z_k)$ is always a valid suboptimality certificate (Proposition~\ref{prop:fw_gap}).
\end{remark}

For box constraints, the LP oracle decomposes per coordinate in $O(d)$ time:
\begin{equation}
(z_k)_i = \begin{cases} l_i & \text{if } (\nabla f(x_k))_i > 0 \\ u_i & \text{if } (\nabla f(x_k))_i \leq 0 \end{cases}
\end{equation}
This requires no projection oracle (unlike projected gradient) and costs $O(d)$ per iteration.

\subsection{Interior vs Boundary Behaviour}

\textbf{Interior optimum:} Frank--Wolfe exhibits a characteristic zig-zag pattern because $z_k$ always selects a vertex of $\mathcal{X}$, and the convex combination $x_{k+1} = \beta x_k + (1-\beta) z_k$ approximates the optimum by averaging many vertex selections. The Theorem~\ref{thm:fw} bound with $L = 2$ (for $f(x) = \|x - x^{\star}\|^2$) and $D = \sqrt{(5-0.5)^2 + 15^2} \approx 15.7$ gives $f(x_k) - f^{\star} \leq 2 \cdot 2 \cdot 15.7^2 / (k+2) = 987/(k+2)$, which predicts $f(x_{180}) - f^{\star} \leq 5.4$. This is a loose bound; the actual convergence is much faster due to the interior location.

\begin{proposition}[Frank--Wolfe Gap as Primal--Dual Certificate]
\label{prop:fw_gap}
Define the Frank--Wolfe gap $g_k^{\text{FW}} = \nabla f(x_k)^T(x_k - z_k)$ where $z_k = \arg\min_{z \in \mathcal{X}} \nabla f(x_k)^T z$. For any convex $f$ and any $x^{\star} \in \mathcal{X}$:
\begin{equation}
f(x_k) - f^{\star} \leq f(x_k) - \min_{y \in \mathcal{X}} \left[ f(x_k) + \nabla f(x_k)^T(y - x_k) \right] = \nabla f(x_k)^T(x_k - z_k) = g_k^{\text{FW}}.
\end{equation}
The first inequality is convexity ($f(x^{\star}) \geq f(x_k) + \nabla f(x_k)^T(x^{\star} - x_k)$ by definition); the second equality uses the LP oracle definition of $z_k$ as the linear minimiser. Thus $g_k^{\text{FW}}$ provides a computable, $f^{\star}$-free upper bound on the suboptimality gap, valid at every iteration.
\end{proposition}

The \textbf{Frank--Wolfe gap} at iteration $k$ is defined as
\begin{equation}
g_k^{\text{FW}} = \nabla f(x_k)^T (x_k - z_k),
\end{equation}
and satisfies $f(x_k) - f^{\star} \leq g_k^{\text{FW}}$ for convex $f$ (Proposition~\ref{prop:fw_gap}). This provides a computable certificate of optimality without knowing $f^{\star}$: when $g_k^{\text{FW}} \leq \varepsilon$, the current iterate is $\varepsilon$-suboptimal. For the interior case with $\beta = 0.985$, the empirically measured final FW gap is $g_{180}^{\text{FW}} \approx 0.082$ (computed numerically), while the actual suboptimality is $f(x_{180}) - f^{\star} = 0.00455 \ll g_{180}^{\text{FW}}$, confirming that the gap bound $f(x_k) - f^{\star} \leq g_k^{\text{FW}}$ holds and is not too loose once the iterate is near the interior optimum.

\textbf{Boundary optimum:} Frank--Wolfe is well-suited to boundary optima: the LP oracle frequently selects the vertex $(0.5, 0)$ closest to the constrained minimum. The iterate naturally approaches the boundary without projection. The residual gap ($f = 0.364$ vs $f^{\star}_c = 0.25$ after 140 iterations) reflects the $O(1/k)$ rate; the standard decaying schedule $\gamma_k = 2/(k+2)$ would guarantee a tighter bound.

\textbf{Comparison with Projected Gradient Descent:} Projected GD achieves a linear rate $O((1-\mu/L)^k)$ for strongly convex $f$, much faster than Frank--Wolfe's $O(1/k)$. However, Frank--Wolfe replaces the projection oracle with the LP oracle: for box constraints, both are $O(d)$, making Frank--Wolfe competitive in cost per iteration. For complex constraint sets (nuclear norm balls, probability simplices, flow polytopes), the LP oracle can be orders of magnitude cheaper than the projection oracle, making Frank--Wolfe the method of choice.

\begin{remark}[Frank--Wolfe in Machine Learning Practice]
The Frank--Wolfe algorithm achieves its most significant advantages over projected gradient methods in three settings common in machine learning:
\begin{itemize}[nosep]
\item \textbf{Low-rank matrix completion} (nuclear norm constraint $\|W\|_* \leq \tau$): projecting onto the nuclear norm ball requires a full SVD ($O(\min(m,n)^2 \max(m,n))$), while the LP oracle requires only the top singular vector ($O(mn)$ via power iteration) --- a speedup of $O(\min(m,n))$.
\item \textbf{Sparse optimisation} (simplex constraint $\|w\|_1 \leq \tau$ or probability simplex $\Delta_d$): the LP oracle is a single \texttt{argmax}, costing $O(d)$, while projection onto $\Delta_d$ requires sorting ($O(d \log d)$).
\item \textbf{Structured prediction} with combinatorial constraint sets (e.g., doubly stochastic matrices, flow polytopes): the LP oracle corresponds to a combinatorial algorithm (optimal assignment, max-flow), while projection is intractable.
\end{itemize}
In these settings, the slower $O(1/k)$ convergence rate is more than compensated by the per-iteration cost saving.
\end{remark}

\section{Conclusion}
\label{sec:conclusion}
% ============================================================

This report has systematically evaluated optimisation algorithms across six major categories, comparing theoretical guarantees against empirical behaviour on three benchmarks spanning the convex-to-highly-ill-conditioned spectrum. Several consistent themes emerge.

\textbf{Condition number governs everything.} The condition number $\kappa$ of the problem's Hessian is the single most important determinant of convergence behaviour (Figure~\ref{fig:theory_cond}). On Benchmark~A ($\kappa \approx 1.12$), nearly all methods converge rapidly and the differences are minor. On Benchmark~C ($\kappa \approx 2508$), the same methods diverge dramatically in performance, with differences of two orders of magnitude in final objective value. Theorem~\ref{thm:gd_linear} quantifies this: GD requires $O(\kappa \ln(1/\varepsilon)) \approx 34,691$ iterations for $10^{-6}$ accuracy at $\kappa = 2508$ (or $\approx 27,624$ at the rounded $\kappa = 2000$), versus $O(\sqrt{\kappa}\ln(1/\varepsilon)) \approx 692$ for Nesterov at $\kappa = 2508$ (or $\approx 618$ at $\kappa = 2000$) --- a $50\times$ theoretical speedup (compared to $44.7\times$ in the figure, which uses $\kappa = 2000$).

\textbf{Second-order information is decisive on ill-conditioned problems.} Newton's method reaches $f = 0.686$ on Rosenbrock in 20 iterations (and $f = 0.0005$ in 50 iterations) --- far better than first-order methods with 80--150 iterations, as verified in Figure~\ref{fig:q3_newton_quad}. Proposition~\ref{prop:newton_quadratic} explains the extreme case: on the quadratic Benchmark~A, Newton converges to machine precision in a single step. The cost (solving a $d \times d$ system) scales as $O(d^3)$, prohibitive for large $d$ where quasi-Newton methods (L-BFGS) or conjugate gradient provide practical alternatives with $O(d)$ memory.

\textbf{Nesterov acceleration provides the best first-order option.} With $O(1/k^2)$ rate on convex objectives, Nesterov achieves $f = 0.479$ on the non-convex Rosenbrock --- $7\times$ better than GD's $f = 3.39$ --- demonstrating momentum's practical benefit on near-quadratic landscapes. The explicit quantitative comparison in Section~\ref{sec:q2} shows that GD's linear rate reduces error by only $7.2\%$ in 150 iterations at $\kappa=2000$. The convex $O(1/k^2)$ bound (using local $L \approx 1002$, $\|x_0-x^{\star}\|^2 = 4$) predicts error $\leq 2 \times 1002 \times 4/(151)^2 \approx 0.352$ after 150 steps; the observed $0.479 > 0.352$ is consistent with Rosenbrock's non-convexity (Remark~\ref{rem:nesterov_nonconvex}). For convex problems at $\kappa=2000$, Theorem~\ref{thm:nesterov} guarantees 618 vs 27,624 iterations ($44.7\times$ speedup) to reach $10^{-6}$ accuracy.

\textbf{Polyak step size requires exact $f^{\star}$.} While achieving the best Q1 result when $f^{\star}$ is correctly specified, Polyak diverges catastrophically when $f^{\star}$ is misspecified. This practical limitation makes it less suitable than Adagrad or RMSprop for general use.

\textbf{Derivative-free methods are surprisingly competitive on low-dimensional problems.} Nelder--Mead achieves $f \approx 10^{-9}$ on Rosenbrock with 200 iterations --- machine precision --- surpassing every gradient-based method tested. The simplex's geometric adaptation to the curved valley implicitly captures second-order curvature information. However, this comes without convergence guarantees and the method scales poorly: for $d > 10$ the simplex cannot adequately cover the search space.

\textbf{Constraints were inactive for the Q5 setup.} The unconstrained Benchmark~B minimum $x_1^{\star} \approx 0.582$ already satisfies $x_1 \geq 0.5$, meaning all constrained methods converge to the same point. The comparison highlights trajectory differences: projected GD enforces feasibility immediately, while penalty methods and unconstrained GD pass through the infeasible region before converging to the naturally feasible minimum.

\textbf{Frank--Wolfe exploits structure at the cost of rate.} The $O(1/k)$ rate is slower than projected gradient descent's linear rate, but the LP oracle is $O(d)$ versus the $O(d^2)$ (or more) cost of general projection. For large-scale problems with structured constraint sets (matrix factorisation with nuclear norm constraints, sparse learning with simplex constraints), Frank--Wolfe is the practical choice.

\medskip
\textbf{Overall lesson: match the algorithm to the problem structure.} The hierarchy of algorithm effectiveness on the three benchmarks tells a clear story:

\begin{itemize}[nosep]
\item On \textbf{well-conditioned convex} problems (Benchmark~A): virtually all methods converge; the choice of algorithm is a secondary concern compared to hyperparameter tuning.
\item On \textbf{mildly non-convex, moderate conditioning} problems (Benchmark~B): momentum and adaptive methods provide modest benefits over GD; all gradient methods work reliably.
\item On \textbf{highly ill-conditioned non-convex} problems (Benchmark~C): the choice of algorithm is decisive. Newton's method and Nelder--Mead (for $d = 2$) are orders of magnitude better than first-order gradient methods. For large $d$ where these are intractable, Nesterov is the best first-order option.
\end{itemize}

def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        x = x - alpha * grad_fn(x)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Polyak Step Size}]
def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adagrad}]
def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float)
    G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={RMSprop}]
def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float)
    v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Heavy Ball / Polyak Momentum}]
def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x)
        z = beta * z + alpha * g
        x = x - z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Nesterov Momentum}]
def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z
        g = grad_fn(lookahead)
        z = beta_k * z - alpha * g
        x = x + z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adam Optimiser}]
def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t)
        v_hat = v_vec / (1 - beta2**t)
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Newton's Method with Hessian Damping}]
def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))
        try:
            p = np.linalg.solve(H_reg, g)
        except np.linalg.LinAlgError:
            p = g
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)
\end{lstlisting}

\begin{lstlisting}[caption={Frank--Wolfe (Conditional Gradient)}]
def frank_wolfe(grad_fn, loss_fn, x0, bounds, beta, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, z_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
\end{lstlisting}
