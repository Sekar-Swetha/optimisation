\begin{abstract}
This report presents a systematic comparative study of gradient-based and derivative-free optimisation algorithms across problems of increasing difficulty: a well-conditioned quadratic (Benchmark~A, $\kappa \approx 1$), a mildly non-convex sinusoidal perturbation (Benchmark~B, $\kappa \approx 6$), and the ill-conditioned Rosenbrock function (Benchmark~C, $\kappa \approx 2504$), which serves as the primary discriminator between methods.

Six algorithm families are evaluated. \emph{Adaptive step-size methods} (Q1): the Polyak rule requires exact knowledge of $f^{\star}$, diverging catastrophically at iteration~3 with $\alpha_3 \approx 136$ when $f^{\star}$ is misspecified by 0.48, but achieving the best first-order Rosenbrock result ($f = 0.024$) when correct; Heavy Ball offers the best robust result without oracle knowledge ($f = 1.40$). \emph{Momentum methods} (Q2): Nesterov's $O(1/k^2)$ acceleration delivers $f = 0.479$ on Rosenbrock ($7.1\times$ better than GD), verified against the theoretical bound; mini-batch SGD with $b=5$ provides $8\times$ more gradient updates per epoch than $b=40$, explaining faster per-epoch convergence. \emph{Newton's method} (Q3): achieves one-step convergence on the quadratic and demonstrates the Newton decrement as a self-certified stopping criterion ($\lambda/2 = 8.3\times10^{-5}$ at Benchmark~B convergence). \emph{Derivative-free methods} (Q4): finite differences with $\delta=0.05$ closely tracks exact GD, while $\delta=0.8$ fails due to $O(1.2)$ truncation error; the U-shaped error-vs-$\delta$ curve confirms the optimal $\delta_{\rm opt} \approx 10^{-8}$. \emph{Constrained optimisation} (Q5): projected gradient descent enforces $x_1 \geq 0.5$ as a hard invariant from iteration~1; KKT analysis confirms the constraint is inactive at the optimum, making PGD equivalent to unconstrained GD asymptotically. \emph{Frank--Wolfe} (Q6): interior optimum converges to $f = 0.00455$ ($\beta=0.985$); boundary optimum stalls at $f = 0.364$ vs.\ $f^{\star} = 0.25$ due to a persistent two-step oscillation at $(0.5,\,0)$ provable from the LMO selection rule.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% ============================================================

Optimisation lies at the heart of machine learning and data analysis: training a neural network, fitting a regression model, or solving a resource allocation problem all reduce to minimising some objective function. The challenge is that real-world objectives are seldom simple quadratics -- they may be non-convex, ill-conditioned, noisy, or high-dimensional, and gradients may be expensive or unavailable. Choosing the right optimisation algorithm for a given problem structure is therefore a fundamental skill.

This report systematically evaluates six families of optimisation algorithms across problems of increasing difficulty. \textbf{Benchmark A} (quadratic loss) serves as a well-conditioned baseline where exact solutions exist. \textbf{Benchmark B} (non-convex sinusoidal perturbation) introduces mild non-convexity and moderate anisotropy. \textbf{Benchmark C} (Rosenbrock) is the canonical stress test: a narrow curved valley with condition number $\kappa \approx 2000$ at the optimum makes gradient descent painfully slow and tests the limits of every first-order method.

The structure of the report follows the six assignment questions. Each section states the algorithm formulations precisely, provides hyperparameter tables, presents quantitative convergence results verified against the implementation, and analyses \emph{why} the observed behaviour arises from the algorithm's theoretical properties. A final conclusion synthesises cross-question findings and discusses practical guidelines for algorithm selection.

All experiments use \texttt{numpy} with random seed 42 for reproducibility. Code is provided in \texttt{CS7DS2\_Final\_Code\_25336453.py} and reproduced in Appendix~\ref{app:code}.

The key theoretical tools from the course that are applied throughout are: \emph{descent lemma} (bounding function decrease per step from Lipschitz gradient), \emph{Lyapunov functions} (proving convergence via non-increasing energy sequences), \emph{duality} (KKT conditions, Frank--Wolfe duality gap), and \emph{spectral analysis} (eigenvalue bounds on Hessians determining step size limits and convergence rates).

\section{Benchmark Problems and Experimental Setup}
\label{sec:benchmarks}

\subsection{Key Properties and Definitions}

\begin{definition}[Lipschitz gradient and strong convexity]
A differentiable function $f:\mathbb{R}^d \to \mathbb{R}$ has $L$-\emph{Lipschitz gradient} if $\|\nabla f(x) - \nabla f(y)\| \leq L\|x-y\|$ for all $x, y$, equivalently $\lambda_{\max}(\nabla^2 f) \leq L$ when $f$ is twice differentiable. It is $\mu$-\emph{strongly convex} if $f(y) \geq f(x) + \nabla f(x)^{\!\top}(y-x) + \frac{\mu}{2}\|y-x\|^2$, equivalently $\lambda_{\min}(\nabla^2 f) \geq \mu > 0$. The \emph{condition number} $\kappa = L/\mu$ governs convergence rates: GD requires $O(\kappa)$ iterations and accelerated methods require $O(\sqrt{\kappa})$ to achieve $\varepsilon$-accuracy.
\end{definition}

\subsection{Benchmark A: Linear Regression Quadratic Loss}
A synthetic dataset with $m = 1000$ samples and two parameters is generated as:
\begin{equation}
\theta^{\star} = \begin{bmatrix} 3 \\ 4 \end{bmatrix}, \quad x^{(i)} \sim \mathcal{N}(0, I_2), \quad y^{(i)} = {\theta^{\star}}^{\!\top} x^{(i)} + \varepsilon^{(i)}, \quad \varepsilon^{(i)} \sim \mathcal{N}(0, 1).
\end{equation}
The loss function is the mean squared error:
\begin{equation}
J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \!\left(\theta^{\!\top} x^{(i)} - y^{(i)}\right)^{\!2} = \frac{1}{2}\theta^{\!\top} H \theta - b^{\!\top}\theta + c,
\end{equation}
where $H = \frac{1}{m}X^{\!\top}X$ is the (constant) Hessian, $b = \frac{1}{m}X^{\!\top}y$, and $c = \frac{1}{2m}\|y\|^2$. The gradient is $\nabla J(\theta) = H\theta - b = \frac{1}{m}X^{\!\top}(X\theta - y)$, and the exact minimiser is the ordinary least-squares solution $\theta^{\star}_{\text{OLS}} = H^{-1}b \approx (3.028,\, 4.017)$. Due to observation noise, the minimum loss is $J^{\star} \approx 0.4826$, not zero. The Hessian $H$ has eigenvalues determined by the Gram matrix of $X$; for large $m$ with i.i.d.\ Gaussian features, $H \approx I_2$, giving condition number $\kappa(H) \approx 1$, making this benchmark well-conditioned. \textbf{Starting point:} $\theta_0 = [0,\, 0]^{\!\top}$.

\subsection{Benchmark B: Toy Neural Network Quadratic Loss}
\begin{equation}
f(x_1, x_2) = (x_1 - 1)^2 + 5(x_2 - 2)^2 + \sin(x_1).
\end{equation}
This function combines a quadratic bowl with a sinusoidal perturbation that introduces mild non-convexity along the $x_1$ axis. The gradient and Hessian are:
\begin{align}
\nabla f(x) &= \begin{bmatrix} 2(x_1 - 1) + \cos(x_1) \\ 10(x_2 - 2) \end{bmatrix}, \qquad
H(x) = \begin{bmatrix} 2 - \sin(x_1) & 0 \\ 0 & 10 \end{bmatrix}.
\end{align}
The minimum occurs at $x^{\star} \approx (0.583,\, 2.0)$, satisfying $2(x_1^{\star}-1) + \cos(x_1^{\star}) = 0$ and $x_2^{\star} = 2$, with $f^{\star} \approx 0.7244$. The Hessian eigenvalues range between $\approx [1.5,\, 3.0]$ and $10$, giving a moderate condition number $\kappa \approx 5$--7 that varies with $x_1$. \textbf{Starting point:} $x_0 = [-1,\, 4]^{\!\top}$.

\subsection{Benchmark C: Rosenbrock Function}
\begin{equation}
f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2.
\label{eq:rosenbrock}
\end{equation}
Originally proposed by Rosenbrock~\cite{rosenbrock1960} as a test for numerical optimisation methods, the global minimum is at $(1, 1)$ with $f^{\star} = 0$. The gradient is:
\begin{equation}
\nabla f(x) = \begin{bmatrix} -2(1-x_1) - 400x_1(x_2 - x_1^2) \\ 200(x_2 - x_1^2) \end{bmatrix},
\end{equation}
and the Hessian is:
\begin{equation}
H(x) = \begin{bmatrix} 2 + 1200x_1^2 - 400x_2 & -400x_1 \\ -400x_1 & 200 \end{bmatrix}.
\end{equation}
At the optimum $(1,1)$: $H(1,1) = \begin{bmatrix} 802 & -400 \\ -400 & 200 \end{bmatrix}$, whose eigenvalues are $\lambda_1 \approx 0.50$ and $\lambda_2 \approx 1001.5$, giving $\kappa(H^{\star}) \approx 2001$.

This extreme ill-conditioning, combined with the narrow curved valley along $x_2 = x_1^2$, makes the Rosenbrock function a canonical stress test for optimisation algorithms. The two-scale structure is key: along the valley axis ($x_2 \approx x_1^2$), progress is governed by the shallow curvature $\lambda_1 \approx 0.5$; orthogonal to the valley, the steep curvature $\lambda_2 \approx 1000$ constrains the maximum stable step size to $\alpha < 2/\lambda_2 \approx 0.002$. Gradient descent must use $\alpha \approx 0.001$ for stability, yielding a per-step decrease of $(1 - \alpha \lambda_1) \approx 1 - 0.0005$ in the flat direction --- meaning thousands of iterations are needed to halve the distance to the optimum along the valley.

An important subtlety is that the condition number \emph{varies non-monotonically along the trajectory}: at the starting point $x_0 = (-1, 1)$, $H(x_0) = \begin{bmatrix} 802 & 400 \\ 400 & 200 \end{bmatrix}$ has eigenvalues $\approx 0.40$ and $1001.6$, giving $\kappa(H(x_0)) \approx 2508$. At the valley floor $(0,0)$ (where all trajectories pass during descent), $H(0,0) = \mathrm{diag}(2, 200)$ with $\kappa = 100$ --- a dramatically better-conditioned point. At the optimum $(1,1)$, $\kappa$ returns to $\approx 2504$. This non-monotonic conditioning profile means gradient methods can make rapid progress crossing the valley floor but slow down again as they approach the optimum along the curved valley. \textbf{Starting point:} $x_0 = [-1,\, 1]^{\!\top}$.

\section{Question 1: Adaptive Step-Size Methods \hfill [30 marks]}
\label{sec:q1}
% ============================================================

\subsection{Motivation and Algorithm Formulations}

A fundamental challenge in gradient descent is choosing the step size $\alpha$. A constant step size must satisfy $\alpha < 2/L$ (where $L$ is the Lipschitz constant of the gradient) for convergence, but must also be large enough to make meaningful progress. Adaptive step-size methods address this by computing $\alpha_k$ automatically from the iterate's gradient and function-value information, potentially achieving faster convergence without manual tuning.

Four adaptive methods are compared against a constant-step gradient descent baseline across all three benchmarks for 120 iterations. The \emph{baseline gradient descent} update is $x_{k+1} = x_k - \alpha \nabla f(x_k)$ with fixed $\alpha$.

For a smooth $f$ with Lipschitz gradient constant $L$ (i.e., $\|\nabla f(x) - \nabla f(y)\| \leq L\|x-y\|$, or equivalently $\lambda_{\max}(H) \leq L$ for quadratics), stability requires $\alpha < 2/L$. For a strongly convex function with $\mu I \preceq H \preceq LI$, the optimal constant step is:
\begin{equation}
\alpha^{\star} = \frac{2}{L + \mu} = \frac{2}{\lambda_{\max} + \lambda_{\min}},
\end{equation}
yielding the tightest possible convergence factor $\rho^{\star} = (\kappa - 1)/(\kappa + 1)$ per iteration. For Benchmark~A ($\kappa \approx 1$), the optimal step is $\alpha^{\star} \approx 1$, so any $\alpha \in (0, 2)$ converges; for Benchmark~C ($\kappa \approx 2504$), $\alpha^{\star} \approx 2/1002 \approx 0.002$, confirming the small step size $\alpha = 0.0012$ used in experiments. The challenge of step-size selection is thus directly governed by the condition number.

\begin{algorithm}[H]
\caption{Polyak Step Size}
\label{alg:polyak}
\begin{algorithmic}[1]
\Require Initial point $x_0$, known optimal value $f^{\star}$, regularisation $\varepsilon > 0$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $\alpha_k \gets \dfrac{f(x_k) - f^{\star}}{\|g_k\|^2 + \varepsilon}$  \Comment{Polyak rule: normalised residual}
    \State $x_{k+1} \gets x_k - \alpha_k\, g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} When $f^{\star}$ is exact and $f$ is convex, the Polyak step minimises the worst-case number of iterations needed to reach $f(x_k) - f^{\star} \leq \epsilon$, achieving the $O(1/k)$ convergence rate without requiring knowledge of the Lipschitz constant $L$~\cite{polyak1969}. Specifically, for a convex $f$ with $\varepsilon = 0$:
\begin{equation}
\min_{0 \leq j \leq k} f(x_j) - f^{\star} \leq \frac{\|x_0 - x^{\star}\|^2}{2\sum_{j=0}^{k} \alpha_j}.
\end{equation}

\begin{algorithm}[H]
\caption{Adagrad (Adaptive Gradient Algorithm)}
\label{alg:adagrad}
\begin{algorithmic}[1]
\Require Initial point $x_0$, base learning rate $\alpha_0$, tolerance $\varepsilon$, iterations $N$
\State $G_0 \gets \mathbf{0} \in \mathbb{R}^d$ \Comment{Accumulated squared gradients}
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $G_{k+1} \gets G_k + g_k \odot g_k$ \Comment{Per-coordinate accumulation}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{G_{k+1}} + \varepsilon} \odot g_k$ \Comment{Per-coordinate scaling}
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} Adagrad~\cite{duchi2011} adapts the learning rate per coordinate: dimensions with large historical gradients receive smaller effective rates, and vice versa. For coordinates $i$ with accumulated gradient $G_{k,i} = \sum_{j=0}^{k} g_{j,i}^2$, the effective step decays as $\alpha_{k,i} = \alpha_0/\sqrt{G_{k,i}}$. For a constant gradient with $\|g\| = c$, $G_{k,i} = kc_i^2$, so $\alpha_{k,i} = \alpha_0/(c_i\sqrt{k}) = O(k^{-1/2})$. This monotonic $O(1/\sqrt{k})$ decay is beneficial for sparse data where later gradients are small, but can prematurely reduce the effective rate on dense problems with persistent gradients, preventing convergence to a sharp minimum (see Figure~\ref{fig:q1_stepsize_theory}).

\begin{algorithm}[H]
\caption{RMSprop}
\label{alg:rmsprop}
\begin{algorithmic}[1]
\Require Initial point $x_0$, learning rate $\alpha_0$, decay $\beta \in (0,1)$, tolerance $\varepsilon$, iterations $N$
\State $v_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $v_{k+1} \gets \beta\, v_k + (1 - \beta)\, g_k \odot g_k$ \Comment{Exponential moving average of $g^2$}
    \State $x_{k+1} \gets x_k - \dfrac{\alpha_0}{\sqrt{v_{k+1}} + \varepsilon} \odot g_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} RMSprop~\cite{tieleman2012} addresses Adagrad's monotonic step-decay by replacing the cumulative sum with an exponential moving average. With discount factor $\beta = 0.9$, the effective window captures approximately the last $1/(1-\beta) = 10$ gradient observations. For a constant gradient with magnitude $c$, the recursion $v_k = \beta v_{k-1} + (1-\beta)c^2$ with $v_0=0$ gives $v_k = (1-\beta^k)c^2 \to c^2$ as $k\to\infty$, so $\alpha_k = \alpha_0/\sqrt{v_k} \to \alpha_0/c$: RMSprop's effective step \emph{plateaus} at a constant value rather than decaying to zero (see Figure~\ref{fig:q1_stepsize_theory}). This allows the effective step size to remain bounded away from zero, making RMSprop better suited to non-stationary loss landscapes and long-horizon optimisation.

\begin{figure}[H]
\centering
\includegraphics[width=0.95\textwidth]{figures/q1_adaptive_stepsize_theory.pdf}

\begin{algorithm}[H]
\caption{Heavy Ball (Polyak Momentum)}
\label{alg:heavyball}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, momentum $\beta \in [0,1)$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets \beta\, z_k + \alpha\, \nabla f(x_k)$ \Comment{Velocity update}
    \State $x_{k+1} \gets x_k - z_{k+1}$ \Comment{Position update}
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} The Heavy Ball method adds an inertia term: the iterate moves in the direction of accumulated past gradients weighted exponentially by $\beta^k$. For strongly convex quadratics with condition number $\kappa$, the optimal parameters $\alpha^* = (2/(\sqrt{\lambda_{\max}}+\sqrt{\lambda_{\min}}))^2$ and $\beta^* = ((\sqrt{\kappa}-1)/(\sqrt{\kappa}+1))^2$ achieve the linear convergence rate $O((\frac{\sqrt\kappa-1}{\sqrt\kappa+1})^k)$, which is asymptotically faster than gradient descent's $O((\frac{\kappa-1}{\kappa+1})^k)$ rate. For Benchmark~C at the optimum ($\kappa \approx 2003$), the theoretical optimum is $\alpha^* \approx 0.00382$ and $\beta^* \approx 0.914$, giving convergence factor $\rho^* \approx 0.956$ vs.\ GD's $\rho_{\rm GD} \approx 0.999$: a $44.8\times$ speedup in theory. The used values ($\alpha = 0.0008$, $\beta = 0.86$) are more conservative to account for the non-quadratic behaviour of Rosenbrock far from the optimum, where the Hessian changes significantly and the optimal-quadratic parameters would cause divergence.

\begin{remark}
The Polyak step size requires the exact optimal value $f^{\star}$. In these experiments, $f^{\star} = 0$ is specified for all benchmarks. This is correct only for Benchmark~C (Rosenbrock, whose global minimum is 0); for Benchmarks~A and~B, the true minima are $\approx 0.4826$ and $\approx 0.7244$ respectively, so $f^{\star} = 0$ is a deliberate misspecification that tests algorithm robustness.
\end{remark}

\begin{remark}
Adagrad was originally designed for \emph{sparse} gradient problems (e.g., natural language processing with sparse feature activations), where different coordinates receive gradients infrequently. In such settings, the monotonically decaying effective step $\alpha_{k,i} = \alpha_0/\sqrt{G_{k,i}}$ is beneficial: rarely-updated coordinates retain a large effective rate. For \emph{dense} gradient problems like Benchmarks~A--C, every coordinate is updated at every step, so Adagrad's cumulative sum grows continuously and the effective rate eventually falls below any useful threshold. This explains why Adagrad performs comparably to GD on Benchmarks~A and~B but falls behind Heavy Ball and Nesterov on the long-horizon Rosenbrock problem.
\end{remark}

\begin{remark}[Adagrad coordinate scaling on Rosenbrock]
On Benchmark~C (Rosenbrock), Adagrad's per-coordinate scaling has a nuanced effect. At iteration~120, the effective step sizes are approximately $\alpha_{120,x_1} \approx 0.00175$ and $\alpha_{120,x_2} \approx 0.00246$. Compared to GD's fixed $\alpha = 0.0012$ for both coordinates, Adagrad takes \emph{larger} effective steps in both directions ($1.5\times$ and $2\times$ larger), explaining why Adagrad ($f=2.203$) substantially outperforms GD ($f=3.514$). The slightly larger step in the $x_2$ direction (higher curvature) reflects that near the valley floor ($x_2 \approx x_1^2$), the $x_2$ gradient $= 200(x_2 - x_1^2)$ is small (nearly satisfied constraint), so $G_{k,x_2}$ accumulates slowly, preserving a larger effective step. This mild asymmetry actually benefits convergence here, since the $x_2$ component has larger error near the starting point.
\end{remark}

\subsection{Algorithm Formulations}

\begin{algorithm}[H]
\caption{Nesterov Accelerated Gradient}
\label{alg:nesterov}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, max momentum $\beta_{\max}$, iterations $N$
\State $z_0 \gets \mathbf{0}$
\For{$k = 1, 2, \ldots, N$}
    \State $\beta_k \gets \min\!\left(\dfrac{k-1}{k+2},\ \beta_{\max}\right)$ \Comment{Increasing momentum schedule}
    \State $\tilde{x}_k \gets x_k + \beta_k\, z_k$ \Comment{Lookahead point}
    \State $z_{k+1} \gets \beta_k\, z_k - \alpha\, \nabla f(\tilde{x}_k)$
    \State $x_{k+1} \gets x_k + z_{k+1}$
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} The critical distinction from Heavy Ball is the \emph{lookahead}: the gradient is evaluated at the extrapolated point $\tilde{x}_k = x_k + \beta_k z_k$ rather than $x_k$. This ``corrected gradient'' allows Nesterov to anticipate overshooting and adjust its direction. For \emph{convex} (not necessarily strongly convex) functions with Lipschitz gradient constant $L$:
\begin{theorem}[Nesterov acceleration for convex functions~\cite{nesterov1983}]
With $\alpha = 1/L$ and the schedule $\beta_k = (k-1)/(k+2)$, Nesterov's method achieves:
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2L\|x_0 - x^{\star}\|^2}{(k+1)^2} = O\!\left(\frac{1}{k^2}\right),
\end{equation}
which is \emph{optimal} among all first-order methods for smooth convex optimisation (no black-box first-order method can do better).
\end{theorem}
In contrast, gradient descent achieves only $O(L\|x_0-x^\star\|^2/k) = O(1/k)$.

\paragraph{Theorem verification on the benchmarks.} For Benchmark~A: $L \approx 1.033$, $\|x_0 - x^{\star}\|^2 \approx 25.3$, so the bound at $k=150$ gives $2L\|x_0-x^{\star}\|^2/(k+1)^2 = 2 \times 1.033 \times 25.3/151^2 \approx 0.0023$. The actual excess is $\approx 0$ (machine precision), so the bound is valid with a large safety factor, reflecting the strong convexity of the quadratic. For Benchmark~C: $L \approx 1002$ at the optimum, and the theorem bound at $k=150$ with $\alpha = 1/L$ gives $2 \times 1002 \times 8/151^2 \approx 0.70$, while the actual excess is $0.479$ --- within the bound. Our used step $\alpha = 0.0007 < 1/L \approx 0.001$ is conservative, yielding a slightly worse result than what is theoretically achievable with $\alpha = 1/L$.

For \emph{strongly convex} functions (e.g., Benchmark~A with $\mu = \lambda_{\min}(H) > 0$), both GD and Nesterov achieve \emph{linear} convergence, but at different rates. GD converges at rate $(1 - \mu/L)^k$ while Nesterov achieves the faster rate $(1 - \sqrt{\mu/L})^k$, giving a speedup by squaring the convergence factor --- the same asymptotic improvement as transitioning from $O(1/k)$ to $O(1/k^2)$ in the convex setting. This explains why Nesterov is only marginally faster on Benchmarks~A and~B (near-quadratic, well-conditioned) but dramatically faster on Benchmark~C (near-convex, ill-conditioned along the valley).

\paragraph{Proof sketch of $O(1/k^2)$ rate.}
The analysis uses the \emph{Lyapunov function} $\Phi_k = (k+1)^2 (f(x_k) - f^{\star}) + 2L\|y_k - x^{\star}\|^2$, where $y_k$ is a suitably defined auxiliary sequence. With step $\alpha = 1/L$ and the schedule $\beta_k = (k-1)/(k+2)$, one can show $\Phi_{k+1} \leq \Phi_k$ (the energy is non-increasing), which immediately yields:
\begin{equation}
(k+1)^2 (f(x_k) - f^{\star}) \leq \Phi_k \leq \Phi_0 = 2L\|x_0 - x^{\star}\|^2,
\end{equation}
giving $f(x_k) - f^{\star} \leq 2L\|x_0 - x^{\star}\|^2/(k+1)^2$. The key insight is that the factor $(k+1)^2$ in $\Phi_k$ grows \emph{quadratically} with $k$, allowing the energy decrease per step to be only $O(1/k^2)$ while still guaranteeing convergence.

\begin{algorithm}[H]
\caption{Adam Optimiser}
\label{alg:adam}
\begin{algorithmic}[1]
\Require $x_0$, learning rate $\alpha$, moment parameters $\beta_1, \beta_2$, tolerance $\varepsilon$, iterations $N$
\State $m_0 \gets \mathbf{0},\ v_0 \gets \mathbf{0}$
\For{$t = 1, 2, \ldots, N$}
    \State $g_t \gets \nabla f(x_t)$
    \State $m_t \gets \beta_1\, m_{t-1} + (1 - \beta_1)\, g_t$ \Comment{First moment (mean)}
    \State $v_t \gets \beta_2\, v_{t-1} + (1 - \beta_2)\, g_t \odot g_t$ \Comment{Second moment (variance)}
    \State $\hat{m}_t \gets m_t / (1 - \beta_1^t)$ \Comment{Bias-corrected mean}
    \State $\hat{v}_t \gets v_t / (1 - \beta_2^t)$ \Comment{Bias-corrected variance}
    \State $x_{t+1} \gets x_t - \alpha\, \hat{m}_t \,/\, (\sqrt{\hat{v}_t} + \varepsilon)$
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} Adam~\cite{kingma2015} combines Nesterov-style momentum (via the exponential moving average $m_t$) with per-coordinate adaptive scaling (via $v_t$), inheriting advantages of both RMSprop and momentum methods. The bias-correction terms $(1-\beta_1^t)$ and $(1-\beta_2^t)$ prevent the early iterates from being biased towards zero when $m_0 = v_0 = 0$. The effective step magnitude per coordinate is bounded: $|(\Delta x_t)_i| \leq \alpha(1-\beta_1)/\sqrt{1-\beta_2}$ approximately, providing a natural upper bound on per-step movement.

\begin{remark}
Reddi \emph{et al.}\ (2018) showed that Adam can \emph{fail to converge} on simple stochastic convex optimisation problems due to the exponential moving average $v_t$ forgetting large past gradients: in adversarial online settings, Adam's effective learning rate can increase when large-gradient steps are taken, causing divergence. This issue does not arise in our deterministic (full-batch) experiments since $v_t$ sees the true gradient at every step. The \emph{AMSGrad} variant fixes this by using $\hat{v}_t = \max(\hat{v}_{t-1}, v_t)$ (non-decreasing second moment), restoring convergence guarantees at the cost of slightly reduced adaptivity.
\end{remark}

\subsection{Mini-Batch Stochastic Gradient Descent}

\subsubsection{Algorithm and Implementation}

Mini-batch SGD on Benchmark~A uses learning rate $\alpha = 0.06$ and batch sizes $b \in \{5, 40\}$ over 50 epochs, with data randomly permuted at each epoch.

\begin{algorithm}[H]
\caption{Mini-Batch SGD}
\label{alg:sgd}
\begin{algorithmic}[1]
\Require Data $(X, y)$, initial $\theta_0$, learning rate $\alpha$, batch size $b$, epochs $E$
\For{$e = 1, 2, \ldots, E$}
    \State Randomly permute training indices $\{1, \ldots, m\}$
    \For{each mini-batch $\mathcal{B}$ of size $b$}
        \State $g \gets \frac{1}{b} X_{\mathcal{B}}^{\!\top}(X_{\mathcal{B}}\theta - y_{\mathcal{B}})$ \Comment{Stochastic gradient}
        \State $\theta \gets \theta - \alpha\, g$
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Key quantities:} With $m=1000$, batch $b=5$ gives $\lfloor 1000/5 \rfloor = 200$ updates/epoch; $b=40$ gives $\lfloor 1000/40 \rfloor = 25$ updates/epoch. Over $E=50$ epochs, this amounts to $200 \times 50 = 10{,}000$ gradient steps for $b=5$ versus $25 \times 50 = 1{,}250$ steps for $b=40$ --- an $8\times$ difference that largely explains the observed convergence gap: $b=5$ provides $8\times$ more parameter updates for the same number of epochs, more than compensating for the $\sqrt{8}\approx 2.8\times$ higher gradient noise. The stochastic gradient estimator has variance $\mathrm{Var}[\hat{g}] \propto \sigma^2/b$ where $\sigma^2$ is the per-sample gradient variance, so larger batches produce lower-variance gradient estimates. The noise floor (the limiting $f$ value achievable with constant $\alpha$) is approximately $f^{\star} + O(\alpha \sigma^2/b)$; with $\alpha = 0.06$, $\sigma=1$: $f_{\rm floor}^{(b=5)} \approx 0.4826 + 0.012 = 0.4946$ and $f_{\rm floor}^{(b=40)} \approx 0.4826 + 0.0015 = 0.4841$. The trade-off is: \emph{fewer but noisier steps} (small $b$) vs.\ \emph{more but costlier steps} (large $b$). For strongly convex objectives, the optimal batch size that minimises wall-clock time is typically moderate ($b \approx \sqrt{m} \approx 32$ for $m=1000$).

\subsubsection{Learning Rate and Convergence}
Mini-batch SGD with constant learning rate $\alpha$ does \emph{not} converge to the exact minimum even as $k \to \infty$: the final iterate oscillates in a neighbourhood of radius $O(\alpha \sigma^2/b)$ around $\theta^{\star}$. This ``noise floor'' is visible in Figure~\ref{fig:q2_sgd_batch}. To achieve exact convergence, the learning rate must decay to zero, e.g., $\alpha_k = \alpha_0/(k + k_0)$ (diminishing schedule), which leads to $O(1/k)$ convergence rate for strongly convex problems --- at the cost of slower initial progress. Practical training schedules (cosine annealing, step decay) interpolate between these regimes.

\subsubsection{Optimal Batch Size Analysis}
The total computation to reach $\varepsilon$-accuracy can be analysed by counting gradient evaluations. For strongly convex $f$ ($\mu$-strong convexity, $L$-Lipschitz gradient), full-batch GD requires $O(mL/\mu \cdot \log(1/\varepsilon))$ sample evaluations (one pass = $m$ evaluations, $O(\kappa \log(1/\varepsilon))$ passes). Mini-batch SGD with batch $b$ requires approximately $O((L/\mu + \sigma^2/(\mu^2 b\varepsilon)) \cdot b)$ evaluations per accuracy level. The crossover to linear speedup occurs for $b \leq m/\kappa$. For Benchmark~A ($\kappa \approx 1.12$), this gives $b_{\rm linear} \approx m/\kappa \approx 893$, meaning \emph{almost any} batch size provides near-linear speedup in total evaluations. In practice, $b \in \{32, 64, 128\}$ (hardware-aligned) is optimal for GPU throughput.

\subsubsection{Per-Step vs.\ Per-Epoch Perspective}
The Figure~\ref{fig:q2_sgd_batch} x-axis measures epochs (full passes through the data). On a \emph{per-gradient-step} basis, $b=5$ and $b=40$ converge at similar rates (same learning rate $\alpha=0.06$, similar gradient quality). The observed faster per-epoch convergence for $b=5$ is entirely due to the $8\times$ more gradient steps per epoch. This distinction matters for hardware-parallel implementations: if $b=5$ and $b=40$ steps take the same wall-clock time (e.g., due to vectorisation), then $b=40$ would be preferred for lower gradient noise. In practice, batches are padded to be multiples of the hardware vector width (e.g., 32 or 64 on GPUs), making $b=5$ suboptimal for throughput but $b=40$ closer to hardware-optimal.

\subsection{First and Second-Order Local Approximations of $g(x) = x^4$}

Consider $g(x) = x^4$ at the expansion point $x_0 = 0.25$. The function values are:
\begin{equation}
g(x_0) = 0.25^4 = 0.00390625, \quad g'(x_0) = 4 \cdot 0.25^3 = 0.0625, \quad g''(x_0) = 12 \cdot 0.25^2 = 0.75.
\end{equation}

\textbf{First-order (Taylor) approximation:}
\begin{equation}
g(x) \approx g_1(x) = g(x_0) + g'(x_0)(x - x_0) = 0.00391 + 0.0625(x - 0.25).
\end{equation}

\textbf{Second-order approximation:}
\begin{equation}
g(x) \approx g_2(x) = g_1(x) + \tfrac{1}{2}g''(x_0)(x - x_0)^2 = 0.00391 + 0.0625(x - 0.25) + 0.375(x - 0.25)^2.
\end{equation}

The \textbf{Newton update} from $x_0$ minimises $g_2(x)$, yielding:
\begin{equation}
x_{\text{Newton}} = x_0 - \frac{g'(x_0)}{g''(x_0)} = 0.25 - \frac{0.0625}{0.75} \approx 0.1667.
\end{equation}
Iterating from $x_0 = 0.25$, Newton's method on $g(x) = x^4$ applies the update $x_{k+1} = x_k - g'(x_k)/g''(x_k) = x_k - 4x_k^3/(12x_k^2) = x_k - x_k/3 = (2/3)x_k$, giving the closed-form sequence $x_k = (2/3)^k \cdot 0.25$. This is \emph{linear} convergence with factor $\rho = 2/3$ --- not the quadratic convergence of Newton's theorem. The reason is that the second-order sufficiency condition $g''(x^{\star}) > 0$ fails: $g''(0) = 0$, so the Hessian is singular at the minimum and Newton's quadratic convergence theory does not apply. Gradient descent with $\alpha = 0.05$ requires $\approx 41$ iterations to reach $|x_{41}| \approx 0.175$, compared to Newton's $|x_{10}| \approx 0.0043$ in 10 iterations --- confirming Newton's practical advantage even without the full quadratic rate. The approximation figure illustrates \emph{why}: the quadratic model $g_2(x)$ captures the true function far better than the linear tangent, enabling much larger effective steps per iteration.

\subsection{Newton's Method in Multiple Dimensions}

\begin{algorithm}[H]
\caption{Damped Newton's Method}
\label{alg:newton}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, damping $\lambda > 0$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $g_k \gets \nabla f(x_k)$
    \State $H_k \gets \nabla^2 f(x_k) + \lambda I$ \Comment{Tikhonov-regularised Hessian}
    \State Solve $H_k p_k = g_k$ for $p_k$ \Comment{Newton direction}
    \State $x_{k+1} \gets x_k - \alpha\, p_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory and stopping criterion:} Newton's direction $p_k = H_k^{-1}g_k$ is the minimiser of the second-order model $f(x_k) + g_k^{\!\top}(x-x_k) + \frac{1}{2}(x-x_k)^{\!\top}H_k(x-x_k)$. The \emph{Newton decrement} $\lambda(x_k) = \sqrt{g_k^{\!\top} H_k^{-1} g_k}$ measures the gap between the second-order model and $f^{\star}$: the model value at the Newton step is $f(x_k) - \lambda(x_k)^2/2$, so $\lambda(x_k)^2/2$ is the predicted improvement. Terminating when $\lambda(x_k)/2 \leq \varepsilon$ guarantees $f(x_k) - f^{\star} \leq \varepsilon$ under the local quadratic approximation --- providing a self-certified stopping criterion without knowing $f^{\star}$. At Benchmark~B's converged point, $\lambda \approx 1.7 \times 10^{-4}$, confirming convergence; at Benchmark~C after 20 iterations, $\lambda \approx 0.63$, confirming the iterate is still far from the optimum and more iterations are needed. For strictly convex functions with $\alpha = 1$ (pure Newton), the method achieves \emph{quadratic} local convergence~\cite{nocedal2006}:
\begin{equation}
\|x_{k+1} - x^{\star}\| \leq C\,\|x_k - x^{\star}\|^2, \quad C = \frac{L_H}{2\mu},
\end{equation}
where $L_H$ is the Lipschitz constant of the Hessian and $\mu$ is the strong convexity parameter, meaning the number of correct decimal digits roughly doubles per iteration once the iterate enters a neighbourhood of $x^{\star}$. Damping ($\alpha < 1$) and Hessian regularisation ($\lambda > 0$) are used to ensure descent far from the optimum and handle positive-definiteness on non-convex problems.

\begin{remark}
Benchmark~C (Rosenbrock) is \emph{non-convex}: there exist points where the Hessian is not positive semidefinite. For non-convex functions, Newton's method (and first-order methods) can only guarantee convergence to a \emph{first-order stationary point} ($\nabla f = 0$), not necessarily the global minimum. Fortunately, the Rosenbrock function is known to have a unique global minimum at $(1,1)$ for the 2D case, so convergence to any stationary point is convergence to the global minimum.
\end{remark}

\begin{remark}[Hessian staleness on curved trajectories]
On non-quadratic functions like Rosenbrock, the Hessian $H(x_k)$ used in the Newton step is only accurate locally: the quadratic model $f(x_k) + g_k^{\!\top}(x-x_k) + \frac{1}{2}(x-x_k)^{\!\top}H_k(x-x_k)$ approximates $f$ well only within a trust region $\|x - x_k\| \leq r$ of radius $r = O(\mu/L_H)$, where $L_H$ is the Hessian Lipschitz constant. On Rosenbrock, the Hessian changes rapidly along the curved valley ($L_H$ is large due to the $1200x_1^2$ term), so the quadratic model becomes inaccurate quickly, requiring the damped step $\alpha = 0.22 \ll 1$ to stay within the region of approximation accuracy. This is the fundamental motivation for trust-region Newton methods, which explicitly constrain the Newton step to remain within a ball where the quadratic model is reliable.
\end{remark}

\subsection{Computational Cost Discussion}

Each Newton iteration requires computing the Hessian $H_k$ ($O(d^2)$ entries for $d$-dimensional problems), solving $H_k p_k = g_k$ ($O(d^3)$ via Gaussian elimination or $O(d^2)$ with exploitable structure), versus $O(d)$ per gradient descent step. For large-scale problems ($d \gg 100$), this quadratic/cubic per-iteration cost makes exact Newton impractical. The preferred alternative is \textbf{L-BFGS} (Limited-memory BFGS)~\cite{nocedal2006}, which approximates the Hessian inverse using the secant pairs $\{(s_j, y_j)\}_{j=k-m}^{k-1}$ from the last $m$ gradient differences ($s_j = x_{j+1} - x_j$, $y_j = \nabla f(x_{j+1}) - \nabla f(x_j)$), requiring only $O(md)$ storage and $O(md)$ per iteration. The two-loop recursion allows applying the approximate Hessian inverse without explicitly forming or storing any matrix, making L-BFGS the standard choice for smooth large-scale optimisation, providing near-Newton superlinear convergence with gradient-descent-level per-iteration cost. For the $d=2$ problems here, Newton's dramatically superior convergence rate easily justifies the marginal additional per-iteration cost.

\subsection{Part A: Finite Differences and Nesterov Random Search (Benchmark B)}

\subsubsection{Forward Finite-Difference Gradient Approximation}

When the gradient $\nabla f$ is unavailable, it can be approximated by finite differences:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x)}{\delta}, \quad e_i \text{ is the $i$-th standard basis vector.}
\end{equation}
The approximation error has two components:
\begin{equation}
\text{Total error} = \underbrace{O(\delta)}_{\text{truncation}} + \underbrace{O\!\left(\frac{\varepsilon_{\rm mach}}{\delta}\right)}_{\text{floating-point}}.
\end{equation}
This is minimised at $\delta_{\rm opt} \approx \sqrt{\varepsilon_{\rm mach}} \approx 10^{-8}$ for double precision, yielding an error of $O(\sqrt{\varepsilon_{\rm mach}}) \approx 10^{-8}$. \emph{Central differences} $\frac{f(x+\delta e_i) - f(x-\delta e_i)}{2\delta}$ reduce truncation error to $O(\delta^2)$, pushing the optimal $\delta_{\rm opt}^{\rm central} \approx \varepsilon_{\rm mach}^{1/3} \approx 10^{-5.3}$ with total error $O(\varepsilon_{\rm mach}^{2/3}) \approx 10^{-10.7}$. For this assignment, $\delta = 0.05$ is ``good'' (small enough that truncation is manageable using forward differences), while $\delta = 0.8$ is ``poor'' (large truncation error dominates).

Each gradient evaluation requires $d + 1 = 3$ function evaluations (one baseline $f(x)$ plus one per coordinate). For Benchmark~B, the second derivative in the $x_1$ direction is $f''_{11} = 2 - \sin(x_1) \approx 1.5$ at the starting point. The truncation error with $\delta = 0.8$ is $O(\delta f'') = O(0.8 \times 1.5) = O(1.2)$, which is comparable in magnitude to the true gradient itself ($\|\nabla f\| \approx 3.5$ at $x_0$), explaining the poor convergence.

\subsubsection{Alternative: Central Finite Differences}

For comparison, \emph{central differences} use:
\begin{equation}
\frac{\partial f}{\partial x_i}(x) \approx \frac{f(x + \delta e_i) - f(x - \delta e_i)}{2\delta},
\end{equation}
which achieves truncation error $O(\delta^2)$ (vs.\ $O(\delta)$ for forward differences) by cancelling the leading error term. The optimal $\delta_{\rm opt}^{\rm central} \approx \varepsilon_{\rm mach}^{1/3} \approx 10^{-5.3}$ gives total error $O(\varepsilon_{\rm mach}^{2/3}) \approx 10^{-10.7}$, significantly better than the forward-difference optimum $O(\sqrt{\varepsilon_{\rm mach}}) \approx 10^{-8}$. The cost is $2d$ function evaluations per gradient step (vs.\ $d+1$ for forward differences). For Benchmark~B at $\delta=0.05$, the central difference truncation error is $O(\delta^2 f'''/(6)) \approx O(0.0025 \times 3) = O(0.008)$, versus the forward difference error $O(\delta f''/2) \approx O(0.05 \times 0.9) = O(0.046)$ --- a $5\times$ improvement. The Figure~\ref{fig:q4_fd_error} (right panel) illustrates this on the $x_2$ direction.

\subsubsection{Nesterov Random Search}

\begin{algorithm}[H]
\caption{Nesterov Random Search (Zeroth-Order)}
\label{alg:nrs}
\begin{algorithmic}[1]
\Require Initial point $x_0$, step size $\alpha$, perturbation $\delta$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State Sample $u_k \sim \mathcal{N}(0, I_d)$; normalise: $u_k \gets u_k / \|u_k\|$
    \State $\hat{g}_k \gets \dfrac{f(x_k + \delta u_k) - f(x_k)}{\delta}\, u_k$ \Comment{Directional derivative along $u_k$}
    \State $x_{k+1} \gets x_k - \alpha\, \hat{g}_k$
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} $\hat{g}_k = \frac{f(x+\delta u) - f(x)}{\delta} u$ is an unbiased estimator of the \emph{smoothed} gradient $\nabla f_\delta(x) = \mathbb{E}_u[f(x+\delta u)/\delta \cdot u]$. For small $\delta$, $\nabla f_\delta \approx \nabla f$. The key advantage is that only \textbf{two function evaluations} are required per iteration regardless of dimension $d$, making it $d/2$ times cheaper than finite differences per step. The cost is higher gradient variance: each step uses only a one-dimensional directional derivative, discarding information from the remaining $d-1$ directions. Formally, $\mathbb{E}[\hat{g}_k \hat{g}_k^{\!\top}] = \frac{1}{d}\nabla f \nabla f^{\!\top} + \frac{\|\nabla f\|^2}{d} I_d$, so the variance of the estimator is $O(\|\nabla f\|^2 / d)$ \emph{per coordinate} --- meaning the random search gradient has the same mean as the true gradient but is noisier by a factor of $\Theta(\sqrt{d})$. This extra noise inflates the convergence bound from $O(1/k)$ (exact gradient) to $O(1/\sqrt{k})$ (one random direction), since the additional noise requires the step size $\alpha$ to be $O(1/\sqrt{k})$ for stability, exactly as in stochastic gradient descent.

\subsection{Part B: Derivative-Free Methods on Benchmark C}

\subsubsection{Nelder--Mead Simplex Method}

The Nelder--Mead algorithm~\cite{neldermead1965} maintains a simplex of $n+1 = 3$ vertices in $\mathbb{R}^2$ and iteratively deforms it through four operations. The vertices are always sorted $f(x_1) \leq f(x_2) \leq f(x_3)$ (best to worst); all operations are defined relative to the centroid $\bar{x} = \frac{1}{n}\sum_{i=1}^n x_i$ of the $n$ \emph{best} vertices (excluding the worst):
\begin{enumerate}[nosep]
    \item \textbf{Reflection} ($\alpha_r = 1.0$): $x_r = \bar{x} + \alpha_r(\bar{x} - x_{n+1})$ reflects worst vertex through centroid. Accept if $f(x_1) \leq f(x_r) < f(x_n)$.
    \item \textbf{Expansion} ($\gamma = 2.0$): if $f(x_r) < f(x_1)$, try $x_e = \bar{x} + \gamma(\bar{x} - x_{n+1})$; accept best of $x_r, x_e$.
    \item \textbf{Contraction} ($\rho = 0.5$): if reflection worsened, contract: $x_c = \bar{x} + \rho(x_r - \bar{x})$ (outside) or $x_c = \bar{x} + \rho(x_{n+1} - \bar{x})$ (inside).
    \item \textbf{Shrink} ($\sigma = 0.5$): if contraction fails, contract all $x_i \leftarrow x_1 + \sigma(x_i - x_1)$ towards best vertex.
\end{enumerate}

\noindent Importantly, no gradient information is required at any step. The simplex geometry adapts to the local landscape: it elongates in flat directions (where large steps help) and contracts near the minimum (where precision is needed). \textbf{Settings:} initial simplex step $= 0.35$, 160 iterations.

Nelder--Mead has no general convergence guarantee in $d \geq 2$: McKinnon (1999) exhibited a smooth strongly convex function in $\mathbb{R}^2$ on which the Nelder--Mead simplex converges to a non-stationary point, violating the intuition that simplex methods ``explore'' sufficiently. Its $O(1/k)$ convergence rate in $d=2$ under regular (non-degenerate) iterations reflects the geometric contraction of the simplex diameter. \subsection{Problem Setup}

\textbf{Problem:} Minimise Benchmark~B, $f(x) = (x_1-1)^2 + 5(x_2-2)^2 + \sin(x_1)$, subject to $x_1 \geq 0.5$, starting from the infeasible point $x_0 = (0.2, 4.0)$.

\textbf{Note:} The unconstrained minimum is at $x^{\star} \approx (0.583, 2.0)$, for which $x_1^{\star} \approx 0.583 > 0.5$. Therefore the constraint $x_1 \geq 0.5$ is \emph{inactive} at the optimum: the constrained and unconstrained minima coincide. This makes the problem pedagogically useful --- methods must start from an infeasible point and navigate to feasibility, but once feasible, standard descent towards $x^{\star}$ is optimal.

\begin{algorithm}[H]
\caption{Projected Gradient Descent (PGD)}
\label{alg:pgd}
\begin{algorithmic}[1]
\Require Initial $x_0$ (possibly infeasible), step size $\alpha$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_{k+1} \gets x_k - \alpha\, \nabla f(x_k)$ \Comment{Unconstrained gradient step}
    \State $x_{k+1} \gets \Pi_{\mathcal{X}}(z_{k+1})$ \Comment{Project: $x_1 \leftarrow \max(0.5,\, x_1)$}
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} For a closed convex set $\mathcal{X}$, the projection $\Pi_{\mathcal{X}}(z) = \arg\min_{x \in \mathcal{X}} \|x - z\|$ is a contraction and the projected gradient step is equivalent to a constrained steepest descent. PGD converges at rate $O(1/k)$ for convex $f$. For the half-space constraint $\{x : x_1 \geq 0.5\}$, the projection is simply $(z_1, z_2) \mapsto (\max(0.5, z_1), z_2)$.

\begin{algorithm}[H]
\caption{Penalty Method (Gradient Descent on Penalised Objective)}
\label{alg:penalty}
\begin{algorithmic}[1]
\Require Initial $x_0$, step size $\alpha$, penalty weight $\lambda > 0$, iterations $N$
\State Define penalised objective $F_\lambda(x) = f(x) + \lambda \max(0,\, 0.5 - x_1)$
\For{$k = 0, 1, \ldots, N-1$}
    \State $x_{k+1} \gets x_k - \alpha\, \nabla F_\lambda(x_k)$ \Comment{Note: $\nabla F_\lambda$ has subgradient at $x_1 = 0.5$}
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} The penalty method converts the constrained problem into an unconstrained one by adding a penalty term that increases as the constraint is violated. As $\lambda \to \infty$, the penalised minimum converges to the constrained minimum, but the modified objective becomes increasingly ill-conditioned, requiring smaller step sizes for stability. Three penalty weights are tested: $\lambda \in \{0.15, 1.8, 4.5\}$.

\paragraph{KKT Optimality Conditions.}
For the constrained problem $\min_x f(x)$ subject to $g(x) \leq 0$ (where $g(x) = 0.5 - x_1$), the Karush--Kuhn--Tucker (KKT) conditions for a local minimum $x^{\star}$ are:
\begin{align}
\nabla f(x^{\star}) + \mu^{\star} \nabla g(x^{\star}) &= 0 \quad \text{(stationarity)}, \label{eq:kkt_stat} \\
g(x^{\star}) &\leq 0 \quad \text{(primal feasibility)}, \\
\mu^{\star} &\geq 0 \quad \text{(dual feasibility)}, \\
\mu^{\star} g(x^{\star}) &= 0 \quad \text{(complementary slackness)}.
\end{align}
Since the unconstrained minimum $x^{\star} \approx (0.583, 2.0)$ satisfies $g(x^{\star}) = 0.5 - 0.583 = -0.083 < 0$ (strictly feasible), complementary slackness requires $\mu^{\star} = 0$. Stationarity \eqref{eq:kkt_stat} then reduces to $\nabla f(x^{\star}) = 0$, which is precisely the unconstrained first-order condition. This confirms analytically that the constraint is inactive and the constrained optimum equals the unconstrained optimum.

\begin{remark}
Since both $f$ and $g$ are continuously differentiable, and the feasible set $\{x : g(x) \leq 0\}$ satisfies the linear independence constraint qualification (LICQ) at the optimum (the gradient $\nabla g = [-1, 0]^{\!\top}$ is non-zero), the KKT conditions are not only necessary but also \emph{sufficient} for global optimality here, because $f$ is convex on $\mathcal{X}$ near the minimum.
\end{remark}

\begin{itemize}[nosep]
\item \textbf{Projected GD} enforces feasibility \emph{immediately} and \emph{exactly} at every iteration. This is the fundamental advantage of projection: feasibility is a hard invariant, not an asymptotic property. The cost is requiring a projection oracle, which for half-space constraints is trivial ($O(d)$) but can be expensive for general convex sets (e.g., semidefinite constraints require a matrix eigendecomposition).
\item \textbf{Penalty methods} trade exact feasibility for simplicity: only a modified gradient computation is needed, with no projection oracle. The weight $\lambda$ encodes the feasibility--efficiency trade-off: the penalised minimum $x_\lambda^{\star}$ satisfies $\|g(x_\lambda^{\star})\| = O(1/\lambda)$ for smooth problems, so $\lambda \to \infty$ gives $x_\lambda^{\star} \to x^{\star}$ but the condition number of the penalised Hessian grows as $O(\lambda)$, requiring progressively smaller step sizes.
\item \textbf{Augmented Lagrangian (ALM)} methods~\cite{nocedal2006} improve on penalty methods by adding a Lagrange multiplier estimate $\hat{\mu}$ that is updated across outer iterations: $F_{\rm ALM}(x) = f(x) + \hat{\mu}\,g(x) + \frac{\rho}{2}g(x)^2$. With fixed $\rho$ and updated $\hat{\mu} \leftarrow \hat{\mu} + \rho\,g(x_k)$ after each inner solve, ALM achieves feasibility accuracy $O(1/\rho^k)$ (geometric rather than algebraic) without requiring $\rho \to \infty$. This avoids the ill-conditioning issue of pure penalty methods.
\end{itemize}

\noindent For completeness, the ALM update for the Q5 constraint $g(x) = 0.5 - x_1 \leq 0$ is:
\begin{equation}
F_{\rm ALM}(x; \hat{\mu}) = f(x) + \hat{\mu}(0.5 - x_1) + \frac{\rho}{2}\max(0,\, 0.5 - x_1)^2,
\end{equation}
with inner solve $x_{k+1} \leftarrow \arg\min_x F_{\rm ALM}(x; \hat{\mu}_k)$ (solved via gradient descent) and outer update $\hat{\mu}_{k+1} \leftarrow \max(0, \hat{\mu}_k + \rho\max(0, 0.5 - x_{k+1,1}))$. For inactive constraints (as here), $g(x^{\star}) < 0$ implies $\hat{\mu}_k \to 0$, so the ALM converges to the unconstrained minimum without any conditioning penalty.

\section{Question 6: Linear Programmes and Frank--Wolfe Algorithm \hfill [30 marks]}

\subsection{Task I: Linear Programme over $\mathcal{X}$}

\textbf{Problem:} Minimise $f(x) = a^{\!\top}x = x_1 + 2x_2$ over the box $\mathcal{X} = \{0.5 \leq x_1 \leq 5,\, -5 \leq x_2 \leq 10\}$.

Since $a = [1, 2]^{\!\top}$ has all-positive components, $f$ is minimised by setting each coordinate to its lower bound independently:
\begin{equation}
x^{\star} = (0.5,\, -5), \qquad f^{\star} = 1 \cdot 0.5 + 2 \cdot (-5) = -9.5.
\end{equation}

This illustrates the \textbf{fundamental theorem of linear programming}: for a linear objective over a bounded polyhedron (here, a box), the optimum is always attained at a \emph{vertex}. The feasible region has $2^2 = 4$ vertices: $(0.5, -5)$, $(5, -5)$, $(0.5, 10)$, $(5, 10)$, and evaluation at each confirms $(0.5, -5)$ achieves the minimum.

\paragraph{Exact LP solvers.}
For small-dimensional box constraints, the linear programme is trivially solved by coordinate-wise inspection of $a_i$'s sign. For general polyhedra $\{x : Ax \leq b\}$ in $\mathbb{R}^d$ with $m$ constraints, the \emph{simplex method} traces vertices of the feasible polytope until optimality is confirmed (exponential worst case, polynomial average), while interior-point methods solve in polynomial time $O((m+d)^{3.5})$. The Frank--Wolfe algorithm is preferred over both when (i)~the objective is non-linear and smooth (not a pure LP), and (ii)~the LMO (solving a sequence of LP sub-problems) is available as a subroutine. In the present experiment, the sub-problem $\min_{z \in \mathcal{X}} \nabla f(x_k)^{\!\top} z$ is solved exactly by the coordinate-wise rule in $O(d)$, making Frank--Wolfe's per-iteration cost equivalent to projected gradient descent for this box-constrained setting.

\subsection{Frank--Wolfe (Conditional Gradient) Algorithm}

\begin{algorithm}[H]
\caption{Frank--Wolfe (Conditional Gradient) with Fixed Mixing Parameter~\cite{frankwolfe1956}}
\label{alg:fw}
\begin{algorithmic}[1]
\Require $x_0 \in \mathcal{X}$, mixing parameter $\beta \in (0,1)$, iterations $N$
\For{$k = 0, 1, \ldots, N-1$}
    \State $z_k \gets \arg\min_{x \in \mathcal{X}}\, \nabla f(x_k)^{\!\top} x$ \Comment{Linear minimisation oracle (LMO)}
    \State $x_{k+1} \gets \beta\, x_k + (1-\beta)\, z_k$ \Comment{Convex combination; $\gamma = 1-\beta$}
\EndFor
\end{algorithmic}
\end{algorithm}

\noindent\textbf{Theory:} The standard Frank--Wolfe update is $x_{k+1} = (1-\gamma_k)x_k + \gamma_k z_k$ with $\gamma_k = 2/(k+2)$, achieving $O(1/k)$ convergence for smooth convex $f$. In this implementation, a \emph{fixed} mixing parameter $\beta$ is used (so $\gamma = 1-\beta$ is constant), which corresponds to a fixed step-size version. The LMO for box constraints decomposes per coordinate:
\begin{equation}
(z_k)_i = \begin{cases} l_i & \text{if } (\nabla f(x_k))_i > 0 \\ u_i & \text{if } (\nabla f(x_k))_i \leq 0 \end{cases}
\end{equation}
where $[l_i, u_i]$ is the $i$-th coordinate's box constraint. This requires $O(d)$ operations. Crucially, Frank--Wolfe needs \emph{no projection oracle}: feasibility is maintained by taking convex combinations of feasible points.

\begin{remark}
With fixed $\beta$, iterates remain in $\mathcal{X}$ because $x_{k+1} = \beta x_k + (1-\beta) z_k$ is a convex combination of two feasible points. This is the fundamental feasibility-preserving property of Frank--Wolfe.
\end{remark}

\subsection{Task II: Interior Optimum $f(x) = (x_1 - 1)^2 + (x_2 - 5)^2$}

\subsection{Interior vs.\ Boundary Behaviour: Theoretical Analysis}

\textbf{Interior optimum:} Frank--Wolfe exhibits a characteristic ``zig-zag'' convergence: as $x_k$ approaches the interior optimum $(1,5)$, the gradient $\nabla f(x_k) = 2(x_k - (1,5))$ becomes small but the sign of each component still determines the LP vertex $z_k$. Small perturbations cause $z_k$ to jump between $\{(0.5,-5), (0.5,10), (5,-5), (5,10)\}$, generating oscillatory iterates. The convergence rate for smooth convex $f$ with the standard $\gamma_k = 2/(k+2)$ schedule is $O(1/k)$:
\begin{equation}
f(x_k) - f^{\star} \leq \frac{2CL}{k+1}, \quad C = \mathrm{diam}(\mathcal{X})^2 = (4.5^2 + 15^2) \approx 245, \quad L = 2 \text{ (Lipschitz const.\ of } \nabla f\text{)}.
\end{equation}
This gives the bound $f(x_k) - f^{\star} \leq 980/(k+1)$, which is loose but correct in order. At $k=180$, the bound gives $\leq 5.42$, while the actual values are $0.009$ and $0.005$ --- factors of $600\times$ and $1084\times$ below the bound, reflecting the fast practical convergence near the interior optimum. With fixed $\gamma = 1-\beta$, the per-iteration decrease depends on $\gamma$ and the FW gap $\langle \nabla f(x_k), x_k - z_k \rangle$.

\textbf{Boundary optimum:} Frank--Wolfe is well-suited to boundary optima because the LMO selects the vertex that minimises the linearised objective, which naturally points towards the constraint boundary when the true optimum is there. With $f(x) = \|x\|^2$, gradient $\nabla f = 2x > 0$ elementwise for $x \in \mathcal{X}$, so $z_k = (0.5, -5)$ at nearly every iteration, driving the iterate towards the lower-left corner.

The fixed $\gamma = 0.07$ schedule causes \emph{persistent oscillation} near the constrained optimum $x^{\star} = (0.5, 0)$. At $x_k \approx (0.5, 0)$, the gradient is $\nabla f \approx [1, 0]$. Since $\nabla f_{2} = 0$, the LMO selects $z_{2}$ based on the sign of $\nabla f_2$: when $x_{k,2} > 0$, $\nabla f_2 > 0$ so $z_2 = -5$ (lower bound); when $x_{k,2} < 0$, $z_2 = 10$ (upper bound). This sign alternation causes $x_{k,2}$ to oscillate between small positive and small negative values indefinitely. Concretely, at $x_k = (0.5, 0)$: $z_k = (0.5, -5)$ (assuming $\nabla f_2 = 0^+$), giving $x_{k+1} = 0.93(0.5, 0) + 0.07(0.5, -5) = (0.5, -0.35)$. Then $\nabla f_2 < 0$ so $z_{k+1} = (0.5, 10)$, giving $x_{k+2} = 0.93(0.5, -0.35) + 0.07(0.5, 10) = (0.5, -0.325 + 0.7) = (0.5, 0.375)$. This oscillation around $x_2 = 0$ explains why $f = 0.364 > f^{\star} = 0.25$. Using the standard $\gamma_k = 2/(k+2)$ schedule eliminates this gap: as $\gamma_k \to 0$, the oscillation amplitude $\gamma_k |z_{k,2} - x_{k,2}| \to 0$, allowing the iterate to stabilise at $x^{\star}$. Numerically verified: with $\gamma_k = 2/(k+2)$ from the same starting point $(3,3)$, $f(x_{140}) - f^{\star} \approx 2\times10^{-6}$ (essentially converged to machine precision), compared to $f(x_{140}) - f^{\star} = 0.114$ with fixed $\gamma=0.07$ --- a $57{,}000\times$ improvement from the schedule change alone. With fixed $\gamma$, even after 500 iterations the oscillation persists at $f - f^{\star} \approx 0.17$, confirming that the fixed-$\beta$ parameterisation is the fundamental bottleneck.

\textbf{Frank--Wolfe duality gap as a stopping criterion.} Define the \emph{FW gap} $g_k = \langle \nabla f(x_k), x_k - z_k \rangle$. This quantity is non-negative (since $z_k$ minimises the linearisation) and equals zero at optimality ($\nabla f(x^{\star}) = 0$ for interior optima). The FW gap provides a computable certificate of optimality: if $g_k \leq \epsilon$, then $f(x_k) - f^{\star} \leq \epsilon$ (for convex $f$), making it a practical stopping criterion that does not require knowing $f^{\star}$.

\textbf{Away-steps and pairwise variants.} The standard Frank--Wolfe suffers from the zig-zag phenomenon because it can only move \emph{towards} vertices of $\mathcal{X}$, never away from them. The \emph{away-steps} extension also considers moving away from the active vertex most responsible for the current position, while the \emph{pairwise} Frank--Wolfe directly swaps weight between the worst active vertex and the best LMO vertex in a single step. Both variants maintain the $O(1)$ LMO cost per iteration while achieving \emph{linear} convergence rates on strongly convex problems, compared to the $O(1/k)$ rate of the standard update. For the interior optimum experiment, either variant would eliminate the zig-zag oscillations visible in Figure~\ref{fig:q6_fw_conv} and accelerate convergence substantially.

\textbf{Comparison with projected gradient descent:} Frank--Wolfe avoids projections entirely, replacing them with LMO calls. For simple sets like boxes, projections are as cheap as the LMO ($O(d)$), so the advantage is mainly structural (sparse iterates preserved in sparse problems, e.g., $\ell_1$-norm balls naturally produce sparse solutions via Frank--Wolfe). For complex constraint sets (e.g., nuclear-norm balls requiring SVD, spectrahedra requiring eigendecomposition), the LMO can be orders of magnitude cheaper than projection, making Frank--Wolfe the preferred algorithm in structured machine learning problems such as matrix completion and semidefinite programming relaxations.

\paragraph{Key cross-cutting findings:}

\begin{enumerate}[nosep]
\item \textbf{Problem structure determines method choice.} On the well-conditioned quadratic (Benchmark~A), nearly all methods perform comparably once properly tuned, because the loss is globally well-approximated by its quadratic model everywhere. On the ill-conditioned Rosenbrock function, Figure~\ref{fig:all_rosenbrock} shows a clear hierarchy: only methods that explicitly exploit curvature information (Newton: $f=0.686$ in 20 iters) or accumulate consistent momentum (Nesterov: $f=0.479$, Polyak with exact $f^{\star}$: $f=0.021$) make meaningful progress. Adam and GD trail by $7\times$ and $450\times$ respectively.

\item \textbf{Adaptive step sizes require correct knowledge.} The Polyak step is theoretically optimal when $f^{\star}$ is known exactly, but diverges catastrophically on Benchmark~A when $f^{\star}=0$ is misspecified (true optimum $0.4826$). This sensitivity makes Polyak impractical for most real applications. RMSprop and Adagrad provide robustness by basing adaptation on gradient history rather than function-value comparisons.

\item \textbf{Second-order information provides asymptotic quadratic convergence.} Newton's method converges in one iteration on the quadratic benchmark and achieves a $5.4\times$ lower objective than gradient descent on Rosenbrock with one-quarter the iterations. The computational overhead of Hessian computation is justified for small-dimensional problems; for large-scale problems, quasi-Newton methods (L-BFGS) capture the benefits of curvature information at $O(d)$ cost per iteration.

\item \textbf{Derivative-free methods trade accuracy for universality.} When gradients are unavailable, finite differences with a well-chosen $\delta$ closely approximate gradient descent, but zeroth-order random search sacrifices convergence speed for dimension-independent cost per iteration. Grid search provides global guarantees but is exponentially expensive in dimension.

\item \textbf{Constrained optimisation requires explicit feasibility management.} Projected GD enforces the hard constraint $x_1 \geq 0.5$ immediately and exactly at every step, while penalty methods gradually steer iterates towards feasibility with quality proportional to $\lambda$. The optimal method depends on the cost of projection: cheap for simple constraints, prohibitive for complex sets (where Frank--Wolfe is preferred).

\item \textbf{Frank--Wolfe avoids projection via linear subproblems.} By replacing gradient steps with LP oracle calls, Frank--Wolfe maintains feasibility as a structural invariant rather than as a per-step enforcement. The fixed mixing parameter $\beta$ trades convergence speed for simplicity; a diminishing schedule $\gamma_k = 2/(k+2)$ would improve final accuracy, especially near boundary optima.
\end{enumerate}

\paragraph{Practical guidelines:}
\begin{itemize}[nosep]
\item For smooth convex problems with known structure: \textbf{Nesterov} or \textbf{Adam} achieve near-optimal rates efficiently.
\item For small-dimensional problems where the Hessian is available: \textbf{Newton's method} is the clear winner, with the Newton decrement $\lambda(x)/2$ providing a certified stopping criterion.
\item For stochastic/large-scale settings: \textbf{Adam or RMSprop} provide robust performance with automatic coordinate-wise adaptation; use AMSGrad variant if convergence guarantees are needed.
\item For constrained problems with simple projections: \textbf{projected GD}.
\item For constrained problems with expensive projections or structured feasible sets: \textbf{Frank--Wolfe} (avoid-steps or pairwise variant for faster convergence).
\item When gradients are unavailable: \textbf{Nelder--Mead} for low-dimensional problems ($d \leq 5$); \textbf{random search} for high-dimensional problems; \textbf{finite differences} as a near-gradient-quality approximation when the function is smooth and the budget allows $d+1$ evaluations per step.
\item The condition number $\kappa$ is the single most important problem parameter: it determines the number of iterations needed as $O(\kappa)$ for first-order methods and $O(\sqrt{\kappa})$ for accelerated/momentum methods. For $\kappa \approx 2000$ (Rosenbrock), the gap between GD and Nesterov is $\approx\sqrt{2000} \approx 45\times$ in iterations needed.
\end{itemize}

\paragraph{Limitations and future directions.}
This study is limited to two-dimensional problems, where hyperparameter tuning is tractable and visualisation is direct. In higher dimensions ($d \geq 100$), several key behaviours change: (i)~the condition number $\kappa$ typically grows with $d$ for random matrices ($\kappa \sim O(\sqrt{d})$ for Wishart matrices), making accelerated methods increasingly important; (ii)~Newton's $O(d^3)$ Hessian solve becomes prohibitive, motivating quasi-Newton (L-BFGS) and stochastic second-order methods; (iii)~mini-batch variance scales differently (central limit theorem improves gradient quality in high $d$). Future extensions include: variance reduction techniques (SVRG, SAGA) that interpolate between SGD noise and full-batch stability; stochastic Frank--Wolfe methods for constrained problems with noisy gradients; and adaptive methods with theoretical convergence guarantees (AMSGrad, AdaFactor). The Rosenbrock function, while canonical, has a very specific ill-conditioning structure; future benchmarks should include ill-conditioned quadratics, deep network losses, and logistic regression to provide a more complete picture.

def gradient_descent(grad_fn, loss_fn, x0, alpha, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        x = x - alpha * grad_fn(x)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Polyak Step Size}]
def polyak_step(grad_fn, loss_fn, x0, f_star, eps, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        alpha_k = (loss_fn(x) - f_star) / (np.dot(g, g) + eps)
        alpha_hist.append(alpha_k)
        x = x - alpha_k * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adagrad}]
def adagrad(grad_fn, loss_fn, x0, alpha0, eps, n_iters):
    x = x0.copy().astype(float)
    G = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        G += g**2
        eff_alpha = alpha0 / (np.sqrt(G) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={RMSprop}]
def rmsprop(grad_fn, loss_fn, x0, alpha0, beta, eps, n_iters):
    x = x0.copy().astype(float)
    v = np.zeros_like(x)
    x_hist, f_hist, alpha_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        v = beta * v + (1 - beta) * g**2
        eff_alpha = alpha0 / (np.sqrt(v) + eps)
        alpha_hist.append(np.mean(eff_alpha))
        x = x - eff_alpha * g
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(alpha_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Heavy Ball}]
def heavy_ball(grad_fn, loss_fn, x0, alpha, beta, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for _ in range(n_iters):
        g = grad_fn(x)
        z = beta * z + alpha * g
        x = x - z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Nesterov Accelerated Gradient}]
def nesterov_momentum(grad_fn, loss_fn, x0, alpha, beta_max, n_iters):
    x = x0.copy().astype(float)
    z = np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for k in range(1, n_iters + 1):
        beta_k = min((k - 1) / (k + 2), beta_max)
        lookahead = x + beta_k * z     # evaluate gradient ahead
        g = grad_fn(lookahead)
        z = beta_k * z - alpha * g
        x = x + z
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Adam Optimiser}]
def adam_optimiser(grad_fn, loss_fn, x0, alpha, beta1, beta2, eps, n_iters):
    x = x0.copy().astype(float)
    m_vec, v_vec = np.zeros_like(x), np.zeros_like(x)
    x_hist, f_hist = [x.copy()], [loss_fn(x)]
    for t in range(1, n_iters + 1):
        g = grad_fn(x)
        m_vec = beta1 * m_vec + (1 - beta1) * g
        v_vec = beta2 * v_vec + (1 - beta2) * g**2
        m_hat = m_vec / (1 - beta1**t)       # bias correction
        v_hat = v_vec / (1 - beta2**t)
        x = x - alpha * m_hat / (np.sqrt(v_hat) + eps)
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist)
\end{lstlisting}

\begin{lstlisting}[caption={Newton's Method with Damping}]
def newtons_method(grad_fn, hess_fn, loss_fn, x0, alpha, n_iters, damping=1e-8):
    x = x0.copy().astype(float)
    x_hist, f_hist, update_norms = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        H = hess_fn(x) if callable(hess_fn) else hess_fn
        H_reg = H + damping * np.eye(len(x))   # Tikhonov regularisation
        try:
            p = np.linalg.solve(H_reg, g)
        except np.linalg.LinAlgError:
            p = g                               # fallback to gradient
        update_norms.append(np.linalg.norm(alpha * p))
        x = x - alpha * p
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(update_norms)
\end{lstlisting}

\begin{lstlisting}[caption={Frank--Wolfe Algorithm}]
def frank_wolfe(grad_fn, loss_fn, x0, bounds, beta, n_iters):
    x = x0.copy().astype(float)
    x_hist, f_hist, z_hist = [x.copy()], [loss_fn(x)], []
    for _ in range(n_iters):
        g = grad_fn(x)
        # LMO: minimise g^T z over box
        z = np.array([bounds[i][0] if g[i] > 0 else bounds[i][1]
                       for i in range(len(g))])
        z_hist.append(z.copy())
        x = beta * x + (1 - beta) * z   # convex combination
        x_hist.append(x.copy())
        f_hist.append(loss_fn(x))
    return np.array(x_hist), np.array(f_hist), np.array(z_hist)
\end{lstlisting}
